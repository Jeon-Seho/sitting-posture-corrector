# FE 개발 PC에 직접 설치하는 프로그램 (2026-10-12)
# requirements-dev.txt(Python 패키지)와 frontend/package.json(npm 패키지)은 설치 명령이 자동으로 받는다.
# 이 파일은 자동으로 받지 못하는 프로그램만 적는다. 기계가 읽는 형식이 아니라 사람이 보는 목록이다.
# 형식: 이름 | 버전 | 어디서 받나(Windows) | 어느 검사에 필요한가 (docs/development.md)

# 기본 (python tools/dev.py setup, test, check-frontend)
Git            | 최신        | winget install Git.Git                          | 전부
Node.js        | 24 이상     | winget install OpenJS.NodeJS.LTS                | check-frontend, 수동 브라우저 점검
Python         | 3.9 이상    | winget install Python.Python.3.13               | test, 모든 tools/*.py

# 서버 기본 검사 (check-backend)
JDK            | 17          | winget install EclipseAdoptium.Temurin.17.JDK   | 컴파일·기본 시험 (check-backend)
# Gradle·Maven은 설치하지 않는다. backend/gradlew(Gradle Wrapper)가 처음 실행할 때 Gradle 9.7.1을 받는다(backend/README.md).
JDK            | 21          | winget install EclipseAdoptium.Temurin.21.JDK   | Checkstyle (check-backend)
Chrome         | 최신        | winget install Google.Chrome                    | 수동 테마·JWT·자정 점검

# 별도 개발·DB 통합·배포 환경 (기본 check에는 불필요)
Docker Desktop | 최신        | winget install Docker.DockerDesktop             | dev-server의 임시 MySQL 선택·Compose 배포 (실행 중이어야 함)

# 환경변수 (사용자 변수, 설정 뒤 터미널·VS Code를 새로 연다)
# JAVA_HOME        = C:\Program Files\Eclipse Adoptium\jdk-17.x.x-hotspot   (17 이상)
# 확인: backend\gradlew.bat -p backend --version  → Launcher JVM 이 17 이상이어야 한다
# check-backend 등 make 단계도 backend/gradlew를 부른다. 처음 한 번 .cache/gradle 에 Gradle과 의존성을 받는다.

# 새 Windows PC는 tools/setup-windows.ps1 이 Git·Node.js·Python과 저장소 준비를 한 번에 한다(JDK·Chrome·Docker는 위대로 따로).
