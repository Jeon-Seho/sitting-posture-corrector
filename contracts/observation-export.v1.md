# 관측 전체 내보내기

`/dev`에서 전체 데이터 JSON 하나를 명시적으로 내려받는다. 실제 영상·오디오와 카메라 장치 ID는 포함하거나 저장하지 않는다. v8부터 카메라를 켜기 전 입력한 측정자 이름(`participant`, 1~30자)을 담고 파일 이름 앞에 붙인다(2026-11-03 사용자 결정). 이름이 든 파일은 저장소에 넣지 않는다. 출력은 현재 탭 메모리에만 머무르며 서버로 전송하거나 자동 저장하지 않는다. 메모에 개인 정보를 입력하지 않도록 안내한다. **안내 과제는 수행을 검증한 정답이 아니다.** 참여자별 분리와 라벨 검토는 별도다.

## 전체 데이터

`observation-keypoint-replay-v8` JSON은 Pose 원래 인덱스 0..32의 image/world x·y·z·visibility를 33개 순서로 기록한다. 프레임마다 관측 시각·검증 전 원시 시각·영상 시각·수집 경과 시각·크기·추출기 ID·추론 시간·실행 delegate·어깨 추적 상태·측정 가능 여부를 포함한다. 기존 특징은 측정 가능한 프레임에서 로컬 관측 화면이 원본 좌표로 계산하며, 측정 불가나 값 누락은 null이다. `phase`, `task`, `round`, `trial`, `attempt`, `segment`, `measurement`는 안내 맥락이고, 최상위 plan·수동/자동 모드·스트레칭 메모·중단 표식과 누락 수를 보존한다. v7(`front-observation-base-hold-v7`)은 각 동작 뒤 기준 측정 구간(`phase=hold`, `task=neutral`, `measurement=true`)을 두고, 동작마다 8~15초 중 1초 단위로 뽑은 측정 시간을 최상위 `schedule`(`round`, `trial`, `action`, `phase`, `durationMs`)에 기록한다. 2026-11-03부터 시작 창은 「이탈 → 기준」 반복(`plan.cycle=repeat`)만 제공한다. `stretch`는 계약상 유효하지만 새 기록에서 고를 수 없다. 안내를 시작하기 전에 끝난 기록은 빈 배열이다. 유효하지 않거나 없는 값은 null이며 0으로 보완하지 않는다. 시간 역전의 좌표 원본은 보존하되 유효 관측으로 해석하지 않는다.

v8(`scope=reference_and_hold_phases`)은 라벨이 있는 구간만 기록한다. 기준 등록(`phase=registering`)과 측정 구간(`measurement=true`)만 남기고, 준비·이동·복귀·대기·일시 정지 프레임은 저장하지 않는다. 기준 등록 프레임은 기준을 다시 계산하는 데 쓰인다. v7까지(`scope=all_phases_replay_only`)는 모든 단계를 기록했고 측정자 이름이 없다. 프로토콜(`front-observation-base-hold-v7`)과 `schedule`은 v7과 같다.

화면 측정 경로에서 7~10Hz로 채택한 추론 관측을 기록한다. 관측은 100ms 간격의 시간 칸에 맞춰 채택한다. 칸은 마지막 채택 시각이 아니라 자체 일정으로 넘어가므로 추적이 10fps보다 빠르면 약 10Hz가 되고, 채택 간격은 최소 50ms다. 카메라 화면 오른쪽 위에 최근 3초 채택 속도를 표시하고, 7Hz 미만이면 경고 문구로 바꾸지만 기록은 계속한다(2026-11-03, 이전에는 직전 채택과 100ms 미만이면 버려서 약 13fps 추적에서 6.7Hz, 30fps에서 약 7.5Hz였다). 카메라의 모든 영상 프레임이나 실측 전신 좌표를 보장하지 않으며 화면 밖 좌표는 모델 추정이다. 메모리 한도 6,000프레임 도달 시 측정을 자동 종료하고 보존된 자료를 내보내도록 알린다. 이전 v1(13점)·v2~v4(23점)·v5~v7(33점) 파일도 리플레이로 읽는다. v4~v6은 `front-observation-optional-stretch-v6`(측정 5초·스트레칭 8초·복귀 준비 5초, 기준 측정 없음)만 받는다. 파일 불러오기는 64MiB 이하만 허용한다.

## ML 후보 특징 (2026-11-03 다운로드 제거)

별도의 `observation-ml-candidates-v1` 다운로드는 없앴다. 학습할 때 전체 데이터 JSON의 33점 원본에서 필요한 특징을 골라 계산한다. 기존 후보 5개(기준 대비 머리–어깨 간격·얼굴 세로 길이·어깨 높이·어깨폭·코–어깨 상대 z)의 계산식은 [`observationComparison.ts`](../model/prototype/observationComparison.ts)에 그대로 있다. 이전에 받은 `observation-ml-candidates-v1` 파일은 기준 대비 상대값과 팔 13..22 좌표만 담고 있어 머리·어깨의 절대 위치나 좌우 이동은 복원할 수 없다.

기록 v6·v7은 공통 카메라의 `measurable` 값을 보존하고, 측정 불가 프레임을 비교·ML 후보값으로 재해석하지 않는다. 기존 v5에는 이 값이 없어 null로 읽는다.

현재 서버 추론의 입력 계약 `shoulder-relative-deltas-v1`은 머리 간격·좌우 변위·어깨 기울기 변화와 현재·기준 품질을 요구한다. 전체 데이터 JSON에서 계산한 후보 특징은 해당 입력과 필드·계산식이 다르므로 서버 추론 또는 확정된 학습 입력에 바로 사용할 수 없다. 실제 사용할 ML 모델과 전처리 계약을 정한 뒤 별도 변환·검증이 필요하다.
