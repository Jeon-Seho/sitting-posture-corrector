# 프레임별 2단계 RF 파일럿

한 프레임의 개인 기준 대비 특징으로 세로 이동 보정 RF와 자세 분류 RF를 차례로 실행한다. 자세 분류기의 학습 대상은 기존 라벨의 기준 자세(`neutral`, 0)와 이탈(`deviation`, 1)이다. 유효한 프레임마다 이탈 점수 하나를 내며, 모델은 3초 지속·복귀·재알림을 계산하지 않는다. 이 경로와 산출물은 **연구 후보**이며 서비스 추론 API에는 아직 연결하지 않았다.

기존 [1초 창 2단계 실험](../replay_pilot/TWO_STAGE.md)은 별도로 보존한다. 이전 창 모델의 가중치를 프레임 모델로 사용하지 않으며, 프레임 입력으로 두 모델을 다시 학습한다. 기존 실험 자료·보고서·가중치는 수정하지 않는다.

## 입력과 품질

- 입력은 서비스와 같은 순서의 코·눈·귀·입꼬리·어깨 9점 `[x, y, visibility]`다. 4:3 화면의 정규화 좌표를 기준 640×480 픽셀 공간으로 해석한다. 다른 4:3 해상도의 정규화 값은 같은 계산을 쓰며, 실제 카메라의 크롭·해상도에 따른 추적 차이는 별도 검증이 필요하다. 수집 도중 해상도나 추출기가 바뀐 리플레이는 거부한다.
- 모델이 사용하는 9점의 `visibility`가 모두 최소값 이상이고 좌표가 화면 안에 있어야 한다. 시작값 **0.65는 기존 코·어깨 품질 검사에서 가져온 탐색 설정**이며, 모델 파일의 보고서에 저장한다. 프레임 입력은 서비스 전송과 같이 좌표 5자리·visibility 2자리로 반올림한다.
- 낮은 가시성, 좌표 누락, 외부의 측정 불가 신호, 고개 돌림은 점수를 내지 않는다. 모델 앞단에서 걸러낸 시간은 정상·이탈 또는 복귀로 채우지 않는다. 기준 등록 중 품질이 나쁘면 등록도 다시 시작한다.
- MediaPipe의 visibility는 추정값이므로 높은 값이 실제 좌표의 정확성을 보증하지 않는다. 품질 검사는 입력의 유효성을 확인하는 단계이며 별도의 자세 라벨이 아니다.
- 현재 서비스 DB의 기준 자세에는 visibility가 없다. `reference_from_points(..., quality_verified=True)`는 **기준 등록 시 9점의 품질을 별도로 확인한 경우에만** 사용한다. 기존 서버의 저장 좌표만으로 이 조건을 소급 확인할 수 없다.

기존 3초·20표본 기준 자세 등록은 개인 기준을 만드는 단계다. 자세 이탈이 3초 이어졌는지는 별도의 판정 서버가 정한다.

## 학습과 평가

v8 리플레이에서 측정 구간마다 유효 프레임 하나를 예제 하나로 만든다. `task`의 `neutral`을 0, `deviation`을 1로 사용하고 별도의 분류 대상을 추가하지 않는다. 1초 중앙값을 만들지 않는다. 사람을 통째로 학습·시험에서 나눈 뒤 안쪽 참여자 분할로 분류기의 설정과 임계값을 선택한다. 파일은 촬영 안내 라벨이라는 출처를 기록하며, 실제 수행이 일치하는지는 별도 확인이 필요하다.

보정 RF는 학습 참여자의 기준 안내 프레임에만 640×480 기준 세로 이동을 합성해 학습한다. 자세 RF는 각 학습 참여자를 제외하고 만든 보정기의 출력으로 입력을 준비한 뒤 기존 25배 특징 증강으로 학습한다. 시험 참여자의 이탈 자료는 어느 모델의 학습이나 설정 선택에도 넣지 않는다. 인접 프레임과 증강 자료는 독립 참여자가 아니며, 합성 이동 보정은 실제 의자 이동량을 추정한다고 입증된 기능이 아니다.

참여자별 평가에는 최소 4개 참여자 그룹이 필요하고 각 그룹에 두 안내 라벨이 모두 있어야 한다. 모든 사람으로 학습한 두 파일은 별도 독립 시험이 없는 탐색 후보이고, 보고서의 사람별 분리 결과를 이 후보의 실제 사용자 성능으로 바꾸어 말하지 않는다. 저장된 모델 점수는 보정된 실제 확률이 아니다. 모델 선택·임계값·관측 품질 기준을 확정하려면 확인된 라벨과 독립 참여자·실제 사용 자료가 필요하다.

## 실행

저장소의 `requirements-dev.txt`를 설치한 Python 환경이 필요하다. 실제 리플레이, 이름 매핑, 모델 파일, 보고서는 저장소 밖의 접근 제한 폴더에 보관한다.

```sh
python -m model.analysis.frame_pilot catalog --input "<private>/replays" --output "<private>/catalog.json"
python -m model.analysis.frame_pilot evaluate --catalog "<private>/catalog.json" --output "<private>/frame-run-01"
```

카탈로그의 참여자 이름–ID 대응을 별도로 확인한 뒤에만 `identity_reviewed`를 `true`로 바꾼다. 신원 확인 전 파이프라인 점검에는 `--allow-unverified-identities`를 명시하며 결과를 탐색용으로 취급한다. `--min-visibility`는 기록되는 실험 설정이며 시험 참여자 결과에 맞춰 바꾸지 않는다. `--classifier-trees`·`--corrector-trees`는 예산을 조절하는 탐색 옵션으로, 실제 설정은 보고서에 남는다.

어떤 그룹에 안내 라벨 한 종류만 있어 위 평가를 실행할 수 없다면 `evaluate`에 `--candidate-only`를 추가해 고정 설정의 전체 자료 후보만 만들 수 있다. 이 방식은 각 학습자의 입력 보정을 다른 학습자의 기준 프레임으로 교차 계산하지만, **참여자별 성능 평가나 모델·임계값 선택을 하지 않는다**. 최소 두 그룹과 학습 전체의 두 클래스가 필요하다. 로컬 비교 화면의 0.5는 점수 관찰용 임시 기준이며 검증된 판정 임계값이 아니다. 신원 미확인일 때는 별도로 `--allow-unverified-identities`도 명시해야 한다.

출력은 `frame-corrector.joblib`, `frame-posture.joblib`, `report.json`이다. 보고서는 입력·코드·모델 해시, 참여자별 분리, 각 라벨의 제외 프레임 수와 설정을 기록한다. `joblib`을 불러오는 행위는 코드를 실행할 수 있으므로, 해시가 맞더라도 **출처를 신뢰하는 파일만** 사용한다.

### 고정 설정의 참여자별 증강 비교

기존 [25배 증강 방식](../replay_pilot/AUGMENT_50K.md)을 프레임에 적용해, 증강하지 않은 RF와 증강한 RF를 같은 평가 참여자의 원본 프레임으로 비교한다.

```sh
python -m model.analysis.frame_pilot.holdout --catalog "<private>/catalog.json" --output "<private>/frame-holdout-01"
```

매 반복에서 참여자 한 그룹을 시험에만 사용하며 해당 사람의 기준 등록만 개인 기준으로 사용한다. 보정기는 학습 참여자의 기준 프레임에 51개 합성 세로 이동을 적용하고, 분류기는 다른 참여자로 학습한 보정기의 출력을 기준으로 원본 또는 25배 증강 입력을 학습한다. 같은 학습 분할·모델 설정·원본 시험 프레임에서 두 결과를 비교한다. 증강 프레임은 새 참여자나 새 촬영이 아니다.

기존 후보와 같은 보정 RF 80개·분류 RF 120개 트리와 이탈 점수 0.5를 **평가 전에 고정**하며, 시험 참여자로 모델이나 기준을 고르지 않는다. `--workers`는 독립 학습의 동시 실행 수(1~4)이고 `--classifier-trees`·`--corrector-trees`는 탐색용 설정이다. 학습 참여자 중 한 라벨이 없는 그룹도 포함할 수 있지만, 그 그룹의 balanced accuracy는 계산하지 않는다. 보고서는 두 라벨이 있는 그룹만 사람별 balanced accuracy 평균에 포함하고 단일 라벨 그룹과 전체 프레임 분모도 별도로 기록한다.

미확인 참여자 이름을 사용하려면 탐색용으로 `--allow-unverified-identities`를 명시한다. `report.json`의 참여자별 분리 결과는 **학습 절차의 탐색 평가**다. 함께 만들어지는 전체 자료 후보는 시험 참여자의 자료도 학습에 사용했으므로 별도의 독립 시험이 없다. 0.5는 평가를 위해 고정한 값이지 운영 임계값으로 검증된 수치가 아니다.

### 같은 평가에서 100배 증강 비교

25배 평가 결과를 입력으로 사용해 같은 참여자 분할·학습 설정·시험 프레임을 유지하면서 분류기의 학습 특징을 원본당 100개로 늘린다. 앞의 25개는 기존 방식과 같고 나머지 75개는 같은 범위의 잡음을 추가한다. 원본과 증강본의 가중치 합은 유지하며, 시험 프레임은 증강하지 않는다. 보정기의 학습 방식은 그대로다.

```sh
python -m model.analysis.frame_pilot.holdout_100 --catalog "<private>/catalog.json" --prior-dir "<private>/frame-holdout-01" --output "<private>/frame-holdout-100" --checkpoint-dir "<private>/frame-holdout-100-checkpoint" --workers 2
```

기존 보고서·모델과 카탈로그의 해시, 학습 코드, 환경, 설정 및 시험 프레임 수가 일치해야 비교할 수 있다. 신원 미확인 자료에는 `--allow-unverified-identities`가 필요하다. 체크포인트를 지정하면 중단 후 같은 명령으로 이미 완료된 학습을 재사용한다. 데이터·코드·설정이 바뀌면 새 체크포인트가 필요하며, `joblib` 파일을 포함하므로 신뢰하는 비공개 폴더만 지정한다. 결과 폴더는 아직 존재하지 않아야 한다.

#### 다른 컴퓨터에서 재개

실제 촬영과 모델은 Git에 올리지 않는다. 보안이 유지되는 방법으로 비공개 묶음을 별도로 전달하고 저장소 바깥에 둔다. 묶음에는 참여자 이름·랜드마크·모델 가중치가 포함되므로 공개 공유하지 않는다. `joblib`은 코드를 실행할 수 있어 자신이 만든 신뢰할 수 있는 묶음만 불러온다.

먼저 기존 환경에서 묶음을 만든다. 같은 경로의 자료를 다시 덮어쓰지 않도록 출력 폴더는 새로 지정한다.

```sh
python tools/frame_resume.py pack --catalog "<private>/catalog.json" --prior-dir "<private>/frame-holdout-01" --checkpoint-dir "<private>/frame-holdout-100-checkpoint" --output "<private>/transfer-bundle"
```

집 컴퓨터에서 같은 소스 브랜치와 학습 당시 Python·numpy·scikit-learn·joblib 버전을 준비한다. 학습 환경 버전은 이전 `report.json`의 `environment`에 기록돼 있으며, 이번 실행은 Python 3.9.6, numpy 1.26.4, scikit-learn 1.6.1, joblib 1.4.2를 사용했다. 필요한 Python 패키지는 `model/analysis/requirements-training.txt`에서 설치한다. 동일 버전에서도 다른 OS나 CPU의 모델 호환성은 재개 준비 단계에서 파일을 불러와 확인한다.

```sh
python tools/frame_resume.py prepare --bundle "<private>/transfer-bundle" --session "<private>/resumed-frame-100"
python tools/frame_resume.py run --session "<private>/resumed-frame-100" --workers 2
```

`prepare`는 실제 학습을 실행하지 않는다. 입력·코드·이전 결과와 체크포인트를 검증하고 변경된 파일 경로만 다시 연결해 새 세션을 만든다. 이미 존재하는 세션을 덮어쓰지 않는다. `run`은 저장된 보정 모델과 완료된 평가를 사용하며 중단된 분류기 학습부터 진행한다. 결과는 새 세션의 `result/`에 저장된다. 참가자 신원·안내 라벨 검토 및 독립 시험의 한계는 그대로 남는다.

여기서 **0.5는 분류기의 이탈 점수를 기준과 이탈로 나누는 실험용 분류 기준**이다. 점수가 0.5 이상이면 이탈로 계산하며, 0.5초나 정확도 50%를 뜻하지 않는다. 점수는 실제 발생 확률로 보정되어 있지 않고, 운영 기준도 아직 검증되지 않았다. 3초 지속 여부는 별도 판정 서버가 처리한다.

평가 대상에서 빠진 자료는 별도로 확인한다. 아래 명령은 기준·이탈 라벨별 원본/유효/제외 프레임 수, 제외 이유, 유효 프레임이 하나도 없는 시도 수를 집계한다. 원본 좌표나 참여자 이름은 보고서에 넣지 않는다. 신원 확인 전에는 여기에도 `--allow-unverified-identities`가 필요하다.

```sh
python -m model.analysis.frame_pilot.coverage --catalog "<private>/catalog.json" --output "<private>/frame-coverage.json"
```

모델이 점수를 낼 수 없는 시도는 분류 정확도 분모에서 빠지므로, 이 집계와 평가 성능을 함께 읽는다. 제외는 이탈 예측 성공이나 실패로 임의 변환하지 않는다.

같은 환경에서 새 후보를 [로컬 웹캠 비교](../live_comparison/README.md) 화면으로 확인할 수 있다.

```sh
python -m model.analysis.live_comparison.server --artifacts-dir "<private>/frame-run-01"
```

브라우저에서 `http://127.0.0.1:8765/`를 연다. 화면은 모델이 프레임 입력인지 기존 1초 창 입력인지 표시한다. `--candidate-only` 결과의 기준은 「임시 비교 기준 · 검증 전」으로 표시한다. 연구 화면은 포즈 추출을 최소 100ms 간격으로 요청하므로 카메라가 보낸 모든 프레임을 처리한다는 뜻은 아니다. 프레임 후보의 「보정 전」은 **같은 프레임 분류기에 보정 전 입력을 넣은 비교**이며, 별도로 학습한 미보정 모델은 아니다. 웹캠 화면의 3초 알림은 연구 화면 내부의 비교용이며 운영 판정 서버의 사건 기록이 아니다.

## 서비스 연동 전 확인

서비스의 프론트는 9점을 보내지만 현재 백엔드→추론 v2는 특징 3개만 보낸다. 6개 특징·기준 어깨 폭과 기준 품질을 누가 계산·검증할지, 세션·순번·시간·측정 불가·모델 버전·임계값을 어떤 버전의 계약으로 전달할지 합의해야 한다. 이 파일럿은 서비스 계약을 우회해 연결하지 않는다. 새 후보의 전체 지연·FPS, 실제 사용자 오알림과 놓침도 아직 측정하지 않았다.
