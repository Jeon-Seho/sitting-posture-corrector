# 웹캠 자세 비교 실험

개인 기준 대비 **기존 서버의 규칙 점수**와 합성 세로 이동 보정 후 재학습한 **2단계 분류기**를 같은 웹캠 관측으로 비교하는 로컬 연구 도구다. 서비스의 알림·API는 바꾸지 않는다. 이 화면의 기준/이탈 표시는 관측 점수와 실험 임계값을 비교한 결과다. 알림은 연구 화면에서 두 방식에 각각 발생시키며 운영 서버의 사건·알림 기록이 아니다.

2026-11-12부터 기존 1초 창 후보와 별도로 학습한 [프레임별 RF 후보](../frame_pilot/README.md)도 불러올 수 있다. 프레임 후보는 관측마다 추론하며 화면에 「현재 프레임」으로 표시한다. 두 후보의 파일·입력 버전은 서로 바꿔 쓰지 않는다. 프레임 후보에서 「보정 전」은 같은 분류기에 보정 전 입력을 넣은 비교다.

프런트·추론·판정 서버 사이의 JSON 예시와 2단계 모델 연동 범위는 [백엔드 데이터 흐름](../../BACKEND_DATA_FLOW.md)에 정리한다.

## 준비와 실행

- Python 가상환경에 루트 `requirements-dev.txt`와 `model/analysis/requirements-trees.txt`를 준비한다.
- `frontend/node_modules/@mediapipe/tasks-vision/vision_bundle.mjs`와 `frontend/public/mediapipe/`의 Heavy·WASM 자산이 필요하다. 없으면 저장소의 프론트 준비 절차(`python tools/dev.py setup-frontend`)를 실행한다.
- 기존 `model.analysis.replay_pilot.two_stage` 또는 새 `model.analysis.frame_pilot`이 만든 **신뢰할 수 있는** 비공개 결과 폴더가 필요하다. 보고서와 해당 모델 파일들의 해시가 일치해야 한다. `joblib`은 임의 코드를 실행할 수 있으므로 출처를 확인하지 않은 파일을 사용하지 않는다.

저장소 루트에서 Windows PowerShell 예시:

```powershell
.\.venv\Scripts\python.exe -m model.analysis.live_comparison.server `
  --artifacts-dir "<저장소 밖의 two-stage 결과 폴더>"
```

같은 PC의 Chrome 또는 Edge에서 `http://127.0.0.1:8765/`를 연다. 카메라를 시작하고 얼굴과 양 어깨를 화면에 둔 뒤 **기준 자세 등록**을 누른다. 3초 이상·20개 이상 유효 표본을 모으면 등록이 완료되고, 이후 충분한 관측이 모이면 점수가 표시된다. 종료 버튼은 카메라를 끄고 해당 비교 세션을 지운다. 서버 종료는 실행한 터미널에서 Ctrl+C다. 다른 포트가 필요하면 `--port 8766`을 전달한다.

화면 점수는 `100 × (1 − 원점수)`로, 100점에 가까울수록 등록한 기준에 가깝다. 숫자와 막대는 화면에서만 시정수 2.4초로 부드럽게 바뀐다. 상태·알림은 평활화하지 않은 원점수로 판정하므로 표시 점수와 즉시 일치하지 않을 수 있다. 측정이 불가하면 점수는 바로 지운다. 보정 전 모델 점수도 같은 방향과 평활화로 표시한다.

**같은 자세의 판정 비교**는 같은 유효 관측에서 규칙과 모델의 `유지`·`이탈`을 나란히 보여준다. 두 방식의 점수 크기를 직접 비교하지 않고 각자의 원점수와 임계값으로 나눈 판정을 비교한다. 판정 차이는 어느 방식이 정확한지를 증명하지 않는다. 이전의 고정 차이 장면은 제거했다.

### 카메라 특징 설명

영상 아래쪽의 **규칙 기준 / 모델 기준** 버튼으로 표시를 바꾼다. 영상의 색과 아래 특징 목록은 모델에 따라 최근 1초 창 또는 현재 프레임을 설명하며, 표시 점수가 아닌 평활화 전 원점수에 기초한다. 색과 설명을 계산하는 동안 기존 점수·이탈 판정·알림 계산은 바뀌지 않는다.

- **규칙 기준:** 머리–어깨 높이·좌우 치우침·어깨 기울기 세 성분의 이탈 지수 중 가장 큰 것이 점수를 정한다. 빨강은 해당 성분이 기존 이탈 기준 70에 도달한 경우, 초록은 기준 등록 표본에서 관찰한 개인 변화 범위 안, 노랑은 그 범위 밖이지만 이탈 기준 미만이거나 등록 범위를 구하지 못한 경우다. 이 등록 범위는 짧은 등록 구간의 최댓값이며 검증된 정상 범위가 아니다.
- **모델 기준:** 다른 다섯 입력은 그대로 두고 각 특징 하나만 기준값 0으로 대체한 뒤 보정기와 분류기를 모두 다시 실행한다. 빨강은 대체했을 때 평활화 전 100점 방향 점수가 0.1점 이상 오르는 특징, 초록은 0.1점 이상 떨어지는 특징, 노랑은 그 차이가 0.1점 미만인 특징이다. 예를 들어 `기준 대체 시 +8.0점`은 다른 특징을 고정한 이 비교에서 점수가 8점 오른다는 뜻이다. 0.1점은 표시용 구분일 뿐 이탈 판정 기준이 아니다.
- 코·눈·귀·입꼬리·어깨 중 모델이 사용하는 점의 visibility가 부족하면 두 점수 모두 즉시 측정 불가로 지운다. 기준 등록 중에도 해당 관측을 제외하고 등록을 다시 시작한다. 시작 기준은 0.65이며 아직 실측으로 확정하지 않은 입력 품질 설정이다. 설명 계산만 실패한 경우에는 점수를 유지하고 설명을 회색으로 둔다.

모델의 대체 비교는 특징 간 상호작용의 영향을 받으며 실제로 만들기 어려운 입력 조합일 수 있다. 관절별 인과 기여도·의학적 정상 여부나 예측 정확도가 아니다. 카메라의 점은 특징을 찾기 위한 대표 위치다: 코는 머리–어깨 높이, 귀는 좌우 치우침, 어깨는 어깨 관련 특징, 눈과 입은 얼굴 높이를 나타낸다. 실제 특징 계산에는 이들 외에도 어깨 등 여러 점이 함께 쓰인다. 어깨처럼 대표 위치가 겹치면 빨강·노랑·초록 순으로 표시하고, 하나라도 확인할 수 없으면 회색으로 표시한다. 목록에서 각 특징을 따로 볼 수 있다. 영상과 이전 장면은 저장하지 않는다.

### 자세별 시나리오 기록

카메라를 시작해 기준을 등록한 뒤 오른쪽 **자세별 점수 기록**에서 안내에 따라 각 자세를 취한다. 해당 자세의 **현재 점수 기록**을 누르면 화면에 보이는 규칙·모델 점수와 그 순간의 판정을 함께 기록한다. 관측이 끊기거나 측정 불가이면 자동 기록을 사용할 수 없다. 점수는 카메라 없이 직접 입력할 수도 있으며, 다시 기록하면 해당 자세의 이전 입력을 바꾼다. 테스트 중 카메라를 종료하거나 기준을 다시 등록해도 입력은 남는다. 저장 전에 탭을 닫거나 새로고침하면 입력은 사라진다.

**기록한 결과 JSON 저장**을 누르면 입력된 자세만 새 파일로 저장한다. 기본 위치는 이 저장소의 `model/test/senario/`이며, 다른 위치가 필요하면 실행할 때 `--scenario-dir "<경로>"`를 지정한다. 이 폴더는 Git 제외 대상이다. 파일마다 새 이름을 만들어 이전 파일을 덮어쓰지 않는다.

자동 기록은 평활화한 화면 점수(반올림), 원점수·기준·순간 판정, 보정 전 모델 원점수와 보정량, 특징 설명, 기록 시각, 이 탭에서의 기준 등록 순서와 **세션 누적** 화면 알림 횟수를 담는다. 누적 횟수는 해당 자세에서 새로 울린 횟수가 아니다. 입력한 점수를 수정하면 그 행은 `manual`로 바뀌고 자동 판정·특징 정보는 저장하지 않는다. 하나의 점수만 입력한 행은 다른 점수를 `null`로 저장한다. 원본 영상, 키포인트 좌표, 세션 토큰, 참여자 이름은 저장하지 않는다.

**알림 횟수 비교**는 규칙과 모델 각각의 원래 판정에서 이탈이 3초 이어질 때 화면 알림을 띄우고 센다. 이탈이 계속되면 60초 후 다시 알리고, 기준 내 관측이 3초 지속되면 사건을 닫는다. 측정 불가·누락은 연속 시간과 열린 사건을 끊는다. 기본 시간은 [ADR 0020](../../../docs/decisions/0020-single-api-decision-engine.md)을 참고했으나 이 연구용 관측 창의 로컬 비교이며 운영 서버 판정 결과의 재현이나 저장은 아니다. 카메라를 종료해도 횟수는 남고 기준을 다시 등록하면 초기화된다.

**시스템 알림 켜기**를 눌러 브라우저 권한을 허용하면 같은 사건에 시스템 알림도 요청한다. 화면 횟수는 실제 화면 알림 발생 횟수이며 브라우저/OS의 시스템 알림 표시 성공 횟수는 아니다. 시스템 알림이 차단되거나 지원되지 않아도 화면 알림과 집계는 계속된다.

기존 창 모델을 다시 만들려면 [25배 증강 실험](../replay_pilot/AUGMENT_50K.md)과 [2단계 실험](../replay_pilot/TWO_STAGE.md)을 순서대로 실행한다. 새 모델은 [프레임 파일럿](../frame_pilot/README.md) 명령으로 별도 학습한다. 결과·원본·카탈로그·참여자별 보고서는 Git 밖의 접근 제한 위치에 둔다. 전체 자료 후보는 별도의 독립 평가를 받지 않았다.

### macOS에서 실행

Git에는 가중치가 없으므로 Windows의 `two-stage` 결과 폴더에서 다음 네 파일을 같은 폴더에 모아 맥북의 저장소 **밖**으로 별도 전송한다. 모델은 접근 제한이 가능한 위치에 보관한다.

```text
report.json
all-data-posture.joblib
all-data-synthetic-vertical-corrector.joblib
all-data-posture-after-correction.joblib
```

Python 3.12와 Node.js 24 이상이 준비된 맥북에서 저장소 루트의 터미널을 열고 다음을 실행한다. 마지막 경로는 네 파일을 옮긴 폴더로 바꾼다. 고정 의존성은 Windows에서 이번에 학습한 scikit-learn 1.6.1과 일치한다.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r model/analysis/requirements-training.txt
npm --prefix frontend ci
npm --prefix frontend run assets
python -m model.analysis.live_comparison.server --artifacts-dir "$HOME/posture-private/two-stage"
```

Chrome 또는 Edge에서 `http://127.0.0.1:8765/`를 열고 사이트의 카메라 권한을 허용한다. 첫 실행에서 Pose 모델과 WASM 자산을 내려받을 수 있다.

## 비교 조건

- 4:3 카메라 프레임과 기존 앱의 MediaPipe Pose Heavy 모델을 사용한다. 좌표는 640×480 기준 공간으로 계산하며, 다른 비율이거나 측정 중 영상 크기가 바뀌면 판정하지 않는다. 등록은 9점 평균과 모델의 9점 품질 조건을 사용한다.
- 연구 화면은 포즈 추출을 최소 100ms 간격으로 요청하고 처리 중에는 다음 관측을 기다린다. 프레임 후보는 이렇게 얻은 유효 관측마다 점수를 내며, 카메라의 모든 원본 프레임을 처리하거나 초당 10회가 보장되는 것은 아니다.
- 사용하는 9점은 코, 양 눈, 양 귀, 양 입꼬리, 양 어깨다. 입꼬리는 양 눈과의 세로 거리인 얼굴 높이 특징에 반영되며, 입을 벌린 정도는 측정하지 않는다. 화면 영상 위에도 9점을 표시한다.
- 분류기 입력은 기준 대비 머리 높이·좌우 치우침·어깨 기울기·얼굴 높이·어깨 높이·어깨 폭 변화의 **6개**다. 세로 이동 보정기는 이 6개에 기준 어깨 폭을 더한 7개를 입력받는다. 규칙 점수는 앞의 3개만 쓴다.
- 기존 창 후보는 기준 등록 뒤 최근 1초의 6개 특징 중앙값으로 평가하며 최소 5표본·800ms가 필요하고 500ms마다 갱신한다. 새 프레임 후보는 관측마다 평가한다. 측정 불가나 관측 공백은 이전 관측을 이어 붙이지 않는다.
- 규칙 점수는 실제 추론 서비스의 `score_feature_deltas`를 호출하고 실험 비교 기준 0.70을 사용한다. 모델은 재학습 보고서의 `all_data_candidate.threshold`를 사용한다. 서로 다른 두 점수는 보정된 확률이 아니며 점수 크기만으로 성능을 비교할 수 없다.
- 프레임 후보를 `--candidate-only`로 학습한 경우 모델의 0.5 기준은 임시 화면 비교값이다. 화면에 검증 전임을 표시하며, 이 기준의 정확도·알림 품질은 평가하지 않았다.
- 측정 불가·고개 회전·관측 공백은 정상으로 처리하지 않는다. 구도가 바뀌면 사용자가 기준을 다시 등록해야 한다. 모델의 보정값은 합성 2D 세로 이동을 기준으로 학습한 값으로, 실제 의자 이동량이나 의학적 판단이 아니다.
- 영상은 브라우저 안에서만 Pose로 처리하고, 필요한 9개 2D 점은 같은 기기의 `127.0.0.1` 서버에 전송해 휘발성 세션 메모리에만 보관한다. 원본 영상과 좌표는 디스크에 저장하거나 외부로 전송하지 않는다. 사용자가 시나리오 저장을 누르면 위의 점수·특징 설명만 선택한 로컬 폴더에 기록한다. 서버에는 인증이 없으므로 반드시 loopback에만 바인딩한다.

이 화면은 모델 연결 확인과 동작 관찰용이다. 기존 자료는 이름별 임시 그룹 및 수행 검증 전 안내 라벨을 사용했고 일상 작업·실제 알림 지연과 오알림은 독립 평가하지 않았다.
