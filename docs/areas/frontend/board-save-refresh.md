# 메모·담당 배정 저장과 화면 갱신 수정

- 분야: 프론트
- 작업: GP-0094

## 원인과 변경

기본 메모 생성과 담당자 배정의 API 저장 자체는 재현 환경에서 정상 동작했다. 다만 편집 중 다른 항목만 갱신돼도 전체 workspace 버전 충돌로 저장이 막혔으며, 긴 카드 이력에서는 오류가 하단에 묻혔다. 메모 본문 변경 시 사용자가 함께 선택한 상태도 무조건 planned로 되돌리는 문제가 있었다.

웹은 편집 시작 시 원본을 보관하고 저장 직전 최신 자료와 해당 항목을 비교한다. 해당 항목이 그대로면 다른 변경·번호 카운터를 유지하며 저장한다. 같은 항목이 수정 또는 삭제됐으면 입력을 유지하고 저장을 차단한다. 마지막 POST 버전 검사도 유지하므로 확인 이후 발생한 변경을 덮어쓰지 않는다. 자동 새로고침 응답이 편집 도중 도착하거나 이전 버전으로 돌아가는 것도 차단한다.

메모 본문과 상태를 함께 변경하면 선택한 상태를 유지한다. 상태를 바꾸지 않고 요청 내용만 고치면 기존 접수함 규칙대로 새 요청으로 돌아간다. 저장 중/오류/입력 복사는 고정 하단에서 확인한다.

## 검증

- 실제 관리판에서 메모 생성, 본문+진행 상태 동시 저장, 담당 배정, 재접속 후 유지 확인.
- 메모 편집 중 GP-0094 AI 기록 추가 후 메모 저장: 양쪽 변경 유지.
- GP-0094 편집 중 같은 카드 AI 기록 추가: 저장 차단, 입력과 최신 AI 이력 보존 확인.
- Node 회귀 검사 7개: 다른 카드/메모 갱신, 동일 항목 수정·삭제, 새 메모, 계획 담당 배정, 명시적 메모 상태, 새 요청 재접수.
- 전체 check: Python 29개, 프론트 40개, Node 저장 회귀 7개, 타입·빌드·문서 연결 검사 통과.
