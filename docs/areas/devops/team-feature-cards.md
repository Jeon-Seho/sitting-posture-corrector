## 기준과 범위

2026-09-29 팀 제안: 계정(가입·로그인·정보 관리·탈퇴) → 기준 자세 촬영 → 실시간 촬영·탐지 → 경고 → 누적 통계 → 설정 관리. 프론트16개와 백엔드9개로 명시한다. 반복된 설정 관리 API는 하나로 합친다.
기존7개 번호를 유지·세분화하고 누락18개를 추가했다. 기존 완료 계획 GP-0008/0042는 로컬 구현 이력으로 유지한다. API 기능 완료로 간주하지 않는다.
화면 구현과 서버 기능을 분리한다. 기존 촬영·대시보드·설정 화면3개는 재사용 가능한 구현이 있어 검수 대기다. 실제 회원가입·로그인 화면은 현재 로컬 프로필 진입과 다르므로 할 일로 둔다.
요구사항 정본은 [팀 요구사항](../../team-requirements.md), 현재 코드 근거는 ServiceApp.tsx, pages/SetupPage.tsx, DashboardPage.tsx, SettingsPage.tsx, lib/serviceStore.ts 및 기존 계획의 검증 기록이다. 백엔드에는 아직 API 구현이 없다.

## 경계와 선행 관계

- 프론트엔드 API 연동은 공통 통신 기반만 소유한다. 각 화면의 호출과 상태 처리는 개별 기능 카드가 소유한다.
- GP-0021의 가입·정보 관리와 GP-0023의 설정은 독립 카드로 분리했다. 기존 비밀번호·복구 범위도 회원 정보 관리 카드에 남겼다.
- GP-0026은 모델 추론 서비스, GP-0061는 백엔드 판단 API 어댑터다. 판정 로직을 중복 구현하지 않는다.
- 키포인트 수집 API 추가는 영상/좌표 영구 저장 승인이나 전송 방식 확정을 뜻하지 않는다. 기존 동의·배치·버전 계약 결정을 선행한다.
- 기존 GP-0022 세션 저장, GP-0031 동시 저장, GP-0033 실환경 검증, GP-0036 통합 검증은 고유 범위를 유지한다.
- 담당자는 임의 배정하지 않았다. API 계약 확정 후 세부 필드와 경계가 바뀌면 기존 번호와 이력을 유지해 갱신한다.
