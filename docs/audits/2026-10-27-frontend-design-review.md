**결론: 이전 서버와의 합성 통합 시험은 통과했지만, 최신 develop으로 병합·운영 배포할 준비는 끝나지 않았다.**
아래는 코드 경로를 읽은 설계 검토이며, 각 장애를 실제 운영에서 재현했다는 뜻은 아니다.

> R5는 과거 저장 결과로 오늘 날짜를 바꾸는 부분만 수정했고 자정 정책은 남아 있다.
> 최신 origin/develop은 FE JWT도 포함한 `6e768a4`다. SSH 서버 도달은 확인했지만 web/io-api가 실행되지 않아 최신 API 연결은 미완료다.

## 병합 차단 문제

### R1 · P1 — 인증 계약이 최신 서버와 다르다

**상황:** 최신 develop 서버에 현재 프론트를 붙인다.
`accounts/client.ts`는 `/auth/csrf`와 쿠키 인증을 쓰고, `coordinateController.ts`의 `hello`에는 access token이 없다.
최신 서버는 CSRF API를 없애고 REST Bearer와 `hello.access_token`을 요구한다. 따라서 주소 설정만으로 해결되지 않는다.

**수정 방향:** `feature/frontend-auth-token`의 accountClient·serverAuth·api 구현을 참고하되,
현재 `accounts/`와 기존 `auth/`에 인증 관리자를 둘 다 두지 않는다. 하나의 인증 경계가 토큰·현재 계정·갱신·로그아웃을 관리한다.
access token은 메모리, refresh token은 HttpOnly 쿠키에 둔다. 동시 갱신은 하나로 합치고
로그아웃 뒤 늦게 도착한 갱신 응답으로 계정을 되살리지 않는다. 측정 중 토큰 갱신과 소켓 재연결은 별개다.

**완료 조건:** 최신 BE·DB V2.6으로 가입/로그인/새로고침/만료 갱신/갱신 실패/다른 탭 계정 변경/WS 인증을 검증한다.
기존 쿠키 기반 시험 성공을 이 항목의 완료 근거로 쓰지 않는다. 담당: FE + BE.

### R2 · P1 — 앱 종료 뒤 복구를 보장할 보관함이 없다

**상황:** 측정 또는 결과 저장 중 탭·Electron 앱을 완전히 닫고 다시 연다.
`accounts/draftStorage.ts`의 중간 측정·미저장 결과는 `sessionStorage`에 있다.
같은 탭 새로고침과 달리, 탭 수명이 끝난 뒤 보존은 보장되지 않는다.
오늘 표시용 localStorage 사본은 재시도 큐가 아니므로 이를 대신하지 못한다.

**수정 방향:** 계정별 영속 outbox(미완료 요청 보관함)를 두거나 서버에서 미완료 세션을 조회해 복구하는 계약을 채택한다.
세션 ID·원래 요청 본문·마지막 확인 결과·확인 상태를 보존하고, 다른 계정에서는 처리하지 않는다.
보관 기간과 탈퇴 시 정리도 함께 정의한다. 서버에 저장됐는지 모르는 결과는 완료로 표시하지 않는다.

**완료 조건:** 실제 창 종료/재시작·강제 종료·저장 실패 후 재로그인으로 같은 요청 ID의 복구를 확인한다.
담당: FE, 서버 조회가 필요하면 BE.

### R3 · P1 — 표시용 사본이 서버 정본을 덮어쓴다

**상황:** 같은 세션 ID의 오래된 로컬 결과와 서버의 최신 결과가 함께 있다.
`useRemoteWorkspace.ts`는 `initial.records`에 `loaded.today`를 뒤에서 upsert한다.
`storage/records.ts`의 upsert는 같은 ID를 교체하므로 로컬 사본이 우선한다.
특히 미확인 결과를 `rememberPending`에서 오늘 사본에 넣기 때문에 확인된 서버 결과가 미확인 값으로 돌아갈 수 있다.
새로 불러올 때도 서버 목록과 기존 목록을 합칠 뿐, 삭제된 항목을 제거하는 규칙이 없다.

**수정 방향:** 서버가 조회 범위에서 반환한 자료를 정본으로 두고, 미확인 결과는 별도 목록으로 표시한다.
캐시 합치기는 조회 날짜·페이지 범위 안에서만 수행하고 서버의 삭제·수정 결과를 반영한다.
서버 반환 자료를 로컬 미확인 사본으로 교체하지 않는다.

**완료 조건:** 같은 ID의 서버/캐시 충돌, 다른 기기에서 삭제, 미확인→확인 전환을 회귀 검증한다. 담당: FE + BE 조회 범위 확인.

### R4 · P1 — 측정 중 로그아웃이 종료·저장을 건너뛴다

**상황:** 측정 중 사이드바에서 로그아웃한다.
`AccountApp.tsx`의 logout은 미저장 결과만 검사하고, 진행 중 측정은 `camera.stop()`·`setSession(null)`로 제거한다.
이때 컨트롤러는 unmount되어 소켓이 닫히지만 정상 종료/결과 저장을 완료하는 흐름은 실행하지 않는다.
서버가 끊김을 처리하는 것과 사용자가 결과를 보관·확인하는 것은 서로 다른 책임이다.

**수정 방향:** 로그아웃·비밀번호 변경·탈퇴·앱 종료의 측정 종료 정책을 공통으로 정의한다.
사용자 로그아웃은 종료/저장을 기다리거나 명시적인 미확인 보관 후 진행한다.
인증 강제 만료는 카메라를 즉시 멈추되 계정별 복구 자료를 먼저 보존한다.

**완료 조건:** 실행 중/휴식 중/시작 요청 중/저장 중 로그아웃과 강제 만료를 검증한다. 담당: FE + BE.

### R5 · P1 — 오늘 날짜와 기록 날짜의 기준이 일치하지 않는다

**상황:** 로그인한 채 자정을 넘기거나, 어제 종료된 결과를 오늘 재시도 저장한다.
`client.records()`는 R1의 `today`를 검사하고도 반환하지 않는다.
`useRemoteWorkspace`의 today는 로그인 응답으로 시작하고 저장한 기록의 `endedAt` 날짜로 바뀐다.
따라서 과거 결과 재시도가 화면의 ‘오늘’을 과거로 돌릴 수 있고, 아무 작업 없이 자정을 넘기면 날짜가 갱신되지 않는다.
`todayStorage`와 기록 분류는 시작 날짜를 쓰는데 today 변경은 종료 날짜를 써 자정 통과 세션도 불일치한다.

**수정 방향:** 서버 날짜를 기록 데이터와 분리해 관리하고 R1의 today를 소비한다.
자정·화면 복귀 때 날짜와 조회 범위를 새로 확인한다. 과거 기록 저장 응답으로 오늘을 변경하지 않는다.
자정 세션 분리·일별 집계 귀속 정책은 FE/BE/기획이 먼저 합의한다.

**완료 조건:** 자정 대기, 자정 걸친 측정, PC 시계 오차, 이전 날짜 미저장 결과 재시도를 검증한다. 담당: FE + BE + 기획.

### R6 · P1 — 패키징 앱과 운영 웹의 접속 설계가 다르다

**상황:** 현재 EXE에 운영 API 주소만 넣는다.
`electron/main.cjs`는 `app://posegood`의 로컬 화면을 연다. 기본 API 주소가 비어 있으면
요청도 app 출처를 사용하며, 외부 API를 지정해도 `app://`와 API 사이의 CORS·refresh 쿠키 정책은
`app.posegood.site`와 `api.posegood.site`의 같은 사이트 웹 구성과 다르다.
기존 EXE 검증은 로컬 가계정 시험이며 운영 인증의 증거가 아니다.

**수정 방향:** HTTPS 웹 화면을 앱에서 여는 기존 제안과, 로컬 번들 유지 방식 중 하나를 확정한다.
선택한 방식에 대해 허용 URL·출처·쿠키·WS·오프라인 오류·업데이트 경로를 검증한다.
개발용 Vite 프록시가 패키징 EXE에도 존재한다고 가정하지 않는다.

**완료 조건:** 배포와 같은 출처의 실제 패키징 앱에서 일반 계정 로그인·재시작·갱신·측정을 통과한다. 담당: FE + DevOps + BE.

## 유지할 설계

- 서버 모드에서 좌표를 보내고 서버 판정을 표시하는 책임 분리.
- B1 재시도에서 같은 registration_id와 요청 본문을 쓰는 방식.
- 계정별 자료 키와 늦은 응답의 계정 경계 검사.
- 연결 유실 시 카메라 중지, 미확인 상태 표시, 자동 소켓 재연결 금지.
- 손상 자료를 조용히 지우지 않고 보존하는 방식.
