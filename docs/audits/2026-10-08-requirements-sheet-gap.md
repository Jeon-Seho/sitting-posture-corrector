# 요구사항 정의서 V0.1과 현재 구현의 차이 (2026-10-08)

- 대상: 유진(DB·BE, 요구사항 정의서 작성자)
- 작성: 동욱 요청, Claude 작성 (2026-10-08)
- 비교 기준: 팀 구글 시트 「자세교정_요구사항정의서_V0.1」(2026-09-29, DRAFT)과 `lee_app1`(develop PR #22·#23·#24 스키마 V2.0 반영)
- 범위: 시트와 지금 코드·결정이 **다른 항목만** 적었다. 같은 항목은 적지 않았다.

## 읽는 법

| 표시 | 뜻 | 시트 처리 |
|---|---|---|
| **확정** | 팀 또는 담당자가 정했고 코드나 정책에 들어갔다 | 시트를 이 값으로 고쳐 주세요 |
| **확정(구현 전)** | 정했지만 아직 코드에 없다 | 시트를 고치고, 구현 전이라고 적어 주세요 |
| **임시** | 지금 코드에 들어 있지만 확정은 아니다 | 시트에 현재값으로 적고 "임시"로 두세요 |
| **참고만** | 동욱이 계속 바꾸고 있다 | **시트·DB를 아직 고치지 마세요.** 방향만 참고해 주세요 |

## 3. 참고만 (동욱이 계속 바꾸는 중)

아래 항목은 **판정 방식과 특징값을 우리가 계속 바꾸고 있어서 참고로만 봐 주세요.**
시트 문구, `feature_def` 시드, 기준 자세 저장 구조를 아직 바꾸지 않는 것이 좋습니다. 정해지면 따로 알리겠습니다.

| 시트 ID | 시트 | 현재 | 앞으로 |
|---|---|---|---|
| SFR-014 | 특징값 4개: 목 전방 이동·어깨 기울기·**상체 기울기**·좌우 균형 | 3개: 머리 높이(`HEAD_GAP`), 좌우 쏠림(`LATERAL_OFFSET`), 어깨 기울기(`SHOULDER_TILT`). `feature_def` 시드도 3행이다 | **추가 예정**. 후보는 귀–어깨 높이(움츠림·주저앉음), 어깨 폭 비율(굽은 어깨), 어깨 높이, 몸통 비틀림. 실측 기록으로 쓸지 정한다 |
| SFR-017 | 최근 5초를 LSTM에 넣어 확률 산출 | 프레임마다 규칙 점수. LSTM 미연결. DevOps의 시험용 LSTM은 10구간 단위 | 판정 방식을 계속 바꾼다. 단일 최댓값 대신 특징 조합으로 자세 유형을 구분하는 방향을 시험 중이다 |
| SFR-045, 확인필요 #2 | 붕괴 확정은 한 곳에서만 | 지금 앱, DevOps CEP, 팀 `backend/cep` 세 곳이 각각 판정한다. 시트가 짚은 문제가 맞다 | DevOps 회의에서 판정 엔진을 정한다([계획 0022](../plans/active/0022-kafka-realtime-pipeline.md)) |
| 확인필요 #10 | 붕괴 유형 | 화면에 변화 유형(앞으로 숙임·기울어짐 등)을 표시한다 | 특징이 늘면 유형도 늘어난다 |

## 4. 시트에 있지만 아직 구현하지 않은 기능

시트 문구는 그대로 두고, 상태만 "미구현"으로 표시하면 된다.

| 시트 ID | 요구 | 현재 |
|---|---|---|
| SFR-029 | 자리 비움을 제외 구간으로 | 자동 감지가 없다. 판정 불가 3초 규칙으로 측정이 멈추는 것으로 대신한다(구현 전) |
| SFR-012 | 두 명 이상일 때 기준 위치로 대상 선택 | 한 명만 추적한다(MediaPipe `numPoses: 1`). 기준 위치는 서버 모드 세션에만 보낸다 |
| QUR-002 | 시간당 알림 상한(`NOTIFY_MAX_PER_HOUR`) | DB·백엔드에 값(12)만 있고, 앱 판정에는 적용하지 않는다 |
| DAR-004, SFR-043·044 | 특징값 시계열을 Kafka·HDFS에 적재 | 로컬 모드는 아무것도 보내지 않는다. DevOps 플랫폼에서 진행 중이다 |

## 5. 시트 자체에 고칠 것

- **참고 문서**: 시트가 참고한 `docs/team-requirements.md`와 `outputs/requirements/자세교정_요구사항_2026-09-28.xlsx`는 2026-10-08 저장소에서 지웠다. 이 시트가 요구사항 정본이라고 적어 주세요.
- **확인필요 상태**: 16건 모두 "미결"이다. 위 1절 기준으로 #4·#15는 결정됨, #3·#12는 임시값 있음으로 바꿀 수 있다.
- **비기능 목표값**: `TARGET_FPS`, `TARGET_LATENCY_MS`, `TARGET_CONCURRENT_USERS`가 비어 있어 완료 여부를 확인할 수 없다.
  동시 사용자 수는 DevOps 측정치를 참고할 수 있다(2026-10-06): 프레임 구간마다 보내면 동시 4~5명이 한계, 0.5초로 묶으면 이론상 약 50명. 0.5초 묶음은 아직 구현 전이다.
