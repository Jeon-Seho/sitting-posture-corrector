# 앱·웹 PiP와 사용자 흐름 검토

> 후속 사용자 결정(2026-10-26): 웹의 작은 창·PiP를 끄고 Electron 앱에만 유지한다. 아래는 결정 전 조사 기록이며 웹 PiP 비교 구현 제안은 현재 작업 범위에서 제외한다. 적용 기준은 [ADR 0017](../decisions/0017-desktop-app-shell-and-redesign.md)이다.

- 날짜: 2026-10-26
- 기준: develop `3285cce` (작업 시작 시 원격 동기화)
- 범위: 현행 코드·디자인 문서·Chrome/WICG/Electron 공식 자료 조사. 구현 변경 전 검토다.
- 관찰 한계: 로컬 웹 로그인 화면을 브라우저에서 확인했다. 로그인 후 화면은 코드 기준으로 검토했다. 실제 Chrome 카메라·자동 PiP·Electron 카메라 창은 재현 시험하지 않았다. 아래 조작 수는 사용자 실험 결과가 아닌 코드에서 센 정상 경로다.

## 결론

전면적인 브랜드 교체보다 측정 시작·작은 창·종료 동작을 먼저 재설계한다. 현재 색상과 글꼴, 측정/기록/설정의 큰 구조는 유지할 수 있다. 사용자의 핵심 목표는 큰 카메라 화면을 계속 보는 것이 아니라 다른 작업을 하면서 자세 알림을 받고 기록을 남기는 것이다.

웹 Document PiP의 출처 표시를 없애는 옵션은 없다. 카메라 사용 여부는 자동 PiP 자격과 관계가 있고, 출처 표시 제거 권한과는 관계가 없다. 앱에서 주소 없는 창과 자유로운 조작이 필수라면 Electron의 전용 작은 창으로 구현하는 것이 적합하다.

## PiP의 현재 구현과 원인

근거 코드: [작은 창 훅](../../frontend/src/features/camera/useCameraWindow.ts), [창 내용](../../frontend/src/features/camera/CameraWindow.tsx), [앱 창](../../frontend/electron/main.cjs).

| 항목 | 확인한 사실 | 사용자 영향 |
| --- | --- | --- |
| 웹 작은 창 | Document PiP를 우선 요청하고 API가 없을 때 video PiP 사용 | Chrome이 그리는 출처 UI는 사이트 CSS 밖에 있음 |
| 수동 열기 | 훅의 `open`, `supported`, `message`를 CameraWindow 화면이 사용하지 않음 | README의 직접 열기 안내와 달리 앱 버튼으로 재시도할 수 없고 실패 안내도 안 보임 |
| 자동 열기 | 카메라 on이면 Media Session action을 등록. Document PiP가 없으면 등록하지 않음 | 측정 중이 아닌 카메라 준비 때도 자동 열기 대상. video PiP만 되는 환경에는 자동 경로가 없음 |
| 닫기 | 내부 X는 측정 종료·저장. 브라우저 X의 `pagehide`는 창 참조만 정리 | 비슷한 X 두 개의 결과가 다름. 자동 PiP 복귀 닫힘까지 종료로 취급하면 안 됨 |
| video PiP | 원본 스트림을 별도 video에 연결 | 앱의 상태 문구·버튼·CSS 거울 효과는 video PiP 화면에 자동 포함되지 않음 |
| 상태 | 상태 바가 hover/focus 때 나타나고 alert만 항상 노출 | 평소에는 측정 중인지 카메라 미리보기인지 구분하기 어려움 |
| 조작 크기 | 작은 창 버튼 28×28px | 디자인 시스템의 일반 44px/작은 36px 기준보다 작음 |
| 앱 | 카메라 작은 창도 웹용 CameraWindow 사용. 별도 BrowserWindow는 자세 알림용뿐 | 메인 앱의 제목 표시줄 제거 설정이 카메라 PiP까지 적용되지는 않음 |
| 문서 | DESIGN.md의 탭 설명은 측정/자세 등록/기록/설정, 실제 navigation은 측정/기록/달력/설정 | 다음 디자인 작업의 기준을 실제 코드와 맞춰야 함 |

사용자가 말한 주소창은 현재 구현상 Document PiP의 출처 표시일 가능성이 높다. 스크린샷으로 동일 현상을 재현하지 않았으므로 일반 팝업 주소창과 동일하다고 확정하지 않는다.

## Chrome이 카메라에 제공하는 지원

[Chrome 공식 자동 PiP 안내](https://developer.chrome.com/blog/automatic-picture-in-picture)에 따르면 데스크톱 Chrome 120부터 다음 조건에서 탭 전환 시 자동 PiP를 지원한다.

- `enterpictureinpicture` Media Session action handler 등록.
- `getUserMedia`로 카메라 또는 마이크를 실제 사용 중.
- 사용자가 브라우저의 자동 PiP 설정을 허용.

카메라만으로 자격을 만족할 수 있어 PiP를 위해 마이크 권한을 추가할 필요는 없다. 실제 실행은 브라우저가 결정하므로 버튼으로 여는 경로도 필요하다. 공식 안내는 자동으로 열린 창이 원래 페이지로 돌아오면 닫힌다고 설명한다. 이 닫힘을 세션 종료와 연결하지 않는다.

[Document PiP 공식 API](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)의 `disallowReturnToOpener`는 탭 복귀 버튼을 숨기는 옵션이며 주소/출처 제거 옵션이 아니다. `preferInitialWindowPlacement`도 위치·크기 재사용에 관한 힌트다. [WICG 보안 기준](https://wicg.github.io/document-picture-in-picture/#spoofing)은 출처 식별 등 위장 방지 UI를 요구한다. 제목 변경·CSS·PWA 설치로 Chrome의 PiP 출처 표시를 없앨 수 있다고 약속하면 안 된다.

## 환경별 대안

| 방식 | 장점 | 제약·판단 |
| --- | --- | --- |
| 웹 Document PiP | 상태, 쉬기, 복귀, 종료 등 HTML 조작 가능 | 출처 표시 수용 필요. 상태 확인과 조작을 우선할 때 적합 |
| 웹 video PiP | 영상 위주의 작은 창. 현행 코드에 fallback 있음 | 사용자 정의 HTML 버튼 불가. 브라우저별 출처/컨트롤 UI가 전혀 없다고 보장할 수 없음. 실제 Chrome에서 외관 비교 필요 |
| canvas를 영상으로 만들어 video PiP | 영상 안에 자세 문구·테두리를 합성 가능 | 추가 렌더링/스트림 비용과 백그라운드 갱신 검증 필요. 합성한 버튼 모양은 클릭 가능한 앱 버튼이 아님 |
| 앱 전용 작은 창 | `frame:false`, `alwaysOnTop:true`로 주소 없는 작은 창 구성 가능 | IPC·카메라 공유·닫기·포커스·다중 모니터 생명주기를 추가 구현해야 함 |
| 앱 내부 떠 있는 창 | 이미 구현됨. 자유로운 UI | 다른 앱 위에는 뜨지 않으므로 외부 작업용 PiP를 대신하지 못함 |
| PWA/일반 팝업 | 메인 화면을 별도 창에서 사용 가능 | PWA가 Document PiP의 보안 UI를 제거하지 않음. 일반 팝업도 항상 위를 보장하지 않음 |

앱 전용 창은 [Electron BrowserWindow 공식 문서](https://www.electronjs.org/docs/latest/api/browser-window)를 기준으로 설계한다. 기존 카메라를 다시 요청하는 방식 대신 현행 스트림의 미리보기 공유 가능성을 먼저 검증한다. 판정·전송·세션 소유자는 기존 메인 흐름에 유지한다.

## 사용자가 목표에 도달하기까지의 조작 수

로그인 완료 직후의 측정 화면에서 출발한다. 타이핑·기다리기·자세 조정은 클릭에 포함하지 않았고 권한 팝업은 별도로 센다. 다른 카메라 선택, 권한 거부, 품질 실패, 저장 실패는 추가 조작이 필요하다.

| 목표 | 현행 정상 경로 | 조작 수·시간 | 개선 목표 |
| --- | --- | --- | --- |
| 첫 측정 시작 | 카메라 켜기 → 최초 권한 허용 → 인식 → 자동 등록 → 자동 시작 | 앱 1회 + 권한 1회. 등록은 대기 3초 + 수집 3초, 초기화/인식 시간 별도 | 1회 유지. 버튼에 자동 등록·측정 시작을 명확히 안내 |
| 등록 후 다음 측정 | 카메라 켜기 → 인식 유지 → 자동 시작 | 권한 유지 시 1회 + 2.5초 대기 | 1회 유지. 자동 시작 상태·취소를 명확히 표시 |
| 카메라·기준 준비 상태에서 수동 시작 | 측정 시작 | 1회 | 같은 목적의 시작 버튼 2개를 주 행동 1개로 정리 |
| 다른 웹 탭에서도 보기 | 탭 전환 → 허용되면 자동 PiP | 탭 전환 1회. 거부 시 화면 내 수동 재시도 경로 없음 | 작은 창 열기 1회로 직접 실행 가능, 자동 실패도 복구 가능 |
| 다른 앱에서도 보기 | 현재는 같은 PiP 경로에 의존 | 앱 전환 시 동작·카메라 지속 여부 실기기 미확인 | 앱 전용 창 열기 1회, 이후 작업 전환 |
| 측정 종료·결과 확인 | 측정 화면의 종료 또는 작은 창 내부 X | 1회. 브라우저 X는 세션 종료가 아님 | 명시적 종료·저장 1회. 창 닫기는 미리보기 닫기로 구분 |
| 오늘 기록 요약 | 기록 탭 | 1회 | 유지 |
| 오늘 세션 상세 | 기록 → 세션 행 펼치기 | 2회 | 유지 |
| 지난 날짜 요약 | 달력 → 날짜 선택 | 기본 표시 월이면 2회, 월 이동마다 추가 | 기록 화면에서 오늘/날짜 선택을 함께 제공하는 안 비교 |
| 기준 다시 등록 | 설정 → 다시 등록 → 인식·등록 | 2회 + 자동 등록 대기. 이미 측정 화면에 있으면 다시 등록 1회 | 카메라 위치 변경 안내와 가까운 곳에 재등록 유지 |

시작 클릭 수 자체는 이미 적다. 가장 큰 문제는 자동 동작을 예측하기 어렵고, 자동 PiP가 실패하면 다음 행동이 막힌다는 점이다. 경로 근거는 [SetupPage](../../frontend/src/pages/SetupPage.tsx), [자동 시작](../../frontend/src/features/camera/useAutoStart.ts), [라우팅](../../frontend/src/app/navigation.ts), [기록](../../frontend/src/features/history/LocalHistory.tsx)이다.

## 재디자인 우선순위

1. **P0 작은 창 경로 복구:** 카메라/측정 화면에 수동 열기 버튼, 지원 여부, 열린 상태, 실패 안내·재시도를 연결한다. 자동 PiP는 명시적인 측정 상태와 사용자 설정에 맞춰 등록한다.
2. **P0 닫기 의미 정리:** 권장안은 X=미리보기 닫기, 별도 종료·저장 버튼이다. 현행 내부 X=종료·저장 결정과 다르므로 구현 시 제품 문서와 검증을 함께 바꾼다. 자동 복귀 닫힘은 종료하지 않는다.
3. **P1 작은 창 중심 화면:** 상태 한 줄은 항상 보이고 영상 숨김, 쉬기/재개, 측정 화면 복귀, 종료·저장을 제공한다. 조작 영역은 최소 36px, 가능하면 44px. 측정 불가를 초록으로 표시하지 않는다.
4. **P1 플랫폼 분리:** 웹은 Document PiP와 영상 전용 PiP를 실제 Chrome에서 비교, 앱은 전용 작은 창으로 설계한다. '작은 창'과 '영상 숨김'을 구분해 쓴다.
5. **P1 시작 화면 정리:** 큰 카메라와 안내를 유지하되 시작 행동은 하나로 통일. FPS 같은 개발 정보는 접힘 영역으로 이동. 첫 사용자의 자동 등록/자동 시작을 버튼 주변에서 예고한다.
6. **P2 기록 탐색:** 오늘과 지난 기록이 나뉜 이유를 명확히 하거나 날짜 선택을 기록 화면에 통합하는 안을 비교한다. 현재도 오늘 요약 1회라 클릭 감소 효과를 과장하지 않는다.
7. **P2 문서 동기화:** 실제 탭, 현재 최소 창 크기(1180×760), 수동 PiP 버튼 유무를 DESIGN/README와 맞춘다. 웹은 작은 노트북·좁은 창에서 따로 검증한다.

## 후속 결정 적용 결과(2026-10-26)

웹에서 CameraWindow를 마운트하지 않고 훅에서도 Electron bridge가 없으면 수동 PiP 요청·미리보기 스트림 연결·자동 PiP 등록을 차단했다. 웹 영상에는 `disablePictureInPicture`를 지정했다. 앱의 기존 작은 창·PiP 경로와 카메라/측정/저장 생명주기는 유지한다. 주소 없는 전용 네이티브 카메라 창은 추가하지 않았다.

- `python tools/dev.py check-frontend`: 53개 파일·351개 테스트, TypeScript 검사·프로덕션 빌드 통과. 기존 번들 크기 경고가 남는다.
