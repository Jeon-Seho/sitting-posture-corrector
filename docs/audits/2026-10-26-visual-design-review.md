# 색상·레이아웃 재디자인 판단

- 날짜: 2026-10-26
- 대상: develop 기반 `codex/frontend-pip-design-review`, 로그인·측정 준비·기록·달력·설정.
- 방법: 실제 React 화면을 1360×860 Chrome에서 렌더링해 확인. 기록에는 명시적인 발표용 예시 자료만 사용했다. 작은 창은 실제 Electron과 합성 영상으로 검증했다. 사용자 실험이나 실제 장치 정확도 평가가 아니다.

## 판단

**색상 체계는 정리하고, 레이아웃은 재디자인하는 편이 좋다.** 주황색 로고·브랜드 강조는 유지할 수 있다. 현재의 크림·갈색·살구색을 넓은 바탕과 선·버튼·상태에 모두 쓰는 방식은 작업 화면의 정보 위계를 약하게 만든다. 로그인 소개의 따뜻한 인상은 살리고, 로그인 후 도구 화면은 중립 바탕·명확한 상태색·간결한 배치로 바꾸는 방향을 권한다.

이 판단은 디자인 검토다. 제안한 전체 화면의 색상과 레이아웃을 제품에 일괄 적용한 것은 아니다. 이번 구현 변경은 앱의 주소 없는 작은 창과 그 조작부에 한정한다.

## 색상에서 바꿀 것

| 항목 | 현행 관찰 | 권장 방향 |
| --- | --- | --- |
| 브랜드 | 로고·버튼의 `#c4532a`는 기억하기 쉽고 기존 그림과 일치 | 유지. 주요 행동과 선택된 메뉴에 집중 |
| 바탕 | `#fbf5ee` 바탕, `#fffaf4` 사이드바, 살구색 선택·선이 화면 전체에 반복 | 로그인은 현재 온기 유지. 작업 화면은 `#f5f6f4` 수준의 낮은 채도 바탕·흰 작업 면으로 비교 |
| 상태 | 실제 CSS의 경고 `#b8432a`가 주요 행동 `#c4532a`와 유사한 주황·갈색 계열 | 자세 흐트러짐은 절제된 로즈, 정상은 초록, 측정 불가는 중립 회색으로 역할 분리. 문구·아이콘 병행 |
| 본문 | 주 텍스트는 충분히 선명하나 작은 설명·경계가 부드러워 많은 설정을 훑기 어려움 | 본문과 보조 설명 크기·간격의 계층 정리. 모든 보조 글자를 일괄 진하게 바꾸지는 않음 |
| 둥근 모양 | 카메라 28px, 카드 22px, 알약 버튼이 대부분의 화면에 반복 | 큰 작업 면 14~18px, 버튼 10~12px 중심. 상태 칩에만 알약 형태를 주로 사용 |

현행 CSS 토큰의 계산상 대비는 muted `#7c6b61`/bg `#fbf5ee` 약 4.69:1, faint `#b5a496`/bg 약 2.23:1, unknown `#8e7f74`/bg 약 3.57:1이다. 이 값은 토큰 조합의 상대휘도로 계산했으며 모든 실제 element의 접근성 합격/불합격을 판정한 것은 아니다. 특히 faint와 unknown을 작은 필수 본문에 쓸 때는 해당 요소의 실제 배경·크기·투명도를 확인해야 한다.

## 화면별 레이아웃 판단

| 화면 | 유지할 것 | 재설계할 것 |
| --- | --- | --- |
| 로그인 | 브랜드·소개 그림·좌우 소개/폼 구조 | 소개 폭을 줄여 입력 영역을 더 빨리 찾게 함. 화면 전체의 따뜻한 색은 이곳에 집중 |
| 측정 준비 | 카메라·얼굴/어깨 안내·자동 기준 등록 | 준비 목록과 팁이 오른쪽 전체를 차지하고 아직 누를 수 없는 측정 시작 버튼까지 노출됨. 안내를 짧게 합치고 주 행동은 하나로 정리 |
| 측정 중 | 현재 상태·쉬기/종료·카메라 확인 | 큰 카메라·점수·요약·흐름의 균등한 강조를 줄임. 현재 상태와 작은 창 전환을 우선, 카메라는 필요할 때 펼치는 안 비교. 이번에 실제 측정 중 화면의 전체 시각 검수는 하지 않았으며 코드 기반 제안 |
| 기록 | 오늘 합계·세션 행·상세 펼치기 | 80% 원형 수치가 큰 중앙 영역을 차지함. 유지율·측정시간·알림을 짧은 가로 요약으로 정렬하고 세션·추세를 가까이 배치 |
| 달력 | 날짜별 접근·최근 흐름 | 연간 활동 격자·달력·추세의 세 가지 시각 요소가 경쟁함. 기록 안의 날짜/기간 선택으로 통합하고 연간 활동은 보조로 내리는 안 비교 |
| 설정 | 알림·카메라·자동 실행·계정이라는 분류 | 긴 카드 열과 우측 계정 카드, 하단의 여러 접힘 영역으로 시선이 분산됨. 분류 탭/섹션으로 나누고 앱 전용 설정은 웹에서 숨김 |
| 작은 창 | 기존 영상 공유·크기/위치 조절 | 주소 없는 native 창 구현 완료. 항상 보이는 상태 막대와 36px 버튼, 접으면 48px 상태 막대. 브라우저 PiP UI를 제거 |

## 제안 시안과 적용 순서

대화의 비교 시안은 `현재 구조`와 `차분한 작업 화면 · 권장` 두 가지다. 현재 구조는 실제 화면을 단순화한 재구성이며 스크린샷이 아니다. 권장안은 브랜드 주황 유지·중립 바탕·좁은 사이드바·상태/조작 중심 측정·기록/달력 통합을 보여 준다. 시안의 수치는 예시이며 카메라나 설정 동작을 실제로 실행하지 않는다.

1. 공통 토큰과 화면 틀: 바탕/상태색·타이포·여백·카드/버튼 모양, 사이드바 폭. 현행 232px에서 172~192px를 시안으로 비교하되 확정치로 취급하지 않는다.
2. 측정 준비·측정 중·작은 창: 가장 자주 사용하는 흐름의 정보 위계를 통일한다.
3. 기록·기간 선택: 오늘/지난 날짜와 최근 추세를 같은 구조에서 확인한다.
4. 설정·로그인: 공통 규칙을 적용하고 입력/설정 탐색의 집중도를 정리한다.

적용 전 실제 앱 기본 크기 1360×860·최소 1180×760와 웹 960/690/390px에서 긴 한글·키보드 초점·상태 변화·빈 기록·측정 불가를 확인한다. 시간 정책과 기록 값은 바꾸지 않는다. 제품 최저 창 크기·사이드바 축소·기록/달력 통합은 별도 구현 때 검증하고 문서를 동기화한다.
