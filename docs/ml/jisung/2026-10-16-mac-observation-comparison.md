# 정면 2D·상대 z 관측 비교 화면

현재 진입 주소는 `/dev`, 분리된 예시는 `/dev?demo=1`이다. 아래는 당시 구현 기록이며
[2026-10-26 경로 통일](../../decisions/0042-unified-dev-observation-route.md)이 이전 주소/실험실 진입을 대체한다.

- 날짜·환경: 2026-10-16 / mac
- 브랜치·기준: `feature/repo-jisung-local-forecast` / `5ae2e72`
- 상태: 연구용 관측 화면 구현. 실제 네 동작의 구분 가능성을 확인한 결과는 아님.

[10월 15일 논의](2026-10-15-desktop-ml-scope-and-depth-review.md)를 이어 머리 내밀기·고개 숙임·몸통 전체 접근·
어깨 올리기에서 어떤 2D 신호와 상대 z가 나오는지 직접 비교하는 화면을 추가했다.

## 사용

1. 프론트 서버를 켜고 `/dev?view=observation` 또는 기존 실험실 상단의 `2D · 상대 z 비교`로 이동한다.
2. 카메라를 고정하고 얼굴·양어깨가 보이게 한 뒤 `카메라 켜기`와 `기준 2초 등록`을 누른다.
3. 기준 자세에서 네 동작을 하나씩 선택해 직접 수행한다. 화면의 2D 4개 항목과 상대 z 1개 항목을 본다.
4. 동작을 약 1초 유지하고 `비교표에 담기`를 눌러 표에서 나란히 확인한다. 기준 복귀도 함께 담아 본다.
5. `동작별 비교표 CSV`로 담은 동작의 1초 중앙값을, `관측 시계열 CSV`로 동작·시각·품질별 표본을 내려받는다.
6. 종료 후에도 두 CSV를 내려받을 수 있다. 새 실행·재등록은 자료가 있으면 확인창을 표시하므로 먼저 CSV를 받는다.

실제 화면에는 예시 시작 버튼이 없다. 접힌 `측정 방법과 주의사항`에서 설명용 예시를 별도 탭으로 열 수 있다.
예시 화면은 가상 점을 표시할 뿐 수집·비교표 저장·CSV 다운로드를 하지 않는다. 실제 사람이 그 동작을
했을 때 나올 패턴이나 분류 성능이 아니다. 실제 탭의 자료와 메모리는 공유하지 않는다.
후속 요청으로 파생 수치 CSV를 추가했다. 영상·원본 좌표는 내보내지 않고 자동 저장·서버 전송도 하지 않는다.
시계열은 기준 등록 완료 후 최근 최대 12,000행(약 10Hz)이며 앞부분이 잘리면 화면과 CSV에 행 수를 알린다.
`비교표 비우기`는 요약 표만 비우고 시계열은 유지한다. 누락은 빈 칸·중단 행으로 남기며 자동 보간하지 않는다.
단위·출처·수동 동작 표식·CSV 열은 [ADR 0039](../../decisions/0039-front-observation-comparison.md)의 후속 절을 따른다.

실제 CSV 파일명은 `posture-observation-camera-trace-…csv` 또는 `…camera-summary-…csv`다.
과거 내려받은 `synthetic` 파일은 실제 측정 자료로 해석하지 않는다. 자료가 있는 새 측정·재등록·표 비우기는
확인 전까지 보존하고, 새로고침/이동 경고도 요청한다. 모델·영상 크기가 바뀌면 측정만 멈추고 기존 CSV는
이전 기준으로 내보낸다. 브라우저 강제 종료나 이미 지운 자료의 복구를 보장하지 않는다.

## 읽는 법

2D의 머리–어깨 간격, 눈–입 세로 길이, 어깨 중점 높이, 영상 어깨폭을 따로 보며 분모는 등록 어깨폭으로
고정한다. 공통 확대를 정규화로 없애지 않는다. 상대 z는 동일 Pose world의 `코 z−양어깨 평균 z`이며
기준 world 어깨폭 대비 변화와 추정 미터를 표시한다. Face와 Pose 좌표계를 섞지 않는다.
수치와 그래프의 공식·부호·누락·기준 조건은 [ADR 0039](../../decisions/0039-front-observation-comparison.md)에 있다.

2D가 유효해도 z는 없을 수 있다. 비어 있는 값은 0이 아니다. 좌표 변화가 동작 원인을 확정하지 않으므로
사용자가 수행한 동작과 화면 조건, 반복했을 때 구분 가능/모호한지만 별도로 기록한다.
본 수집·학습·정확도 평가는 하지 않았다. [계획 0052](../../plans/active/0052-ml-rebuild.md)의 L0/G0는 계속 미완료다.

## 검증

구현의 합성 테스트·타입·빌드·브라우저 조작 결과는 [실행 기록 0053](../../plans/completed/0053-front-observation-comparison.md)에 남겼다.
프론트 749개 테스트와 타입·생산 빌드·저장소 검증은 통과했다. 전체 게이트는 기존 학습 패키지
`numpy`·`joblib` 부재, 통합 브라우저는 MySQL 드라이버 `pymysql` 부재로 실패했다.
실제 카메라와 네 동작에서 상대 z가 유효한지는 사용자 확인이 필요하다.

후속 CSV 구현은 [실행 기록 0054](../../plans/completed/0054-observation-csv.md)에 남겼다.
프론트 756개 테스트·타입·생산 빌드·문서 검사와 합성 브라우저의 실제 CSV 다운로드/파싱을 통과했다.

예시가 실제 자료 버퍼를 비울 수 있었던 문제의 후속 보호는 [실행 기록 0055](../../plans/completed/0055-observation-data-protection.md)에 있다.
예시를 별도 탭의 표시 전용으로 격리하고, 실제 자료 초기화 확인·조건 변경 보존·이탈 경고를 추가했다.
프론트 762개 테스트·타입·빌드 및 합성 브라우저의 확인창 취소/명시적 초기화 검증을 통과했다.

## 후속: 화면을 따라 하는 3바퀴 자동 안내

사용자 지정 순서는 머리 앞으로 내밀기 → 고개 숙이기 → 몸통 전체 접근 → 어깨 올리기다.
각 동작에 **이동 2초 → 유지 5초 → 기준 복귀·유지 5초**를 주고 3바퀴 반복한다. 총 12회·36구간,
명목상 2분 24초다. 기준 등록에 필요한 2초와 중단/지연은 별도다. 복귀 시간에는 돌아가는 움직임도 들어간다.

1. 실제 측정 화면에서 카메라를 켜고 편안한 정면 자세로 기준을 등록한다.
2. 그 기준 자세에서 `3바퀴 자동 안내 시작`을 누르고 큰 동작 이름·남은 초를 따른다.
3. 유지 시간에는 현재 자세를 그대로 두고, 복귀 안내가 나오면 기준 자세로 돌아와 다음 동작을 기다린다.
4. 추적이 끊기거나 탭을 숨기면 안내가 멈춘다. 화면에 지정된 자세/준비를 확인하고 재개하면 현재 단계를
   처음부터 센다. 유지 재개는 해당 동작 자세를 다시 잡은 뒤 누른다. z만 없으면 안내는 계속하되 z는 결측이다.
5. 세 바퀴 완료 시 카메라가 꺼진다. `자동 안내 시계열 CSV`로 전 구간을 받는다. 중도 종료도 자료를 보존한다.

CSV v2의 `protocol_round`, `protocol_task_action`, `protocol_phase`(move/hold/return),
`protocol_phase_index`, `protocol_phase_attempt`, `protocol_state`로 구간을 구분한다.
유지만 비교하려면 observation·running·hold 행을 선택하고 같은 실행/단계/시도/구간의
`protocol_phase_completed` 사건이 있는지 확인한다. 부분 시도·paused·이동·복귀를 안정 유지로 섞지 않는다.
기존 수동 비교표는 동작당 최신 1초 요약이므로 세 바퀴 비교에는 **관측 시계열 CSV**를 사용한다.
열의 단위·결측·완료 사건과 주의점은 [ADR 0039](../../decisions/0039-front-observation-comparison.md)에 있다.

구현 및 검증 기록은 [0056](../../plans/completed/0056-observation-guided-protocol.md)에 있다.
프론트 93개 파일·782개 테스트·타입·빌드를 통과했고, 합성 브라우저에서 완료 36구간·유지 12구간과
중단/재개 구분을 확인했다. 실제 카메라/사람 수행은 이 구현 검증에 사용하지 않았다.
자동 안내는 수행 과제 표식이다. 실제 동작의 성공·정답·분류 정확도나 상대 z의 타당성을 확인한 결과가 아니다.

## 후속: 카메라와 안내를 함께 보기

사용자가 카메라와 안내를 같이 보기 어렵다고 확인하여, 상단을 덮는 고정 안내 대신 왼쪽 카메라·오른쪽
현재/다음 지시와 타이머로 바꿨다. 시작하면 해당 영역으로 이동하고, 수치·그래프·수동 비교는 필요할 때
펼쳐 본다. 중간 정지 시에도 CSV를 받을 수 있다. 2/5/5초·3바퀴와 구간/품질 정책은 같다.

어깨 동작은 기존에도 양쪽 동시 상승이었다. 제목·유지/재개 안내를 `양쪽 어깨 함께 올리기`로 명확히 했다.
특징은 양어깨 중점의 높이 변화여서 좌우를 개별 검증하는 자료가 아니다. 새로운 CSV의 설명 이름만
명확해지며 action ID와 CSV 버전은 유지한다. 원본 좌표·새 학습·미래 예측은 추가하지 않았다.
구현/검증 기록은 [0057](../../plans/completed/0057-observation-camera-guidance-ux.md)에 있다.
93개 파일·784개 프론트 테스트·타입·빌드와 합성 브라우저의 시작 포커스·양어깨 유지·정지/재개·완료 CSV를 확인했다.
이 절은 0057 당시 배치 기록이다. 현재 화면은 아래 [0058](../../plans/completed/0058-observation-immersive-ui.md)의
영상 위 안내와 게이지 배치로 갱신했다.

## 후속: 영상 위 안내와 두꺼운 단계 게이지

사용자가 선택한 1번 시안을 따라 Electron 앱에 맞는 검정 바탕과 테두리 없는 색상면으로 화면을 바꿨다.
카메라 영상을 크게 두고 모서리에 현재 동작·타이머·다음 안내·일시 정지/종료 버튼을 겹쳐 배치한다.
얼굴·양어깨가 보이는 중앙은 비우고, 좁은 화면과 긴 일시 정지 안내에서도 설명과 버튼이 겹치지 않도록 한다.
영상과 관측점은 같은 영역에서 비율을 보존하고 좌우 반전한다. 수치·그래프·수동 비교는 계속 접힌 영역에서 확인한다.

영상 아래 단계 게이지를 56px 높이로 두껍게 하고, 게이지 안에 `이동`, `유지`, `복귀`와 남은 초를 넣었다.
진행 중인 단계는 색으로 구분하고, 일시 정지 중에는 남은 시간을 고정한 채 `남음 · 멈춤`을 표시한다.
재개는 해당 자세와 추적을 확인한 뒤 현재 단계를 처음부터 다시 센다. 시작 때 한 번만 화면을 이동하며
표본 갱신이나 정지/재개 때문에 화면을 다시 이동하지 않는다.

이동 2초·유지 5초·기준 복귀 5초, 네 동작·3바퀴·36구간은 유지한다. 2D 추적 불가·탭 숨김·500ms 초과
누락/진행 지연 시 일시 정지하고, z만 없으면 빈 값으로 기록한다. 완료·중도 종료 후 CSV 보존, 수동 다운로드,
새 측정·재등록 전 확인창, 실제/예시 탭의 분리와 예시의 수집·CSV 금지도 그대로다. 어깨 과제는 양쪽 동시 상승이며
수행 성공이나 자세 상태를 새로 판정하지 않는다. 원본 영상·좌표 저장이나 미래 예측도 추가하지 않았다.

구현/검증 기록은 [0058](../../plans/completed/0058-observation-immersive-ui.md)에 있다.
프론트 93개 파일·786개 테스트와 타입 검사·생산 빌드를 통과했다. 합성 UI에서 영상/관측점 정렬,
두꺼운 게이지 내부 단계·시간·멈춤 표시, 좁은 화면의 안내와 조작 배치, 정지/재개·완료 후 CSV 보존을 확인했다.
이는 합성 관측을 사용한 구현 검증이며 실제 카메라·사람의 네 동작 수행 결과나 구분 정확도가 아니다.
