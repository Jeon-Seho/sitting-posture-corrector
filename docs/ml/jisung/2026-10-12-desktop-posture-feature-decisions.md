## 합의한 개발 방향

1. 목표는 처음 등록한 개인 기준에서 관측된 변화량이다. 공통 바른 자세나 해부학적 정상 자세를 정의하지 않는다.
2. 촬영은 정면·카메라 고정이다. 높은 모니터 카메라와 낮은 노트북 카메라는 각각 같은 구도로 기준을 등록한다.
3. 현재 입력은 MediaPipe Pose Heavy의 얼굴 11점과 어깨 2점, 원래 index 0~12다. 전신 추론 출력에서 보존 범위를 선택하는 방식이다.
4. 로컬에서 기준 등록·수집·특징·판정을 먼저 개발한다. 모델 코어와 실행 어댑터를 분리해 서버 연결을 준비한다.
5. 기준 시계열은 별도로 보존하고 기준 자세를 개발상 정상으로 가정한다. 검증된 정답으로 취급하지 않는다.
6. 정답 라벨 비용을 고려해 기하 변화량부터 비교한다. Face Landmarker와 작은 시간 CNN은 후속 비교 후보다.
7. 현재 구도에서 손목은 안정적으로 관측하기 어려우므로 초기 입력에서 제외한다. 양손 들기·스트레칭 분류와 보너스도 이번 목표에 포함하지 않는다.

## 특징 비교와 주의점

영상 비율을 반영한 픽셀 좌표 `p=(W*x,H*y)`를 사용한다. 기준 어깨 중점은 c0, 현재 중점은 ct,
기준 어깨 폭은 s0, 현재 폭은 st다. 기준 폭이 유효하고 촬영 조건이 같을 때 비교한다.

| 입력 | 정의 |
| --- | --- |
| A 절대 변화 | `(p_i(t)-p_i(0))/s0` |
| B 상대 변화 | `dq_i=((p_i(t)-ct)-(p_i(0)-c0))/s0` |
| C 결합 | B + `dc=(ct-c0)/s0` + `st/s0` |

C부터 비교하되 최적안으로 확정하지 않는다. A=dq+dc이므로 성분을 나누는 표현의 효과를 비교한다.
어깨 중심 정렬만으로 머리·어깨가 함께 움직인 정보를 지우지 않고, 매 프레임 수평 회전 정렬도 하지 않는다.
눈 6점의 수가 점수를 지배하지 않게 묶음별로 비교하며 새 얼굴 특징에는 품질 마스크가 필요하다.
화면 밖·가림·정보 부족은 측정 불가이고 정상이나 최대 이탈로 대체하지 않는다.
3초 기준 등록은 시작점이며 자연 변동 분포 학습에 충분하다고 가정하지 않는다.

상세 근거는 [특징 설계](../../research/personal-baseline-feature-design.md),
[최종 점검표](../../research/personal-baseline-final-review.md), [ADR 0023](../../decisions/0023-baseline-feature-comparison.md)를 따른다.

## 현재 구현과 남은 작업

- 구현: MediaPipe 모델 준비·13점 선택·추론 루프를 `frontend/src/features/mediapipe/`로 분리했다.
- 구현: 완료된 기준 등록의 원본 13점 시계열을 IndexedDB에 보존하고 별도 JSON으로 내려받는다.
  라벨은 `baseline_posture`, 출처는 `registration_assumption`, `ground_truth_verified=false`다.
- 구현: 과제 CSV는 v3이며 좌표·촬영 조건·자기 보고 확인을 기록한다. 앱 판정·특징 열은 없다.
  기존 v1/v2 자료 준비 도구는 v3를 아직 지원하지 않는다.
- 현재 규칙: headGap은 코 높이, offset은 귀 중점의 좌우 위치, tilt는 어깨선 변화다.
  turn은 코와 귀 중점의 상대 위치로 고개 회전을 제외한다. 13점 전체를 활용한 새 점수는 아니다.
- 미구현: 13점 기준 대표값·그룹별 품질·A/B/C 특징·새 통합 점수·새 모델 서버 연결.
- 자료 연결 보완: 기준 UUID에 참여자·촬영 회차·카메라 조건을 연결한다. 현재 기준 archive의 participant_code는 null이다.

## test_0.2.3 비교

이 브랜치에는 기존 코·어깨 변화량/속도 6개를 사용하는 상대좌표 LSTM 실험과,
Face Landmarker + Pose Lite를 사용하는 얼굴 시간 CNN 경로가 있다.
얼굴 CNN은 얼굴 기준 대비 회전·크기·어깨 관계·손목·속도·누락 마스크 26개를 40프레임 창으로 처리한다.
자세 출력은 neutral/forward/slouch/tilt, 행동 출력은 still/head_turn/translation/arm_raise/neck_motion이다.

현재 목표와의 차이 및 대응:

| 문제 | 대응 |
| --- | --- |
| 자세 종류 분류와 기준 대비 변화량의 목표가 다름 | 변화 성분·크기 정의와 모델 출력을 먼저 맞춤 |
| 합성 자료 성능은 실제 사람 성능이 아님 | 실제 기준 유지·의도적 변화 구간에서 비교 |
| CNN을 도입해도 정답 라벨이 자동으로 생기지 않음 | 기하 평가를 먼저 하고 학습 필요성을 확인 |
| 40프레임 준비·재포착·지속 확인에 따른 지연 | 실제 관측 시각과 알림 지연을 측정 |
| 얼굴만으로 몸통·어깨 자세를 평가하기 어려움 | 머리 관측과 얼굴·어깨 관측 범위를 구분 |
| 손목·양손 들기 기능이 현재 촬영 범위와 목표에 맞지 않음 | 비교 도입 시 특징/출력/보너스를 제거하고 재학습. 단순 0 대입으로 기존 모델을 재사용하지 않음 |

재사용 검토 대상은 기준 대비 회전, 누락 마스크, 시계열 공백 처리다. 브랜치 전체 병합이나 모델 채택은 하지 않았다.
실제 모델 가중치와 실행 파일은 Git에 포함되지 않아 이번 환경에서 실행 검증하지 않았다.

## 서버 연결과 사양

서버 사양은 사용자 제공 i7-8700 / RAM 16GB / GTX 1050이다.
테스트 CNN 소스 구조 계산: 파라미터 5,625개, float32 순수 가중치 약 22.5KB,
40프레임 창당 약 21만 곱셈-누산이다. 런타임·JSON·MediaPipe 비용을 포함한 실측값이 아니다.
서버 추론은 CPU 측정부터 시작하고 실제 지연·동시 요청·학습 시간·GPU 필요성은 별도로 확인한다.

로컬/서버의 기준 ID·시간·포인트 순서·좌우 반전·품질·특징/모델 버전을 맞춘다.
같은 합성 자료에서 출력 일치를 확인한다. 서버 시간 정책은 CEP가 소유하고 추론에 중복하지 않는다.
기존 v2 입력은 세 특징 변화량용이며 13점이나 새 시계열 특징은 새 계약이 필요하다.
FE의 서버 제안은 9점 전송이므로 로컬 13점 연구 입력과 선택 범위를 구분한다.
[ADR 0024](../../decisions/0024-local-development-server-boundary.md)에 실행 경계를 기록했다.

## 원격 develop의 Git 규칙 확인과 후속 변경

확인한 원격 develop(8708e02)의 CONTRIBUTING.md에 명명 규칙이 있으며 AGENTS.md가 이를 참조한다.
확인 시점 원격에는 codex 유형이 있었다. 이후 사용자 요청으로 현재 작업의 [CONTRIBUTING.md](../../../CONTRIBUTING.md)에서 이 유형을 삭제했다.
어떤 AI를 사용하든 등록 담당자의 일반 작업과 동일하게 취급하고 작업 내용에 따른 유형을 사용한다.
이 규칙 변경은 현재 로컬 작업에 반영했으며 원격 반영은 아직 하지 않았다.

- 브랜치: `<type>/<scope>-<description>`. ML 작업 영역은 `model`, 여러 영역은 `repo`다.
- 현재 작업 브랜치는 `codex/repo-baseline-mediapipe`에서 `feature/repo-baseline-mediapipe`로 이름을 변경했다. 과거 기록과 다른 기존 브랜치는 소급 변경하지 않는다.
- 개인 이름이나 버전 번호만으로 새 브랜치 이름을 만들지 않는다. 기존 test_0.2.3은 소급 변경 대상이 아니다.
- 커밋: `<type>(<scope>): <summary>`, 하나의 목적·72자 이내 제목. 한국어 요약 가능.
- main/develop 직접 push 금지. hook·자동 명명 검사 도구는 추가하지 않는다.
- 새 ML 기능 예: `feature/model-baseline-features`, `feat(model): 개인 기준 대비 특징 추가`.
