# 개인 자세 ML 수집 학습 평가 재설계

- 작성: 2026-10-15
- 상태: 관측 한계 정의 우선. 본 수집·학습은 목표와 관측 조건을 확정한 뒤 재검토한다. 새 도구·모델은 미구현.
- 대상: 본인 1명으로 시작하는 개인 파일럿, i7-8700 추정·RAM 16GB·GTX 1050급 PC.
- 실행 계획: [계획 0052](../plans/active/0052-ml-rebuild.md), [범위 결정 ADR 0038](../decisions/0038-ml-rebuild-scope.md).

서비스 프론트·백엔드는 유지하고 ML의 수집·자료 준비·학습·평가 경로를 새로 만든다.
첫 작업은 **정면 어깨 위 관측에서 측정할 수 있는 변화와 판정에서 제외할 신체 상태를 나누는 것**이다.
[판정 한계](measurement-limits.md)를 먼저 따른다. 등록 기준과의 차이가 실제 정상·나쁜 자세를 뜻하지 않는다.
지원 현상을 확정한 뒤에만 같은 사람의 다른 날에서 변화 측정과 지속 알림을 검증한다.
미래 좌표 예측, 붕괴 시각의 조기 예측, 전신·해부학적 정상 자세 판단은 이번 목표에 포함하지 않는다.
새 코드가 기존 실험을 유지해야 할 의무는 없다. 재사용은 새 명세와 합성 검증을 통과하는 작은 모듈에 한정한다.

## 범위와 서비스 연결 경계

현재 구현 기준은 병합 커밋 `69ffc44`다. 기존 [정상 수집과 좌표 예측 계획](current-plan.md)은 당시 `/dev` 구현을 설명한다.
새 계획은 그 실험에 분류기를 덧붙이는 작업이 아니라, 관측 한계부터 다시 정하는 별도 연구 경로다.
아래 G1~G6의 수집 시간·라벨·모델은 한계 확인을 통과했을 때의 참고안이며 바로 실행할 확정 명세가 아니다.
분류기나 LSTM 없이 측정·지속시간 규칙으로 끝내는 결과도 허용한다.

| 영역 | 이번 계획 |
| --- | --- |
| 서비스 화면·계정·세션·기록·알림 시간 엔진 | 코드와 공개 계약 유지 |
| ML 수집기 | 서비스 UI와 독립된 로컬 연구 도구로 신규 구현 |
| ML 자료·특징·학습·평가 | 하나의 새 파이프라인으로 구현 |
| 기존 `/dev`·자동 정상 선별·Panoptic 좌표 예측 | 이관 필수 대상에서 제외. 과거 결과는 비교 이력으로 보존 |
| Kafka·Spark·HDFS·DB | 재설계·설정 변경 제외. 로컬 ML 실험의 필수 의존성으로 삼지 않음 |
| 실제 서비스 연결 | 호환성 확인과 필요한 계약 변경 목록까지 작성. 모델 자동 교체는 제외 |

서비스를 그대로 둔다는 제약을 다음처럼 구분한다.

| 입력 경로 | 현재 받을 수 있는 정보 | 새 ML에서의 역할 |
| --- | --- | --- |
| 실제 BE→추론 [`inference-request.v2`](../../contracts/inference-request.v2.schema.json) | 머리 간격·좌우 치우침·어깨 기울기 변화량 3개와 품질 2개 | `legacy3` 입력의 무상태 규칙·분류기 호환성 평가 |
| 목표 [`posture.frames.v1`](../../contracts/realtime/frames/posture-frames.v1.schema.json) | 9개 점의 영상 x·y·visibility와 프레임 시각 | `image9` 연구 입력 후보. 현재 BE가 전달하는 입력으로 간주하지 않음 |
| 새 연구 수집 | 추출기 ID가 있는 원본 관측·기준·시각·독립 라벨 | 자료를 한 번 모아 입력 후보를 같은 촬영에서 비교 |

현재 추론 요청에는 명시적 측정 세션 ID가 없고, 기준 ID와 순번만 있다.
ML 서버가 이를 임의의 세션으로 추정해 LSTM 이력을 쌓지 않는다. 시퀀스 모델의 서비스 도입에는
세션 식별·초기화·순서·누락·재시도 및 필요한 입력을 담은 새 계약과 생산자·소비자의 후속 작업이 필요하다.
연구 모델의 성능과 현재 서비스 입력으로 낼 수 있는 성능은 따로 보고한다.

## 장비와 실행 예산

빅데이터 플랫폼은 학교 서버에 두며, ML을 분리해도 동급 PC를 쓰는 조건이다.
분리 목적은 적재·집계와 학습의 자원 경합을 줄이는 것이다. GPU 가속이나 학습 시간을 보장하는 배치는 아니다.
G0에서 실제 CPU 모델, OS, 가용 메모리, GPU VRAM·드라이버, 브라우저의 추출 delegate를 확인한다.

아래 수치는 **초기 개발 예산과 측정 목표**다. 실제 장비 성능이나 확정된 연구 임계값이 아니다.

| 항목 | 시작 설정과 예산 | 초과 시 처리 |
| --- | --- | --- |
| 수집 | 기존 서비스 조건인 640×480, 자료 목표 10Hz, 카메라 한 대 | 추출기·delegate·주기를 비교하고 실제 시각 기록. 부족한 프레임을 복제하지 않음 |
| 추출기 | Pose Lite·Full을 동일한 촬영 과제로 비교한 뒤 하나 고정 | Heavy·Face 동시 실행을 기본 의존성으로 추가하지 않음 |
| 수집 메모리 | 브라우저 관련 프로세스 전체 약 2GiB 이내를 초기 목표로 관찰 | 30~60초 단위 파일 묶음과 스트리밍 저장으로 버퍼 제한 |
| 학습 | CPU 프로세스 1개, intra-op 2스레드부터, loader worker 0 | 여유가 확인된 전용 ML PC에서만 4스레드와 비교 |
| 학습 메모리 | 프로세스 트리 RSS 6GiB 이하, 시작 전 가용 RAM 8GiB 이상 | 자료를 순차 읽고 창은 인덱스로 생성. 메모리 예산을 넘기면 중단 |
| 학습 탐색 | 초기 학습 실행 총 10회 이내, LSTM 최대 6회 | 후보·seed를 늘리기 전에 자료·오류 원인 검토 |
| 단일 학습 | 최대 30 epoch, early stopping patience 5, 배치 32 | 실행당 30분의 작업 상한에서 체크포인트와 진단을 남기고 중단 |
| 모델 추론 | CPU 배치 1, 모델 자체 p95 20ms 이내를 초기 목표로 측정 | 모델 축소 또는 단순 모델 선택. 포즈 추출·파일 I/O와 별도로 측정 |

16GB 장비에서 플랫폼과 학습을 함께 실행해야 하면 먼저 실제 가용 메모리와 CPU를 측정한다.
Spark 집계·대량 재생·모델 학습을 겹쳐 실행하지 않는 일정을 기본으로 잡는다.
GTX 1050은 선택 가속 후보이며, GPU가 없어도 수집 이후 학습·평가가 끝나는 경로를 먼저 만든다.
Python은 준비된 3.12 환경과 기존 CPU 의존성 핀을 출발점으로 삼고, 패키지 업그레이드는 이 계획에서 수행하지 않는다.

## L0 판정 한계 정의와 G0 관측 확인

먼저 [판정 한계](measurement-limits.md)의 지원 항목·제외 상태·반례를 확인한다.
얼굴·양어깨의 2D 상대 형태와 영상상 위치·크기를 분리하며, 보이지 않는 몸통 상태는 정답으로 추정하지 않는다.
팔꿈치 포함은 필수 조건으로 확정하지 않는다. 목표 현상을 실제로 더 구별할 때만 촬영 범위 확대를 검토한다.
0.3초 미래 회귀와 LSTM 분류기는 기본 구현 대상에서 보류한다.

G0는 학습 자료를 모으기 위한 촬영이 아니다. 먼저 저장 없이 본인의 라이브 관측에서 반례를 찾는다.
필요하면 별도 10~15분 장비·구도 확인을 제안하되 학습·검증·최종 시험에 사용하지 않는다.

1. 형태를 유지한 이동, 가려진 몸통만 바뀐 경우, 카메라·의자·몸 이동의 모호성을 확인한다.
2. 영상상 머리·어깨 기울기와 고개 돌림·가림을 비교한다. 정면에서 앞뒤 방향을 확정하지 않는다.
3. 팔꿈치 포함 등 확장은 명시한 목표에 필요한 정보가 늘어나는지로 판단한다. 다른 시점은 사용 조건 변경안이다.
4. 사람의 수행 기록과 모델에 실제 남는 입력을 확인한다. 현재 룰 점수로 정답을 만들지 않는다.
5. 지원 현상·제외 상태·구도·추출기·점·품질·기준·라벨을 고정한 뒤 처리 시간·유효율·메모리를 측정한다.

머리·어깨만으로 구분할 수 없는 몸통 움직임은 일단 목표에서 제외한다.
필요한 관측 범위가 달라지면 본 수집 전에 설계를 바꾼다. 요구와 촬영 제약이 양립하지 않으면 해당 판정은 제외한다.
모델 크기나 점수 임계값으로 관측 공백을 덮지 않는다. 지원 현상이 정해지지 않으면 G1 이후로 진행하지 않는다.
카메라가 움직였을 때 자세 변화와 구분되지 않으면 측정을 중단하고 새 기준을 등록하는 운영 조건을 명시한다.

## G1 수집 도구와 자료 형식 — L0/G0 통과 후 재검토

새 로컬 수집 도구는 원본 관측과 사람의 라벨을 분리해 기록한다. 영상·음성을 저장하거나 업로드하지 않는다.
SDK가 내는 점은 추정치다. 원본 관측이라는 표현은 표시 평활화·보간 전 출력을 뜻하며, 실제 신체 좌표의 정답을 뜻하지 않는다.

초기 수집 범위 후보는 얼굴·귀·양어깨의 MediaPipe 인덱스 0~12다. 이 범위는 모델 입력의 확정이 아니라
9점 부분집합과 13점 후보를 같은 자료에서 비교하기 위한 보존 범위다. G0에서 목표를 관측할 수 있는지 확인한다.
영상 좌표 x·y·visibility를 기본으로 기록하고 world 좌표는 별도 선택 채널로 둔다.
world를 필수 입력으로 채택하려면 가용성과 의미를 검증하고, world가 없는 입력과 섞지 않는다.

새 연구 계약 `ml-capture-v1`은 구현 단계에 별도 스키마와 합성 예제로 작성한다. 기존 CSV v2/v3나 정상 JSON의 버전을 바꾸지 않는다.

| 파일 | 기록할 내용 |
| --- | --- |
| `capture.json` | 데이터·추출기·SDK 버전, 점 순서·반전 여부, 640×480 조건, 촬영·기준 ID, 세션 역할, 시계 원점 |
| `frames.jsonl` | 새 관측 ID, 단조 증가 촬영 시각과 도착 시각, 원본 점·가시성, 추론 비용, 관측 실패 및 구간 경계 |
| `labels.jsonl` | 실제 수행 시작·끝, 기준 유지/이탈/전이/측정 불가, 행동 맥락, 라벨 출처·검토 상태·시각 불확실성 |
| `calibration.json` | 명시적으로 확인한 20~30초 기준 구간과 기준 ID. 학습·평가 관측과 분리 |
| `manifest.json` | 파일별 SHA-256, 촬영일·회차·자료 역할, 학습/검증/시험 배정, 설정·코드 버전 |

위 파일명은 계획한 출력 형식이며 현재 제공되는 CLI나 산출물이 아니다.
원본 관측은 묶음 파일로 순차 저장하고, 시계열 창을 중복 배열로 모두 저장하지 않는다.
실제 자료·익명 참가자 목록·모델·스케일러·예측 결과는 저장소 밖 비공개 작업 폴더에 둔다.
Git에는 합성 fixture, 스키마, 코드와 실제 좌표를 포함하지 않는 집계 보고서만 둔다.

기존 자료를 가져오는 경우에는 명시적 importer를 사용한다.
CSV v3의 없는 품질·기준·라벨을 v2 값으로 채우지 않고, 이전 자동 정상 자료를 사람의 정답으로 바꾸지 않는다.
추출기·시각·기준·라벨의 출처가 충분하지 않은 자료는 새 학습 세트에서 제외한다.

## G2 본인 한 명의 촬영과 정답 — 조건부 참고안

처음부터 혼자 실행할 수 있게 한다. 과제 안내 시각과 실제 자세를 취한 시각을 별도로 기록한다.
참여자가 단축키로 실제 시작·복귀를 표시하고, 촬영 블록 뒤 수행 여부를 확인한다.
확신할 수 없는 구간은 `uncertain`으로 남긴다. 과제 지시, 모델 예측, 기준 거리로 자동 정답을 만들지 않는다.

혼자 표시한 라벨은 `self_reported`다. 나중에 관찰자가 실시간으로 별도 표시한 자료가 생기면 `observer_reviewed`로 구분한다.
영상이 없으므로 사후에 실제 자세를 재검수했다고 기록할 수 없다. 본인 라벨에 대한 일치도와 실제 자세 정확도를 구분한다.
라벨 불확실성이 큰 경우에는 관찰자를 둔 검토 회차가 필요하며, 임의의 정답을 추가해 학습하지 않는다.

| 단계 | 조건부 수집안 | 용도 |
| --- | --- | --- |
| D0 | 10~15분, 본 수집과 별도 | 구도·장비·라벨 지침 확정. 모델 선택에 사용하지 않음 |
| D1 | 15분 | 학습. 기준 유지와 여러 강도의 의도적 이탈·복귀 |
| D2 | 다른 날 15분 | 학습. 같은 구도에서 새 촬영, 과제 순서를 바꿈 |
| D3 | 다른 날 15분 | 검증. 특징·모델·점수 임계값·early stopping 선택 |
| D4 | 다른 날 30분 | 설정을 고정한 뒤 한 번 실행하는 개인 시험 |

아래 분류·사건 평가가 필요하다고 확정된 경우의 기존 참고안은 본 수집 75분이다. 현재 수집 지시나 충분한 데이터 양의 보장이 아니다.
10Hz가 유지되면 품질 제외 전 관측 상한은 학습 18,000개·검증 9,000개·시험 18,000개다.
이 행 수는 독립 표본 수가 아니다. 참여자는 한 명이며 시험 촬영일도 우선 한 날이다.

15분 회차의 시작안은 기준 등록 약 30초, 기준을 유지하는 일상 작업 4분,
짧은 움직임 2분, 지속 이탈·복귀 약 6분, 가림·자리 비움·중단 약 1분, 확인·여유 약 1분 30초다.
지속 이탈은 관측 가능한 후보별로 8~15초 정도 유지하고 충분히 복귀하는 과제를 섞는다.
짧은 움직임은 1~2초 과제를 포함하되 실제 수행 길이로 라벨을 정한다.
D4는 약 20분의 자연 작업과 약 10분의 사전 정의한 이탈·복귀·관측 실패 과제로 구성한다.
자연 작업에서 기준을 벗어났다면 정상 시간으로 강제 집계하지 않는다.

분류가 필요해지면 `reference`와 `deviation`은 L0에서 지원한 관측 현상의 기준 유지/변화에 한정하는 후보 라벨이다.
정상/나쁜 자세로 해석하지 않는다. 앞뒤 움직임처럼 범위에서 제외한 해석은 라벨명으로 확정하지 않는다.
`transition/uncertain`은 확실한 정답에서 제외하고,
`unmeasurable/away/rest`는 정상이나 이탈 학습 클래스에 넣지 않는다.
실제 수행 과제와 관측된 현상은 따로 보존하며, 처음부터 데이터가 부족한 다중 클래스 모델을 필수로 만들지 않는다.
방향을 식별할 근거가 부족하면 서비스 출력도 `unspecified`로 둔다.

## G3 자료 준비와 특징

순서는 **파일 검증 → 촬영일 분할 → 기준 분리 → 특징 변환 fitting → 시간 창 생성**으로 고정한다.

- 같은 사람의 D1/D2만 학습, D3만 검증, D4만 시험에 둔다. 한 촬영의 프레임·겹친 창을 무작위로 나누지 않는다.
- 이는 [개인 파일럿](../research/personal-pilot-training.md)의 확장이다. [참여자 홀드아웃 연구](../research/protocol.md)를 대체하지 않는다.
- 참여자가 늘면 참여자 단위로 학습/검증/시험을 먼저 나누고 촬영일은 그 안에서 묶는다. 시험 참여자의 이탈 자료는 학습·튜닝에 쓰지 않는다.
- 각 날의 20~30초 확인 기준은 허용된 개인 등록에만 사용한다. 시험일의 이탈·전체 분포로 스케일러나 정상 범위를 다시 맞추지 않는다.
- 스케일러·특징 선택·클래스 가중치·증강 통계는 학습 자료로만 정한다. 검증은 선택, 시험은 최종 보고에만 쓴다.
- 원본 hash·추출기 ID·점 순서·좌우 반전·기준 ID·시간 역전·중복·누락·회차 경계를 검사하고 제외 이유와 양을 남긴다.

기준은 그날 촬영 시작에 고정한다. 측정 중 이탈한 자세로 중심을 자동 갱신하지 않는다.
기준 실패·카메라 이동·추출기 변경은 새 촬영 구간으로 나눈다.
미래를 참조하는 보간, 중앙 이동평균, 양방향 모델은 사용하지 않는다.
초기에는 누락을 보간하지 않고 명시적인 구간 단절로 처리한다. 동일 관측을 반복해 새 프레임이나 유효 시간으로 세지 않는다.
목표 10Hz의 구간 배정·허용 시각 오차·단절 기준은 G0 뒤 본 수집 전에 고정한다.

| 특징 프로파일 | 후보 정보 | 제약 |
| --- | --- | --- |
| `legacy3` | 실제 서비스와 같은 세 변화량 | 기존 특징 정의·기준 등록·평활화·구간 빈도와 일치하는 어댑터를 합성 사례로 확인. 일치하지 않으면 호환 성능으로 보고하지 않음 |
| `image9` | 9점의 머리-어깨 상대 위치, 어깨 방향, 등록 위치 대비 공통 이동, 등록 어깨폭 대비 비율 | 확대와 축소를 모두 보존하고 영상 반전을 명시. 모델 입력은 우선 32특징 이하로 제한 |
| `world13` | 알려진 추출기의 world 좌표에서 얻은 특징 | 선택적 소거 비교. 깊이의 정답이나 현재 서비스가 받는 입력으로 간주하지 않음 |

`image9`의 전체 이동·크기 신호를 현재 프레임의 중심·폭 정규화 하나로 모두 제거하지 않는다.
상대 형태와 등록 영상 위치를 별도 특징으로 둔다. 카메라 이동과 신체 이동의 모호성은 운영 조건과 품질 게이트에 남긴다.
관측 가능한 라벨을 구별하지 못하면 수집·시점·목표를 먼저 바꾼다.

서로 다른 프로파일의 성능 차이는 입력 정보의 차이다. 모델 효과는 같은 프로파일·같은 시각·같은 품질 구간에서 비교한다.
`legacy3` 호환 평가와 새 좌표 모델을 한 표에서 같은 입력의 모델 비교처럼 순위 매기지 않는다.

현재 서비스의 간이 등록은 3초·최소 15표본인 반면 새 연구 기준은 20~30초다.
`legacy3`를 실제 호환 후보로 평가하려면 원본 기준 구간에서 현재 서비스와 같은 등록·특징·관측 빈도를 별도로 재현하고,
연구 기준과 다른 기준 ID를 부여한다. 새 기준으로 얻은 결과를 기존 서비스의 성능이라고 부르지 않는다.

## G4 학습 후보와 자원 제한 — 분류 필요성이 확인된 경우

현 단계의 구현 순서는 관측 한계 확인과 단순 측정이다. 아래 모델 표는 미리 구현할 목록이 아니다.
사람의 라벨로 구별할 지원 현상과 규칙의 실패 원인이 확인돼야 B1을 검토한다.
LSTM M2는 기본 후보에서 보류하며, 유효한 시간 이력으로 해결할 문제와 추가 이득 평가를 먼저 명시해야 한다.

| 후보 | 학습 내용 | 역할 |
| --- | --- | --- |
| B0 | 확인한 기준 유지 구간의 강건한 중심·범위와 고정 거리 규칙 | 관측 변화 측정의 단순 기준선 |
| B1 | 표준화와 Logistic Regression으로 현재 관측 상태 분류 | 규칙의 실패를 설명한 뒤 검토할 작은 분류기 |
| M2 | 단방향 단층 LSTM으로 창 끝의 현재 관측 상태 분류 | 보류. 시간 이력의 필요성을 먼저 입증할 경우에만 검토 |

### 출력 점수: 3클래스 softmax (2026-10-29 사용자 결정)

목표는 "알림을 보낼 자세인가"의 판정이다. 분류기는 `기준`·`이탈`·`스트레칭` 세 클래스의 softmax 확률을 낸다
([ADR 0043](../decisions/0043-base-deviation-stretch-collection.md)). 처음 정한 2클래스(기준·이탈)는 기지개·스트레칭을
이탈로 잡을 수 있어 같은 날 3클래스로 바꿨다.

- `p(이탈)`을 서비스 응답의 `collapse_probability`로 쓴다. 화면 점수는 기존대로 `100 × (1 − collapse_probability)`다.
  스트레칭 확률이 높으면 `p(이탈)`이 자동으로 낮아져 알림이 나지 않는다.
- 알림 경계는 [ADR 0005](../decisions/0005-score-visuals.md)의 기본값(30점 이하, 즉 확률 0.7 이상이 3초 지속)과
  [ADR 0020](../decisions/0020-single-api-decision-engine.md)의 시간 규칙을 그대로 따른다.
  n초 지속 판단은 판정 서버가 하므로 LSTM은 쓰지 않는다. 모델은 한 순간의 모양만 분류한다.
- 같은 모양에 서로 다른 라벨을 붙이지 않는다. 잠깐 한 이탈과 오래 한 이탈은 순간 라벨이 모두 `이탈`이고, 잠시냐 지속이냐는 시간 규칙이 가른다.
- 동작 이름(머리 내밀기 등) 라벨은 쓰지 않는다. 이탈은 참여자가 알림이 필요하다고 생각하는 자세를 매번 다르게 잡는다.
- 스트레칭 구분에는 팔꿈치·손목·손 좌표가 필요하다. 어깨·고개 모양만으로는 어깨 올리기와 기지개가 겹친다.
  `/dev` 리플레이 v2가 원래 인덱스 0..22를 기록한다. 서비스 프레임 계약(9점)에는 팔 점이 없어 서비스 적용 전에 계약 변경이 필요하다.
- 스트레칭 중 시간 규칙: 스트레칭을 정상으로 세면 열린 이탈 사건이 스트레칭 3초만으로 복귀 확정된다.
  짧은 가림 유지 규칙처럼 타이머를 멈추고 점수를 유지하는 쪽을 권장한다. 스트레칭은 5초를 넘기도 하므로 한도를 따로 정한다. 미정이다.
- 확률은 보정 검증 전에는 실제 확률이 아니다. `collapse_probability`라는 이름도 보정을 뜻하지 않는다(ADR 0020).
- 측정 불가는 확률로 표현하지 않는다. 품질 실패는 기존대로 `valid=false`(점수 0, 유형 `none`)다.
  가림·고개 돌림처럼 짧고 흔한 경우는 아래 짧은 가림 유지 규칙을 따른다.
- 입력 후보는 `/dev` 관측 값(머리–어깨 간격·얼굴 세로 길이·어깨 높이·어깨폭·코–어깨 상대 z)과 팔 visibility·위치다.
  상대 z는 의존도가 부풀었을 수 있어 보조 후보로만 둔다([점검](jisung/2026-10-29-desktop-replay-training-feasibility.md#상대-z-의존도-점검)).
  현재 `inference-request.v2`는 이전 3특징만 받으므로 서비스에 쓰려면 계약과 BE 특징 계산을 바꿔야 한다.
- 판정 서버가 시간을 맡으면 기준·이탈은 규칙(B0)으로도 될 수 있다. 같은 수집 자료로 B0와 softmax(B1)를 함께 평가하고, 차이가 없으면 단순한 쪽을 고른다.

### 짧은 가림 유지 규칙 (2026-10-29 사용자 결정, BE 구현 요청)

마시기·고개 돌림처럼 얼굴만 잠깐 판정할 수 없는 경우에 측정 불가가 자주 뜨지 않게 한다.
develop의 [ADR 0020](../decisions/0020-single-api-decision-engine.md) 시간 정책은 판정 불가 구간이 오면 연속 판정을 끊고 열린 사건을 중단한다.
아래는 그 정책의 예외이며, 시간 판정의 주인인 API 판정 엔진(`SessionEngine`)이 구현한다. 아직 구현하지 않았다.

| 항목 | 규칙 |
| --- | --- |
| 유지 대상 | 어깨는 판정 가능(양 어깨 visibility·가장자리·어깨폭 조건 통과)한데 얼굴만 실패한 구간. 사유는 고개 돌림(`head_turn`) 또는 얼굴 가림(코·입 visibility 미달, 새 사유 `face_occluded`) |
| 즉시 측정 불가 | 어깨 실패·사람 없음·카메라 끊김·화면 가장자리·좌표 누락. 기존 정책 그대로 |
| 유지 한도 | 연속 2초. 초기값이며 검증 전이다. 정책 설정값으로 둔다 |
| 유지 중 판정 | 이탈 누적과 복귀 누적을 멈춘다. 초기화하지 않고, 열린 사건도 중단하지 않는다. 확정·복귀·재알림 결정을 내지 않는다 |
| 유지 중 표시 | 직전 유효 구간의 `collapse_probability`·유형을 그대로 보낸다. 측정 불가 상태로 표시하지 않는다 |
| 한도 초과 | 한도를 넘은 시점부터 기존 측정 불가로 처리한다(연속 판정 끊기·사건 중단·UNMEASURABLE). 이미 지난 유지 2초를 소급해 바꾸지 않는다 |
| 직전 값 없음 | 세션 시작 직후·측정 불가 직후처럼 직전 유효 구간이 없으면 유지하지 않고 바로 측정 불가로 처리한다 |
| 통계 | 유지 구간은 관측이 없으므로 정상·이탈 누적과 유지율 분모에서 뺀다 |
| 추론 | API가 유지 구간에서는 추론 서버를 부르지 않는다. `InferenceClient`의 유효성 검사(품질 미달 구간을 유효로 받지 않음)를 바꾸지 않는다 |

- BE가 정할 것: 유지 구간을 DB에 기존 UNMEASURABLE로 남길지 새 제외 사유로 남길지, 그리고 WS 응답에 유지 상태를 알릴 필드가 필요한지.
- ML 쪽: 학습·평가 정답에 유지 구간을 넣지 않는다. 오프라인 재생기도 같은 규칙으로 측정 불가 표시 횟수·오알림·놓친 알림을 보고한다.
- 검증: 지금 리플레이 2개에는 가림·고개 돌림 과제가 없다. 마시기·고개 돌림이 섞인 평소 작업 녹화로 한도 2초를 정한다.

B0부터 확인하고 충분하면 학습 모델을 추가하지 않는다. 새 연구의 주 입력 시작 후보는 `image9`이며 G0에서 식별 가능성을 확인한다.
`legacy3`는 현재 서비스 입력의 한계를 확인하는 별도 비교다. 새 ML이 이 입력만으로 충분해야 한다는 조건은 두지 않는다.
세 후보의 입력·시간 정책을 맞춰야 모델 비교로 인정한다.
미래 좌표 회귀·대규모 영상 학습·포즈 추정기 재학습은 이번 실험에 넣지 않는다.

M2 시작안은 10Hz의 과거 2초, 최대 32특징, hidden 16 또는 32, 층 1개, 이진 출력이다.
창의 정답은 **창 끝의 현재 상태**이며 미래 라벨이나 창 전체 다수결로 대체하지 않는다.
유효한 과거 이력에 상태 전이가 포함되는 것은 허용하되, 정답 시점 자체가 불확실하면 학습 대상에서 뺀다.
세션·기준·추출기·관측 단절을 넘는 창은 만들지 않는다. 새 창이 준비되지 않은 시간은 준비 중으로 보고한다.

이 구조의 파라미터 상한은 입력 32·hidden 32에서 8,481개, float32 가중치만 33,924바이트다.
이는 제안 구조의 계산이며 런타임 메모리·FPS 측정값이 아니다.
PyTorch·포즈 추정·브라우저 비용은 별도로 측정한다.

분류와 M2 비교까지 필요해진 경우의 탐색 상한 참고안은 선택한 프로파일 하나에서 B0 fitting 1회,
B1의 정규화 강도 3개, M2의 hidden 후보 2개×seed 3개로 총 10회 이내다. M2를 실행할 의무는 없다.
다른 입력 프로파일의 학습 탐색은 별도 캠페인으로 예산과 선택 규칙을 먼저 기록한다.
최종 시험 전에 비교할 프로파일·모델을 모두 고정하고, 시험 결과로 탐색 범위를 추가하지 않는다.
한 LSTM 구조는 검증 성능의 seed별 중앙값으로 선택하고, 동률이면 작은 구조를 택한다.
배포 후보 seed와 체크포인트도 검증 결과만으로 정하고 시험을 보기 전에 고정한다.
초기에는 증강을 사용하지 않는다. 실제 회차 변화에 대한 오류를 본 뒤 학습 세트에 한정한 소거 비교로 추가한다.

## G5 고정 평가와 선택 기준

평가 명령은 자료·기준·특징·scaler·모델·시간 정책의 해시를 받아 원본 관측 순서로 재생한다.
분류 출력과 사람의 라벨을 먼저 저장하고, 동일한 시간 정책으로 사건을 평가한다.
제품의 기본 3초 지속·3초 복귀·60초 재알림은 [ADR 0020](../decisions/0020-single-api-decision-engine.md)의 시간 정책을 따른다.
시간 정책은 모델 학습 목표가 아니며 서비스에서는 기존 백엔드가 계속 소유한다.
오프라인 평가용 재생기는 골든 합성 사례로 기존 정책과의 일치를 확인하고, 서비스 시간 엔진을 대체하지 않는다.

| 지표 | 계산과 보고 |
| --- | --- |
| 상태 | Macro-F1, balanced accuracy, 클래스별 recall, 혼동행렬. 원 관측 기준으로 계산 |
| 사건 | 사람의 이탈 구간에 고정 지속시간 조건을 적용한 사건과 예측 첫 알림을 시간순 1대1로 대응 |
| 오알림 | 대응하는 실제 사건이 없는 첫 알림 수 ÷ 측정 가능한 비사건 시간. 분·시간과 원래 개수도 함께 보고 |
| 놓침 | 대응 알림이 없는 실제 사건 수와 전체 사건 수. 알고리즘의 기권으로 못 잡은 사건도 숨기지 않음 |
| 감지 지연 | 실제 이탈 시작 및 지속시간 충족 시점 각각에서 첫 알림까지의 시간. 라벨 시각이 불확실하면 범위로 표시 |
| 복귀·재알림 | 복귀 지연과 동일 사건의 중복 알림을 별도 보고. 재알림을 새 사건으로 세지 않음 |
| 관측 품질 | 유효 관측률, 준비 중·기권 시간, 품질·누락으로 제외한 시간과 라벨별 제외량 |
| 자원 | 포즈 처리·모델 자체·전체 결과 지연의 p50/p95, 실제 FPS, CPU·RSS, 학습 시간 |

주석 지침과 허용 대응 시간은 D3를 보기 전에 명세로 고정한다.
실제 이탈 사건에 겹치지 않는 이른 알림은 미래 예측 성공이 아니라 오알림으로 센다.
관측 불가 구간은 정상 시간으로 세지 않으며, 사람이 측정 가능하다고 라벨링한 구간에서 모델이 기권하면 그 양을 보고한다.
비교 모델의 품질 게이트·분모·시간 정책을 동일하게 유지한다.

초기 선택 원칙은 검증 회차에서 **단순 후보의 사건 검출을 유지하면서 오알림을 줄이고 지연을 과도하게 늘리지 않는 것**이다.
같은 입력의 B0/B1 중 검출 수, 오알림 수, 지연 순으로 고른 단순 후보를 비교 기준으로 둔다.
M2의 시작 선택 규칙은 검출 수가 줄지 않고, 오알림 수가 늘지 않으며, 감지 지연 중앙값이 단순 후보보다
0.5초 넘게 늘지 않는 것이다. 이 중 검출·오알림·지연 하나 이상이 개선돼야 복잡한 후보를 선택한다.
0.5초는 초기 개발 허용안이며 G0 뒤 D1 전에 동결한다. 실제 성능이나 연구적으로 입증된 허용 지연이 아니다.
검출 수·관측 범위가 줄었거나 오알림 개선 없이 지연만 늘어난 LSTM은 채택하지 않는다.
지표가 엇갈리거나 차이가 불분명하면 작은 모델을 남기고 다음 개발 촬영을 추가한다.
작업자가 허용할 오알림·놓침·추가 지연 수치는 위 시작안을 검토해 D1 전에 기록하고, 최종 시험 결과에 맞춰 소급 변경하지 않는다.
검증·시험에 두 상태와 지속 이탈 사건이 실제로 포함됐는지 확인한다. 사건이나 분모가 없으면 관련 지표는 산출 불가로 표시하고
완벽한 성능으로 대체하지 않는다. 예측 알림이 0개일 때 사건 precision도 산출 불가로 두고 recall·놓침 수를 함께 보고한다.

D3로 선택을 끝낸 뒤 B0·B1·선택한 M2와 설정을 고정하여 D4를 한 번 평가한다.
D4가 나쁘다고 다른 후보로 교체해 같은 D4를 다시 최종 성능으로 쓰지 않는다. 새 개발 주기는 새 시험일을 확보한다.
한 명·한 시험일에서 겹친 창을 독립 표본처럼 세어 95% 신뢰구간이나 새 사용자 정확도를 만들지 않는다.
결과는 본인 라벨에 대한 회차별 서술 통계다. 관찰자 정답·여러 독립 시험일·참여자 모집은 후속 연구로 구분한다.

## 구현 순서와 산출물

아래 경로와 명령은 **새로 구현할 인터페이스 제안**이다. 아직 실행 가능한 도구로 안내하지 않는다.
L0/G0를 통과하기 전에는 수집기·학습 도구 구현을 시작하지 않는다. 단순 측정으로 충분하면 학습 단계는 축소한다.

```text
tools/ml_collector/          독립 로컬 수집과 수동 라벨 표시
model/posture_ml/            새 자료 검사·품질·특징·학습·평가·export
tests/test_posture_ml_*.py   합성 자료·누수·시각·실제 학습과 재생 검증
```

공통 CLI는 `validate → split → prepare → train → evaluate → replay → export`로 구성한다.
`evaluate`는 고정 모델과 새 시험 manifest만 받아 보고서를 만들고, fitting을 호출할 수 없게 분리한다.
평가 모델·입력·설정의 해시는 실행 전후 같아야 한다. 모든 명령은 입력 원본을 읽기만 한다.

| 순서 | 구현 산출물 | 다음 단계로 가는 조건 |
| --- | --- | --- |
| 0 | 판정 한계 명세·G0 반례 확인 기록 | 지원 현상·제외 상태·촬영 조건·라벨이 양립함. 양립하지 않으면 목표나 관측 조건 수정 |
| 1 | 스키마·합성 파일·독립 수집·장비 보고 | 확정된 관측·라벨을 보존하고 저장·시각이 이어짐 |
| 2 | 촬영일 manifest·검사·특징·B0·평가 재생기 | D1/D2/D3 역할 누수 없음, 원본부터 동일 결과를 재현 |
| 3 | 필요한 경우 B1·자원 측정·개인 검증 보고 | 단순 측정의 실패와 추가 학습의 목적을 설명할 수 있음 |
| 4 | 필요한 경우 작은 M2·제한 탐색·고정 모델 | 시간 이력의 필요성을 명시한 뒤 공정하게 비교. 이득이 없으면 채택 중단 |
| 5 | D4 최종 개인 시험·모델 묶음·연결 요구서 | 고정 결과·자원·한계를 보고하고 서비스에 필요한 입력과 변경을 구분 |

모델 묶음에는 입력·추출기·특징·기준 정의, scaler, 가중치, 라벨 매핑, 선택 과정, 코드·자료·환경 해시를 함께 둔다.
현재 서비스 응답 필드에 맞는 `legacy3` 모델만 기존 계약의 호환성 후보로 내보낸다.
`model_version`은 BE가 검증하므로 실제 교체에는 설정 일치와 통합 검증이 별도로 필요하다.
좌표·이력 모델을 기존 특징 필드에 숨겨 넣거나 서비스 계약을 조용히 바꾸지 않는다.

수집·학습·검증·시험은 로컬 파일만으로 끝나야 한다. Kafka·HDFS는 필요할 때 검증된 자료를 전달하는 후속 경로이며
학습 성공이나 평가 재현의 선행 조건으로 두지 않는다.

## 검증과 중단 조건

- 합성 예제는 시간 역전·중복·프레임 누락·카메라/기준/추출기 변경·계약 불일치·평가 fitting 시도를 거부해야 한다.
- 명시적인 합성 자료로 작은 실제 B1/M2 학습과 export→재로딩→동일 추론을 검증한다. 학습 함수를 mock한 검사로 대체하지 않는다.
- 개인 회차 분할과 별도로 참여자 분할의 기존 금지 조건도 검증한다. 참가자 평가 모드에 한 사람을 여러 분할로 넣으면 실패해야 한다.
- 원본→특징→학습→평가 전체 CLI를 합성 자료로 `make test`와 `make check`·CI에 연결한다.
- 수집 도구의 저장·시작/중단·새 기준·라벨 기능은 합성 입력의 실제 도구 경로로 확인한다.
- CPU 검증은 가속기 없이 통과해야 한다. 실제 학교 PC의 장비 보고와 실제 개인 자료 보고는 CI 합성 결과와 분리한다.
- 목표 동작이 관측되지 않거나 라벨을 신뢰할 수 없으면 본 수집을 중단한다. 수집 방식·목표·시점을 먼저 바꾼다.
- 단순 후보보다 낫지 않은 복잡한 모델을 서비스 도입 조건으로 삼지 않는다. 실패한 비교도 결과로 보존한다.
