# 2026-10-14 실제 촬영·수집·모델의 빈 부분

범위는 `/dev`의 실제 웹캠 동작 관찰과 현재 코드의 읽기 전용 감사다. 아래 관찰은 정확도 평가나 새
모델 학습 완료를 뜻하지 않는다. 구현 방향은 [현재 ML 계획](current-plan.md), 지연·GPU·모델 속도의
실측 조건과 수치는 [카메라 성능 기록](camera-performance.md)을 따른다.

이 문서에는 화면에서 읽은 집계 수치와 비식별 동작 설명만 남긴다. 실제 영상·스크린샷·랜드마크·참여자
식별 정보는 첨부하거나 저장소에 추가하지 않았다. 간헐적인 화면 관찰이므로 프레임 단위 정답, 순수
검출 떨림 수치, 감지 정확도는 계산하지 않았다. 아래의 다음 실험은 제안이며 수행 완료가 아니다.

## 후속 구현 상태 (2026-10-14)

아래 감사는 수정 전 관찰을 보존한다. 후속 구현은 정상 중심 고정·등록 검증, 자동 6% 기본 선별과 연속 창/탈락 이유,
MediaPipe JSON→참여자 분할→LSTM 학습→v2 모델 연결, 진단 추출기 메타데이터를 추가했다.
[현재 ML 계획](current-plan.md)과 [학습 안내](mediapipe-training.md)가 최신 동작이다. 실제 자료는 아직 없어 사용자 모델을
재학습하거나 판정 정확도를 검증한 것은 아니다. 가려진 점의 깊이 정확도, 전신/허리 관측 부재, 정상화에서 제거되는
전체 이동, 스트레칭 의도 구분은 계속 남아 있는 측정 한계다. 학습 평가 정답은 보간한 좌표 대신 300ms 목표 ±50ms의
가장 가까운 실제 관측을 사용하며, 정확히 300ms 미래의 실측 평가와 구분한다.

## 실제 동작에서 확인한 것

2026-10-14 Apple M1에서 Full · GPU · responsive, 웹캠 640×480으로 약 **5분 52초**의 세션을 관찰했다.
다음 시각은 세션 내부 경과 시각이며, 동작 이름은 당시 화면의 시각적 설명이다. 정답 자세 라벨이 아니다.

| 세션 시각 | 화면에서 관찰한 동작 | 그 시점에 표시된 값 |
| --- | --- | --- |
| 03:31 | 정면으로 앉음 | 기준 거리 3.4% |
| 03:39 | 화면 오른쪽으로 고개 회전 | 기준 거리 17.7%, 연속 이탈 1.8초 |
| 03:45 | 상체를 화면 왼쪽으로 이동 | 기준 거리 11.1%, 기준 범위 상태 |
| 03:49 | 상체를 화면 왼쪽으로 기울임 | 기준 거리 20.9%, 연속 이탈 3.2초 |
| 03:59 | 반대 방향으로 고개 회전 | 기준 거리 26.5%, 연속 이탈 3.2초 |
| 04:08 | 정면으로 복귀 | 기준 거리 2.8%, 연속 이탈 0초 |

알림 기록에는 **03:40 거리 15.7%·해당 기록 최대 19.6%**, **03:48 거리 21.0%·최대 23.3%**가 남았고
총 알림 수는 2회였다. 위 표의 시점과 알림 발생 시점이 다르므로 순간 거리 값은 서로 다를 수 있다.
약 5:52 종료 시 화면에는 비교 가능한 시간 **5:37**, 측정 누락 **00:00**, 자동 정상 수집 **0행**이
표시됐다. 연결·구도·등록 시간은 비교 가능 시간과 다르며, `00:00`이라는 표시만으로 모든 프레임에
누락이 없었다고 입증할 수는 없다.

얼굴·어깨의 점들은 관찰한 움직임을 대체로 따라갔고 확인한 화면에서는 13/13로 표시됐다. 옆으로 돌아 가려진
위치의 점도 13점으로 표시됐다. 따라서 점이 존재한다는 사실과 숨겨진 점의 실제 3D 위치가 정확하다는
주장은 구분해야 한다. 순수 수평 이동만 통제하지 못했으므로 03:45를 놓침(false negative)의 증거로
단정하지 않는다.

정면으로 보이는 여러 순간에도 LSTM 얼굴 중심 예측에 오른쪽 **6.6~11.3%**가 반복해서 표시됐다.
방향 편향을 의심할 단서는 있지만, 입력 시각과 0.3초 뒤 실제 좌표를 맞춰 분석하지 않았으므로 편향이나
예측 오류가 확정된 것은 아니다. 화면 관찰만으로 원본 좌표의 잡음과 실제 미세 움직임도 분리할 수 없다.

## 우선순위별 빈 부분

### 우선 1: 정상 프로파일이 잘못된 기준 등록을 검증하지 않는다

**코드 확인:** 수동 정상 구간에서 특징의 중심과 허용 폭을 함께 fitting하지만, 측정 시에는 새 등록의
`baselineOverride`를 중심으로 사용한다. 기존 프로파일은 주로 허용 폭을 제공한다. 새 등록 자세가 이전에
확인한 정상 분포의 중심과 일치하는지 검사하는 단계는 없다.
[개인 범위 fitting·점수 코드](../../model/prototype/normalPosture.ts),
[새 기준을 전달하는 실험 엔진](../../model/prototype/forecast.ts).

따라서 구도 검사를 통과하는 잘못된 자세로 기준을 등록하면 그 자세가 새 비교 중심이 될 수 있다.
이는 현재 개인 기준 방식의 한계이며, 이번 실측에서 잘못된 등록이 실제 발생했다는 뜻은 아니다.
현재 구현을 “학습한 정상 자세로 등록 자세의 정상 여부까지 검증하는 모델”이라고 설명하면 안 된다.

**작은 다음 실험:** 동일한 확인용 정상 구간을 고정하고 의도한 기준 등록과 변형한 기준 등록을 각각
반복한다. 원래 중심 대비 변화, 새 중심 대비 변화, 알림 결과를 나란히 비교한다. 카메라 위치·추출 모델을
고정하고, 잘못된 등록을 거부할지 사용자에게 확인받을지 판단할 근거를 먼저 모은다. 시험 참여자의 이탈로
허용 폭이나 거부 임계값을 튜닝하지 않는다.

### 우선 1: 현재 LSTM의 입력 도메인과 수집 자료의 학습 연결이 미완성이다

**코드 확인:** 브라우저 가중치는 `Panoptic-face9-body4-not-MediaPipe`, `domain_validated: false`를 명시한다.
MediaPipe의 얼굴·귀·어깨를 의미가 가까운 점에 대응시키지만 점 정의와 좌표축은 동일하다고 검증되지 않았다.
기존 [Panoptic 학습 경로](../../model/analysis/panoptic_lstm.py)는 있고, `/dev` 자동·수동 수집 JSON을 검증하고
참여자 분할·시간 창으로 변환하여 재학습하는 어댑터는 현재 `model/`·`tools/`에서 확인되지 않았다.
[브라우저 입력·가중치 계약 검사](../../model/prototype/forecast.ts),
[자동 수집 계약](../../contracts/auto-normal-posture-collection.v1.md),
[수동 수집 계약](../../contracts/normal-posture-collection.v1.md).

**작은 다음 실험:** 먼저 합성 수집 JSON으로 모델 ID·특징 순서·단위·시간·구간 경계·참여자 분할을 검증하는
변환기를 만든다. 그 뒤 별도 동의·수집한 동일 MediaPipe 입력에서 위치 유지, 등속, LSTM을 같은 미래 시각에
비교한다. 입력 보간값을 평가 정답으로 쓰지 않고, 0.3초 뒤 실제 유효 관측과 대응시킨다. 이번 관찰의
오른쪽 예측 반복은 이 평가에서 확인할 가설로 남긴다.

### 우선 2: 13점 표시·화면 위치·3D 판정은 서로 다른 측정이다

**코드 확인:** 13/13 카운터는 image x/y/visibility를 검사한다. ML 입력은 world xyz의 유한값과 어깨 폭도
요구하므로 13/13이어도 입력이 거부될 수 있다. 반대로 world 좌표가 유한하다는 이유만으로 가려진 점의
깊이 정확도가 입증되지는 않는다. 현재 검사에서 world의 개별 visibility는 판정 조건에 들어가지 않는다.
[점 수 표시의 입력](../../frontend/src/features/developer/useDeveloperSession.ts),
[3D 입력 품질 검사](../../model/prototype/forecast.ts).

매 프레임 world 좌표에서 어깨 중심을 빼고 어깨 폭으로 나누므로 전체 평행 이동과 일정한 크기 변화는
제거된다. 13점 밖의 골반·허리·척추 곡률도 직접 관측하지 않는다. 영상의 등록 점선은 image 평균이고
모델 기준은 정규화 world 좌표의 차원별 중앙값이다. 따라서 점선과의 픽셀 거리, 화면 이동 %, 자세 거리 %는
같은 양이 아니다. [등록 영상 기준](../../model/prototype/developerGuidance.ts).

화면 평활화는 수집·등록·모델에 들어가지 않는다. 250ms 초과 시 표시 필터가 초기화되며, 최신 영상에
이전 추론 시점의 점을 그리므로 움직일 때 시간 차가 생길 수 있다.
[표시 전용 필터](../../frontend/src/features/developer/displaySmoothing.ts),
[영상·오버레이 표시](../../frontend/src/features/developer/DeveloperCameraStage.tsx).

**작은 다음 실험:** 고정된 정면에서 미세 움직임, 몸 모양을 유지한 좌우 이동, 몸통 기울임, 고개 회전,
한쪽 가림을 따로 수행한다. image/world 유효율·탈락 지점·원본 좌표 변화·표시 지연을 분리해 집계한다.
순수 떨림은 정지 조건의 반복 측정으로 별도 평가하고, 숨겨진 점에 대한 외부 정답이 없으면 깊이 오차를
정확도 수치로 보고하지 않는다.

### 우선 2: 자동 0.5% 자료는 정상 분포와 연속 학습 창을 보장하지 않는다

**코드 확인:** 0.5%는 각 점의 최대 오차가 아니라 얼굴 9점·귀 2점·어깨 2점의 그룹별 평균 거리를 다시
평균한 값이다. 이미지 픽셀 오차나 정상 확률도 아니다. 기준에서 매우 가까운 원본 프레임만 선별하므로
자연스러운 정상 변동을 충분히 담지 못한다. 탈락·시간 단절은 구간을 끊고 자동 자료를 즉시 정상 프로파일에
학습시키지는 않는다. [자동 수집](../../frontend/src/features/developer/autoNormalCollection.ts).

이번 세션의 0행은 이 설정에서 수집 자료를 확보하지 못했다는 관찰이다. 0.5% 조건의 엄격함·좌표 잡음·
기준 차이 중 무엇이 얼마나 기여했는지는 프레임별 탈락 이유의 집계 없이 확정할 수 없다. 총 행 수가 늘어도
짧고 분리된 구간뿐이면 LSTM의 3초 입력과 0.3초 미래 정답을 만들 연속 창은 부족할 수 있다. 정상 자료만
모아서는 이탈의 놓침·감지 지연을 평가할 수 없다.

**작은 다음 실험:** 한 번의 확인된 정상 수동 촬영에서 기준 거리 분포와 0.5% 통과율·구간 길이·유효 연속
창 수를 집계한다. 다른 후보 선별값은 오프라인 민감도 분석으로 비교하며 사용자가 지정한 운영값을 임의로
바꾸지 않는다. 자동 약라벨과 수동 자기 보고를 분리하고 평가용 일시 움직임·지속 이탈·측정 불가 구간에만
최소한의 시작/끝 라벨을 붙인다. 자기 룰의 자동 라벨을 평가 정답으로 재사용하지 않는다.

### 우선 3: 세션 진단 기록만으로 추출 모델을 재현할 수 없다

**코드 확인:** 이번 변경에서 수집 자료·개인 프로파일·모델 벤치마크에는 추출 모델 ID를 보존하지만,
일반 `developer-lab-export-v1`의 `model_id`는 예측 모델 ID다. 세션 진단 JSON에는 MediaPipe의
Lite/Full/Heavy 추출기 ID가 별도로 없다. 서로 다른 추출기의 실험 기록을 나중에 비교할 때 조건이 누락될 수 있다.
[세션 내보내기](../../frontend/src/features/developer/session.ts),
[진단 계약](../../contracts/developer-lab-export.v1.md).

**작은 다음 구현·검증:** 세션 시작 시 추출기 ID·실제 delegate·해상도·pacing을 고정해 진단 메타데이터에
선택 필드로 남기고, 과거 기록의 값은 미확인으로 유지한다. 원본 영상·좌표를 진단 JSON에 섞지 않는다.
계약·합성 예제·호환성 검증을 함께 추가한 뒤 완료로 기록한다.

## 이번 감사의 결론과 제한

실제 움직임에 반응하고 지속 이탈 알림이 발생하는 흐름은 관찰했다. 자동 정상 수집은 이번 세션에서
자료를 확보하지 못했다. 정상 등록 검증, MediaPipe 자료로의 학습 연결, 동기화된 미래 예측 평가,
누락·연속 창 품질 분석은 남아 있다. 성능 개선과 화면 동작 확인을 이 연구 과제들의 완료로 대신하지 않는다.

이 문서 작성에는 코드 조회와 제공된 실측 관찰만 사용했다. 새로운 테스트·촬영·학습을 실행하지 않았다.
