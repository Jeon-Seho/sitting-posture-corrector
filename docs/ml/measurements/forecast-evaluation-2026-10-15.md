# 새 촬영에서 개인 MediaPipe LSTM·기본 Panoptic과 마지막 위치 유지 비교

2026-10-15, 참여자 1명의 새 평가 촬영 1회. 이 촬영에서는 마지막 위치 유지(`hold_last`)의
좌표 MAE가 기존 개인 MediaPipe LSTM보다 약 48.8% 낮았다. 이는 해당 회차의 미래 좌표 예측 비교이며,
다른 참여자·동작에 대한 모델 우위나 자세 판정 정확도를 입증하지 않는다.

## 평가와 학습의 분리

새 자료는 [평가 전용 수집 계약](../../../contracts/forecast-evaluation-collection.v1.md)에 따라
`forecast-evaluation-collection-v1`, `forecast_evaluation`, `evaluation_only`, `trainingAllowed:false`로 수집했다.
정상 라벨·개인 정상 범위가 없으며 학습 자료로 읽기와 pilot manifest 생성에서 거부된다.
확인 과정에서 개인 범위를 맞추거나 현재 범위를 갱신하지 않았다.

기존 개인 MediaPipe LSTM의 모델·체크포인트·학습 manifest·학습 보고서의 네 해시는 평가 전후 같았다.
새 자료로 재학습, 스케일러 재추정, 개인 보정, 모델 선택을 수행하지 않았다.
원본 좌표, 참여자 코드, 수집 ID, 모델 가중치와 비공개 파일 경로는 이 집계 문서에 포함하지 않는다.

## 실행 조건과 유효 표본

- 좌표 추출: MediaPipe Pose Full float16, `tasks-vision` 1.0.1. 화면에서 GPU 사용을 확인했다.
- 예측 실행: Node.js 24.18.0에서 실제 TypeScript `readForecastWeights`와 `predictLstm`을 CPU로 실행했다. 자료 검증은 Python 3.12.14를 사용했다.
- 입력: 어깨 중심·폭으로 정규화한 13점 xyz, 39축. 100ms 격자 30개 입력, 명목 목표는 입력 격자 끝 300ms 뒤다.
- 비교군: `hold_last`는 같은 입력 격자의 마지막 좌표를 유지한다. 두 방식은 같은 입력과 같은 미래 실측을 비교한다.
- 수집 결과: 유효 관측 30,083.8ms, 저장 표본 278개, 품질 누락 사건 3개, 연속 구간 4개다.
- 평가 창은 마지막 연속 구간의 263표본·28,672.7ms에서만 만들어졌다. 나머지 구간을 이어 붙이지 않았다.
- 후보 255창 중 명목 목표 ±50ms 안에 실제 관측이 없는 23창을 제외해 232창을 비교했다. 목표 좌표를 보간하지 않았다.
- 비중첩 확인은 연속 구간별 시간순으로, 새 창의 첫 원본 입력 관측 시각이 직전 선택 창의 실제 목표 시각보다 늦은 창만 고르는 방식이다. 8창이 남았다.

이 평가 촬영의 해상도와 장치 모델은 별도로 확인하지 않았으므로 이전 촬영의 설정으로 대체해 기록하지 않는다.
실행 당시 작업 트리는 커밋 `a1e1c11`에 미커밋 변경을 포함한다. 해당 커밋만으로 이번 평가 구현 전체가 재현된다는 뜻은 아니다.

입력은 인접 유효 실측 사이에서만 격자로 보간한다. 두 모델 모두 입력 보간에 사용한 마지막
원본 관측이 목표 관측보다 앞서야 한다. 입력 격자 끝에서 실제 목표까지의 간격 중앙값은
301.75ms였고, 마지막 원본 입력 관측부터 목표까지 남은 유효 예측 시간 중앙값은 216.85ms였다.
따라서 이 결과를 관측 확보 뒤 정확히 300ms를 예측한 성능으로 해석하지 않는다.

## 좌표 오차 결과

아래 값의 단위는 어깨너비이며 작을수록 좋다. MAE와 RMSE는 39개 좌표축 오차다.
그룹 균등 점 거리는 얼굴·귀·어깨 그룹별 점의 3D 유클리드 거리 평균을 구한 뒤,
세 그룹에 같은 가중치를 준 값이다.

| 지표 | 개인 MediaPipe LSTM | 마지막 위치 유지 |
| --- | ---: | ---: |
| 232창 MAE | 0.0274931733 | 0.0140757571 |
| 232창 RMSE | 0.0395765055 | 0.0223841306 |
| 232창 그룹 균등 점 거리 | 0.0462810572 | 0.0239545124 |
| 창별 MAE가 더 낮은 횟수 | 32 / 232 | 200 / 232 |
| 비중첩 8창 MAE | 0.0291593390 | 0.0104390243 |
| 비중첩 창별 MAE가 더 낮은 횟수 | 0 / 8 | 8 / 8 |

232창은 같은 짧은 촬영을 겹쳐 잘라 만든 값으로 서로 상관이 있다. 승리 횟수는 이 창들의
서술 통계이며 독립 시행 기반 유의성이나 확률이 아니다. 비중첩 8창도 같은 참여자·같은
촬영에 속하므로 참여자 8명 또는 독립 촬영 8회로 취급하지 않는다. 신뢰구간이나 유의성 검정은 하지 않았다.

## 현재 화면의 기본 Panoptic 모델 추가 비교

추가로 현재 화면 설정을 직접 확인했을 때 선택된 모델은 `panoptic-lstm-v1`이었다.
위 주 비교의 개인 MediaPipe LSTM과 구분하기 위해, 현재 기본 Panoptic 모델도 같은 232창·실제 목표로 평가했다.
비중첩 8창의 선택도 같았으며, 마지막 위치 유지 결과는 앞선 비교와 정확히 일치함을 확인했다.
아래는 전체 232창 집계다. 위 창별 승리 횟수와 비중첩 MAE는 개인 MediaPipe LSTM의 결과이며
Panoptic 결과로 재사용하지 않는다.

| 지표 | 현재 기본 Panoptic | 마지막 위치 유지 |
| --- | ---: | ---: |
| 232창 MAE | 0.0556032469 | 0.0140757571 |
| 232창 RMSE | 0.0695569277 | 0.0223841306 |
| 232창 그룹 균등 점 거리 | 0.0983894905 | 0.0239545124 |

Panoptic 가중치 해시는 추가 평가 전후 같았고, 학습이나 화면 모델 선택·교체는 하지 않았다.
Panoptic에서 MediaPipe 입력으로의 대응은 근사이며 도메인 적합성이 검증되지 않았다.
따라서 이 수치는 현재 웹캠 입력 대응 경로의 오차이며, Panoptic 원래 학습 도메인의 성능을 나타내지 않는다.

## 해석의 한계

이번 촬영에서는 두 LSTM보다 마지막 위치 유지의 좌표 오차가 더 작았다. 이 결과로 LSTM이 모든 동작에서
불필요하다거나 마지막 위치 유지가 다른 사람에게도 우수하다고 결론 내리지 않는다.
이번 값은 정상·이탈 정답, 이탈 사건 검출, 오알림, 교정 효과 또는 의학적 정상성 검증이 아니다.
모델을 바꾸거나 선택하려면 별도 학습·검증 회차를 사용하고, 이번 평가 자료를 튜닝 자료로 재사용하지 않는다.

## 구현 검증

- `make check`: Python 186개, 프론트 71파일·652개 테스트, TypeScript와 Vite 빌드 통과. Java 21/Maven 부재로 백엔드 단계에서 중단되어 전체 게이트 성공은 아니다.
- 신규 평가 전용 검증을 포함한 `python3 -m unittest tests.test_forecast_evaluation_capture tests.test_mediapipe_lstm -v`: 27개 통과. 신규 7개와 위 Python 186개에 포함된 기존 20개이며 두 실행 수를 합산하지 않는다.
- 수집 코어 14개와 UI·hook 13개의 개별 프론트 검증은 위 전체 652개에 포함된다. 평가 확인의 fitting 미호출, 기존 개인 범위 보존, 평가 전용 내보내기와 학습 입력 차단을 합성 자료로 확인했다.
- `make check-browser`: 최초 실행은 샌드박스의 로컬 서버 bind 제한으로 실패했다. 허용된 재실행에서는 생산 번들의 합성 카메라·테스트 진입점 제외 검사와 임시 서버 3개 정리는 통과했다. Java runtime 부재로 서비스 준비에 실패해 실제 브라우저 회귀 단계는 실행하지 못했다.
- 실제 내장 브라우저에서 평가 모드 선택 → 30.1초 수집 → 학습 제외 용도 확인 → 전용 JSON 다운로드를 완료했다. 이 수동 관찰은 일반 서비스의 합성 브라우저 회귀 검증을 대체하지 않는다.
- 최종 `make check-repo`와 `git diff --check`가 통과했다.
