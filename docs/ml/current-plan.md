## 최신 사용자 지정: 종합 0.7배 진입 (2026-10-15)

얼굴 추적 최신 변경은 [Face와 공개 학습 자료](face-and-public-data.md)와 [ADR0037](../decisions/0037-developer-face-landmarker.md)을 따른다.
`/dev`는 Face Landmarker를 별도 Worker에서 실행하며 얼굴 전용/기존 Pose/겹쳐 보기를 제공한다.
안경 조건별10초 비교는 실제 차이·유효 관측·지연을 기록한다. Face 상대z와 기존Pose world39D를 섞지 않으며 현재 수집/알림/LSTM은Pose 원본이다.
공개 Panoptic은 같은 추출기로RGB를 재처리하는 시계열 후보, MultiPosture는 시간 없는 몸통 분류 후보, EYEDIAP은 접근 신청이 필요한 머리 움직임 검증 후보다. 이번에 새 실제 모델을 학습하지 않았다.

새 측정은 종합 >0.7배에서 이탈, ≤0.7×2/3(약0.47)배에서 복귀한다. 점수 단위·영상18%/12% 하한·이탈/복귀3초·자동 후보0.5배/1초·무음은 유지한다. reading·알림·행에 적용 경계를 기록하며 과거 기록의 1배 기준을 바꾸지 않는다. 실제 관찰과 오탐/정확도 검증을 구분한다.
[ADR 0036](../decisions/0036-composite-entry-point-seven.md) · [검증 기록](../plans/completed/0050-posture-entry-point-seven.md).

실제 화면 관찰에서 경계를 잠깐 넘은 뒤 중간 띠에서도 진입 시간이 계속 쌓이는 문제를 발견했다.
새 개발 판정은 알림 전에는 0.7배 초과가 연속되어야 하며, 이하로 내려오면 진입 시간을 초기화한다.
알림이 확정된 뒤에만 약0.47배 복귀 경계를 사용하고 복귀 중 다시 넘으면 복귀 시간을 재시작한다.

## 앞선 조정: 영상 v2와 더 좁은 자동 정상 선별 (2026-10-15)

새 측정의 몸 공통 이동 하한을 **45%→18% 등록 어깨폭**, 영상 어깨폭 축소 하한을 **20%→12%**로 조정했다.
당시 종합 경계는 1배였고, 현재 새 측정은 위 0.7배·연속 진입 규칙을 따른다. 3초 지속/복귀·200ms 평활화·기본 무음을 유지하며 이전 결과에는 임계값을 소급하지 않는다.
자동 수집은 기존 거리 선택(기본 6%)에 **종합 ≤0.5배 + 실측 룰 범위 안 + 연속 실측 1초**를 추가한다.
확인 중 프레임은 소급 저장하지 않으며 품질 누락·구간·등록/선택 변경은 시간을 초기화한다.
보존한 이전 자동 자료 613행은 재검토/학습 차단으로 표시했다. 새 선별 출처가 없는 보존 행이 섞인 export도 재검토 표시와 학습 차단을 적용한다.
이 조정은 개발 관찰을 반영한 설정이며 실제 기대기/눕기 정확도나 오탐률의 검증 결과가 아니다. 재학습·평가 전용 자료 사용은 하지 않았다.
[정책 ADR 0035](../decisions/0035-posture-and-clean-normal-selection.md) · [구현·검증 0049](../plans/completed/0049-posture-and-auto-selection-tuning.md).

## 이전 영상 v1: 정규화로 사라지는 큰 몸 변화 보완 (2026-10-15)

초기 영상 v1은 등록 당시 영상 위치·어깨폭을 고정해 얼굴/어깨 공통 이동과 어깨폭 축소를 별도로 계산했다. 현재 새 측정은 위 v2를 사용한다.
기존 상대 자세 점수와 몸 전체 변화 점수 중 큰 값을 **종합 이탈 점수**로 사용한다. >1 진입·≤2/3 복귀와 기존 3초 지속/복귀, 기본 음소거를 유지한다.
작은 흔들림은 등록 변동과 개발 하한, 200ms 시간 평활화로 허용한다. 개발 시작 하한은 공통 이동 0.45 등록 어깨폭과 축소 20%이며 실제 검증 임계값이 아니다.
몸 전체 이탈은 자동 정상 후보에서 제외한다. 기존 13점/39차원 LSTM·정상 프로파일과 학습 자료를 바꾸거나 재학습하지 않는다.
고정 카메라·올바른 시작 등록이 필요하며 카메라 이동·큰 회전과 실제 후방 각도를 구분하지 못한다. 가림은 측정 불가다.
[설계 ADR 0034](../decisions/0034-fixed-image-posture-anchor.md) · [구현·검증 0048](../plans/completed/0048-recline-posture-guard.md).
이 보완은 새로운 학습 모델의 효과 주장과 별개다. 앞선 실제 개인 LSTM/기본 Panoptic 비교는 [별도 측정](measurements/forecast-evaluation-2026-10-15.md)에 보존한다.

아래의 구현·검증 기록은 2026-10-14 연결 작업 당시 범위다.

## 역할을 먼저 구분한다

| 구성 | 배우거나 계산하는 것 | 사용자에게 의미하는 것 |
| --- | --- | --- |
| MediaPipe Full | 영상에서 얼굴·귀·어깨 13점 추출 | 실제 좌표 관측. 개발 화면 기본 추출기 |
| 개인 정상 범위 | 확인한 수동 구간의 9개 특징 중심·변동 폭 | 등록 후보가 본인이 확인한 범위 안인지, 현재 얼마나 벗어났는지 |
| 거리·시간 룰 | 등록 기준과의 거리 및 이탈 지속시간 | 비교군과 정상 프로파일이 없을 때의 기본 판단 |
| LSTM | 최근 30시점×39차원으로 0.3초 뒤 좌표 회귀 | 미래 이동·잔차를 비교하는 보조 신호. 정상/비정상 분류기가 아님 |

정상은 의학적 기준이 아니라 **사용자가 확인한 허용 자세 구간**이다. 예측 오차가 작아도 자세가 지속적으로 벗어날 수 있다. 정상 범위와 지속시간이 주 판단이며, LSTM을 복잡하다는 이유만으로 채택하지 않는다.

```text
카메라 → 실제 추출기 ID + 원본 13점 → 품질 통과 → 어깨 중심·폭 정규화
  ├─ 수동 30초 확인 → 개인 중심/허용 폭 고정 → 등록 후보 검증 → 범위 + 지속시간
  ├─ 등록 후 자동 선별 → 원본 JSON 다운로드 → 분할 검사 → LSTM 학습 → 수동 불러오기
  └─ 현재 관측 → 등록 기준 거리·시간 비교 / 미래 좌표 예측 비교

표시 전용 평활화는 별도 경로. 수집·학습·품질 판정에는 평활화 전 관측 사용.
```

## 정상 데이터 수집

| 구분 | 자동 | 수동 |
| --- | --- | --- |
| 라벨 | 정상자세(자동), 미검토 규칙 약라벨 | 정상자세(수동), 참여자가 확인한 구간 |
| 시작 | 실제 측정에서 기준 등록 뒤 자동 | 30초 측정하기 → 준비 3초 → 유효 30초 |
| 선별 | 기본 **6% 이하**, **0.5%·3%·6%** 선택 | 얼굴·양어깨가 유효하게 보인 시간과 최소 100표본 |
| 사용 | 초기 예측 학습 후보. 자동 개인 범위 fitting 없음 | 개인 등록용 범위 적용 또는 학습 자료용 다운로드 |
| 보관 | 메모리 후 명시적 다운로드 | 메모리 후 명시적 다운로드 |

자동 수집의 백분율은 현재 어깨폭을 100%로 본 등록 기준과의 3D 점 거리다. 얼굴 9점·귀 2점·어깨 2점의 그룹별 평균 거리를 같은 비중으로 합친다. 화면 픽셀·정상 확률·LSTM 오차·개인 범위 점수와 다르다.

- 기본 6%는 수집 가용성을 확인하기 위한 개발 선택이다. 정상 정확도를 검증한 수치가 아니다. 과거 0.5% 관찰에서 약 6분간 0행이었던 점을 계기로 선택지를 넓혔다.
- 조건을 유지하는 새 유효 관측마다 최대 10Hz로 한 행을 추가한다. 최대 6,000행에서 기존 행을 지우지 않고 멈춘다.
- 품질 실패, 범위 밖, 250ms 초과 단절, 일시정지, 기준·추출기·선별값 변경은 구간을 분리한다. 낮은 품질을 정상으로 저장하지 않는다.
- v2 파일은 각 행의 `maximumDeviation`과 선택 출처를 보존한다. 한 파일에 선별값이 다른 구간이 있어도 어떤 기준으로 모았는지 복원할 수 있다. 기존 v1의 0.5% 의미를 바꾸지 않는다.
- 화면은 총 행뿐 아니라 가장 긴 연속 구간, 연속 학습 후보, 범위·품질·시간 등 탈락 사유를 보여준다. 후보 창은 학습 완료 수나 정확도 수치가 아니다.
- 학습 창 하나에는 **100ms 간격 33시점, 약 3.2초의 연속 구간**이 필요하다. 입력 30시점의 마지막에서 300ms 뒤가 목표 시각이다. 오프라인은 그 시각 ±50ms 안의 실제 관측만 타깃으로 사용하므로 화면의 후보 창 수와 최종 창 수가 다를 수 있다. 떨어진 정상 행을 붙이지 않는다.

수동 수집은 30초 구간을 사용자가 확인해야 한다. `personal_calibration`은 개인 범위용, `training_normal`은 참여자 분할 학습용이다. 실제 영상·좌표·프로파일·가중치·익명 분할 목록은 Git에 넣지 않는다.

## 정상 자료로 등록 자세를 검증한다

확인한 정상 구간에서 얼굴 중심 xyz·귀 중심 xyz·어깨 방향 xyz, 총 9축의 중앙값과 허용 폭을 맞춘다.

```text
허용 폭 = max(개발 하한, 절대 중앙편차의 q95 × 1.5)
정상 범위 점수 = max(|후보 또는 현재 특징 − 학습한 중심| / 허용 폭)
```

얼굴·귀 6축의 하한은 0.12, 어깨 방향 3축은 0.10 어깨폭 단위다. 기존 개발 상수를 재사용하며 의학적 허용각이나 검증된 임계값은 아니다.

1. 기존 등록 시간·품질 조건으로 후보를 만든다. 최소 8초·실제 65표본 조건은 유지한다.
2. 프로파일과 실제 관측의 **알려진 추출기 ID가 정확히 같은지** 확인한다. Full·Heavy·Lite 또는 버전을 추측해 호환 처리하지 않는다.
3. 후보를 **학습한 중심**과 비교한다. 점수 **1 이하 통과**, **1 초과 거부**이며 가장 크게 벗어난 얼굴/귀/어깨와 축을 안내한다.
4. 범위로 돌아오면 등록을 다시 시도한다. 측정 중에도 학습 중심을 고정한다. 새 등록 자세로 중심을 덮어써서 구부정한 자세가 0점이 되는 경로를 제거했다.
5. 프로파일 없음은 정상 학습 검증 없음으로 안내하고 기존 룰 기준 등록을 사용한다. 출처 미상·불일치·손상·측정 불가는 학습 범위 검증 통과로 표시하지 않는다.

점수 1은 허용 폭의 경계이지 확률·건강 점수 100%가 아니다. 개인 범위 판단은 **1 초과에서 이탈**, **2/3 이하에서 복귀 확인**한다. 기존 비교용 거리 룰의 임계값은 별도다. 이탈 3초·복귀 3초·재알림 60초는 개발 시간 설정이다.

현재 정규화는 전체 이동과 크기 변화를 제거한다. 정면 카메라의 깊이 오차·가림·추적 흔들림과 상체 아래쪽 미관측은 남는다. 사용자가 확인한 정상 범위를 지킨다고 의학적으로 올바른 자세가 입증되지는 않는다.

## 수집 JSON을 LSTM으로 연결한다

자세한 설치·manifest·실행 예제는 [MediaPipe 학습 안내](mediapipe-training.md)를 따른다. `/dev` 수집 화면에도 수집→학습→불러오기 절차와 복사 가능한 명령을 둔다. 브라우저는 학습을 실행하거나 업로드하지 않는다.

```bash
# 저장소 루트의 학습용 Python 환경에서 실행. 내려받은 파일명에 맞춰 변경한다.
python -m model.analysis.mediapipe_lstm manifest --mode pilot \
  --output "$HOME/posture-private/manifest.json" \
  "$HOME/posture-private/normal-auto.json"

python -m model.analysis.mediapipe_lstm validate \
  --manifest "$HOME/posture-private/manifest.json" --mode pilot

python -m model.analysis.mediapipe_lstm train \
  --manifest "$HOME/posture-private/manifest.json" --mode pilot \
  --output "$HOME/posture-private/run-01" --epochs 25
```

- `manifest --mode pilot`은 명시한 파일의 실제 추출기·익명 참여자·hash를 읽어 한 사람의 train-only 목록을 새로 만든다. 모르는 추출기·모델 혼합·여러 참여자를 pilot으로 자동 배정하지 않고 기존 목록도 덮어쓰지 않는다.
- `validate`와 `prepare`는 자료·분할·연속 창을 검사하는 dry run이다. 학습 패키지 없이 실행한다.
- 실제 `train`은 별도 선택 환경 `model/analysis/requirements-lstm.txt`의 NumPy/PyTorch를 사용한다. 추출 GPU 가속과 별개의 CPU 학습 경로다. 새 브라우저 패키지는 없다.
- 입력: 확인한 수동 v1, 자동 v1/v2. manifest에 원본 파일 hash, 정확한 `poseModelId`, 익명 참여자 train/validation/test 소유권을 적는다.
- 원본 좌표로 정규화 값을 다시 계산해 저장된 값과 대조한다. 누락·역전·중복 시각, 서로 다른 모델, 수집/기준/구간/선별값 경계를 넘는 창을 거부하거나 분리한다.
- 창은 분할 후 생성한다. 100ms 격자, 입력 30시점, 미래 목표 300ms, stride 100ms다. 입력만 유효 양끝점 사이 **250ms 이하**를 보간한다. 타깃은 목표 시각 ±50ms 안에서 가장 가까운 실제 관측이며 보간하지 않는다. 실제 타깃이 없으면 창을 제외하고, 250~350ms의 실제 horizon과 시각 오프셋을 보고한다. 등속 비교군도 같은 실제 타깃 시각으로 평가한다. 라이브 예측 입력의 500ms 지연 허용을 학습 자료로 확대하지 않는다.
- 결과는 새 비공개 폴더의 `model.json`, `report.json`, `research-lstm.pt`다. 완료 모델을 덮어쓰거나 기존 브라우저 기본 모델을 자동 교체하지 않는다. 사용자가 설정에서 `model.json`을 선택한다.

### 좌표 계약은 정확히 일치시킨다

새 모델은 `forecast-weights-v2`, `data_domain: mediapipe`, `domain_validated: false`다. `pose_model_id`와 `feature_definition: mediapipe-world13-shoulder-normalized-xyz-v1`을 기록한다.

`point_definition`은 `MediaPipe-13-world-shoulder-normalized-v1`, 좌표 순서는 MediaPipe 원본 인덱스 **`[0,6,5,4,1,2,3,10,9,7,8,11,12]`**다. 어깨 중점과 3D 어깨폭으로 정규화한 xyz 총 39차원이며 브라우저의 `liveForecastPoints`와 같은 정의다. 새로운 실제 모델 ID와 연결할 때도 일치를 확인한다.

기존 `forecast-weights-v1` Panoptic 모델은 별도 레거시 비교 경로다. 점 정의·세계 좌표 축이 MediaPipe와 근사 대응이라는 한계를 유지한다. v2라는 파일 형식이나 정확한 좌표 대응만으로 실제 자세 판정 성능이 검증되는 것은 아니다.

## 한 사람 pilot과 참여자 분할 평가

| 모드 | 자료 배정과 학습 | 주장할 수 있는 범위 |
| --- | --- | --- |
| `pilot` | train만, validation/test는 비움. 본인의 개인 보정 자료도 사용할 수 있음 | 파일→창→학습→브라우저 연결 및 학습 자료 적합 확인 |
| `participant_holdout` 기본 | 세 분할 모두 필요. 참여자 중복 금지. 수동은 `training_normal`만 | 별도 참여자의 미래 좌표 예측 오차 비교. 자세 정확도·교정 효과와는 별개 |

변환기는 train 입력으로만 맞춘다. 표준 모드의 모델 선택은 validation에서 하고 test는 선택 뒤 평가한다. pilot은 독립 시험 성능으로 보고하지 않는다. 학습에 사용한 창의 오차를 새 사람 성능으로 쓰지 않는다.

자동 약라벨과 수동 확인 자료의 개수를 별도로 보고한다. 자동 정상 라벨을 평가 정답으로 재사용하지 않는다. 예측 오차는 LSTM·마지막 위치 유지·등속 예측을 같은 창에서 비교한다. 모델의 판정 이득을 보려면 별도 평가 구간에 `기준 유지 / 잠깐 이탈 후 복귀 / 지속 이탈 / 측정 불가`의 시작·끝을 표시해야 한다.

후속 A/B/C 비교는 고정 거리+시간, 개인 정상 범위+시간, 개인 정상 범위+시간+LSTM이다. 시간당 오알림, 이탈 놓침, 감지·복귀 지연, 유효 관측률, p95 지연/FPS를 보고한다. 시험 참여자의 이탈 자료를 학습·튜닝에 쓰지 않는다. [연구 프로토콜](../research/protocol.md).

## 실제로 확인한 것과 아직 확인하지 않은 것

- **이전 실제 속도 측정:** M1 Metal 경로에서 `/dev` Full+단축 대기는 20초 평균 23.5–27.2 FPS, 기존 Heavy+대기는 12.7 FPS였다. 일반 서비스는 Heavy/기존 대기를 유지한다. [전체 비교](camera-performance.md), [ADR 0031](../decisions/0031-developer-camera-performance.md).
- **이전 실제 동작 관찰:** 고개·상체 변화와 복귀에 알림이 반응했고, 0.5% 자동 선별은 약 6분 관찰에서 0행이었다. 한 사람의 단기 관찰로 정확도를 추정하지 않는다. [당시 감사](live-keypoint-audit.md)의 정상 등록·학습 연결 공백은 이번 변경으로 구현 보완했지만, 실제 데이터의 효과 검증은 남았다.
- **이전 Panoptic 학습 결과:** 학습에 사용한 동일 창에서 위치 유지 0.044814, LSTM 0.045511, 등속 0.064127 평균 점 거리/어깨폭이었다. 독립 시험이 아니며 LSTM이 위치 유지보다 약 1.55% 불리했다. [당시 기록](jisung/2026-10-13-mac-dev-lstm-training.md).
- **이번 변경:** Python 186개·프론트 645개 및 타입/빌드, 합성 2 epoch 학습과 브라우저 추론 동등성을 확인했다. 전체 게이트의 백엔드·서비스 브라우저 검증은 Java/Maven 부재, Compose는 Docker daemon 부재로 미완료다. 실제 참여자 자료·개인 정상 모델·실제 MediaPipe LSTM을 새로 수집/학습한 것으로 표시하지 않는다.
- **남은 한계:** 13점은 상체 아래를 관측하지 않고, 정규화는 전체 이동·크기 정보를 제거한다. 13/13 관측률은 깊이 정확도가 아니다. 의도적 스트레칭과 자세 붕괴의 의도를 모델이 학습한 상태도 아니다.

## 서비스 경계와 검증

모델·특징·개인화는 `model/prototype/`, 오프라인 학습은 `model/analysis/`, 개발 UI는 `frontend/src/features/developer/`에 둔다. 일반 서비스와 서버/CEP에 새 학습·등록 검증 흐름을 자동 적용하지 않는다.

낮은 품질과 250ms 초과 실제 관측 단절은 룰·알림·수집 연속성을 끊는다. 예측 입력만 이미 도착한 유효 양끝점 사이 최대 500ms를 보간하며, 보간값을 원본 수집이나 등록 실제 표본으로 세지 않는다. 표시 전용 평활화도 수집·판정과 분리한다. [시간 정책 ADR 0030](../decisions/0030-predictor-cadence-recovery.md).

최종 검증 수치와 환경 제약은 [작업 계획 0045](../plans/completed/0045-normal-reference-and-mediapipe-training.md)에서 갱신한다. 이전 성능 작업의 검증은 [완료 계획 0044](../plans/completed/0044-camera-performance-and-model-comparison.md)에 보존한다. 합성 검증 통과는 실제 카메라 정확도·음향·장시간 수집·새 참여자 성능을 대신하지 않는다.

서비스 승격은 **독립 참여자에서 판정 이득 확인 → 장치·카메라 환경 검증 → 서비스 계약·보관 정책 검토** 이후 별도로 결정한다.
