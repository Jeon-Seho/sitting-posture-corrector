# 품질 기준

본인 자세 오프라인 학습은 [개인 실험 규격](research/personal-pilot-training.md)을 따른다.
`tests/test_personal_training.py`의 명시적 합성 학습·회차 분리·holdout fitting 누수·품질/시간 경계 검증은 `make check`의 Python discovery에 포함된다.
개인 실험의 창별 수치를 새 참여자 성능·실생활 정확도·알림 효과로 보고하지 않는다.

## 현재 실행되는 게이트

| 게이트 | 명령 | 실패 조건 |
| --- | --- | --- |
| 저장소 지도 | `make check-repo` | 필수 파일 누락, 작업 지침 비대화 |
| 문서 연결 | `make check-repo` | 저장소 내 Markdown 링크 대상 누락·경로 이탈 |
| 산출물 분리 | `make check-repo` | 실제 데이터/가중치/환경 파일 후보가 Git에 포함됨 |
| 출력 계약·자료 준비 | `make test` | 스키마 오류, 합성 예제 불일치, 잘못된 입력 수용, 참여자 누수·hash/시각·시간 창 경계 오류 |
| 검사기 회귀 | `make test` | 깨진 링크·금지 산출물 검사가 실패함 |
| 프론트 프로토타입 | `make check-frontend` | 품질·상태 전이·알림 정책 테스트 실패, TypeScript 오류, 빌드 실패 |
| API·CEP 수직 흐름 | `make check-backend` | Java API/추론/Esper 경계·시간·통계·재시도/실패 테스트, 합성 Vite 프록시+3서비스 HTTP 계약, benchmark 소규모 요청·정리 실패 |
| 합성 브라우저 통합 | `make check-browser` | 실제 앱·서버의 측정/종료/복구·기록 일치, 확인창 키보드·초점/배경 차단 실패, 브라우저 오류 또는 시험 프로세스 정리 실패 |

| MySQL·Compose·계정 브라우저 | `make check-compose` | 실제 마이그레이션·인증/CSRF·소유권·원 요청 재시도·API/CEP 복구·삭제·백업 복원·내부 토큰/포트 격리·실제 계정 UI·시험 자원 정리 실패 |

CI는 `make check`를 실행한다. Docker/Compose도 필수다. `make check-local`은 영구 모드 게이트를 제외하므로 전체 성공으로 보고하지 않는다. 브랜치 보호와 필수 상태 체크 설정은 원격 저장소 관리에서 별도로 적용해야 한다.
현재 게이트는 앱 기능, 지연, 모델 성능, 전체 개인정보 탐지를 보증하지 않는다.
브라우저 게이트는 Chrome/Chromium의 독립 임시 프로필과 합성 카메라 입력을 사용한다. `make check`는 서버 JAR 준비 후 이를 실행하며
CI에도 같은 명령이 연결된다. 카메라 정확도·실제 음향·장시간 백그라운드는 별도 장치 확인 대상이다.
수집 바로가기·390/690/1440px 자세 선택·카메라 창 드래그/방향키/크기 변경과 실제 Document PiP는
명시적 `browser-smoke` 모드의 `synthetic=1&preview=1`에서 생성한 canvas 영상만 사용한다.
기존 기본 합성 모드는 영상 스트림 없이 특징만 사용한다. 두 모드 모두 getUserMedia 호출은 실패시킨다.
시험용 Chrome 종료 뒤 macOS 충돌 보고/업데이트 프로세스가 stderr를 상속해도 Node가 남지 않도록
종료한 Chrome의 진단 파이프를 닫고 Python이 시험 프로세스 그룹/포트를 확인한다.

Compose 계정 UI도 같은 입력 경계를 사용한다. 실제 Nginx/API/MySQL/추론/CEP와 연결하되
카메라 hook만 명시적 Vite serve 테스트 모드에서 합성으로 바꾼다. 최종 Nginx 생산 번들은 별도로 자산/합성 코드 부재를 검사한다.
문서 링크 검사는 인라인 링크의 로컬 파일/디렉터리 경로에 한정하며, 앵커·참조형 링크·외부 URL 가용성은 검사하지 않는다.

자료 준비는 명시적 합성 CSV와 CLI로 분할 소유권·기준 등록 분리·실제 시각/제외 경계를 확인한다.
실제 참여자 자료의 품질·모델 정확도나 최종 창/라벨 정책을 검증한 것은 아니다.
서버 benchmark 게이트는 경로별 warmup 1개·측정 4개·동시 worker 2개로 계약과 실패/정리를 확인하며 지연 임계값은 두지 않는다.
별도 측정과 해석은 [benchmark 안내](audits/2026-10-01-server-benchmark.md)를 따른다.

## 제품 구현 시 추가할 수용 기준

- 측정 불가·등록 전·카메라 재연결이 정상/이탈 결과로 오인되지 않는다.
- 일시적 동작, 지속적 이탈, 프레임 누락, 재등록의 합성 시퀀스를 재생해 알림 상태 전이를 확인한다.
- 시간 계산은 프레임 수 대신 타임스탬프를 사용하며 역전·간격 급증을 처리한다.
- 추론 계약의 생산자와 소비자가 동일한 합성 fixture로 통합 검증을 통과한다.
- 실시간 10 FPS 목표와 p95 지연을 장치·해상도·추론 환경과 함께 측정한다.
- 연구 지표와 분할 검증은 [연구 프로토콜](research/protocol.md)을 따른다.

수치 목표와 실패 허용치는 프로토타입 후 고정한다. 아직 측정되지 않은 목표를 통과한 것으로 기록하지 않는다.

## 결과 보고

작업 완료 시 `make check` 실행 여부, Python/프론트 테스트 수, 타입/빌드 결과,
별도 브라우저 검증과 남은 미검증 사항을 명시한다. CI 설정이 존재하는 것과 원격 CI 실행은 구분한다.
서비스 변경에는 Java 테스트 수와 실제 HTTP 흐름 결과도 명시한다. 기본 메모리 HTTP 검증은 외부 DB·계정·카메라·학습 모델을 사용하지 않는다. Compose 검증은 임시 MySQL과 합성 계정을 실제로 사용하며 실제 카메라나 운영 DB에는 접근하지 않는다.

## Mac 신뢰성 회귀

`make check`의 프론트 게이트에 합성 저장소/카메라/세션·앱·Web Locks 테스트가 포함된다.
손상 원본 보존, 용량/접근 실패, 중단 복구·종료 누적 보존, 재시도 ID/시각 고정, 타 세션 draft 보호,
취소 후 늦게 도착한 스트림/모델 해제, 연속 보정과 취소, GPU→CPU fallback, StrictMode 잠금 생명주기,
develop 준비/기록 비교/확인 창 유지가 회귀 기준이다. 실제 카메라나 개인 자료를 fixture로 사용하지 않는다.
현재 결과와 브라우저 접근 제한은 [점검 기록](audits/2026-09-30-mac-develop.md)을 따른다.

서버 모드의 합성 게이트에는 공유 TS/Python 23사례, 원래 요청 본문 재시도, 응답/중간 기록 검증,
생성 중 종료·종료 응답 대기, 복구 404, 고정 기준·장치 변경, 큐/저장 실패·공백 제외,
원래 서버 사건/통계 보존과 미확인 종료 요약 보관이 포함된다. 원격 CI 실행과 실제 카메라 검증은 별도다.
