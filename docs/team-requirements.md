# 서비스 요구사항 — 팀 공유용

기획 기준: 2026-09-28 / 단일 앱. 구현 현황 갱신: 2026-10-01 / 서버 연결·회귀·개발/연구 도구 보완. 시간 정책 재확인: 2026-10-01.

이 문서 하나로 기능 범위, 역할, 완료 조건, 미결정 사항을 확인한다. 대화에서 선택한 최신 요구를 통합했으며 과거 대안은 제외했다. '확정'은 제품 요구 합의이고 구현 완료나 팀 전체 기술 합의를 뜻하지 않는다. 로컬 서비스 미리보기를 추가했다. 아래 요구의 합의와 실제 구현 완료는 별개다.

## 1. 목적과 현재 기반

사용자가 등록한 개인 기준에서 자세가 지속적으로 벗어날 때 알려주고, 측정 기록을 확인하는 서비스다. 자세의 의학적 정확성·건강상 적합성·통증 개선을 판정하지 않는다.

현재 구현은 React/TypeScript + 실제 웹캠 + MediaPipe Lite + 개인 기준 비교 규칙이며, 연구 화면과 서비스 미리보기를 합친 단일 앱이다([ADR 0008](decisions/0008-single-app-entry.md)). 학습된 LSTM은 미연결이다. Compose는 사용자 선택한 MySQL·이메일/비밀번호·영구 기록/복구를 사용한다. 홈·대시보드는 설정의 `발표용 예시 기록 표시`(새 저장소 기본 꺼짐; 기존 선택 유지)로 발표용 예시 데이터와 로컬 저장 결과를 전환한다. 현재 5초 기준 수집 및 점수 방향을 기반으로 진행하며, 이전에 제안했던 별도 3초 보정을 추가 필수로 강제하지 않는다.

실제 카메라·기준 비교·연구용 좌표 수집은 재사용한다. 연구용 라벨 수집은 일반 사용자 자세 등록 및 서비스 기록과 구분한다. 예시 사진을 저장했다는 이유만으로 개인화 모델이 학습되거나 판정이 엄격해졌다고 표시하지 않는다.

## 2. 담당 역할

### 로그인·회원가입 FE 미리보기 (2026-09-29, GP-0045·GP-0047)

- 첫 화면은 아이디·비밀번호 로그인이다. 입력값이 있으면 실제 계정 조회 없이 홈으로 진입한다.
- 로그인 아래에 카카오·페이스북·네이버 버튼을 세로로 배치하고, 그 아래 회원가입은 옅은 텍스트 링크로 제공한다. 소셜 버튼은 연결 준비 안내만 표시한다.
- 회원가입은 아이디·비밀번호·비밀번호 확인·이름·나이·직업을 입력하고 측정 준비로 이동한다. 비밀번호 일치와 필수 필드·나이 범위를 검사한다.
- 인증 정보는 저장·전송하지 않는다. 가입 프로필은 현재 화면 세션에서만 유지한다. 기존 프로필 설정의 브라우저 저장 기능과 측정 기록은 그대로이며 사용자별 계정 격리는 아직 없다.
- 실제 가입·로그인·소셜 인증과 API 실패/진행 상태는 GP-0046·GP-0048 및 백엔드 카드에서 이어간다. 이 UI를 실제 인증 완료로 해석하지 않는다.
- 검증: 프론트 40개 테스트, 타입 검사·빌드 통과. 합성 입력으로 Edge에서 로그인/로그아웃, 회원가입, 비밀번호 불일치, 소셜 3개 안내, 자격증명 미저장 및 모바일 가로 넘침 없음을 확인했다.

담당자의 이름은 팀에서 지정한다. 디렉터리는 책임 경계이며 실행 위치를 강제하지 않는다.

| 역할 | 담당 | 중복 구현하지 않을 것 |
| --- | --- | --- |
| 디자인·FE | 화면, 입력 검증·안내, 카메라 권한·영상 준비, 화면 이동, 측정 조작, 알림 전달, 서버 응답의 화면 변환 | 자체적인 자세 정답 판정, 서버 저장 성공 추정 |
| 모델/분석 | 측정 품질, 개인 기준 비교, 예시 활용, 상태·유형·특징값·점수 정의, 관측 중단 기준 | 사용자 계정·DB 관리 |
| BE | 인증·프로필·설정, 세션 식별 및 저장, 중복 요청 처리, 중간 저장·복구 API, 요약 제공 | 모델 분류 로직의 별도 복제 |
| DB/데이터 담당 | 자료 구조, 기준·설정 버전, 기록 보존·삭제, 학습 동의 데이터 범위 | 임의의 동의·보관 정책 확정 |
| 공동 | 통계 정의, 계약 필드·단위, 상태별 책임, 실패·복구 검증, 실제 브라우저 검증 | FE·BE가 같은 규칙을 다르게 계산 |

현재 프로토타입은 FE의 공통 엔진이 지속시간·알림 정책을 실행한다. 실제 서비스에서 계산 위치를 바꾸려면 책임을 한곳으로 합의한다. 서버로 반드시 옮긴다고 가정하지 않는다.

## 3. 기본 이용 흐름

1. 가입 시 이름·나이·직업을 입력하고 로그인한다. 계정 식별 방식은 인증 담당과 합의한다. 고정 데모 계정은 발표 옵션일 뿐 실제 계정 요구를 대체하지 않는다.
2. 로그인 성공 후 공통 카메라 준비를 시작한다. 사용 목적을 로그인 화면에서 알린다.
3. 개인 기준 미등록자는 등록 안내, 등록자는 바로 홈으로 이동한다. 카메라 준비를 기다리느라 홈 이동을 막지 않는다.
4. 개인 기준 자세와 잘못된 자세 예시를 촬영·확인하고 완료하면 홈으로 이동한다. 실제 예시 활용 방식은 협의 항목이다.
5. 홈의 측정 시작 → 준비 확인 → 얼굴·어깨가 보이면 기준 자동 등록(3초) → 측정 자동 시작 → 실시간 측정(기록·설정 화면으로 이동해도 계속).
6. 측정 종료 → 이번 결과 표시·저장 → 저장 성공 후 홈·대시보드 최신 결과 반영.
7. 프로필 수정, 기준 재등록, 개인 판정 설정, 탈퇴를 각각 별도 기능으로 제공한다.

별도 알림 벨·알림함·읽음 처리는 제외한다. 저장 실패·계정 처리 결과는 해당 화면에서 안내한다. 홈의 기존 목표·연속 기록·별도 종합 점수는 보류하며 현재 브랜치의 통계 구성을 우선한다.

프로필 정보 수정만으로 자세 기준·과거 측정 기록을 삭제하지 않는다. 새 기준은 다음 측정부터 적용하는 방안을 사용하며 기준 변경 전후 비교에는 변경 사실을 드러낸다.

## 5. 중단·복구 규칙

| 상황 | 동작 | 완료 조건 |
| --- | --- | --- |
| 사이트 내부 화면 이동 | 일시정지하고 기록 보존. 복귀 후 사용자가 측정 재개 클릭 | 페이지 해제로 세션을 잃거나 새 세션을 중복 생성하지 않음 |
| 크롬의 다른 탭으로 이동 | 탭 전환 자체만으로 정지하지 않음 | 실제 관측 지속 여부를 검증. 숨김 이벤트 삭제만으로 완료 처리하지 않음 |
| 실제 카메라 입력 단절 | 일시정지. 입력이 복구돼도 수동 재개 | 준비되지 않은 사용자 상태를 자동으로 집계하지 않음 |
| 새로고침·창 닫기 후 복귀 | 저장 지점까지 복구, 이어하기/종료하기 선택 | 보존하지 못한 시간을 복구했다고 표시하지 않음 |
| 종료 결과 저장 실패 | 결과 보존, 자동 재시도 + 수동 재시도 | 같은 세션의 중복 저장 방지, 저장 성공 전 완료 표시 금지 |

일시정지·관측 공백은 유효 시간과 유지율 분모에서 제외하고 연속 이탈 타이머로 합산하지 않는다. 저장 자동 재시도와 측정 자동 재개는 별개이며 후자는 허용하지 않는다. 연구용 라벨 수집의 숨김·중단·제외 규칙은 서비스 측정 변경으로 자동 변경하지 않는다.

시간 정책은 [ADR 0012](decisions/0012-session-timing-policy.md)로 확정했다.
유효한 연속 이탈 3초에 첫 알림, 열린 사건에서 유효한 정상 상태 2초에 복귀,
같은 사건의 마지막 알림 후 60초에 재알림을 결정한다. 휴식·자리 비움·측정 불가·누락은
열린 사건을 중단하고 연속 이탈·복귀 누적을 초기화한다. 제외 시간은 유효 통계에 넣지 않으며
중단을 복귀로 세지 않는다. 이후 새 사건은 다시 지속시간을 채워야 하며 이전 사건의 재알림 간격을 적용하지 않는다.

## 6. 통계 갱신과 데이터 계약

- 최초 접속·새로고침에 조회하고, 보통의 화면 이동은 공유 데이터를 재사용한다.
- 종료 결과는 즉시 표시하되 저장 상태를 구분한다. 저장 성공 응답으로 최신 요약을 갱신하거나, 응답에 요약이 없으면 한 번 추가 조회한다.
- 저장 성공 후 화면을 다시 열지 않아도 홈·대시보드 데이터가 갱신돼야 한다. 요약 조회만 실패했다면 저장 실패와 구분해 해당 조회만 재시도한다.
- 날짜 변경·주기 자동 조회는 추가하지 않는다. 조회 기준 날짜를 표시한다. 자정 통과 세션 분할·날짜별 집계는 별도로 정의한다.
- 현재 유효 시간 = 전체 − 일시정지 − 측정 불가. 유지율 = 기준 유지 시간 / 유효 시간. 유효 시간이 0이면 계산 불가로 표시한다. 여러 세션 비율은 시간으로 가중 집계한다.
- 40건 등 화면 목록 제한이 전체 누적 통계를 잘라내면 안 된다. 반복 알림 수와 사건 수를 구분한다.
- 현재 내부 변화 점수는 높을수록 이탈, 화면 자세 점수는 100 × (1 − 변화 점수)다. 화면의 알림 기준 점수를 높이면 더 민감하다. 병철 씨의 5초·30초 선택은 개인 설정 예시이며 전체 기본값 변경이 아니다.
- API 경로·DB 테이블·서버 필드명을 이 문서에서 임의 확정하지 않는다. 현재 계약 단위를 우선하고 화면 경계에서 명시적으로 변환한다.

필수 협의 데이터: 사용자 ID·프로필·등록 상태 / 기준 ID·버전·사용 가능 상태 / 현재 상태·유형·특징 단위·품질 / 세션 ID·시각·유효/제외 시간·사건 / 저장 및 복구 상태 / 날짜·시간대·요약 / 적용 설정 및 학습 동의.

단일 진입 앱이다. 주황 표지 로그인에서 이름·나이·직업을 입력하면 들어가며, 사이드바는 홈 / 측정 준비(하위: 실시간 측정) / 자세 등록 / 대시보드 / 설정(하위: 프로필 설정)이다. 하위 탭은 관련 화면에 있을 때만 연하게 나타난다. 기존 연구 화면(`?research=1`)과 그 전용 로그인은 없앴다. 홈·대시보드는 설정의 '발표용 예시 기록 표시'(새 저장소 기본 꺼짐; 기존 선택 유지)로 예시 데이터와 실제 로컬 기록을 전환한다. 실제 인증을 대신하지 않으며, 프로필과 요약은 현재 브라우저에만 저장한다.

구현됨: 내부 화면 이동 시 측정 보존·수동 재개, 입력 공백 시 정지, 로컬 중간 저장·복구, 종료 저장·중복 방지·재시도, 공유 기록 갱신, 실제 기록 보기에서 시연/웹캠 기록 합산(계정 구분 전 임시), 3초 토스트와 선택적 소리, 프로필 편집(사이드바 하위 탭), 로컬 자료 삭제 체험, 사용자용 문구의 자세 등록(좌표 CSV 수집) 화면, 측정 준비에서만 켜는 카메라. 검출 신뢰도 표시, 우측 하단 프로필 버튼, 우측 상단 카메라 상태 표시줄은 제거했다.

검증(단일 앱 통합 시점): 프론트 29개 테스트, 타입 검사, 빌드 통과. 앱 내장 브라우저에서 로그인 → 홈(예시/실제 전환) → 측정 준비·하위 탭 → 자세 등록 → 대시보드 → 설정·프로필 설정 이동을 확인했다. Python 계약 테스트와 `make check` 전체는 이번에 다시 실행하지 않았다. 실제 웹캠 촬영·측정, 소리, 장시간 백그라운드는 미검증이다.

검증(로직 통합, 2026-09-28): Windows에서 `python tools/dev.py check`로 저장소 검사, Python·프론트 테스트, 타입/빌드를 실행했다([ADR 0009](decisions/0009-cross-platform-dev-entry.md)). 헤드리스 Edge와 가짜 카메라로 서비스 흐름과 합성 더미 기록 집계를 검증했고, 결과와 남은 항목은 [계획 0009](plans/completed/0009-service-logic-integration.md)에 기록했다. 실제 웹캠 판정·소리·장시간 백그라운드는 미검증이다.

## 11. Mac develop 보완 (2026-09-30)

[전체 기획 대비 점검](audits/2026-09-30-mac-develop.md)에 기능 32개·비기능 14개·시간 16개별 완료/남은 범위와 검증 근거를 기록했다. 9월 28일 시트/CSV는 검토 원본으로 유지하며 팀 의견 칸을 덮어쓰지 않았다.

새 저장소에서는 발표 예시를 끈 채 시작한다. 로컬 기록은 develop의 합산을 기본으로 유지하며 종류 필터와 오늘/최근 7일/최근 30일/전체 조회를 제공한다. 기록 있는 날짜만 시간 가중 집계하고, 처음/최근 비교는 선택한 종류의 전체 기록에 적용한다. 서비스에서 실제/합성의 기본 분리 여부와 조건이 다른 기록의 비교 정책은 협의 항목이다.

로컬 저장은 JSON뿐 아니라 프로필·설정·시간·사건·전체 Machine을 검증한다. 손상 원본을 보존하고 변경을 차단하며, 같은 origin에서 변경 가능한 탭은 하나다. 복구는 마지막 저장 시각까지이며 수동 재개한다. 최종 결과 저장과 draft 정리 실패를 구분하고 재시도 시 ID/종료시각을 유지한다. 종료 기록에는 적용 규칙을 보관하여 설정 변경 전 결과를 다시 해석하지 않는다. 기준 재등록은 연결 내 원자적 교체이며 영구 기준/예시 개인화까지 완성한 것은 아니다.

## 12. API·CEP 개발 흐름 (2026-09-30)

사용자 승인으로 [API·Esper CEP·FastAPI 책임](decisions/0011-api-cep-boundary.md)을 분리했다.
API는 입력·저장·조회, CEP는 붕괴·회복·재알림 시간 조건, FastAPI는 현재 추론 점수만 담당한다.
기본 붕괴 지속 3초·정상 복귀 2초·같은 사건 재알림 60초와 커스텀 값의 다음 새 세션 적용을 확정했다([ADR 0012](decisions/0012-session-timing-policy.md), 2026-10-01 사용자 재확인).
붕괴 주기는 같은 세션 안의 유효 관측 시간으로 계산하며 휴식·자리 비움·측정 불가·누락을 제외한다.
휴식 이후에는 열린 사건을 중단하고 연속 판정 누적을 초기화하여 새로 시작한다. 자리 비움·측정 불가·누락도 같은 방식으로 판정을 끊는다. 기존 `legacy-interrupt-v1` 식별자는 호환성을 위해 유지하며 현재는 확정 정책이다.
현재 서버 저장은 메모리이며 학습 모델·외부 DB·인증은 연결하지 않았다. 선택형 개발 서버 입력 연결은 아래 13절을 따른다.
계약·동작·검증·다음 스택 의존성은 [서비스 안내](../backend/README.md)를 따른다.

## 13. 개발용 프론트 서버 연결 (2026-10-01)

사용자가 DB·로그인 환경이 없다고 확인하여 기존 스택으로 서버 연결부터 진행했다.
측정 준비에서 서버 판정을 선택하면 고정 시작 기준 대비 세 특징 변화량/품질만 전송하며 영상·원본 좌표는 보내지 않는다.
API가 Python 규칙 추론과 CEP를 조율하고 프론트는 서버 사건·통계를 표시한다. 시간 판정을 중복 실행하지 않는다.
입력 계약·관측 근사와 검증 전 임계값은 [ADR 0013](decisions/0013-frontend-server-feature-connection.md)에 기록했다.

순차 송신·같은 요청 재시도·저장 실패 시 중단·수동 재개·종료 응답 확인을 구현했다.
새로고침 시 원래 기준·장치·영상 크기를 보존하고 서버 기록을 조회한다. 서버 유실 시 같은 ID로 새 세션을 만들지 않는다.
확인된 요약만 보관하는 선택은 서버 종료 미확인으로 표시하며 미확정 시간을 유효 통계에 넣지 않는다.
완료 기록에는 원래 서버 사건·통계와 모델/기준 ID를 보관한다. 기준/미확인 특징 본문은 중간 기록에서만 임시 보관한다.

서버는 메모리·세션당 최대 10,000개 관측의 개발 흐름이며 인증·영구 저장·다른 기기 복구를 제공하지 않는다.
[DB·인증 연결 설계](design/server-persistence-and-auth.md)는 작성했으며 제품/로그인 방식 선택과 실제 연동은 남는다.
실제 카메라 정확도·장시간 백그라운드·지연/FPS·학습 모델 성능은 합성 검증과 구분한다.
현재 구현과 전체 게이트·브라우저 점검의 근거는 [서버 연결 완료 기록](plans/completed/0014-frontend-server-connection.md)에 남겼다.

## 14. 기록 상세와 비교 조건 보완 (2026-10-01)

기록별 상세에서 실제 적용 설정·유효/제외 시간·알림과 사건을 확인한다. 서버 기록은 원래 사건의 좌우 방향,
복귀·중단 사유와 제외 시간 구성을 표시한다. 서버 종료 미확인 자료는 마지막 확인 요약과 요약 보관 시각을 표시하고
이후 복귀·종료 여부를 추정하지 않는다. 오래된 로컬 기록의 기준·모델·설정·제외 구성은 없는 자료로 안내한다.

처음/최근 비교에는 실제 두 구간에 포함된 기록의 판정 출처·적용 설정·모델·개인 기준 정보를 함께 표시한다.
조건 차이와 확인 불가 항목을 안내하며 기존 합산과 7일/30분 임시 기준은 유지한다. 조건별 그룹 비교나 자동 제외는
별도 협의 항목이다. 서버 전체 HTTP 장애/재알림과 합성 브라우저 전체 흐름 검증을 저장소 게이트로 보완한다.
범위와 실행 결과는 [완료 기록](plans/completed/0015-server-regression-and-record-details.md)에 기록했다.

## 15. 확인창·측정/자료 준비 도구 (2026-10-01)

탈퇴와 서버 종료 미확인 요약 보관은 공통 확인창을 사용한다. 초기 초점은 취소에 두고 키보드로 두 선택 사이를
이동한다. Esc·배경 클릭으로 취소하면 자료를 유지하고 열기 버튼으로 초점을 복귀한다. 확인 중 중복 실행을 막고
실패하면 오류를 표시한다. 확인 후 버튼이 사라지면 갱신된 화면의 주영역으로 초점을 이동한다.

합성 HTTP 성능 측정 도구는 추론 단독과 API→추론→CEP 응답 지연·처리량·실패를 구분한다.
실행 조건과 소스/JAR/입력 hash를 보관하며 성능 합격 기준을 임의로 정하지 않는다.
[현재 기기 측정 결과](audits/2026-10-01-server-benchmark.md)는 실제 카메라/FPS·배포 성능과 구분한다.
CEP는 서비스 시작 단계에서 준비하며 준비 자체로 사용자 세션이나 통계를 만들지 않는다.

[자료 준비 도구](research/dataset-preparation.md)는 참여자 단위 분할을 먼저 적용하고 품질·누락·라벨·기준 경계에서
시간 창을 분리한다. 기준 등록은 평가 창에서 제외하고 시험 참여자의 자료를 fit/tuning에 쓰지 않는다.
창 길이·stride·라벨·분할 설정은 명시적으로 받는다. 합성 예제의 설정은 최종 연구 합의가 아니며
실제 자료 수집·모델 학습·에피소드 평가와 기준의 유도 과정 검증은 남는다.

전체 `make check`로 Python 93개·프론트 189개·Java 53개, 타입·Vite/JAR 빌드, 실제 HTTP와 실제 Chrome 합성 회귀
61개를 통과했다. [완료 범위와 한계](plans/completed/0016-remaining-tools-and-validation.md)를 따른다.

## 14. MySQL 계정·Compose와 배포 설정 (2026-10-01)

사용자가 MySQL + 이메일/비밀번호를 선택했다. Compose의 서버 계정 모드에 프로필·설정·기록 저장,
소유권/CSRF·비밀번호 변경·탈퇴, 내구 관측/outbox·API/CEP 재시작 재생·삭제를 구현한다.
기존 로컬/메모리 동작은 개발 모드 이력으로 유지한다. 위 12/13절의 미연결 표기는 당시 상태다.
[계정 API](../contracts/accounts.v1.md), [MySQL 결정](decisions/0014-mysql-persistence-and-accounts.md),
[Compose 실행·배포](../infra/README.md), [플랫폼 담당 작업](design/data-platform-boundary.md)을 기준으로 한다.

배포 서버는 미정이다. Actions 검증→불변 이미지 게시→production SSH 배포 설정까지 준비하고 실제 외부 배포는 하지 않는다.
자료 보관/백업 만료·연구 동의·이메일 확인/비밀번호 분실 복구·기기 간 활성 측정 복구는 후속 요구로 남는다.
최신 검증 결과는 [계획 0017](plans/completed/0017-mysql-accounts-compose-deployment.md)에 기록한다.

## 16. 팀 기능별 작업 카드 (2026-09-29)

계정(회원가입·로그인·정보 관리·탈퇴), 기준 자세 촬영, 실시간 자세 촬영·탐지, 탐지 경고, 누적 통계 대시보드, 설정 관리의 흐름으로 구현한다.
프론트는 화면/기능을 구분한16개, 백엔드는 API9개로 [팀 기능 카드 대응표](areas/devops/team-feature-cards.md)에 명시했다. 반복 제안된 설정 관리 API는 하나다.
실제 서버 인증·저장과 기존 로컬 프로토타입의 완료를 구분한다. 키포인트 수집·판단 API의 전송/보관/추론 책임은 기존 아키텍처·동의 계약을 확정한 후 구현한다.
