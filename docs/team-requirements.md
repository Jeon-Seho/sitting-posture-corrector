# 서비스 요구사항 — 팀 공유용

기준: 2026-09-28 / feature/retro-redisgnV2 (기반 검토 커밋 e35d8b1)

이 문서 하나로 기능 범위, 역할, 완료 조건, 미결정 사항을 확인한다. 대화에서 선택한 최신 요구를 통합했으며 과거 대안은 제외했다. '확정'은 제품 요구 합의이고 구현 완료나 팀 전체 기술 합의를 뜻하지 않는다. 로컬 서비스 미리보기를 추가했다. 아래 요구의 합의와 실제 구현 완료는 별개다.

## 1. 목적과 현재 기반

사용자가 등록한 개인 기준에서 자세가 지속적으로 벗어날 때 알려주고, 측정 기록을 확인하는 서비스다. 자세의 의학적 정확성·건강상 적합성·통증 개선을 판정하지 않는다.

현재 구현은 React/TypeScript + 실제 웹캠 + MediaPipe Lite + 개인 기준 비교 규칙이다. 브랜치명은 heavy지만 최신 자산은 Lite다. 학습된 LSTM, 실제 인증, 서버 기록 저장은 미연결이고 기존 연구 화면의 홈·대시보드는 예시 데이터이며 새 서비스 미리보기는 로컬 저장 결과를 사용한다. 현재 5초 기준 수집 및 점수 방향을 기반으로 진행하며, 이전에 제안했던 별도 3초 보정을 추가 필수로 강제하지 않는다.

실제 카메라·기준 비교·연구용 좌표 수집은 재사용한다. 연구용 라벨 수집은 일반 사용자 자세 등록 및 서비스 기록과 구분한다. 예시 사진을 저장했다는 이유만으로 개인화 모델이 학습되거나 판정이 엄격해졌다고 표시하지 않는다.

## 2. 담당 역할

담당자의 이름은 팀에서 지정한다. 디렉터리는 책임 경계이며 실행 위치를 강제하지 않는다.

| 역할 | 담당 | 중복 구현하지 않을 것 |
| --- | --- | --- |
| 디자인·FE | 화면, 입력 검증·안내, 카메라 권한·영상 준비, 화면 이동, 측정 조작, 알림 전달, 서버 응답의 화면 변환 | 자체적인 자세 정답 판정, 서버 저장 성공 추정 |
| 모델/분석 | 측정 품질, 개인 기준 비교, 예시 활용, 상태·유형·특징값·점수 정의, 관측 중단 기준 | 사용자 계정·DB 관리 |
| BE | 인증·프로필·설정, 세션 식별 및 저장, 중복 요청 처리, 중간 저장·복구 API, 요약 제공 | 모델 분류 로직의 별도 복제 |
| DB/데이터 담당 | 자료 구조, 기준·설정 버전, 기록 보존·삭제, 학습 동의 데이터 범위 | 임의의 동의·보관 정책 확정 |
| 공동 | 통계 정의, 계약 필드·단위, 상태별 책임, 실패·복구 검증, 실제 브라우저 검증 | FE·BE가 같은 규칙을 다르게 계산 |

현재 프로토타입은 FE의 공통 엔진이 지속시간·알림 정책을 실행한다. 실제 서비스에서 계산 위치를 바꾸려면 책임을 한곳으로 합의한다. 서버로 반드시 옮긴다고 가정하지 않는다.

## 3. 기본 이용 흐름

1. 가입 시 이름·나이·직업을 입력하고 로그인한다. 계정 식별 방식은 인증 담당과 합의한다. 고정 데모 계정은 발표 옵션일 뿐 실제 계정 요구를 대체하지 않는다.
2. 로그인 성공 후 공통 카메라 준비를 시작한다. 사용 목적을 로그인 화면에서 알린다.
3. 개인 기준 미등록자는 등록 안내, 등록자는 바로 홈으로 이동한다. 카메라 준비를 기다리느라 홈 이동을 막지 않는다.
4. 개인 기준 자세와 잘못된 자세 예시를 촬영·확인하고 완료하면 홈으로 이동한다. 실제 예시 활용 방식은 협의 항목이다.
5. 홈의 측정 시작 → 준비 확인·현재 기반의 기준 등록/보정 → 측정 시작 클릭 → 실시간 측정.
6. 측정 종료 → 이번 결과 표시·저장 → 저장 성공 후 홈·대시보드 최신 결과 반영.
7. 프로필 수정, 기준 재등록, 개인 판정 설정, 탈퇴를 각각 별도 기능으로 제공한다.

## 5. 중단·복구 규칙

| 상황 | 동작 | 완료 조건 |
| --- | --- | --- |
| 사이트 내부 화면 이동 | 일시정지하고 기록 보존. 복귀 후 사용자가 측정 재개 클릭 | 페이지 해제로 세션을 잃거나 새 세션을 중복 생성하지 않음 |
| 크롬의 다른 탭으로 이동 | 탭 전환 자체만으로 정지하지 않음 | 실제 관측 지속 여부를 검증. 숨김 이벤트 삭제만으로 완료 처리하지 않음 |
| 실제 카메라 입력 단절 | 일시정지. 입력이 복구돼도 수동 재개 | 준비되지 않은 사용자 상태를 자동으로 집계하지 않음 |
| 새로고침·창 닫기 후 복귀 | 저장 지점까지 복구, 이어하기/종료하기 선택 | 보존하지 못한 시간을 복구했다고 표시하지 않음 |
| 종료 결과 저장 실패 | 결과 보존, 자동 재시도 + 수동 재시도 | 같은 세션의 중복 저장 방지, 저장 성공 전 완료 표시 금지 |

일시정지·관측 공백은 유효 시간과 유지율 분모에서 제외하고 연속 이탈 타이머로 합산하지 않는다. 저장 자동 재시도와 측정 자동 재개는 별개이며 후자는 허용하지 않는다. 연구용 라벨 수집의 숨김·중단·제외 규칙은 서비스 측정 변경으로 자동 변경하지 않는다.

## 6. 통계 갱신과 데이터 계약

- 최초 접속·새로고침에 조회하고, 보통의 화면 이동은 공유 데이터를 재사용한다.
- 종료 결과는 즉시 표시하되 저장 상태를 구분한다. 저장 성공 응답으로 최신 요약을 갱신하거나, 응답에 요약이 없으면 한 번 추가 조회한다.
- 저장 성공 후 화면을 다시 열지 않아도 홈·대시보드 데이터가 갱신돼야 한다. 요약 조회만 실패했다면 저장 실패와 구분해 해당 조회만 재시도한다.
- 날짜 변경·주기 자동 조회는 추가하지 않는다. 조회 기준 날짜를 표시한다. 자정 통과 세션 분할·날짜별 집계는 별도로 정의한다.
- 현재 유효 시간 = 전체 − 일시정지 − 측정 불가. 유지율 = 기준 유지 시간 / 유효 시간. 유효 시간이 0이면 계산 불가로 표시한다. 여러 세션 비율은 시간으로 가중 집계한다.
- 40건 등 화면 목록 제한이 전체 누적 통계를 잘라내면 안 된다. 반복 알림 수와 사건 수를 구분한다.
- 현재 내부 변화 점수는 높을수록 이탈, 화면 자세 점수는 100 × (1 − 변화 점수)다. 화면의 알림 기준 점수를 높이면 더 민감하다. 병철 씨의 5초·30초 선택은 개인 설정 예시이며 전체 기본값 변경이 아니다.
- API 경로·DB 테이블·서버 필드명을 이 문서에서 임의 확정하지 않는다. 현재 계약 단위를 우선하고 화면 경계에서 명시적으로 변환한다.

필수 협의 데이터: 사용자 ID·프로필·등록 상태 / 기준 ID·버전·사용 가능 상태 / 현재 상태·유형·특징 단위·품질 / 세션 ID·시각·유효/제외 시간·사건 / 저장 및 복구 상태 / 날짜·시간대·요약 / 적용 설정 및 학습 동의.

## 8. 착수와 완료 판단

FE 화면·공통 상태·흐름 구현은 착수 가능하다. 실서비스 연동과 성능·정확도 검증 완료를 뜻하지 않는다.

순서: 공통 상태/카메라·등록·프로필 → 측정/일시정지/교정 알림 → 저장·통계 갱신·복구 → 계정/탈퇴 연동. 외부 탭에서 실제 관측이 가능한지는 초기에 검증한다.

완료 확인: 최초 등록·재방문 분기, 재등록 취소, 입력 단절 후 수동 재개, 내부 이동 후 기록 유지, 외부 탭 측정, 새로고침 복구, 저장 실패 재시도 및 중복 방지, 음소거 상태의 화면 알림, 종료/대시보드 값 일치, 학습 거절 탈퇴 경로.

기반 검토 당시 Python 10개·프론트 26개 테스트 및 타입·빌드 통과. 실제 카메라 체험·FPS·장시간 백그라운드 관측은 미검증. 새 서비스 미리보기의 범위와 미구현 사항은 아래를 참고한다.

## 9. 문서 역할

- 이 파일: 서비스 요구사항과 팀 협의의 단일 공유 문서. 결정이 바뀌면 이 파일의 해당 항목을 수정한다.
- persona-flow-review.md: 개인용 페르소나 요약과 진행 메모. 요구사항을 중복 복사하지 않는다.
- 기존 contracts/, model/, 연구·ADR 문서: 실행 계약·연구 방법·기술 근거. 팀원이 기능 합의를 읽기 위해 모두 순회할 필요는 없다. 기술 계약을 변경하면 해당 원본도 함께 갱신한다.

기술 자료와 충돌하면 이 문서의 최신 제품 요구를 바탕으로 담당자와 계약 변경을 합의한다. 기존 기술 문서를 이미 변경한 것으로 간주하지 않는다.

## 10. V2 미리보기와 시트 검토 파일

일반 진입은 로컬 프로필·홈·준비·측정·대시보드·설정·프로필 편집 미리보기다. 기존 연구 흐름은 `?research=1`로 유지한다. 실제 인증을 대신하지 않으며, 프로필과 요약은 현재 브라우저에만 저장한다.

이번 구현: 내부 화면 이동 시 측정 보존·수동 재개, 입력 공백 시 정지, 로컬 중간 저장·복구, 종료 저장·중복 방지·재시도, 공유 기록 갱신, 시연/웹캠 통계 분리, 3초 토스트와 선택적 소리, 프로필 편집, 로컬 자료 삭제 체험. 검출 신뢰도 표시는 제거했다.

아직 미완료: 서버 인증/저장/탈퇴, 개인 기준 영구 보관 및 등록 여부 연동, 잘못된 예시 활용, 재등록의 원자적 교체, 날짜별/자정 집계, 여러 탭 동시 저장, 저장소 손상 검증, 외부 탭에서의 실제 관측 보장. 로컬 프로필 존재 여부는 임시 진입 분기이며 기준 등록 완료를 보장하지 않는다.

임시 구현값: 중간 저장 2초 목표, 저장 재시도 5초 목표, 입력/타이머 공백 1.5초 초과 시 수동 재개. 팀의 최종 합의값이 아니다. 실제 기준 수집은 기존 5초/최소20표본, 합성 준비는 기존3초로 구분한다. 소리 선호는 현재 세션 안에서만 유지한다.

[요구사항 검토 파일](../outputs/requirements/자세교정_요구사항_2026-09-28.xlsx)은 기능32개·비기능14개·시간조건16개를 담는다. 합의/구현 상태, 완료 기준, 역할, 근거와 팀 의견 입력 칸을 구분했다. Google Sheets에서 파일 가져오기로 열거나 같은 폴더의 탭별 CSV를 사용할 수 있다. 시트에서 합의한 변경은 이 문서와 관련 기술 계약에 반영한다. 비기능의 추가 제안은 아직 미승인이다.

검증(2026-09-28 갱신): Windows에서 make check 자체 대신 대응 명령으로 저장소 검사, 프로젝트 가상환경 Python10개, 프론트32개 테스트 및 타입/빌드 통과. 기본 Python은 jsonschema가 없어 실패하여 프로젝트 .venv로 검증했다. 헤드리스 Edge와 가짜 카메라로 서비스 흐름과 합성 더미 기록 집계를 검증했고, 발견한 문제와 향후 변경 필요 항목은 [계획 0008](plans/active/0008-service-preview.md)에 기록했다. 실제 웹캠 판정·소리·장시간 백그라운드는 미검증이다.
