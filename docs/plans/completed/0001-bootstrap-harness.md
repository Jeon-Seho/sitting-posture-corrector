## 문제와 완료 기준

기존 컴포넌트 폴더와 제공된 기획을 연결하는 작업·검증 기준이 없다.
기존 경로를 유지하면서 문서 지도, 컴포넌트 지침, 계획, 출력 계약, 로컬/CI 게이트를 구축한다.
`make check`가 실제로 통과하고 실패 사례를 거부해야 완료다.

## 범위와 제외

범위: 저장소 개발 하네스와 합성 계약 fixture.
제외: 서비스 구현, 기술 스택 확정, 실제 데이터 수집, 모델 학습, 원격 푸시/배포.

## 결정과 진행 기록

기존 저장소는 초기 commit과 빈 컴포넌트 폴더만 있었으며 사용자 변경은 없었다.
하네스는 Python 3.9 이상과 jsonschema를 사용한다. 앱/서버의 구현 언어는 보류했다.
제공 원문은 변경 없이 복사하고, 문헌 수치·신규성은 미검증 상태로 명시했다.

## 검증 결과와 남은 한계

- `make check`: Python 3.9.6에서 구조·문서 링크·산출물 경로 검사 및 10개 테스트 통과.
- 계약 거부 사례: 필수 필드 누락, 잘못된 상태 조합, 범위 밖 점수, NaN/Infinity, 미등록 필드.
- 검사기 거부 사례: 깨진 링크, 저장소 밖 링크, 금지 산출물, 강제 추적된 ignore 대상.
- `git diff --check`: 통과.
- 최초 패키지 설치는 제한된 네트워크에서 실패했고, 네트워크 접근을 허용한 재시도로 `.venv`에 설치했다.
- GitHub Actions는 구성만 작성했으며 원격 실행 전이다. 앱 동작·카메라·추론 성능은 검증 대상이 아니다.
- Markdown 검사는 인라인 링크의 로컬 경로만 검사한다. 앵커, 참조형 링크, 외부 URL 가용성은 검사하지 않는다.
- 민감 데이터 검사는 경로·확장자 기반이며 파일 내용에 포함된 개인정보나 비밀값까지 탐지하지 않는다.
