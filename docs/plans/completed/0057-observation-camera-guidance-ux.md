# 카메라와 동작 안내를 함께 보는 측정 UX

## 문제와 완료 기준

현재 화면 캡처에서 넓은 상단 고정 안내가 카메라 윗부분을 가리고, 같은 화면의 오른쪽은 숫자·그래프가
차지한다. 측정 중 카메라와 지시를 함께 볼 수 있게 같은 작업 영역에 나란히 배치한다. 안내 시작 시
그 영역으로 이동하고, 다음 동작을 미리 표시한다. 어깨 과제는 양쪽 동시 상승임을 모든 단계에서 명확히 한다.

## 범위와 제외

관측 화면 레이아웃·안내 문구·표시·필요한 UI 회귀와 사용 문서만 변경한다. 2/5/5초·3바퀴·CSV v2의
구간 의미·기하 계산·품질 정책은 유지한다. 미래 예측·모델 학습·좌표 수집은 추가하지 않는다.
사용자 CSV는 저장소 밖 원본 그대로 읽고, 실제 자료를 테스트 fixture나 저장소에 추가하지 않는다.

## 결정과 진행 기록

- 기존 색상·컴포넌트를 유지하고, 카메라 위를 덮는 고정 안내를 제거한다.
- 측정 중에는 카메라·추적 상태·현재/다음 지시를 우선한다. 자세한 수치·상대 z 설명·수동 비교는 펼쳐 본다.
- 어깨 높이는 양어깨 중점의 변화다. 양쪽 동시 상승이 현재 수행 과제이며, 좌우 개별 수행/성공을 검증하지 않는다.
- 안내 시작 시 스크롤을 이동하되 일시 정지/재개 때 반복해서 이동시키지 않는다. 키보드로 영역에 접근할 수 있게 한다.

## 검증 결과와 남은 한계

- `make check-frontend`: **93개 파일·784개 테스트 통과**, TypeScript·Vite 생산 빌드 통과.
  양어깨 유지/다음 복귀·다음 바퀴 안내와 시작 시 한 번만 포커스/스크롤을 옮기는 회귀 2개를 추가했다.
  기존 JS 청크 크기 경고는 남는다.
- `make check-repo`·`git diff --check`와 새 파일의 공백 검사 통과.
- 현재 실제 화면 캡처에서 고정 안내가 카메라를 덮는 문제를 확인했다. 수정 후 1168×853 뷰포트에서
  카메라와 안내가 x=25/644에 놓이고 서로 겹치지 않음을 DOM/화면으로 확인했다.
- CUA의 명시적 합성 카메라/시계 fixture로 등록·시작 후 측정 영역 포커스, 전체 카메라와 안내 표시,
  양어깨 유지·다음 복귀, 정지 중 중간 CSV, 재개 후 완료, 수치 펼치기를 확인했다.
  CSV Blob은 fixture에서 가로채 파일 저장을 막았다. 최종 v2·1,516행·완료 36구간·양어깨 설명 이름을 확인했다.
  임시 HTML/탭은 제거했고 실제 카메라·영상·사람 좌표를 사용하지 않았다.
- 사용자 CSV는 원본 그대로 읽었고 저장소에 복사하지 않았다. 이 파일의 안내 완료를 실제 수행 성공으로 해석하지 않는다.
- 전체 `make check`·서버/DB의 `make check-browser` 게이트는 재실행하지 않았다. 이전 0053의 선택 Python
  패키지 환경 제약은 그대로다. 새 배치의 실제 사람 수행·좁은 실기기·화면 낭독기 전체 검증은 별도다.
