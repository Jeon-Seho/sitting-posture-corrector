# 개발자 구도 확인의 추적 흔들림 허용

- 상태: completed
- 담당: jisung / Codex
- 시작일: 2026-10-13
- 관련 요구사항/ADR: 사용자의 실제 카메라 안정화 진행률 반복 초기화 피드백, ADR 0026

## 문제와 완료 기준

13점 중 한 점의 2.5% 이동에도 1.5초 준비 시간이 초기화되어 구도 확인이 어렵다.
얼굴·어깨 전체 구도의 작은 흔들림을 허용하고 짧은 관측 손실에는 준비 진행률만 멈춘다.
지속적인 구도 이탈·실제 손실에는 자동 등록하지 않아야 한다.

## 범위와 제외

개발자 구도 안내, 관련 합성 테스트와 결정 문서를 변경한다. 일반 서비스 및 연구 코어의
측정 품질·8초 기준 등록·170ms 표본 연속성 정책을 유지한다. 실제 영상을 fixture로 저장하지 않는다.

## 결정과 진행 기록

구도 준비는 0.9초 유효 관측, 얼굴 평균/어깨 중심/어깨폭의 화면폭 6% 변화 허용,
500ms 최대 간격으로 바꾼다. 400ms 미만 일시적인 손실·구도 이탈은 진행률을 보존하되
해당 시간은 누적하지 않는다. 지속 실패·소스 크기 변경·긴 간격은 초기화한다.
8초 등록 중 품질 실패는 기존 방식으로 재등록한다. 수치는 개발 촬영 준비용 휴리스틱이다.

## 검증 결과와 남은 한계

- `make check` 실행: 저장소 검사, Python 163개, 프론트 51파일 386개 테스트,
  TypeScript·Vite 빌드 통과. Java 21/Maven 부재로 백엔드 단계에서 종료되어 전체 성공은 아니다.
- 합성 회귀로 개별 점 튐·자연스러운 위치 흔들림·300ms 관측 간격, 짧은 손실의 진행률 보존,
  지속 손실·이탈·긴 간격 초기화, 크기 변경과 기준 등록 실패를 확인했다.
  가짜 카메라 세션에서도 작은 영상 좌표 흔들림으로 8초 등록·측정까지 자동 전환했다.
- 브라우저의 합성 데모에서 구도 준비 뒤 자동 등록·실시간 비교 전환을 확인했다.
  사용자 영상은 저장하거나 테스트에 사용하지 않았다. 실제 카메라에서의 체감 개선·성능은 미검증이다.
