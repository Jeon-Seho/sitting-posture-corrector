## 문제와 완료 기준

수동 동작 선택 시 이동과 유지·복귀 시각이 섞인다. 머리 앞으로 내밀기 → 고개 숙이기 → 몸통 전체 접근 →
어깨 올리기 순서로 각 2초 이동·5초 유지·5초 기준 복귀를 3바퀴 자동 안내한다. 명목상 총 144초다.
화면에 현재 동작·단계·남은 시간·바퀴를 표시하고 시계열 CSV에 각 구간을 기록한다.

## 범위와 제외

개발자 관측 화면의 안내 상태기계·훅·UI·CSV 및 합성 회귀를 변경한다. 서비스 API·ML 모델·의학적 판정·
원본 좌표 저장·자동 업로드·실제 카메라 자동 시작은 추가하지 않는다. 기존 변경과 다운로드 자료를 보존한다.
수동 비교표의 동작당 최신 1초 중앙값과 자동 안내의 모든 시계열은 구분한다.

## 결정과 진행 기록

- 기준 등록 후 사용자가 자동 안내를 시작한다. 실제/예시 격리는 유지한다.
- 숨김·2D 추적 불가·500ms 초과 관측/안내 시계 누락 시 안내를 일시 정지한다. 재개 버튼을 직접 누르면
  현재 단계를 처음부터 시작하고 시도 번호와 구간 번호를 올린다. z만 없는 경우는 결측으로 기록하며 2D 안내를 계속한다.
- 단계가 화면에 실제 표시된 시점부터 시간을 재며 지연 시 여러 단계를 건너뛰지 않는다. 각 단계 종료는 별도 사건이다.
- CSV의 바퀴·목표 동작·단계·시도는 안내 표식이며 실제 수행 검증이나 학습 정답이 아니다.
- 완료 시 카메라를 종료하고 자료를 보존한다. CSV 다운로드는 명시적 클릭으로만 한다.
- 수신 신선도는 약 10Hz로 채택한 관측을 기준으로 잰다. 입력 시계가 거의 진행하지 않아 버리는
  콜백만 계속 오는 경우도 안내를 지속하지 않는다.

## 검증 결과와 남은 한계

- 최종 `make check-frontend`: **93개 파일·782개 테스트 통과**, TypeScript·Vite 생산 빌드 통과.
  안내 시계/표시/훅 통합 회귀 20개를 추가했다. 144초·36구간·12회 유지, 숨김/불량/정지·입력 시계 정체,
  명시적 재개 시도, 수동 조작 잠금, 추출 조건 변경 취소, 기존 CSV 보존을 확인했다.
  기존 큰 JS 청크 경고는 남는다.
- CUA 브라우저에서 명시적 합성 카메라/시계 fixture로 실제 React 화면의 등록 → 이동 2초 → 유지 5초 →
  복귀 5초, 사용자 멈춤/재개, 불량 2D 시 재개 잠금·복구, 다음 동작, 3바퀴 완료·카메라 종료를 확인했다.
  CSV 버튼의 Blob 생성은 fixture에서 가로채 실제 파일 다운로드를 막고 내용을 DOM에 검증 표시했다.
  최종 CSV v2는 1,514행·완료 36구간·유지 12구간·세 단계 이름·원본 좌표 열 부재를 확인했다.
  별도 중단 경로는 재시도 2회와 paused 행 4개를 구분했다. 새 실행 확인창도 자료를 보존했다.
  임시 HTML fixture와 시험 탭은 제거했고 실제 카메라/사람 자료는 사용하지 않았다.
- `make check-repo`·`git diff --check`와 새 소스/문서 파일의 공백 검사 통과.
- `make check`와 `make check-browser` 전체 서버/DB 경로는 이번 프론트 내부 작업에서 재실행하지 않았다.
  이전 0053에서 확인한 `.venv`의 numpy/joblib/pymysql 누락 제약과 실제 장치/동작 수행 미검증이 남는다.
  안내 표식은 실제 수행 확인·학습 정답이 아니며, 강제 종료·새로고침 후 영구 복구를 보장하지 않는다.
