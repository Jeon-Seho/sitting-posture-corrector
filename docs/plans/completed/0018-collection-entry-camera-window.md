# 수집 화면 진입과 이동 가능한 카메라 창

- 분야: 프론트
- 작업: GP-0079
- 상태: completed
- 담당: Codex
- 시작일: 2026-10-02
- 관련 요구사항/ADR: 사용자의 자세 선택 확인·다른 주소에서도 카메라 보기 요청, ADR 0008·0016

## 문제와 완료 기준

현재 로컬 미리보기의 시작 화면에는 수집 진입 버튼이 없다. 수집 화면에서도 좁은 창에서는 카메라와 긴 안내 아래에 자세 선택이 놓인다.
프로필 생성 없이 수집 화면으로 바로 진입하고, 카메라를 켜기 전에도 자세·길이를 위에서 선택한다.
사용자가 작은 창을 열면 기존 카메라 스트림을 다른 탭에서도 보고 창 위치/크기를 브라우저 UI로 변경할 수 있다.

## 범위와 제외

프론트 수집 진입·배치와 카메라 미리보기 창만 변경한다. CSV·라벨·알림 정책·서버 인증 계약은 유지한다.
추가 카메라 권한·영상 저장/전송은 없다. 원래 앱 탭을 닫거나 같은 탭에서 다른 사이트로 이동한 뒤 실행을 유지한다고 주장하지 않는다.
수집 중 탭 이동은 기존 규칙대로 촬영을 중단한다. 미리보기와 백그라운드 연구 수집을 구분한다.

## 결정과 진행 기록

현재 사용자의 인앱 브라우저는 프로필 시작 화면이다. 실제 사용자 저장소/카메라를 변경하지 않고 확인했다.
브라우저 PiP는 사용자 동작이 필요하고 원래 문서 수명에 종속된다. Chrome 공식 문서로 확인했다.
지원 시 Document PiP, 그 외 video PiP를 사용한다. 위치와 크기는 사용자가 창을 드래그/리사이즈한다.
현재 인앱 브라우저는 두 PiP API가 모두 없어 앱 내부 드래그/방향키/크기 조절 창을 함께 제공한다.
수집 화면 위쪽의 선택란을 실제 인앱 화면에서 확인했고 사용자 카메라·프로필을 만들지 않았다.
추가 Chrome 검증은 명시적 canvas 합성 영상으로만 실시한다. 프론트 239개·타입/빌드 통과와
실제 Document PiP·같은 스트림·종료 등 72개 브라우저 조건 통과 후 Node 종료 지연을 재현했다.
macOS crash reporter/updater가 시험 Chrome의 stderr를 상속하는 것을 lsof로 확인했다.
Chrome parent 종료 뒤 진단 파이프를 닫는 수정을 추가했다. 해당 실행은 테스트 Node를 종료했고
전체 check/브라우저 게이트 exit 2로 기록한다. 수정 후 최종 전체 검사와 크기 변경 회귀를 다시 실행해 통과했다.

## 검증 결과와 남은 한계

- 최종 `make check`: exit 0 (`.cache/0018-make-check-final.log`).
- Python 122개, 프론트 239개 통과. TypeScript·Vite 빌드와 Java JAR 빌드 통과.
- 기본 Java API 45개·CEP 24개 통과. 기본 프로필에서 제외한 MySQL 11개는 실제 DB 및 복원 DB에서 각각 모두 통과했다.
- 실제 Chrome 회귀 73개, 계정 브라우저 21개, Compose 46개 조건 통과. 시험 브라우저·포트·컨테이너·볼륨 정리도 통과했다.
- 인앱 브라우저에서 프로필 없이 수집 진입 및 상단 자세 선택을 확인했다. 실제 Chrome에서 명시적인 canvas 합성 영상으로 같은 스트림·드래그·방향키·크기 조절·접기·Document PiP·종료를 확인했다.
- 사용자 웹캠, 자동 탭 전환 PiP 및 장시간 백그라운드 정확도는 미검증이다. 합성 검사로 실제 카메라 검증을 대체하지 않는다. 원래 앱 탭을 유지해야 하며 인앱 브라우저는 앱 내부 창만 지원한다.
