## 문제와 완료 기준

영상 없이 키포인트 움직임을 다시 보며 기존 39D 입력으로 변환 가능한지 점검한다.
현재 기록 재생·일시정지·배속·프레임 이동·탐색, JSON 수동 저장/불러오기를 제공한다.
실측 입력과 리플레이를 분리하고 누락을 보간하거나 동작 안내를 정답으로 만들지 않는다.

## 범위와 제외

관측 화면 전용 13점 image/world 기록·유한 메모리·검증된 로컬 JSON·플레이어·검증·문서.
영상·자동 저장·업로드·서비스 연결·기존 CSV 변경·학습 실행·성능 주장은 제외한다.
재생 기록은 모든 단계, 기존 CSV는 측정 구간만 유지한다. 기존 자료 보존 확인에 재생 기록도 포함한다.

## 결정과 진행 기록

현재 카메라가 제공하는 원래 MediaPipe 0..12번 image/world를 보존한다. 39D는 기존 함수로 점검만 한다.
최대 6,000프레임(약 10분/10Hz) 이후 추가 기록을 중단하고 초과 수를 표시한다.
원본 시각·실제 해상도·추출기·안내 단계/시도·세그먼트를 보존하며 개인 식별자는 수집하지 않는다.

## 검증 결과와 남은 한계

- `make check-frontend`: 97파일·826테스트 통과, TypeScript·Vite 빌드 통과. 기존 500kB 번들 경고 유지.
- `make check-repo`, `git diff --check`: 통과.
- 실제 인앱 브라우저: 명시적 합성 81프레임 JSON 불러오기·2배 재생/종료·프레임 이동·화면/ML 측면 전환·JSON 다운로드 확인. 영상 요소 없는 SVG 표시 확인.
- 합성 자료에서 2D 유효79/81·기존39D 변환73프레임 표시 확인. 수치는 합성 연결 결과이며 사람에 대한 성능 결과가 아니다.
- 원본 복사/결측·역전·한도·호환성 거부·숨김/실측 잠금·파일 실패 보존·초기 리플레이 보존 확인·CSV hold-only 회귀를 자동 검증.
- 실제 카메라 기록·장시간 메모리·실제 학습 가능성/동작 분리도는 미검증.
- 백엔드 JAR이 없는 현재 환경에서 `make check-browser`·전체 `make check`는 실행하지 않았다. 서비스/DB 계약 변경은 없다.
