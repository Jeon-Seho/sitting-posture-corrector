## 문제와 완료 기준

소개 문구와 작은 미리보기를 큰 검정 카메라 작업 공간으로 교체한다. 중앙 시작 버튼 하나로
짧은 안내 → 구도 정렬 → 기준 등록 → 예측/룰 비교가 이어진다. 실제 관측점과 기준 가이드를
겹쳐 현재 변화를 볼 수 있고, 결과를 같은 화면에서 비교한다. 기본 다크 테마와 의미 있는
전환 애니메이션을 제공하며 저감 모션을 지원한다.

## 범위와 제외

`features/developer/`만 UI·측정 어댑터를 변경한다. 구도 기하 계산은 별도 연구 코어에 둔다.
기존 사용자 웹·카메라 훅·서비스 판정은 유지한다. 실제 모델이 없을 때 모델 실행/성능을
꾸며내지 않는다. 영상·원본 좌표·기준 윤곽은 메모리 표시 전용이며 기록/내보내기에 추가하지 않는다.

## 결정과 진행 기록

- 3개 에이전트가 카메라 표시, 측정 흐름, 결과 UI를 서로 다른 파일에서 병렬 작업한다.
- 현재 MediaPipe Pose의 얼굴/어깨 13점을 재사용한다. Face Landmarker는 필수 요구가 아니며,
  가이드에 필요한 관측이 이미 존재하므로 추가 추론·의존성은 우선 도입하지 않는다.
- 구도 가이드는 관측 가능성과 위치 정렬을 돕는다. 정상 자세나 의학적 기준을 판단하지 않는다.
- 애니메이션은 안내 전환·정렬 상태·등록 진행·기준 대비 움직임·결과 변화에 한정한다.
- 안내·진행률·기하 수치는 영상 아래에 배치해 얼굴과 어깨 관측을 가리지 않는다.
- 영상 비율이 달라지면 이전 기준과의 겹침·변화값을 숨기고 재등록을 안내한다.
- 최종 검토에서 합성 시연의 논리시간과 누락 처리의 실제 시간 혼용을 발견하고 수정했다.
  엔진은 단조 시간, 시나리오는 유효한 콜백에만 진행하는 별도 시계를 사용한다.
  백그라운드/지연은 측정 불가로 끊고 동작 순서를 건너뛰지 않는다.

## 검증 결과와 남은 한계

- `make check` 실행: 저장소 검사, Python **163개**, 당시 프론트 **379개**, 타입 검사·빌드 통과.
  이후 백엔드 준비 검사에서 Java 21/Maven 부재로 종료되어 전체 성공은 아니다.
- 마지막 카메라·시간 회귀 수정 후 `make check-frontend`: **51개 파일, 382개 테스트** 및
  TypeScript·Vite 빌드 통과. 기존 메인 번들의 500KB 초과 경고는 남아 있다.
- `make check-repo`, `git diff --check` 통과.
- 브라우저에서 합성 안내 → 구도 확인 → 연속 기준 등록 → 실시간 비교 → 종료·기록 표시를 확인했다.
  375px, 기본 895px, 1440px에서 화면과 가이드가 표시되고 수평 넘침이 없었다.
  다크/라이트 전환, 설정의 실제 모델 미연결 표시, 기록 결과를 확인했다.
  `/`의 기존 사용자 화면과 배경색을 확인했으며 개발 테마가 적용되지 않는다.
- 가이드 13점·기준 윤곽·변화 벡터는 합성 입력으로 시각 확인했다. 실제 웹캠·사람의 자세 구분
  정확도·실기기 처리 성능·학습 LSTM 실행은 미검증이다. 백엔드/Compose 검증은 실행하지 못했다.
