- 상태: completed (구현·합성 검증·실제 관찰, 마지막 시간 정책의 실제 재현은 미검증)
- 담당: Codex

- 관련 요구사항/ADR: 사용자 지정 1→0.7배, 직접 카메라 관찰, 무음 유지

## 문제와 완료 기준

`0.7%` 표현은 기존 배수의 0.7배 지정으로 해석하고 사용자에게 먼저 명시했다. 점수 자체의 단위를 바꾸지 않고 새 /dev 실행의 진입 경계를 0.7배로 낮춘다.
복귀는 진입의 2/3인 약 0.467배로 낮춰 히스테리시스를 유지한다. 이탈·복귀 3초, 자동 후보 0.5배/실측 범위 안/1초, 무음을 유지한다.
숫자·게이지·그래프·조건·export가 실제 경계를 읽으며 과거 1배 실행은 재해석하지 않는다. 사용자 자세 변경 때 실제 상태와 알림·수집을 관찰한다.

## 범위와 제외

새 /dev 종합 판정·표시·진단 export. 일반 서비스, 기존 무옵션 예측 정책, LSTM 입력/가중치, 과거 수집·평가 자료는 유지한다.

## 결정과 진행 기록

0.7배 지정은 사용자 설정이며 실제 정확도가 검증된 임계값으로 주장하지 않는다. 실제 카메라 관찰과 합성 회귀를 구분한다.

## 검증 결과와 남은 한계

- `make check`: 변경 중간 상태에서 Python 195개, 프론트 688개, TypeScript·생산 빌드 통과. Java 21/Maven 부재로 백엔드부터 중단했으며 Compose는 실행하지 못했다. 전체 성공이 아니다.
- 실제 카메라에서 정면 구간 약0.5~0.6배와 작은 움직임 구간 약0.4~0.5배·알림 수 유지(5회)를 관찰했다. 움직임 시점에 정답 라벨을 붙인 독립 시험이 아니며 오탐률 결과가 아니다.
- 3분34초 종료한 첫 관찰은 알림 7회·짧은 이탈 후 복귀 12회다. 3분05초 사건에서 최대1.80배였지만 알림 순간0.58배인 것을 발견했다. 진입 후 중간 띠에서 타이머가 계속 진행하는 기존 히스테리시스가 원인이다.
- 새 `/dev`는 알림 전 >0.7배 연속 시간만 누적한다. ≤0.7배가 되면 진입을 끊는다. 확정 뒤에는 약0.467배 복귀 기준을 사용하고 복귀 중 초과하면 복귀 시간을 재시작한다. 기존 무옵션 정책은 유지한다.
- 이 수정 후 첫 `make check-frontend`는 688개 통과·Route 합성 연동 1개가 5초 제한으로 실패했다. 실제 카메라와 동시 실행 상태였다. 같은 전체 73파일을 `npm --prefix frontend run test -- --maxWorkers=2`로 재실행해 **689개 모두 통과**했다. 실패를 숨기거나 테스트 제한을 늘리지 않았다.
- `make check-browser`: 생산 번들 합성 입력 제외·시험 서버 정리는 통과했으나 Java 런타임 부재로 앱 통합은 실행하지 못했다.
- 실제 결과·자동 후보 371행을 저장소 밖 로컬 다운로드로 보존했고 재학습하지 않았다. 마지막 시간 수정 뒤 새 측정은 카메라 연결/구도 단계에서 재시도했다. 수정 뒤의 작은 움직임·기울임·복귀 전체 시나리오는 실제 장치로 아직 확인하지 못했다.

최종 타입·생산 빌드(`npm --prefix frontend run build`)와 `make check-repo`, `git diff --check` 통과.
최종 재연결에서는 기준 등록 후 정면 약0.17배·알림0회, 47초 시점 짧은 진입 후 복귀10회·알림0회를 확인했다. 최종 실제 시험의 지속 이탈·복귀 완결은 별도 확인이 필요하다.
65초의 실제 화면은 상체 전체 기대기보다 고개를 옆으로 돌리는 동작이었으며 상대 모양2.48배·몸 전체0.57배·진입1.1초였다. 75초에 범위 안으로 돌아왔고 알림은0회였다. 84초에도 짧은 진입 후 복귀24회·알림0회였다. 고개 돌림이 상대 분기를 크게 올리는 잔여 한계를 확인했으며, 이를 자세 붕괴 정탐으로 해석하지 않는다. 등/골반을 직접 보는 입력이나 동작 의도 분류는 이번 범위에 포함하지 않았다.

정면 웹캠의 얼굴·어깨 관찰은 기대는 각도나 의도/건강 상태의 정답을 제공하지 않는다. 실제 정확도 및 잘못 등록된 기준의 영향은 후속 평가가 필요하다.
