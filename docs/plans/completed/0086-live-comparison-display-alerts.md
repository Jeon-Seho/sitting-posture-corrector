# 웹캠 비교 화면의 점수와 알림

- 상태: completed
- 담당: 모델 연구 화면
- 시작일: 2026-11-09
- 관련 요구사항/ADR: ADR 0005 점수 표시, ADR 0020 시간 정책

## 문제와 완료 기준

웹캠 비교 화면이 각 방식의 점수를 100점이 좋은 방향으로 표시하고, 화면 숫자는 서서히 변한다. 측정 불가 시 점수와 연속 판정은 즉시 끊는다. 규칙과 모델 각각에 대해 화면에 실제 발생한 알림을 세고, 사용자가 권한을 허용하면 시스템 알림도 제공한다. 사용한 입력점과 모델 특징을 설명한다.

## 범위와 제외

로컬 연구 화면과 합성 UI 시험, 실행 안내만 변경한다. 점수 평활화는 화면 전용이며 모델 입력·임계값·서비스 추론 계약을 바꾸지 않는다. 알림은 같은 관측의 각 방식에 대해 로컬 비교용으로 별도 발생시키며 운영 API의 사건 기록과 구분한다.

## 결정과 진행 기록

- 100점 방향은 ADR 0005의 `100 × (1 − 원점수)`를 따른다. 화면용 평활화는 판정에 쓰지 않는다.
- 비교용 알림 시간은 ADR 0020의 최초 3초·복귀 3초·재알림 60초를 사용하며, 측정 불가와 관측 누락은 연속성을 끊는다. 운영 API가 만든 사건이라고 표기하지 않는다.
- 화면 내 실제 알림 횟수를 세며, 시스템 알림의 OS 표시 여부는 별도 권한·환경에 달려 있음을 밝힌다.
- 화면 점수에 2.4초 시정수 평활화를 적용한다. 9개 입력점은 표시하고, 입의 별도 개폐 판단은 추가하지 않는다.

## 검증 결과와 남은 한계

- `make test`: Python 171개 성공, 이 중 PySpark 미설치로 11개 건너뜀. 기존 Python 환경을 재사용하고 LightGBM 4.6.0은 임시 경로에 설치했다. 첫 실행은 LightGBM 부재로 4개 모듈 로딩에 실패했으며, 의존성을 보완해 재실행했다.
- 포함된 `tests/live_comparison_ui.test.cjs`: 합성 UI 시험 10개 성공. 방향 반전·평활화·측정 불가·두 방식의 알림·복귀/재알림·권한 실패·재등록·입점 표시를 확인했다.
- `node --check model/analysis/live_comparison/web/app.js`와 `git diff --check` 성공. 브라우저에서 수정된 화면과 콘솔 오류 없음을 확인했다.
- 실제 웹캠 자세 관측과 OS 시스템 알림 전달 여부는 사용자 장치·권한으로 직접 확인해야 한다. 메인 프런트의 TypeScript 빌드와 전체 `make check`는 이 독립 연구 화면 변경에 실행하지 않았다.
