## 문제와 완료 기준

기존 RF 파일럿은 1초 중앙값으로 학습하고 0.5초마다 내보낸다. 유효한 프레임마다 독립적인 이탈 점수를 내는 모델 후보를 별도로 준비한다. 지속 이탈 3초·복귀·재알림은 판정 서버의 책임이다. 4:3 관측은 정규화 좌표를 기준 해상도 640×480으로 해석하고 모델이 사용하는 랜드마크의 품질이 부족하면 점수를 내지 않는다.

완료 기준은 보정 RF와 자세 RF 모두에 대한 참여자 분할 프레임별 학습·평가, 버전 있는 후보 산출물, 합성 입력의 모델 실제 학습·다시 읽기·프레임별 추론, 4:3과 관측 품질·누락 경계 검증이다. 기존 1초 창 모델 파일과 보고서를 프레임 모델로 오인하지 않는다.

## 범위와 제외

- 모델 연구 도구·합성 시험·관련 설명을 변경한다. FE·BE의 서비스 API와 기존 시간 판정은 바꾸지 않는다.
- 기존 연구 결과와 학습 가중치, 비공개 자료는 수정하지 않는다. 실제 카메라의 관측 품질이나 독립 참여자 성능은 이번 합성 시험으로 확정하지 않는다.
- 기존의 합성 세로 이동 보정 목표·범위를 보존하고 두 단계 모두 프레임 입력으로 별도 재학습한다. 보정은 실제 의자 이동의 검증된 추정이 아니다.

## 결정과 진행 기록

- 사용자 결정: 유효 프레임마다 RF 점수를 낸다. 3초 지속 판단은 판정 서버에서 수행한다.
- 사용자 결정: 4:3 화면은 정규화해 처리한다. 분류 대상은 기존에 라벨링한 기준 자세와 이탈이다.
- 사용자 결정: 기존 세로 이동 보정 RF와 자세 RF를 둘 다 프레임 단위로 재학습한다.
- MediaPipe visibility는 추정값이다. 입력 품질 임계값은 기존 0.65를 시작값으로 재사용하되 실측 검증 전 확정하지 않는다.
- 실제 자료는 이름 기준 임시 그룹의 신원과 안내 라벨이 아직 검증되지 않았다. 동일 촬영이 서로 다른 이름으로 중복된 3건의 양쪽 파일 6개를 제외하고 나머지 27개 촬영으로 후보만 학습했다. 평가를 위한 모든 클래스가 없는 그룹이 있어 전체 자료 후보와 참여자별 독립 평가는 구분한다.

## 검증 결과와 남은 한계

- `make test`: 196개 중 185개 통과, PySpark가 없는 시험 11개 건너뜀. 합성 참여자 4명의 CLI 카탈로그·2단계 학습·파일 재로딩, 참여자 분리와 관측 품질 복구, 4:3 및 이전 실험과 25배 증강 동등성 검증을 포함한다.
- `node --test tests/live_comparison_ui.test.cjs`: 24개 통과. 연구 화면의 상태 전이·4:3 경계와 임시 임계값 표시를 합성 검사했다. 실제 브라우저 카메라 시험은 아니다.
- 실제 촬영 27개, 신원 미확인 9개 임시 그룹의 유효 프레임 12,641개로 80개 트리 보정기와 120개 트리 분류기를 `--candidate-only`로 학습했다. 한 그룹에 안내 라벨 한 종류만 있었다. 결과 파일의 해시 확인 및 합성 입력 점수·낮은 가시성의 무점수 처리를 검증했다. 성능 평가와 기준값 선택은 하지 않았고 화면의 0.5는 임시값이다. 충돌 확인 자료와 후보 가중치는 접근 제한된 저장소 밖에 보관했다.
- 학습한 후보를 로컬 연구 서버에 불러와 합성 등록·연속 프레임 점수·가시성 부족을 TestClient HTTP로 확인했다. 웹 화면과 MediaPipe 자산 다섯 경로는 HTTP 200을 반환했다. 샌드박스 밖 루프백에서도 서버 시작·HTTP 200·프로세스 종료를 확인했다. 실제 카메라나 서비스 API 연결 시험은 아니다.
- macOS arm64에서 실제 학습 후보에 합성 입력을 넣어 모델 함수만 100회 실행했다. 중앙값 6.26ms, p95 6.52ms다. 카메라·MediaPipe·HTTP·화면 설명은 포함하지 않은 단일 환경 관찰이다.
- 서비스 FE·BE·판정 서버 연결과 실제 정확도, 실제 장치의 전체 지연·FPS·관측 품질은 검증하지 않았다. 기존 서비스 기준 좌표에는 9점 visibility 증거가 없어 기준 등록 품질을 확인하는 연동 설계가 필요하다. `make check`의 FE·BE 타입/빌드는 이 모델 연구 범위에서 실행하지 않았다.
