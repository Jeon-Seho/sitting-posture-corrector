- 관련: [v8 파일럿](../../research/replay-v8-pilot.md), [2단계 실험](../../../model/analysis/replay_pilot/TWO_STAGE.md), [연구 프로토콜](../../research/protocol.md)

## 문제와 완료 기준

다운로드된 v8 리플레이로 기존 파일럿을 탐색적으로 다시 학습하고, 같은 웹캠 관측과 개인 등록 기준에서 학습 모델과 서버의 규칙 점수를 나란히 볼 수 있는 `model/` 안의 로컬 연구 화면을 제공한다. 원본·카탈로그·가중치·개별 보고서는 저장소 밖에 둔다.

## 범위와 제외

- 참여자 이름으로 임시 그룹을 제안한다. 동일인 확인 전 결과를 탐색용으로 표시하고 검증된 일반화 성능으로 주장하지 않는다.
- 기존 25배 증강 및 2단계 도구를 그대로 사용한다. 새로운 임계값이나 학습 방법을 시험 대상에 맞춰 고르지 않는다.
- 기존 프론트의 Pose Heavy 자산과 카메라 측정 가능 조건, 연구 도구의 640×480 특징·등록·1초 중앙값, 서버의 특징 점수 함수를 재사용한다.
- 브라우저에서 카메라를 명시적으로 시작한다. 영상은 브라우저 안에서 처리하고 랜드마크는 loopback 연구 서버의 휘발성 메모리에서만 사용한다. 서비스, 계약, 알림 엔진은 바꾸지 않는다.
- 비교는 연구 모델의 창 단위 점수와 규칙 점수다. 서버 알림 정책의 실시간 재현이나 의학적 판단이 아니다. 두 점수의 임계값 출처는 표시한다.
- 로컬 모델 파일은 시작 시 서버가 신뢰할 수 있는 명시 경로에서만 읽는다. 업로드·자동 저장·임의 파일 제공은 없다.

- [x] 카메라 시작·중단·기준 등록·비교 화면 및 실패 상태 구현

## 결정과 진행 기록

화면은 기존 서비스에 통합하지 않는 loopback 전용 프로세스다. 기존 앱은 프레임 측정 가능 여부만 판단하고 점수는 서버 규칙이 계산하므로 `model.inference.service.score_feature_deltas`를 기준 비교군으로 사용한다. 속도·재현성을 위해 기존 Heavy 및 WASM 자산을 로컬에서 제공한다.

## 검증 결과와 남은 한계

- 원본 20개·임시 참여자 그룹 6개, 원본 창 1,968개와 49,200개 학습 변형으로 기존 도구의 25배·2단계 학습을 완료했다. 입력과 모델 해시를 기록했다. 신원 및 안내 라벨은 독립 검증되지 않았다.
- 2단계 보고의 미이동 참여자별 창 균형 정확도 평균은 약 92.0%다. 기존 문서의 92.1%는 다른 Python·scikit-learn 환경의 실행이며 독립 시험 결과가 아니다.
- `python tools/dev.py check`의 Python 170개 중 159개 통과·11개 PySpark 부재로 건너뜀, 프론트 Vitest 945개와 Node 5개 통과, TypeScript 및 Vite 빌드 통과. 백엔드 Gradle은 JDK 17 부재로 실행 전 실패해 전체 게이트는 실패다. 첫 실행의 Windows 시간대·콘솔 문제는 가상환경 tzdata 설치와 `PYTHONUTF8=1`로 해소했다.
- 추가 비교 도구 테스트 9개 및 그 안의 합성 Node UI 테스트 2개 통과, 합성 좌표를 재학습 모델·로컬 HTTP에 통과시켜 측정과 측정 불가를 확인했다. 브라우저는 초기 화면과 카메라 권한 대기 취소를 확인했다.
- 실제 카메라 권한은 이 브라우저 환경에서 대기 상태여서 실장치의 등록·측정 및 성능은 확인하지 못했다. 실제 기기 카메라 프레임률과 지연은 별도 검증이 필요하다.
