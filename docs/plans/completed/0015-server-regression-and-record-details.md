## 문제와 완료 기준

서버 연결은 개발 범위에서 완료됐지만 전체 HTTP 재알림·응답 유실과 브라우저 측정부터 기록 복구까지의
자동 회귀가 부족하다. 기록 비교는 판정 출처·기준·설정 차이를 드러내지 않고 저장된 서버 사건의 상세도 열어볼 수 없다.

사용자가 즉시 가능한 후속 목록의 우선 1~4번 진행을 승인했다. 다음 결과를 확인한다.

- 실제 HTTP의 60초 재알림 경계와 처리 후 응답 유실 재시도에서 집계·사건이 중복되지 않는다.
- 개발 세션/관측 한도와 개발 프로세스 실패·종료를 자동 회귀로 검증한다.
- 합성 입력만으로 실제 브라우저·프론트·API·추론·CEP의 측정/종료/복구와 기록 갱신을 반복 검증한다.
- 비교 화면은 현재 자료로 알 수 있는 판정 출처·기준·모델·설정 차이와 확인 불가 항목을 표시한다.
- 기록 상세에서 적용 설정·서버 확인 여부·유효/제외 시간·원래 사건과 중단 사유를 볼 수 있다.

## 범위와 제외

프론트 기록 화면과 합성 브라우저 검사, Java/Python 서버·개발 도구 회귀를 보완한다.
기존 기록과 서버 출력 계약을 유지하고 비교의 합산/제외 정책은 바꾸지 않는다.
자료가 없는 과거 기록의 기준·모델·제외 시간을 추정하지 않는다.

DB·인증·영구 기준·동의/삭제·보존 기간, 자정 분할, 소리 선호, 실제 촬영/학습/성능 측정은 제외한다.
기술 스택·의존성과 판정 임계값을 변경하지 않는다. 기존 작업 변경과 사용자 임시 문서를 보존한다.

## 결정과 진행 기록

- 추가 정책 결정 없이 차이와 불확실성을 안내한다. 조건이 다른 기록을 자동 제외하지 않는다.
- 상세 화면은 저장된 값을 표시하며 서버 종료 미확인 요약을 성공한 종료와 구분한다.
- 브라우저 자동화는 합성 카메라 입력과 독립 임시 프로필만 사용한다. 일반 앱이나 프로덕션에 합성 입력을 노출하지 않는다.
- 검증 장치는 카메라 정확도·실제 음향·실제 모델 성능의 증거로 사용하지 않는다.
- `make check-browser`를 전체 `make check`와 기존 CI 실행 명령에 연결했다. Node 24 내장 WebSocket/fetch와 설치된 Chrome을 사용하며 프로젝트 의존성을 추가하지 않았다.
- 실제 API만 같은 포트에서 재시작하여 메모리 유실 후 404와 미확인 보관을 검증한다. 미확인 특징 응답은 실제 처리 응답의 전달만 지연한 뒤 새로고침으로 재전송한다.
- 검토에서 빈 요청 목록의 `every()` 검사와 Node 종료 후 Chrome 정리 누락을 발견하여 비어 있지 않은 실제 요청 검사와 프로세스 그룹 종료 확인으로 보완했다.

## 검증 결과와 남은 한계

- 2026-10-01 Mac에서 `make check` 전체 통과. Python 50개, 프론트 182개,
  Java 51개(API 33/CEP 18), TypeScript·Vite 프로덕션 빌드·두 실행 JAR·저장소 문서/산출물 검사 통과.
- 실제 HTTP의 기본 60초 재알림·커스텀 시간/설정 동결, CEP 처리 후 원응답 유실과 동일 관측 재전송을 검증했다.
  기존/재전송 관측의 추론 호출 수와 동일 hash, 사건·알림·통계 보존을 확인했다.
- 실제 CEP 한도 뒤의 기존 중복/종료 허용, 개발 준비 실패·프로세스 종료·Ctrl+C·강제 종료 회귀를 검증했다.
- 합성 브라우저 40개: 3초 확정·2초 복귀·60초 재알림, 수동 휴식/내부 이동·저품질 제외,
  종료 응답 대기·홈/대시보드/상세와 서버 결과 일치, 미확인 본문 새로고침 재전송,
  실제 API 메모리 유실 404·미확인 보관, 과거 합성 기록의 비교 조건, 일반 개발 입력 비활성화를 확인했다.
- 프로덕션 JS에 합성 입력/시계가 포함되지 않으며 실제 카메라 권한 사용은 0회다.
  원본 서버 사건·통계와 현재 저장 계약·기술 스택·의존성을 유지했다.
- 모든 시험 서비스·추가 API/HTTP proxy·두 Vite·독립 Chrome과 디버깅 포트를 정리했다.
- 최종 통합 로그는 `.cache/server-records-check.log`, 합성 화면은 `.cache/browser-smoke/`에만 두며 Git에 추가하지 않는다.
- 전체 검증 후 새로고침 사례를 강화하여 실제 3초 확정 사건 응답을 보류한 상태로 재로드했다.
  `make check-browser` 대상 재검증 40개와 Node 4개 파일 구문 검사가 통과했다.
  사건이 존재하는 조회/동일 재전송에서도 과거 알림을 재생하지 않으며 결과와 포트를 보존·정리했다.
  최신 로그는 `.cache/browser-final-reload.log`다.
- 원격 CI·Windows/Linux 브라우저 실행,
  실제 카메라·소리·백그라운드·FPS/지연·학습 모델·DB/인증·영구 복구는 이번에 검증하지 않았다.
