## 문제와 완료 기준

기존 CSV 수집과 /dev 관측 수집의 이름이 혼동된다. 개발자 전용 사이드바 메뉴는 /dev로 이동하고 과거 화면은 CSV로 명시한다. 웹과 앱 로컬 실패 페이지는 저장 공간이 달라도 현재 mode·accent의 그림과 배경·버튼을 유지한다.

## 범위와 제외

frontend의 메뉴·수집 안내·정적 오류 페이지·Electron 테마 전달과 시험. /dev 수집·판정 로직, API, 운영 웹 배포는 변경하지 않는다.

## 결정과 진행 기록

- app:// 로컬 실패 페이지에는 새 IPC 권한을 주지 않고 기존 신뢰 출처 검사를 통과한 메인 웹 창만 테마를 저장한다.
- 연결 중 미리보기에는 현재 메모리 테마를 URL로 전달해 저장소 차단 시에도 일치한다.
- 피부·구도·그림 원본은 그대로이며 기존 팔레트별 WebP를 재사용한다.

## 검증 결과와 남은 한계

- 최종 `python tools/dev.py check-frontend`: Vitest 983개 + Node 8개, 타입·빌드 통과. 최초 병렬 브라우저 검수 중 기존 카메라 시험 1개가 5초 제한에 걸렸으며 브라우저 종료 후 재실행해 전체 통과했다. `npm run lint` 오류 0·기존 경고 28개, `git diff --check` 통과.
- 격리 Chrome에서 7개 팔레트×4개 모드(28조합)의 React 오류 페이지와 정적 연결 중·실패 페이지 배경·그림 일치, 일반 계정/로그인 전 메뉴 부재와 개발자 로그인 뒤 왼쪽 자세 수집 → 실제 /dev 진입을 확인했다. 실제 카메라는 실행하지 않았다.
- `npm run desktop:pack` 및 바탕화면 바로가기 갱신 성공. 패키지 이미지 28종 일치·관측 높이 CSS 포함·독립 임시 프로필에 저장한 블러플 다크 테마로 EXE를 재실행해 연결 실패 화면에서 테마 복원을 확인했다. 시험 프로세스는 종료했다.
- 운영 웹은 사용자 요청에 따라 배포하지 않는다. 실제 앱은 운영 웹을 읽으므로 메뉴는 웹 배포 이후 표시된다.
