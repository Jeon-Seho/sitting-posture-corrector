## 문제와 완료 기준

리플레이가 분석 패널 안의 큰 화면으로 표시되어 기존 프리뷰 공간을 활용하지 못한다.
리플레이 탭을 선택하면 카메라가 있는 좌측 프리뷰에 재생 화면, 우측에는 옵션·타임라인·파일 기능만 표시한다.
탭 선택 표시 이동, 테마 아이콘/색상, 카메라 제어의 등장/크기 변경을 짧게 애니메이션 처리한다.
상대 z 좌표 카드는 카드 그리드의 첫 항목으로 이동한다.

## 범위와 제외

관측 Workspace/Tools/Replay/Guide/테마 표시·CSS·관련 검증만 변경한다.
리플레이 상태는 한 인스턴스가 소유한다. 영상·재생 위치·파일 원본을 복제하거나 세션을 초기화하지 않는다.
실측 중에는 프리뷰를 라이브로 유지하며 경쟁 리플레이 조작은 기존처럼 잠근다.
추론·자료 수집·품질/시간 정책·CSV/JSON 형식은 바꾸지 않는다.

## 결정과 진행 기록

- 첫 주석의 위치 표현은 현재 카메라가 있는 좌측 컴포넌트에 재생, 우측에는 옵션으로 해석하고 사용자에게 설명했다.
- 포털로 재생 화면만 프리뷰 슬롯에 표시한다. 카메라 트리는 숨겨도 마운트를 유지한다.
- 애니메이션은 짧은 transform/opacity/색상 전환 위주이며 prefers-reduced-motion에서 끈다.
- Git 상태 조회는 기존 메타데이터 경로 누락으로 실패했다. 기존 파일 변경을 보존한다.

## 검증 결과와 남은 한계

- `make check-frontend`: 99개 파일·840개 테스트 통과. TypeScript·Vite 빌드 통과, 기존 큰 청크 경고 유지.
- 추가 회귀는 리플레이 탭의 프리뷰 전환/라이브 우선순위, 한 플레이어 유지, 위치 보존과 탭 이탈 시 정지,
  카메라 노드 보존을 검증한다. 높이 모션의 제어 상태별 실행·타이머 렌더 비재시작·reduced motion도 검증했다.
- 기존 탭의 자동 갱신 연결이 끊겨 원래 탭과 기록을 보존하고 최신 `/dev`를 별도 탭에서 확인했다.
  사용자 기록은 로컬 JSON으로 백업하고 새 화면의 파일 가져오기로 2,037프레임을 연결했다.
  실제 영상·랜드마크 파일은 저장소에 추가하지 않았다.
- 1624×924에서 좌측 프리뷰 슬롯 안 재생 화면 1개, 우측 옵션 안 화면 0개를 DOM/화면으로 확인했다.
  재생·일시정지·프레임 이동·좌표 보기, 탭 왕복 위치 유지, 테마와 시작 모달/옵션 표시를 확인했다.
- 402×874에서 가로 넘침 없이 상단 프리뷰/아래 옵션과 탭 표시를 확인했다. 실제 카메라 촬영은 하지 않았다.
- 기본 동작에서 탭 이동 240ms 및 테마/옵션 애니메이션을 확인했다. OS의 reduced-motion 전환을 직접
  변경하지는 않았고 해당 분기는 합성 단위 테스트와 CSS 미디어 규칙으로 검증했다.
- `make check-repo`는 기존 Git 메타데이터 경로 누락으로 실패. 수정 문서 링크·필수 경로·공백은 별도 부분 검사한다.
  전체 서버/DB 브라우저 게이트·전체 `make check`는 실행하지 않았다.
