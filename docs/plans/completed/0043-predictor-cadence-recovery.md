## 문제와 완료 기준

정상 영상 점이 보여도 250ms를 넘는 간헐적 처리 지연마다 3초 예측 입력을 모두 버린다.
예측 표시가 만료된 경우도 입력 부족으로 설명한다. 300ms 간헐 지연의 합성 입력에서 예측이 회복되고,
실제 품질 실패·긴 누락은 미측정으로 유지하며 현재 입력 개수와 초기화 이유를 표시한다.

## 범위와 제외

/dev 예측 코어·세션 감시·표시와 회귀 검증. 서비스 카메라 설정·실제 데이터·모델 가중치·학습은 변경하지 않는다.
규칙·알림·자동 라벨의 250ms 연속성 조건은 유지한다.

## 결정과 진행 기록

- 100ms 입력에서 매 20프레임마다 300ms 지연을 삽입하면 기존 구현은 예측 0회, 규칙 유효 570회/600프레임으로 재현된다.
- 실제 진단에는 812개 읽기 중 미측정 47개가 있고, 관측 간격 중앙값 약 81ms·95백분위 약 269ms다. 개별 자료는 저장소에 두지 않는다.
- 예측용만 유효한 두 관측 사이 최대 500ms의 짧은 지연을 인과적으로 보간한다. 가림/유효하지 않은 좌표·백그라운드·긴 단절은 보간하지 않는다.
- 250ms를 넘는 구간은 규칙/알림에서 계속 미측정이다. 500ms는 개발용 처리 지연 허용 상한이며 검증된 정확도 기준이 아니다.

## 검증 결과와 남은 한계

- `make check`: 저장소·문서 검사, Python **163개**, 프론트 **63파일 534개**, TypeScript·Vite 빌드 통과. Java 21/Maven 부재로 백엔드 단계에서 중단해 전체 게이트 통과는 아니다.
- 마지막 화면 문구 수정(초기화 이유와 최근 입력 간격 분리) 뒤 `npx vitest run src/features/developer/DeveloperCameraStage.test.tsx` **21개**와 `npm run build` 타입·빌드 재통과. 기존 500kB 초과 주 번들 경고는 남아 있다.
- 코어 회귀는 반복 300/450/500ms 지연, 500/501ms 경계, 실제 품질 실패/시간 역전, 예측 입력과 잔차 표본 분리, 미래 좌표를 채우지 않는 동작을 포함한다.
- 훅 회귀는 watchdog 도중 실제 LSTM 예측 복구, 실제 입력보다 앞선 감시 시각의 수신 처리, 초기 추론 지연을 관측 시각에 더하지 않는 동작, 종료/만료/백그라운드 차단을 확인한다.
- `make check-browser`: 생산 번들의 합성 진입 제외와 임시 서버 종료 확인 통과. Java Runtime 부재로 서버 준비에 실패하여 통합 브라우저 시나리오는 실행하지 못했다. Compose는 이번 변경에서 별도 재실행하지 않았다.
- 별도 in-app browser `/dev` 합성 데모에서 실제 LSTM 도식과 최근 입력 간격 표시, 규칙 판정·알림 병행, 종료 시 예측 제거를 확인했다. 콘솔 오류는 없었다. 준비량/초기화 이유/만료 안내의 각 분기는 컴포넌트 합성 테스트로 확인했으며 실제 웹캠을 다시 켜서 검증한 결과는 아니다.
- 실제 사용자 웹캠 촬영을 새로 실행하거나 원본 좌표를 보관하지 않았다. 기존 종료 진단의 간격 집계만 원인 확인에 사용했다.

실제 카메라 정확도·장시간 입력 품질은 합성 회귀로 입증하지 않는다. 모델 재학습·의존성 변경·서비스 경로 변경은 없다.
