## 문제와 완료 기준

사용자가 남은 작업을 모두 진행하고 테스트에서 발견한 문제를 수정하도록 요청했다.
직전 목록의 5~7번인 확인창 키보드 접근, 서버 지연 측정 도구, 참여자 분할/시간 창 준비 도구를 완성한다.

- 탈퇴·미확인 요약 보관 확인창에서 초기 초점, Tab/Shift+Tab, Esc, 배경 조작 차단과 닫힌 뒤 초점 복귀를 실제 브라우저로 확인한다.
- 합성 특징으로 추론 단독과 API→추론→CEP의 지연·처리량·실패 수를 구분하고 실행 조건/환경/코드와 입력 hash를 보관한다.
- 명시적 설정으로 참여자 분할을 먼저 생성하고, 자료 누수·hash 변경·촬영 소유 충돌을 거부한다.
- 시간 창은 촬영·구간·기준 등록·라벨·품질·누락 경계를 유지하고 실제 timestamp를 보존한다. 제외 행 양쪽을 연결하거나 보간하지 않는다.
- 새 컴포넌트 검증을 `make check`에 연결하고 기존 서비스·브라우저 회귀를 함께 실행한다. 발견한 결함은 최소 범위로 수정하고 재검증한다.

## 범위와 제외

프론트 공통 확인창과 두 소비자, 합성 브라우저 키보드 회귀, Python 개발 benchmark와 연구용 자료 준비 CLI/합성 사례를 변경한다.
실제 검증에서 확인된 CEP 최초 요청 준비·확인창 초점 복귀 문제도 관련 경계 안에서 수정한다.
한 파일에 모든 기능을 넣지 않고 UI/효과, 측정/환경/HTTP, 설정/자료/분할/창의 책임을 구분한다.

기술 스택·의존성·판정 임계값을 유지한다. DB·인증 환경 선택, 자정 집계·소리 선호·보존 기간 정책은 확정하지 않는다.
실제 카메라/참여자 자료 수집·모델 학습·배포·원격 push는 포함하지 않는다. 기존 변경과 사용자 임시 문서를 보존한다.
연구 창 길이·stride·라벨·분할 방식은 필수 설정으로 받으며 합성 예제의 값은 최종 연구 정책이 아니다.

## 결정과 진행 기록

- 카메라 정확도/FPS와 합성 서버 요청 지연은 구분한다. 미확정 성능 목표를 CI 지연 통과 기준으로 만들지 않는다.
- 실제 자료의 준비 결과와 분할 manifest는 Git 제외/외부 위치에만 쓴다. 저장소에는 명시적 합성 예제만 둔다.
- 시험 참여자의 이탈 자료는 fit/tuning에 넣지 않고 기준 등록 자료는 평가 창에서 분리한다.
- 자료 결과 폴더는 배타적으로 확보하고 완료 manifest를 마지막에 게시한다. 동시 실행이 만든 빈 폴더나 파일을 덮어쓰지 않는다.
- benchmark는 환경/OS proxy·HTTP redirect·자동 재시도를 사용하지 않아 합성 loopback 요청 조건을 유지한다.
- 실제 Chrome에서 요약 보관 후 trigger 제거 시 초점 복귀 실패를 재현했다. 단순 대기 연장으로 통과시키지 않고 원인을 수정한다.
- cold CEP 첫 생성에서 API 502를 관찰했다. 최초 요청의 lazy EPL 준비가 gateway 기한에 영향을 줄 수 있으므로 서비스 시작 단계의 준비와 최초 요청을 함께 검증한다.
- 초점 복귀를 native dialog 닫기와 분리하여 DOM 갱신 이후 실행한다. 제거된 trigger 대신 주영역을 사용하고 복귀 성공을 실제 초점으로 확인한다.
- CEP 준비를 Spring 시작 단계로 옮겼다. 임시 runtime은 즉시 종료하며 사용자 세션·관측·용량을 소비하지 않는다. API 기한·EPL·정책은 유지했다.
- 결과 게시 전 폴더를 배타적으로 확보하고 파일도 배타적으로 쓰며 완료 manifest를 마지막에 게시한다. 실패 정리는 자신이 생성한 파일/폴더에만 적용한다.

## 검증 결과와 남은 한계

2026-10-01 현재 Mac 작업 폴더에서 실행했다. 최초 환경 준비와 JDK 21/Maven은 기존 캐시를 사용했고 새 의존성은 추가하지 않았다.

- `make check` 전체 exit 0: 저장소/링크 검사, Python **93개**, 프론트 **189개(21파일)**, Java **53개(API 33/CEP 20)**, TypeScript·Vite/JAR 빌드 통과.
- 실제 Vite proxy·API·FastAPI·CEP HTTP 흐름에서 3/2/60 경계·고정 정책·중복·처리 후 응답 유실·의존성 실패·최종 종료 확인을 검증했다.
- 전체 게이트의 짧은 benchmark: 각 경로 warmup 1개·측정 4개·worker 2개, 성공 4/실패 0/미실행 0. 서비스 종료·포트 해제 통과.
- 실제 Chrome **61개** 합성 회귀: 기존 측정·휴식·복구·서버 유실·기록 흐름과 native 확인창 키보드/초점/취소/명시적 확인을 검증했다. 브라우저·debug 포트·두 Vite·세 서비스 종료 통과.
- 독립 benchmark: 두 경로 각각 warmup 10개·측정 100개, worker 1개/2개를 차례로 실행하여 총 400개 성공·실패/미실행 0. 같은 소스/JAR/합성 입력 hash와 실행 전후 소스 동일 여부를 확인했다. 환경·median/p95·처리량은 [측정 기록](../../audits/2026-10-01-server-benchmark.md)을 따른다.
- 합성 자료 CLI 실행: train/validation/test 각 2개 창·기준 등록 3개, 완료 manifest·train 참여자만 fit 대상·학습 미실행을 확인했다. 자료 준비 23개와 benchmark 19개 단위 검증도 대상으로 재실행했다.
- fresh CEP/API 최초 생성 HTTP 200(약 277ms), 같은 생성 재요청 200(약 3ms), 빈 사건/통계와 동일 응답·종료 확인·포트 해제를 확인했다. 목표 지연 통과 기준으로 쓰지 않는다.
- 최종 문서 갱신과 완료 계획 이동 후 `make check-repo`와 `git diff --check` 통과. 각 컴포넌트의 마지막 읽기 전용 교차 검토에서 추가 중대한 불일치는 발견하지 않았다.

전체 로그는 `.cache/remaining-tools-check.log`, 브라우저 진단은 `.cache/browser-smoke/browser-run.log`에 보관한다.
Vite의 기존 큰 chunk 안내는 남아 있지만 빌드는 통과했다. 측정치는 합성 loopback HTTP 실행의 관찰값이다.
실제 영상·참여자 자료·모델 가중치·비밀값을 추가하지 않았으며 기술 스택·의존성·확정 정책은 바꾸지 않았다.

DB/로그인 방식·동의/보존/삭제·자정 집계·소리 선호·조건별 비교 정책은 선택/후속 구현이 남는다.
실제 카메라·음향·장시간 백그라운드·장치 FPS·모델 정확도·학습/에피소드 평가·기준 유도 과정,
원격 CI와 Windows/Linux 실행은 검증하지 않았다. 합성 자료 예제의 창 설정은 연구 정책을 확정하지 않는다.
