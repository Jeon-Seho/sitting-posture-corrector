## 문제와 완료 기준

현재 로컬 앱과 예전 서버 클라이언트를 구분하고, 서버 모드에서 현행 계약으로 인증·설정·기준 등록·측정·기록을 연결한다.
기본 로컬 앱은 유지한다. 프론트 합성 API/소켓 시험·타입·빌드와 가능한 브라우저 검증 결과를 기록한다.

## 범위와 제외

프론트와 브라우저용 기준 등록 보조 코드·관련 문서를 바꾼다. BE·DB·인프라 설정과 동의 문서 버전은 바꾸지 않는다.
T1/R1b·이메일 인증 서버·CORS·Kafka·자정 세션 분리·서버 자동 종료 활성화는 외부 의존으로 남긴다.

## 결정과 진행 기록

기존 `VITE_SERVER_ACCOUNTS=true`를 명시적 서버 실행 모드로 복원한다. 새 설정을 추가하지 않는다.
서버 모드는 로컬 계정/기준/기록을 가져오지 않고, 학습된 모델을 연결했다고 표시하지 않는다.
이전 계정 모듈은 참고 코드로 옮겨 현행 형식·탈퇴 철회 없음·현재 UI에 맞춘다.

## 검증 결과와 남은 한계

- 프론트 테스트 402개·TypeScript·Vite 빌드 통과. 합성 카메라/HTTP/소켓 자료만 사용했다.
- `check-browser` 35개 통과: 실제 임시 MySQL·API·추론 + 합성 카메라. 가입 → 기준 등록 → 좌표 WebSocket → 이탈·휴식·복귀 → 종료 저장 → R1 → 로그인 복원. 브라우저·시험 서버·DB·컨테이너 정리 통과.
- `node frontend/scripts/smoke-developer-login.mjs`: 로컬/서버 앱 모두 admin/1234 우회 로그인, 잘못된 비밀번호 거부, 가계정 인증 요청 없음, 브라우저 오류 없음.
- 최초 백엔드 준비의 Java 빌드/단위 단계 통과(API 72개 중 64 통과·8 MySQL 제외, 처리 서비스 60 통과). MySQL 단계는 빠진 Python 패키지 때문에 첫 실행 실패 후 지정된 의존성을 준비했다. 후속 결과는 인계 문서에 기록한다.
- `check-repo`·`git diff --check` 통과. 전체 `make check`, Compose 이미지/배포, 실제 카메라·절전 확인은 실행하지 않았다. 패키징 EXE의 합성 검증은 아래 후속 결과를 따른다.
- 외부 의존·추가 장치 확인은 [쉬운 인계](../../design/frontend-handoff-2026-10-27.md)에 남긴다. 다른 담당자에게 메시지를 전송하지 않았다.

개발자 가계정은 사용자 요청으로 추가했다. DB 계정이나 서버 권한을 만들지 않으며 로컬 앱으로만 진입한다.

후속 검증: `check-backend` 재실행 통과(API 72개 모두 통과·처리 서비스 60개 통과, 실제 MySQL/추론 HTTP 포함). Python 151개 중 150 통과·1 건너뜀. 전체 `make check`와 Compose 검증은 실행하지 않았다.

추가 확인: 초기 로그인 복원과 가입이 겹칠 때의 CSRF 쿠키 경쟁을 직렬화하고 단위 시험 2개로 재현했다. Windows 패키징·실제 EXE admin/1234 우회 로그인(API/DB 요청 없음)도 통과했다. 실제 카메라·절전·운영 배포 확인은 별도다.

최종 패키징 확인: `npm run desktop:pack`, `node scripts/smoke-packaged-ui.mjs`, `node scripts/smoke-desktop.mjs` 통과. EXE 가계정 로그인/API 요청 없음·정적 자산·IPC·보안 컨텍스트·Web Locks·합성 카메라/모델 초기화를 확인했다. 실제 카메라를 사용하지 않았다.
