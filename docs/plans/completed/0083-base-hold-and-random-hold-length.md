## 문제와 완료 기준

기준·이탈 2클래스 학습에 쓸 기준 샘플이 없었다. 등록 프레임은 기준점이라 특징이 0 근처에 몰리고, 복귀 구간은 돌아오는 동작이 섞이며 측정하지 않았다.
각 동작 뒤 기준 측정 구간을 두고, 측정 시간을 동작마다 8~15초 중 1초 단위로 뽑는다. 실제로 뽑은 길이를 리플레이 JSON에 남긴다. 기존 v1~v6 파일은 계속 읽는다.

## 범위와 제외

`/dev` 안내 프로토콜·리플레이 기록 v7·ML 후보 특징 JSON의 `schedule`·안내 문구·관측 내보내기 계약과 문서. 서비스 판정, 기준 등록 방식, 실제 카메라 성능 검증은 제외한다.

## 결정과 진행 기록

- 한 동작: 준비 2초(`move`) → 동작 측정(`hold`) → 복귀 준비 3초(`return`, 측정 안 함) → 기준 측정(`hold`, `task=neutral`).
- 동작 측정과 그 뒤 기준 측정은 같은 길이다. 스트레칭 측정도 같은 규칙이다.
- 프로토콜 `front-observation-base-hold-v7`, 기록 `observation-keypoint-replay-v7`. v4~v6 파일은 이전 프로토콜 ID만 받는다.
- 이탈 강도는 기록하지 않는다(사용자 결정).
- 비교표의 기준 자세 행은 기준 측정 구간 중앙값으로 채워진다.

## 검증 결과와 남은 한계

- `make check`: 저장소 검사, Python 98개, 프론트 927개 테스트와 TypeScript·Vite 빌드 통과. 이후 백엔드 단계는 Java 런타임 부재로 실패.
- `git diff --check` 통과. `npm run lint`의 기존 오류(`any`, hook 의존성 경고)는 이번 변경과 별개로 남아 있다.
- 브라우저: `/dev` 시작 창의 새 안내 문구를 확인했다. 실제 카메라로 한 사이클을 측정하지 않았다.
- 화면 시계가 남은 초를 보여주므로 끝을 예측하는 효과는 남는다. 8~15초·3초는 검증하지 않은 수집 설정이다.
