## 문제와 완료 기준

Mac의 `main` / `02b9ea8`을 확인했다. 원격은 `Jeon-Seho/sitting-posture-corrector`이며 시작 시 작업 트리는 깨끗하다.
현재 구현과 요구를 비교하고, 손상된 로컬 자료·복구·동시 탭·측정 불가·기준 재등록의 실패 경로를 합성 자료로 검증한다.
기존 사용자 자료를 지우거나 손상 자료를 빈 목록으로 덮어쓰지 않는다. `make check`와 카메라 없는 브라우저 흐름을 검증한다.

## 결정과 진행 기록

원본 저장소가 쓰기 작업 공간 밖에 있으므로 허용된 작업 공간의 로컬 복제본에서 수정·검증한 뒤 변경만 반영한다.
Mac에서는 최초 `make setup`으로 공식 Lite 모델 다운로드와 SHA-256 검증이 성공했다. 다른 클라우드의 403을 이 환경의 결과로 간주하지 않는다.
브라우저 종료일 기준 날짜 집계라는 기존 임시 정책을 명시하며 자정 분할 정책은 확정하지 않는다.
사용자가 develop 기능 가져오기를 승인했다. main 수정본은 복구 가능한 로컬 커밋과 백업으로 보존하고,
최신 develop의 기록 비교·실제 웹캠 준비·수집 화면 기능을 유지하며 보완을 통합한다. main 원격 push는 보류한다.

## 검증 결과와 남은 한계

초기 `make check`: Python 10개·프론트 29개·타입·빌드 통과. main 기반 보완 후 프론트 66개·타입 검사 통과. develop 통합본 `make check`: Python 11개·프론트 79개·타입·빌드와 저장소/문서 검사 통과 (Mac Python 3.9.6, Node 24.21.0).
합성 브라우저 흐름에서 빈 홈, 등록, 측정, 화면 이동 후 수동 재개, 두 번째 탭 읽기 전용을 확인했다.
재접속 중 브라우저 제어 연결이 닫혀 통합 후 재검증이 필요하다. 서버·개인화 모델·실제 장치 측정은 구현 완료로 표시하지 않는다.

## 보존·통합과 인도 상태

main 보완본은 로컬 `540ff01`과 `backup/mac-main-reliability-20260930`, 작업 공간의 bundle로 보존했다. 최신 원격 develop은 `9533234`이며 별도 `develop-repo` 작업 트리에서 기능을 유지하며 통합했다. 원본 Desktop 경로에 백업 ref와 검증된 develop을 반영했다. 그 경로에서 `make setup` 및 최종 `make check`를 통과했다(Python 11개·프론트 79개·타입·빌드·저장소/문서). native FSEvents의 기동 대기를 재현하여 명시적 polling 실행 옵션을 추가했고 표준 개발 명령이 55ms에 준비되었다. 앱·소스·모델·WASM의 HTTP 응답 6개와 모델 SHA-256을 확인했다. 시험 서버를 종료하고 포트 5178에 listener가 없음을 확인했다. main은 push하지 않으며 승인된 origin/develop 일반 push와 실제 원격 SHA는 최종 인도 보고에서 확인한다.

[전체 기능·품질·시간 조건 점검](../../audits/2026-09-30-mac-develop.md)에서 해결 범위와 결정/접근이 필요한 항목을 구분한다. 원본 사용자 자료는 테스트하지 않고 Git 외부 자료나 브라우저 저장소를 삭제하지 않는다. CUA 연결은 재접속 후에도 닫혀 통합본 UI 재검증이 막혔다.
