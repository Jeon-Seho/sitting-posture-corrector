## 문제와 완료 기준

/dev에 Face Landmarker를 기본 켜짐으로 추가하고 실제 얼굴 윤곽을 표시한다. Pose와 같은 영상의 얼굴 점 차이·유효 검출·처리 지연을 비교한다. 추출 좌표를 임의로 아래로 이동하지 않는다. 안경 효과는 실제 동일 자세 비교로 확인하며 성공을 가정하지 않는다.

## 범위와 제외

개발 전용 Worker·메모리 얼굴 추적·비교 UI·공식 모델 자산 준비, 합성 실패/시간/폐기 검증. 서비스와 기존 Pose 39D 수집/학습 입력은 유지한다. Face 상대 z를 Pose world xyz로 대체하지 않는다. 공개 자료는 공식 출처·포인트·시간·이용 조건을 조사하고 새 실제 학습은 실행하지 않는다.

## 결정과 진행 기록

공식 Face Landmarker v1과 기존 tasks-vision을 재사용한다. 카메라 이미지 복사 한 장만 진행하며 얼굴 추론은 Worker에서 최대10Hz로 실행한다. Face가 실패하면 추적 불가를 표시하고 기존 Pose 비교는 유지한다. 정확도 정답 없는 차이/움직임 지표를 오차율이나 정확도로 주장하지 않는다.

## 검증 결과와 남은 한계

- `make check`: 저장소 검사·Python195개·프론트703개(76파일)·TypeScript/생산 빌드 통과. Java21/Maven 부재로 백엔드부터 중단했으며 Compose 단계에 도달하지 않았다. 전체 게이트 성공이 아니다.
- 실제 얼굴 비교에서 사용자가 Face를 기본으로 선택한 뒤 기존 Pose 얼굴 기준선을 Face 모드에서 숨겼다. 해당 UI 변경 후 `make check-frontend`를 재실행하여703개·TypeScript·생산 빌드가 다시 통과했다.
- `make check-browser`: 생산 번들 합성 입력 제외·시험 서버 정리 통과, Java 런타임 부재로 앱 통합 회귀는 실행하지 못했다.
- 새 합성 회귀14개: 일치 시각·해상도·가시성·방향·픽셀 단위, 실패를 포함한 분모,단일 요청·취소/늦은 bitmap·다른 얼굴 대상·시간 만료/초과, 진짜 Face 윤곽/어깨 분리·누락 시 얼굴 보간 금지, 비교 UI 출처를 검증했다. 기존 Route/카메라 통합 검증도 실행했다.
- 실제 module Worker의 `ModuleFactory not set` 오류를 확인하고 classic IIFE로 고쳤다. 별도 GPU delegate로 실제 Face 관측과 착용/미착용10초 비교가 동작했다. 첫 병행 검사 중3초 응답 제한은 한 번 작동했고 재연결 후 안정적으로 관측됐다. 해당 원인을 맥북 하드웨어 성능 부족으로 확정하지 않는다.
- [실제 비교 집계](../../ml/measurements/face-tracking-2026-10-15.md): 착용79/79·미착용77/77 유효, 평균 차이16.8/8.0px, Face 추론23.2/24.6ms. 위치 차이는 정답 오차가 아니며 촬영 거리/각도 통제가 불완전하다.
- Face 기본 채택은 /dev 얼굴 추적/표시 선택이다. Pose world39D·정상 수집·LSTM·알림은 유지하며 Face 상대z를 섞지 않는다. 새로운 Face 입력 계약·정상 모델/예측 학습·정답 기반 오탐 검증은 후속이다. 자동 정상 수집은 비교 동안 일시정지했고 새 학습은 실행하지 않았다.
- 공식 Face 모델은 기존SDK를 재사용하고 Git 제외 자산으로 준비했다. 공개 MultiPosture API 접근/라이선스/hash를 다시 확인했고 Panoptic/EYEDIAP 공식 자료와 과거 실제 학습 기록을 구분해 문서화했다. 영상/좌표/가중치를 저장소에 추가하지 않았다.
