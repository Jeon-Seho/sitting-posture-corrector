# 관측 영상과 그래프 동시 보기 계획

- 상태: completed

- 시작일: 2026-10-26
- 관련 요구사항/ADR: 사용자 동시 보기 요청·브라우저 주석 1~2, [관측 화면 설계](../../design/developer-lab.md), [관측 라우트](../../decisions/0042-unified-dev-observation-route.md)

## 문제와 완료 기준

1384×774 브라우저에서 현재 4:3 영상은 832×624px, 카드 그리드는 약 667px 높이다.
큰 영상 아래 탭·카드를 쌓아 그래프를 보는 동안 영상과 측정 제어가 화면 밖으로 사라진다.
영상 속 자신과 수치 변화를 동시에 확인할 수 있어야 하며, 사용자 주석의 카드 문구·정렬도 함께 수정한다.

계획 검토 후 사용자가 구현을 요청했다. 영상은 보이기만 하면 되며 초기 크기는 작게 적용하고 이후 피드백으로 조정한다.

## 범위와 제외

- 이후 구현 범위: ObservationLab/Guide/Tools의 배치·카드 헤더·보조 설명과 관측 CSS, 관련 회귀 검증.
- 기존 4:3 비율·캡처 입력·랜드마크 추출·계산·품질 정책·준비/측정 시간·CSV/JSON 형식은 유지한다.
- 영상 크기/레이아웃 전환으로 카메라 스트림·안내·기준·수집·리플레이를 초기화하지 않는다.
- 같은 스트림의 중복 영상/추론 인스턴스, 새 점수·판정·가짜 측정값은 추가하지 않는다.

## 대안 비교와 권장안

| 대안 | 장점 | 한계 | 판단 |
| --- | --- | --- | --- |
| 좌측 고정 영상 + 우측 분석 | 영상/진행 제어와 그래프를 함께 읽으며 서로 가리지 않음 | 영상이 현재보다 작아지고 충분한 가로 폭이 필요함 | 데스크톱 기본 권장 |
| 모서리에 떠 있는 작은 영상 | 기존 세로 구조를 유지하며 화면 사용량이 적음 | 그래프·수치를 가리고 드래그/키보드 접근 설계가 더 필요함 | 첫 구현의 기본 방식으로 채택하지 않음 |
| 위쪽 축소 영상 + 아래 분석 | 좁은 화면에서 가로 스크롤 없이 동시 확인 가능 | 세로로 볼 수 있는 그래프 수가 줄어듦 | 좁은 화면 대안 |

### 1. 넓은 화면의 함께 보기

- 우선 1200px 이상에서 좌우 분할을 검토한다. 최대 컨테이너 폭은 약 1320px로 늘리고 실측으로 확정한다.
- 1384×774 기준 제안: 좌측 영상 약 540~560×405~420px, 우측 분석 약 650~700px, 간격 20~24px.
  모두 CSS 표시 크기이며 입력 해상도 변경이 아니다.
- 좌측은 sticky로 고정한다. 우측 내용이 길어 페이지를 스크롤해도 영상과 종료 버튼이 보이게 한다.
  별도 내부 스크롤 영역을 여러 개 만들지 않는다.
- 작은 영상의 얼굴을 큰 타이머 카드가 가리지 않도록 현재 동작·남은 시간은 영상 아래 간결한 안내행으로
  이동한다. 다음/일시정지/빨간 종료 버튼은 같은 좌측 영역에서 유지한다.
- 우측 상단에 가운데 정렬 탭을 두고 그 아래 여섯 카드를 2열로 배치한다. 모든 탭에서 좌측 영상을 유지한다.
- 카드 간격·패딩과 그래프를 조정하되 작은 수치·축 글자를 무리하게 줄여 한 화면에 끼워 넣지 않는다.
- 영상 자세 확인이 더 중요할 때 쓸 `영상 크게 / 함께 보기` 전환 하나를 제공한다. 전환은 배치만 바꾼다.

### 2. 좁은 화면과 낮은 화면

- 좌우 열이 읽기 어려워지는 폭에서는 위쪽의 작은 4:3 영상 + 아래 분석으로 전환한다.
- 영상/현재 단계/종료를 포함한 상단 고정 묶음의 높이를 제한해 그래프가 보일 공간을 확보한다.
  예비 목표는 영상 150~200px 높이이며 실제 텍스트 배율·높이를 보고 조정한다.
- 카드가 충분한 폭이면 2열을 유지하고, 320/402px에서는 1열로 전환한다. 떠 있는 영상으로 그래프를 덮지 않는다.
- 카메라가 꺼졌을 때에는 불필요한 고정 빈 공간을 만들지 않는다. 다시 켜기와 기존 분석·리플레이 접근은 유지한다.
- 세로가 짧거나 200% 글자 확대를 사용하면 최소 읽기 크기를 유지하고 자연스러운 페이지 스크롤을 허용한다.

### 3. 브라우저 주석 1: 상대 z 카드

- 여섯째 카드는 설명문 중심의 별도 패널 대신 다른 카드와 동일한 헤더·아이콘·큰 값·작은 단위를 사용한다.
- 제목은 `상대 z 좌표`처럼 현재 표시의 의미에 맞춘다. 현재 값/미측정 표시는 다른 카드와 같은 방식으로 보존한다.
- 수식과 긴 해석 문단은 도움말로 이동하고 카드 아래 보조 문구는 `기준 {값} m · 모델 추정`만 남긴다.
  실제 기준이 없을 때는 `기준 없음`이며 0으로 채우지 않는다. 실제 개인 수치를 소스에 하드코딩하지 않는다.
- 이 카드는 raw world z 차이(m), 기존 핑크 카드는 등록 world 어깨폭으로 정규화한 기준 대비 변화(%)다.
  둘의 단위를 합치거나 raw 값을 퍼센트 그래프 축에 넣지 않는다. 장식용 가짜 그래프도 추가하지 않는다.
- 의미: 현재 구현은 `worldLandmarks[0].z - (worldLandmarks[11].z + worldLandmarks[12].z) / 2`다.
  MediaPipe world 좌표의 단위는 m이며 엉덩이 중점을 원점으로 삼는다. 모델 출력의 좌표 차이이므로
  실제 목의 전방 길이나 깊이 센서 실측 거리로 표현하지 않는다.
- 근거: [MediaPipe Web Pose Landmarker 공식 출력 설명](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js).

### 4. 브라우저 주석 2: 설명 위치와 정렬

- `＋ 코와 어깨 사이가 영상에서 더 벌어짐` 등의 지표 설명을 카드 하단에서 해당 제목 옆의 헤더로 옮긴다.
- 제목과 설명은 아래쪽을 맞춘다(`align-items: flex-end` 방향). 오른쪽 2D/Pose world 표시와 충돌하지 않게 한다.
- 분할 보기에서 카드 폭이 작아지면 설명은 같은 헤더 묶음 안에서 자연스럽게 줄바꿈한다.
  측정값·단위·그래프를 가리거나 말줄임만으로 의미를 잃게 하지 않는다.

## 검증 계획과 수용 기준

- 1384×774, 1280×720: 영상·현재 단계·빨간 종료와 하나 이상의 실제 그래프가 스크롤 없이 함께 보인다.
  우측 나머지 내용을 스크롤해도 좌측 영상·종료 접근이 유지된다. 여섯 카드는 2열을 유지한다.
- 1024px, 402×874, 320×774: 적절한 전환, 가로 넘침 없음, 고정 영상이 수치·탭·버튼을 덮지 않음을 확인한다.
- 다크/라이트, 키보드 탭 이동과 초점 가림, 200% 확대·짧은 높이를 검수한다.
- 카메라 연결/기준 등록/자동 진행/수동 다음/일시정지/종료, 측정 불가, 탭 변경, 레이아웃 전환을 합성 입력으로 검증한다.
  이동 전후 같은 스트림·기준·타이머·누적 프레임을 유지하며 중복 녹화·추론·자료 초기화가 없어야 한다.
- 기존 CSV/JSON 다운로드와 리플레이 접근, 기존 관측 누락 구간 표시를 보존한다.
- 구현 후 `make check-frontend`와 가능한 브라우저 검증을 실행한다. 실제 카메라를 켜는 검증은 합성 UI와 구분한다.

## 구현 조정

- 사용자 후속 지시에 따라 기본 영상은 약 280~360px 너비로 줄여 분석 공간을 우선한다.
- 보기 전환 상태를 별도 Workspace에 두고 동일한 영상/안내/도구 트리를 CSS로 배치한다.
  ObservationLab의 카메라·세션 훅을 이동하거나 새로 만들지 않는다.

## 검증 결과와 남은 한계

- `make check-frontend`: 98개 파일·837개 테스트 통과, TypeScript·Vite 빌드 통과. 기존 500kB 청크 경고 유지.
- 추가 회귀는 실제 ObservationLab에서 합성 기준 등록 후 영상 크게/함께 보기를 전환하여 동일 영상 노드,
  같은 안내 snapshot, 누적 리플레이와 카메라 연결/종료 횟수 보존 및 이후 기록 연속 증가를 확인한다.
- 별도 임시 합성 CameraController를 실제 ObservationLab에 연결한 브라우저 검수에서 준비 2초/기준 8초,
  수동 다음의 시간 잠금·활성화, 측정→일시정지, 보기 전환, 종료 후 리플레이 활성화를 확인했다.
  실제 카메라·영상은 사용하지 않았고 임시 소스/탭은 제거했다.
- 1384×774에서 약 360×270px 영상과 여섯 카드가 동시에 보인다. 1280×720에서 우측 스크롤 후에도
  영상과 종료가 화면 안에 남는다. 1024×768에서는 상단의 작은 영상/안내 구조로 전환했다.
- 402×874 라이트, 320×774 다크에서 가로 넘침 없이 고정 프리뷰와 그래프를 확인했다. 320px의 방향키
  탭 이동과 Tab/Shift+Tab에서 초점이 고정 프리뷰 아래로 드러나는 것을 확인했다.
- 최종 실제 `/dev`는 기존 리플레이 2,037프레임을 유지했고 새로고침·실제 촬영·자료 다운로드를 하지 않았다.
  실제 탭과 합성 검수 탭의 console error는 각각 0건이다. 증거는 루트 `design-qa.md`에 기록한다.
- `make check-repo`: 기존 Git 메타데이터 경로 누락으로 실패. 수정 문서 링크·필수 경로·공백은 별도 부분 검사를 실행한다.
- 실제 사람 영상의 장치별 가독성, 200% 글자 확대, 전체 서버/DB 브라우저 게이트와 `make check`는 미검증이다.
  짧은 높이는 sticky를 해제하도록 구현했으나 별도 활성 측정 스크린샷 검수는 하지 않았다.
- 기본 프리뷰 너비는 CSS 변수 `--oc-preview-width`로 조정할 수 있다. 사용자가 이후 크기를 피드백할 예정이다.
