# 다음 작업

아래는 후속 작업이다. [웹캠 프론트 프로토타입](completed/0003-frontend-prototype.md)으로
정면 카메라·개인 기준 비교 규칙·데모·알림·현재 세션 통계를 먼저 연결했다.
이는 촬영 비교 실험이나 최종 정책 검증을 완료했다는 뜻은 아니다. 진행 작업은 [활성 계획](active/)을 확인한다.

사전 정합성 작업: [현재 계획서의 차이·미결정 사항](../references/current-proposal-review.md)을 바탕으로
LSTM/GRU 역할, 품질 게이트와 학습 클래스, 이탈 유형 제공 여부, 사용자/세션 평가 구분, 이벤트 간격 정의를 정리한다.
기존 v1 출력 계약은 그대로 두며 이진 자세 모델 통합 전 호환성을 검토한다.

1. **촬영 가능성 프로토타입**: 정면/측면/45도에서 누락률·흔들림·분리도 측정, 단일 시점과 자세 유형 결정.
2. **런타임과 스택 결정**: 계획상 React/TypeScript·Spring Boot·Python/LSTM, 클라이언트 특징 추출/분리 추론 방향을 검증하고 버전·전송 계약·DB를 확정.
3. **합성 시퀀스로 최소 흐름 연결**: 기준 등록 → 품질 처리 → 규칙 기반 상태 출력 → 프론트 표시.
4. **확정 알림 정책 유지·실기기 검증**: [ADR 0012](../decisions/0012-session-timing-policy.md)의 3초·2초·60초, 중단 후 새 사건, 제외 시간과 다음 세션 설정을 기존 로컬/CEP 구현에 유지한다. 합성 검증은 구현돼 있으며 실제 입력·기기 검증이 남는다.
5. **수집 프로토콜 동결**: 동의·보관·라벨·분할·설정 확정 후 실제 데이터 수집.
6. **모델 비교와 에피소드 평가**: 기존 M0~M4와 LSTM 계획 통합 후 참여자 분할 누수 검증, 소거실험, 이벤트 재현율·지연·오알림과 재현 정보 기록.
7. **세션 통계·통합 검증**: 사용자별 접근 격리, 이벤트/API/저장 계약, 유효 시간·회복 시간·기간별 대시보드, 목표 장치에서 지연/FPS 검증.
8. **개입 파일럿 설계·실행**: 탐지 성능 검증 후 A/B/A′ 각 1주 계획과 분석 기준 확정. 판정 버전을 고정하고 관찰 결과와 효과 해석의 한계를 보고.

각 작업은 필요할 때 [양식](template.md)으로 실행 계획을 만든다. 기술 부채나 새 미결정 사항도 이 파일에 남긴다.

API·CEP 합성 수직 흐름의 구현 범위와 후속 순서는 [서비스 안내](../../backend/README.md)를 따른다.
정상 복귀/휴식 타이머 정책은 [ADR 0012](../decisions/0012-session-timing-policy.md)로 확정했다.
개발용 세 특징·품질·관측 구간 계약과 선택형 프론트 서버 모드, 동일 요청 재시도·서버 유실 처리를 연결했다
([ADR 0013](../decisions/0013-frontend-server-feature-connection.md)). DB·인증 환경은 미정이며
[연결 설계](../design/server-persistence-and-auth.md)까지만 정리했다. 다음은 실제 입력/품질·성능 검증,
DB·인증 방식 선택과 사용자 격리·영구 저장·재시작 재생 구현이다.
Kafka·Redis는 전달/재생/상태 복구 계약, HDFS·Spark는 승인된 연구 자료·동의/보관/분할 계약 후 단계별 도입한다.
미래 예측·사용자별 LSTM 재학습·대규모 합성 데이터 생성기는 현재 필수 범위가 아니다.

Mac 보완 후 로컬 완료/남은 범위는 [종합 점검](../audits/2026-09-30-mac-develop.md)을 따른다.
서버 인증·복구·동의/삭제, 영구 기준/예시 활용, 실제 장치 검증, 자정 분할과 비교의 조건별 그룹/제외 정책,
자료 보존 한도와 재시도 정책은 여전히 다음 작업이다. 로컬 손상 원본 보존·동시 탭 제한·재보정 취소는 보완했다.

완료한 [서버 회귀·기록 상세 보완](completed/0015-server-regression-and-record-details.md)은 실제 HTTP 재알림/응답 유실,
합성 브라우저 측정·종료·복구와 기록 상세·비교 조건 안내를 구현·검증했다.
[확인창·성능 측정·자료 준비 보완](completed/0016-remaining-tools-and-validation.md)으로 확인창 키보드/초점,
합성 HTTP benchmark, 참여자 분할/시간 창 준비 도구도 구현하고 전체 게이트를 통과했다.
자료 준비 도구는 합성 예제로 검증했으며 실제 자료 수집·연구 설정 확정·학습/에피소드 평가는 남는다.
서버 benchmark는 현재 기기의 합성 요청 지연이며 실제 카메라/FPS·장시간·배포 성능 검증을 대체하지 않는다.
소리 선호 유지·자정 분할·비교 조건별 그룹/제외·보존 기간은 별도 제품 결정과 후속 구현이다.
