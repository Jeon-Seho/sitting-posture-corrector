## 문제와 완료 기준

노트북 내장 카메라가 있는 PC에 USB 카메라를 꽂아 쓰면, 메인 카메라를 고른 적이 없을 때 OS 기본 카메라(대개 내장)가 잡힌다.
앱을 켜 둔 채 꽂거나 빼도 안내가 없다. 측정 중 카메라가 빠지면 오류로 멈춘다. 640×480을 못 주는 카메라도 다른 크기로 열린다.

이 계획은 **동시에 여러 대로 측정하는 것이 아니다.** 측정은 언제나 카메라 한 대다(제품 범위). 여러 대 중 어느 것을 쓰고, 바뀔 때 어떻게 할지를 정한다.

완료 기준: 아래 결정 1~4가 앱에서 동작하고, 가짜 카메라 목록 시험과 실제 노트북 + USB 카메라 확인 결과가 아래에 기록돼 있다.

## 지금 동작 (10/16 코드 확인)

| 상황 | 지금 | 코드 |

## 결정 (2026-10-16 사용자)

1. **처음 켤 때 카메라가 2대 이상이고 메인을 고른 적이 없으면 외장(USB) 카메라를 자동으로 고른다.**
   - 브라우저는 카메라 권한 전에는 이름(`label`)을 숨긴다. 그래서 먼저 기본 카메라로 한 번 열어 권한을 받은 뒤, 이름이 보이는 목록에서 외장을 찾는다.
   - 외장 판별: 이름에 내장 표시(`Integrated`, `Built-in`, `FaceTime`, `내장` 등)가 없는 카메라. 여러 대면 목록에서 첫 번째. 판별할 수 없으면(모두 내장으로 보이거나 이름이 없으면) 지금처럼 기본 카메라를 쓴다.
   - 고른 카메라는 메인으로 저장하고 「USB 카메라로 측정해요. 설정에서 바꿀 수 있어요」를 짧게 알린다. 한 번 저장하면 다음부터는 결정 없이 그 카메라를 쓴다.
   - 사용자가 설정에서 「기본 카메라 (자동)」를 고르면 자동 선택을 다시 하지 않는다(그 선택을 존중).
2. **켜 둔 채 새 카메라를 꽂으면 알림만 한다.** 「새 카메라가 연결됐어요. 바꿀까요?」와 「바꾸기」 버튼. 측정 중에는 바꾸지 않고(기준 자세가 카메라마다 다르다), 측정이 끝난 뒤 바꿀 수 있게 한다.
3. **측정 중 쓰던 카메라가 빠지면 그 자리에서 측정을 끝내고, 그때까지의 기록은 저장한다**(10/16 정정: 팀원이 원한 동작). 다른 카메라로 자동으로 넘어가지 않는다. 결과 화면에 「카메라 연결이 끊겨 측정을 끝냈어요. 끊기기 전까지의 기록은 저장했어요」를 보인다. 새 측정은 측정하기에서 카메라를 고르고 시작한다. 고른 카메라에 기준 자세가 없으면 등록한 뒤 새 측정을 한다. (처음 적은 「자리 비움으로 멈추고 재개」는 취소. 서버 연결 뒤에도 같은 규칙으로 `end`를 보낸다.)
4. **640×480을 못 주는 카메라는 시작하지 않는다**(F13, 팀 결정). 열린 크기가 640×480이 아니면 「이 카메라는 640×480을 지원하지 않아요」를 보이고 다른 카메라를 고르게 한다.
5. **기준 자세는 카메라와 상관없이 하나만 둔다**(10/16 팀 논의로 정정). 카메라를 바꾸거나 다시 꽂아도 그 기준 자세를 그대로 쓰고, 「이 카메라에 맞는 기준 자세가 있는지」 판별하지 않는다. 사용자가 화면을 보며 카메라 각도를 자기 자세에 맞춘다. 다시 잡고 싶으면 「다시 등록」. 이유: 카메라마다 등록하게 하는 건 비효율적이고, ML 학습 자료도 사람마다 기준 하나가 맞다. (같은 날 몇 시간 동안 카메라별로 저장했던 것은 가장 최근 것 하나로 합쳐 읽는다.)
6. **측정 중에 측정하기로 오면 「측정 화면으로」 버튼으로 돌아갈 수 있다**(10/16). 측정 중에는 카메라 선택·등록·시작이 잠기므로, 돌아갈 길이 없던 문제를 막는다.
7. **측정 중 앱을 닫거나 새로 고치면, 다음에 로그인할 때 그때까지의 측정을 묻지 않고 기록으로 저장한다**(10/16, 사용자: 「중단된 측정은 그대로 보낸다」). 「이어하기」 복구 안내는 없앤다. 카메라 빠짐(결정 3)·서버 끊김(ADR 0024)과 같은 원칙이다. 개발자 옵션의 서버 측정 임시본은 서버 종료 확인이 필요해 지금처럼 안내한다.

## 범위와 제외

- 바꾸는 곳: `features/camera/`(선택 규칙·외장 판별·해상도 확인을 순수 함수로), `hooks/useCamera.ts`(연결 순서, `devicechange`, `onended`), 측정하기·설정 화면의 안내 문구·알림.
- 제외: 여러 대 동시 측정, 서버 전송(F1~F3, BE v2 뒤), 기준 자세를 서버에 저장하는 것(F2).

## 결정과 진행 기록

- 2026-10-16 팀 논의: 카메라마다 기준 자세를 등록하게 하는 건 비효율적이고 ML 학습에도 맞지 않아, 결정 5를 「기준 자세 하나」로 정정했다. 카메라별 저장·판별 코드(`baselineFor`, `baselineOtherCamera`, 「다른 카메라로 등록한 기준 자세」 안내)를 없앴다.

- 2026-10-16 실제 확인 뒤 추가: 새로 고친 뒤 기준 자세가 있는데도 자동 시작 대신 수동 「측정 시작」만 남았다. 원인은 새로 고치기 전 측정의 임시 저장본(draft)이 남아 새 측정 시작을 막은 것(`useSessionPersistence.start`)이고, 안내 카드는 화면 맨 위에 있어 보이지 않았다. 결정 7로 고쳤다.

- 2026-10-16 실제 확인(사용자, USB 카메라 2대 `Logi C270 HD WebCam (046d:0825)`·`USB Camera (4c4a:4a55)`, 내장 카메라 없는 노트북): 측정 중 B를 빼면 멈추고 A로 못 넘어가며 다시 꽂아도 못 씀, 「카메라 준비 다시 확인」·「측정 종료」 모두 측정하기로 돌아감, A만 있을 때 「기준 자세를 등록해요」에서 막힘, 다시 꽂은 뒤 「측정 시작」이 잠기고 카메라를 바꿀 수 없음. 원인: 기준 자세 저장 칸이 하나(R1), 측정 중(일시정지 포함) 측정하기가 잠기고 돌아갈 버튼 없음(R2), 끊겨도 다른 카메라로 안 넘어감(R3), 다시 꽂아도 원래 카메라로 안 돌아감(R4). 결정 3을 「측정 종료·저장」으로 정정하고 결정 5·6을 더해 고쳤다.
