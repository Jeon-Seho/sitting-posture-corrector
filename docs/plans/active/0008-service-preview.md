## 문제와 완료 기준

연구용 카메라 기반을 유지하며 사용자 흐름을 검토할 수 있는 서비스 미리보기를 만든다. 내부 이동 시 측정 보존, 수동 재개, 로컬 저장 결과 공유, 소리와 화면 알림 분리, 개인 정보 편집을 확인한다.

## 범위와 제외

실제 인증·서버 저장·학습용 탈퇴 데이터 처리는 API 미연결 상태로 표시한다. 개인화 예시 학습을 구현했다고 주장하지 않는다. 연구용 화면은 별도 진입으로 유지한다. 로컬 저장 실패는 결과 보존 및 재시도로 처리한다.

## 브라우저 검증에서 발견한 문제 (2026-09-28)

헤드리스 Edge(가짜 카메라)로 서비스 흐름과 합성 더미 기록(웹캠 오늘 3·어제 1·시연 1, 진행 중 이벤트가 있는 중간 저장 1)을 넣어 확인했다. 집계 값(오늘 73.3%, 전체 83.9%, 유효 0초 기록 `계산 불가`, 중단 측정 종료·저장 170/150초)은 기대값과 일치했다. 아래 문제를 발견해 수정했다.

1. 새로고침·재로그인 시 측정 모드가 항상 `camera`로 돌아가, 시연 모드 기록이 있어도 홈이 "0회"로 보여 기록이 사라진 것처럼 보였다. → 마지막 모드를 `posegood.v2.mode`에 저장하고 로그인 시 복원한다. 로컬 자료 삭제 시 함께 지운다.
2. 로그인 제출이 프로필 편집 저장과 같은 함수를 써서 홈 상단에 "저장했습니다." 알림이 떴다. → 로그인에서는 알림을 띄우지 않고, 프로필 화면 저장에서만 표시한다.
3. 중단 측정 카드의 두 버튼이 붙어 있고, 사이드바 "연구·라벨 수집" 링크가 브라우저 기본 파란색이라 어두운 배경에서 잘 보이지 않았다. → 버튼을 `.row`로 묶고 사이드바 링크에 패널 색상을 적용했다.

수정 후 재검증: 더미 데이터 시나리오 16/16, 서비스 흐름 E2E(로그인→등록→측정→이동 시 일시정지→수동 재개→종료·저장→새로고침 복구→로컬 자료 삭제→`?research`) 23/23 통과. 프론트 테스트 30개, 타입/빌드, 저장소 검사, Python 10개 통과. 이 환경에는 `make`가 없어 `make check` 구성 명령을 개별 실행했다.

## 향후 변경 필요

우선순위 순. 미완료 기능 목록은 docs/team-requirements.md §10을 따른다.

1. 브라우저 E2E를 저장소와 CI에 연결한다. 이번 검증 스크립트는 작업 공간 밖 임시 파일이라 재현되지 않는다. Playwright 등 도구 선택은 팀 결정이 필요하다.
2. 저장값 형태 검증: `readLocal`은 JSON 파싱 오류만 막는다. `records`가 배열이 아니거나 `settings`에 필드가 빠진 이전 형식이면 화면 오류나 잘못된 규칙이 생길 수 있다(코드 검토 결과, 브라우저 미검증). 형태 확인과 `DEFAULT_RULES` 병합이 필요하다.
3. 탈퇴 흐름: 학습용 자료 동의를 체크하면 삭제 버튼이 비활성화되어 진행할 방법이 없다. 서버 연결 전까지 동의 항목을 숨기거나 안내 문구를 바꾼다.
4. 로그인 시 모드와 관계없이 카메라를 자동으로 켠다. 시연 모드에서는 켜지 않도록 해 불필요한 카메라 사용을 줄인다.
5. 모드별 집계가 분리되어 다른 모드에만 기록이 있으면 홈이 비어 보인다. "다른 모드 기록 N회" 같은 안내를 추가한다.
6. 좁은 화면에서 고정된 프로필 버튼이 카드 내용을 가린다.
7. `ServiceApp.tsx`가 한 줄 JSX 위주로 밀집되어 있어 화면별 컴포넌트로 분리한다.
8. Windows에 `make`가 없어 `make check`를 직접 실행할 수 없다. 대응 스크립트 또는 문서 안내가 필요하다.
