## 문제와 완료 기준

발표용 설명 화면을 사용자용 데스크톱 앱 화면으로 바꾼다. 큰 카메라, 따뜻한 건강 톤, 3개 탭, 부드러운 전환.
시작 프로그램·자동 카메라 연결 지점을 열고, 아직 준비되지 않은 백엔드는 연결하지 않고 연결 지점과 문서만 남긴다.
완료 기준: 판정·시간 정책·저장 동작이 그대로이고, 프론트 테스트·빌드와 브라우저 회귀가 새 화면에서 통과한다.

## 범위와 제외

포함: `frontend/src` 화면·스타일, `frontend/electron` 셸, 브라우저 회귀 스크립트의 화면 문구·선택자, 관련 문서.
제외: 시간 정책·판정 규칙·저장 형식·서버 계약 변경, 새 API 호출, 설치 파일 패키징.

## 결정과 진행 기록

- 라우트 이름은 유지하고 탭으로 묶었다(`home` → 측정하기). 기존 테스트의 흐름 검증을 최대한 보존하기 위해서다.
- ADR 0016의 "카메라 자동 연결 없음"은 데스크톱 + 시작 프로그램 + 사용자 선택일 때만 예외로 바꿨다(ADR 0017).
- 플랫폼 v4(키포인트 전송, T1 10초/T2 5초)와 현재 결정(ADR 0012·0013)의 차이는 연결 지점 문서의 질문으로 남겼다.

## 검증 결과와 남은 한계

- `npm run check`(frontend): 테스트 29파일 242개 통과, `tsc -b`·`vite build` 통과(번들 500kB 경고).
- `python tools/dev.py check`: 저장소 구조·링크 검사는 통과했다. Python 테스트 109개 중 8개가 오류로 끝나 이후 단계가 실행되지 않았다.
  - `fastapi` 미설치로 5개 모듈 import 실패.
  - 배포 테스트는 Windows 파일 잠금과 POSIX 전제 때문에 실패.

  두 경우 모두 이번 변경 파일과 무관하다.
- 브라우저 회귀 스크립트는 `node --check`만 통과했다. 이 PC에는 Maven이 없고 JDK가 17이라 실제 실행은 하지 못했다.
- 인앱 브라우저(카메라 없음)에서 로그인·측정하기(카메라 꺼짐)·기록·설정 화면과 슬라이드 전환을 확인했다.
  실제 카메라 측정 화면, Electron 창의 preload 동작은 확인하지 못했다.
