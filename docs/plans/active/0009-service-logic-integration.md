- 이전 계획: [V2 서비스 흐름 미리보기](../completed/0008-service-preview.md)

## 문제와 완료 기준

`jin_dev3`의 단일 앱 화면·디자인을 그대로 두고, 브라우저 검증에서 찾은 로직 문제의 수정만 얹는다. 화면 배치·스타일은 바꾸지 않는다. 완료 기준은 아래 변경이 브라우저 흐름과 합성 더미 데이터로 확인되고 `python tools/dev.py check`가 통과하는 것이다.

## 범위와 제외

- 포함: `ServiceApp.tsx`의 상태·저장 로직, `lib/serviceStore.ts`, 검증 진입점(`tools/dev.py`, `Makefile`).
- 제외: 화면 파일 분리, 레이아웃·색·간격 변경. 이전 브랜치에서 했던 프로필 버튼 이동·카드 간격·사이드바 링크 색·화면 컴포넌트 분리는 팀원 디자인과 겹쳐 가져오지 않았다(원본은 `feature/retro-redisgnV2`의 `e5ff7bb`).

## 적용한 로직

1. 저장값 읽기 검증: `parseProfile`·`parseRecords`·`parseDraft`·`parseRules`·`parseMode`. 형식이 맞지 않는 기록은 버리고, 설정은 빠진 항목을 `DEFAULT_RULES`로 채운다. 지금은 더미 데이터뿐이라 필드가 늘면 함께 고치는 임시 규칙이다.
2. 실제 기록 보기(예시 기록 표시 꺼짐)에서 실제 웹캠·합성 시연 기록을 모드 구분 없이 합산한다. 계정 구분이 없는 미리보기 기준이며, 행마다 입력 종류를 표시한다.
3. 마지막 측정 모드를 `posegood.v2.mode`에 기억한다. 로컬 자료 삭제 시 함께 지운다.
4. 로그인 시 "저장했습니다." 알림을 띄우지 않는다. 프로필 저장에서만 표시한다.
5. 탈퇴: 학습용 자료 동의 여부가 최종 삭제를 막지 않는다(EXIT-01). 동의 시에는 서버 미연결로 동의가 전달·보관되지 않음을 안내한다.
6. 프로필 검증(`validateProfile`), 중단 측정의 기록화(`recordFromDraft`)를 순수 함수로 옮겨 단위 테스트를 붙였다.
7. Windows 포함 검증 진입점 `tools/dev.py`, `Makefile`은 이를 호출([ADR 0009](../../decisions/0009-cross-platform-dev-entry.md)).

## 검증 결과와 남은 한계

검증 결과는 아래 "검증" 항목에 실행한 것만 적는다.

### 검증

- 2026-09-28, Windows 11: `python tools/dev.py check` 통과. 저장소 검사, Python 11개, 프론트 35개, 타입/빌드.
- 헤드리스 Edge와 가짜 카메라, 합성 더미 기록(웹캠 오늘 3·어제 1·시연 1, 진행 중 이벤트가 있는 중간 저장 1)으로 19개 항목 통과. `origin/main`(PR #5 반영)에 이 브랜치를 로컬에서 시험 병합했을 때도 충돌 없이 같은 검사와 19개 항목이 통과했다. 확인한 항목은 다음과 같다. 로그인 알림 없음, 홈 오늘 합산 74.3%(1560/2100)·4회·3건, 대시보드 83.6%(3260/3900)·5회·4건, 유효 0초 기록 `계산 불가`, 모드 기억, 중단 측정 종료·저장(170/150초, 진행 중 이벤트 닫힘), 시연 측정 1회 저장, 배열이 아닌 기록 JSON·일부만 저장된 설정 처리, 예시 기록 스위치 저장, 동의 체크 상태의 탈퇴와 전체 로컬 자료 삭제. 콘솔 오류는 없었다.
- 미검증: Linux의 `make` 경로와 Python 3.9 실행(3.9는 문법 검사만, CI에서 확인), 실제 카메라 판정, 소리 재생, 장시간 백그라운드.

### 향후 변경 필요

1. 계정·서버가 연결되면 기록 집계 기준(사용자별, 실제 웹캠과 시연의 분리 여부)을 다시 정한다.
2. 저장값 검증 규칙은 더미 데이터 기준이다. 필드가 추가되거나 데이터 계약(§6)이 확정되면 `serviceStore`의 `parse*` 함수를 함께 고친다.
3. 브라우저 검증 스크립트는 저장소에 넣지 않고 담당자가 수동으로 실행한다.
