## 문제와 완료 기준

현재 jisung 작업 브랜치에 최신 develop을 병합한다. `/dev` 관측·기존 연구 파일과 서비스 기능을 보존하고 공통 카메라는 Heavy 33점, GPU 실패 시 CPU 전환을 유지한다. `/`는 서버 기준, `/dev`는 로컬 관측을 사용한다. 테스트 결과를 확인한 뒤 개인 원격 브랜치에 push하고 develop 대상 PR을 연다.

## 범위와 제외

공통 프론트 카메라와 기준 등록, 관측·서비스 연결, 병합 충돌과 관련 문서·합성 테스트. 실제 영상·참여자 자료 및 develop 직접 push와 PR 병합은 제외한다.

## 결정과 진행 기록

사용자가 공통 Heavy 모델, GPU→CPU, 유예 없는 측정 불가 처리와 /dev 로컬 경계를 지정했다. 실제 PR 병합은 요청하지 않았다.

## 검증 결과와 남은 한계

- `make check`: 저장소 검사, Python 210개, Vitest 915개와 Node 5개, TypeScript·Vite 빌드 통과. Java 개발 도구 부재로 백엔드 단계에서 중단되어 전체 통과는 아니다.
- `npm run test:cpu-worker`: 합성 빈 프레임의 Heavy CPU 워커 추론과 브라우저 응답성 통과. 실제 카메라 성능은 측정하지 않았다.
- `make check-browser`: 프로덕션 번들의 합성 코드 부재 확인 후 Docker 데몬 미실행으로 중단. 서비스·DB 전 과정은 미검증이다. 별도 브라우저에서 `/` 로그인 화면과 `/dev` 측정 선택 대화상자를 확인했다.
- 사용자의 원래 브랜치에만 있던 302개 파일 경로가 병합 작업 트리에 모두 남아 있다. 기존 v5 파일을 읽고 측정 품질이 추가된 v6을 내보낸다.
- 기존 Lite 서버 기준에는 모델 ID가 없어 Heavy 관측과 혼용될 수 있다. 배포 전 기준 재등록 또는 모델별 기준 관리 방안을 확인해야 한다.
- ML 후보 특징 내보내기는 현재 서버 추론 입력과 다르며, 학습 모델 입력으로 확정되지 않았다.
