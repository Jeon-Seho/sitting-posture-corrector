## 문제와 완료 기준

서비스 FE·BE를 유지한 채 먼저 정면 어깨 위 관측에서 판정할 변화와 제외할 상태를 정의한다.
그 확인을 통과한 목표에 한해 수집→자료 검사→촬영일 분할→특징→필요한 학습→고정 평가 경로를 새로 만든다.
본인 한 명의 다른 촬영일에서 재현되는지 확인한다. 기존 실험 코드나 LSTM을 살리는 것은 완료 조건이 아니다.

계획 단계에서는 한계·지원 현상·모호한 경우·진행 조건을 먼저 명시한다. 장비·수집·학습안은 그 이후의 조건부 참고안이다.
구현 완료 조건은 아래 L0/G0의 실제 확인 후 필요한 G1~G6 산출물과 검증을 수행하는 것이다. 현재 상태를 구현 완료로 표시하지 않는다.

## 범위와 제외

- 범위: 독립 ML 수집 도구, 새로운 원본/라벨 규격, importer, 검사·특징·학습·평가·재생·export.
- 범위: i7-8700 추정·16GB·GTX 1050급 장비의 CPU 우선 자원 측정과 본인 촬영일 파일럿.
- 제외: 서비스 화면·BE·알림 시간 엔진·DB·공개 계약의 변경, Kafka/Spark/HDFS 재설정.
- 제외: 과거 실험 일괄 이관, 서비스 모델 자동 교체, 미래 붕괴 예측, 참여자 일반화·의료 효과 주장, 보안 검토·배포.

## 단계별 산출물과 검증

| 단계 | 산출물 | 완료 조건 |
| --- | --- | --- |
| L0/G0 | 한계·반례 확인 기록·지원/제외 명세·장비/구도/품질/라벨 조건 | 원하는 목표와 관측 조건이 양립함. 아니면 목표·구도를 바꾸거나 기능 제외. 수집·학습으로 대체하지 않음 |
| G1 | `ml-capture-v1` 스키마·원본/라벨 파일·독립 수집 도구 | 원본과 라벨 분리, 시각/중단/저장/재등록의 합성 실제 경로 검증 |
| G2 | 촬영일·자료 역할·hash manifest | 본인 한 명의 회차 실험임을 표시. 분할 경계·개인 기준·시험 자료 격리 |
| G3 | 새 자료 validator·특징·B0·재생기 | 같은 원본과 설정에서 동일 결과. 누락·중복·미래 참조·평가 fitting 거부 |
| G4 | 필요한 B1/M2 후보·검증 보고·자원 로그 | 단순 측정으로 부족한 이유 확인. M2는 기본 보류. 실행할 경우 학습 전용 fitting·제한 탐색·같은 입력 비교 |
| G5 | 고정된 모델·D4 개인 시험 보고 | 오알림/놓침/지연/관측률/자원을 원래 개수·시간과 함께 보고. 시험으로 재선택 금지 |
| G6 | 모델·scaler·명세·hash 묶음·연결 요구서 | `legacy3` 호환과 좌표/시퀀스 연구 결과를 구분. 서비스 자동 교체 없음 |

## 결정과 진행 기록

- 2026-10-15: 사용자가 서비스 FE·BE를 유지하고 ML만 새로 설계하도록 요청했다.
- 2026-10-15: 본인 한 명부터 시작한다고 확인했다. 개인 회차 파일럿과 참여자 홀드아웃 연구를 분리한다.
- 2026-10-15: 최초 안은 현재 기준 대비 상태 판정이었다. 사용자가 정면 어깨 위의 관측 한계를 먼저 정하도록 수정했다.
  기준과 비슷함을 정상 자세로 해석하지 않는다. 상대 형태·영상상 배치·품질을 나누며 숨은 몸통 판정은 제외한다.
- 2026-10-15: 팔꿈치 필수화·미래 회귀의 연장은 보류한다. LSTM 분류기도 시간 이력의 필요성 확인 전에는 구현하지 않는다.
- 2026-10-15: 기존 D0 10~15분, D1/D2 각 15분, D3 15분, D4 30분 안은 L0/G0 통과 후 재검토할 참고안이다.
  현재는 저장 없는 짧은 관측 반례 확인이 다음 단계이며 본 수집·학습은 아직 진행하지 않는다.
- 2026-10-15: 현재 BE는 세 특징 변화량만 넘기며 측정 세션 ID가 추론 계약에 없다.
  새로운 좌표/LSTM을 ML 구현만 바꾸어 즉시 서비스에 연결할 수 있다고 약속하지 않는다.
- 2026-10-15: 초기 자원 예산은 CPU 2스레드·학습 RSS 6GiB·직렬 실행·총 10회 이내 탐색이다.
  실제 장비의 보장 성능이나 최적 설정이 아니며 G0에서 검증한다.
- 2026-10-15: L0 명세만 작성했다. 실제 G0 확인과 G1~G6은 앞으로 필요성을 판단할 작업이다. 이번 요청에서는 문서만 수정한다.

## 검증 결과와 남은 한계

- 문서 검증 실행: `make check-repo`와 같은 `.venv/Scripts/python.exe tools/dev.py check-repo` 통과.
- `git diff --check` 통과. 변경 범위는 판정 한계·새 계획·ADR와 문서 진입점뿐이다.
- 구조 계산 실행: 단층 LSTM 입력 32·hidden 16/32·이진 head는 각각 3,217/8,481 파라미터다.
  float32 가중치만 각각 12,868/33,924바이트이며 런타임 메모리·FPS 측정이 아니다.
- 실제 반례 확인·새 데이터 수집·학습·평가·학교 장비 부하 측정은 실행하지 않았다.
- 문서 변경이므로 전체 `make check`, Python/프론트 테스트, 타입·빌드는 이번 작업에서 실행하지 않는다.
  구현 단계에서는 새 CLI·수집·학습·평가의 실제 합성 검증을 전체 게이트에 연결한다.
- 서비스와 공개 계약은 이번 설계로 변경되지 않는다. 실제 서비스 연결은 기존 JDK/MySQL 통합 환경 준비와 별도 검증이 필요하다.
