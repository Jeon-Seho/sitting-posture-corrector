# ADR 0014: MySQL 영구 저장과 서버 계정

- 상태: accepted
- 날짜: 2026-10-01
- 근거: 사용자가 DB 작업 전체 구현을 요청하고 **MySQL + 이메일·비밀번호**를 선택했다.
- 개정: [ADR 0018](0018-db-schema-v11-service-storage.md) — 저장 구조는 DB 스키마 V1.1, API는 마이그레이션하지 않고 검증만 한다.

## 결정

기존 Java 21·Spring Boot API에 MySQL 영구 저장과 서버 계정 모드를 추가한다.
프론트는 같은 출처의 API를 사용하며 서버 인증 세션은 DB에 보관한다.
비밀번호는 적응형 단방향 password encoder로 저장하고 인증 cookie는 HttpOnly와 SameSite를 적용한다.
변경 요청은 CSRF를 검증한다. HTTPS 환경의 secure cookie는 배포 설정으로 활성화한다.

모든 측정 요청·기록·프로필·설정은 검증한 인증 주체의 내부 사용자 ID에 속한다.
브라우저 프로필과 요청 body의 사용자 값을 인증이나 소유권의 근거로 사용하지 않는다.
DB 제약과 처리 상태로 중복 요청을 구분하고 내구 관측/전달 기록을 통해 API·CEP 재시작을 복구한다.
최종 요약만 저장하여 연속 판정이 복구됐다고 주장하지 않는다.

가입의 `service-v1`은 계정과 서비스 기록 저장에 대한 명시적 선택을 기록하는 기술 식별자다.
연구·학습 활용 동의로 재사용하지 않으며 법적 요건 충족을 보증하는 표기가 아니다.
자동 보존 기간을 임의로 확정하지 않는다. 사용자 삭제·탈퇴는 별도 구현하고 백업/분석 자료의 삭제 경계는 안내한다.

## 호환성과 검증

기존 메모리/로컬 개발 모드는 유지하고 영구 모드에서 인증을 적용한다.
AI 특징·관측·사건과 확정 3/2/60 정책은 유지한다. 시간 판정의 책임은 CEP에 남는다.
원본 영상·좌표·변화량 원문·비밀번호 원문은 영구 자료에 넣지 않는다.
새 계정/workspace API, 마이그레이션, 두 사용자 격리·동시 중복·DB/HTTP 경계 실패·재시작/삭제를 합성 자료로 검증한다.

MySQL의 실제 저장/트랜잭션 동작은 [InnoDB 공식 문서](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-model.html)를 따른다.
상세 구현과 실행 결과는 [완료 계획](../plans/completed/0017-mysql-accounts-compose-deployment.md)에 기록한다.
