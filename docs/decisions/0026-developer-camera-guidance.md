# ADR 0026: 개발자 화면의 카메라 안내와 기준 겹침

- 날짜: 2026-10-13
- 상태: `/dev` 연구 화면에 한정해 채택

## 배경과 결정

사용자가 소개 카드 대신 큰 검정 카메라 화면, 원클릭 안내·정렬·등록, 영상 위 관측 및
기준 대비 움직임 효과와 모델/룰 결과 비교를 요청했다. 기본 다크 테마와 수동 라이트 전환을
제공하며 장식 무늬·마케팅 문구 대신 측정 상태에 연결된 전환을 사용한다.

기존 MediaPipe Pose의 얼굴·양어깨 관측을 재사용한다. Face Landmarker를 추가하지 않는다.
공통 서비스 카메라/등록 로직은 바꾸지 않고 `/dev` 어댑터가 별도 안내 단계를 진행한다.
구도 확인 뒤에만 8초 기준을 수집하고, 등록 도중 구도·품질이 깨지면 연속 등록을 다시 시작한다.
등록 완료 후에는 의도적인 움직임을 구도 가이드가 차단하지 않는다. 실제 품질 실패는
기존 실험 코어의 `unmeasurable` 규칙을 그대로 따른다.

화면 중앙·거리·안정 유지의 수치는 촬영을 돕는 **개발용 휴리스틱**이며 정상 자세나 모델
정확도 임계값이 아니다. 구현의 `GUIDANCE_SETTINGS`가 현재 값을 소유한다.
서비스 채택에는 카메라 시점·거리·대상 조건을 포함한 별도 검증이 필요하다.

현재 준비 안내는 카메라와 추적기가 준비된 뒤 1.2초씩 3단계다. 구도 확인은 관측 가시성 0.5,
어깨폭/화면폭 0.25–0.72, 얼굴·어깨의 가로 중심 0.5±0.16, 얼굴 평균 y 0.12–0.62,
어깨 중심 y 0.35–0.9를 사용한다. 실제 사용 중 준비 진행률이 반복 초기화된 피드백에 따라
개별 점을 고정하던 조건을 얼굴 평균 위치·어깨 중심·어깨폭의 전체 구도 변화로 교체했다.
각 변화는 시작 구도 대비 화면폭 0.06 이하를 허용하고 0.9초의 유효 구도 관측 후 등록한다.
준비 단계의 관측 간격은 최대 500ms, 짧은 손실·구도 이탈 유예는 400ms다. 유예 동안
진행률을 보존하지만 시간을 추가하거나 등록을 시작하지 않는다. 지속 실패·긴 간격·영상 크기 변경은
진행률을 초기화한다. 한 점의 추적 튐과 작은 자연스러운 움직임은 전체 구도로 평가한다.
이는 정면에서 얼굴과 어깨가 가이드 안에
들어오는 개발 체험을 위한 초기값이며 사람의 자세 유형·정상성을 검증한 결과가 아니다.
등록/판정의 표본 연속성에는 기존 연구 코어의 더 엄격한 170ms 규칙을 그대로 적용한다.

## 표시와 데이터

영상과 관측점은 같은 종횡비·contain·좌우 반전을 적용한다. 기준 윤곽은 등록 구간의
영상 관측점 평균이며 화면 참고선이다. 사람의 뼈·해부학적 위치나 정답 자세를 의미하지 않는다.
현재 좌우 이동·어깨선 각도 변화는 화면 기하 관측값이다. 자세 상태는 연구 코어 출력만 표시한다.
사용자 피드백에 따라 화면 상하 이동도 표시하고 점선을 「등록 당시 화면 위치」로 명명한다.
카메라 아래에서 화면 위치 변화(화면폭/높이)와 실제 3D 자세 거리(현재 어깨폭)를 함께 표시한다.
정규화 과정에서 전체 이동·일정한 크기 변화가 제거되는 판정 특성과 픽셀 위치 비교를 구분하며,
기준 범위 상태를 정확한 위치 일치·정상 자세·정확도라고 표현하지 않는다.
측정이 끊기면 마지막 현재점을 지워 고정된 사람처럼 보이지 않게 한다.

가이드 좌표·기준 윤곽은 메모리 표시 전용으로 실험 기록/진단 JSON에 넣지 않는다.
영상 녹화·자동 저장·전송 기능은 추가하지 않는다. `developer-lab-export-v1`의 원본 제외를 유지한다.
의존성과 서비스 승격 절차는 [모듈 안내](../../frontend/src/features/developer/README.md)에서 관리한다.
