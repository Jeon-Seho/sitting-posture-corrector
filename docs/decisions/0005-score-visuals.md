# ADR 0005: 자세 점수 방향과 화면 표시

- 상태: 채택
- 날짜: 2026-09-19 (2026-10-27 ADR 정리로 옛 0004의 화면 평활화를 2절로 합침. 처음 제목은 「자세 점수 방향과 표시 효과」)
- 분야: FE (화면 표시)
- 원칙: **화면에 보이기 위해 만든 값(점수 반전, 평활화, 파티클)은 입력·기준 등록·판정·수집 CSV에 넘기지 않는다.**

## 1. 점수 방향

사용자가 100점을 좋은 상태로 읽을 수 있도록 요청했다. 화면의 자세 점수는 `100 × (1 − collapse_probability)`로 표시한다
(처음에는 앱 점수 `change_score`, 지금은 서버가 보낸 값 — [ADR 0021](0021-app-sends-information-server-judges.md)). 100은 개인 기준에 가깝고 0은 큰 변화다.
알림 설정도 화면은 5~50점 이하로 표시하며 내부 임계값 0.95~0.50으로 역변환한다. 기본 알림 경계는 30점 이하가 3초 지속되는 경우다.
점수는 의료적 자세 등급이나 정확도가 아니다. 표시 반전으로 움직임 허용 범위가 달라지지 않는다.

## 2. 화면 평활화 (옛 0004, 2026-09-19)

MediaPipe가 주는 관절 좌표는 프레임마다 조금씩 흔들려서, 그대로 그리면 화면의 뼈대 선이 떨린다.
그래서 **화면에 그릴 때만** 브라우저 렌더 주기로 스켈레톤을 시간 기반 지수 평활화(시정수 45ms)한다. 추적 품질을 잃으면 바로 비운다.
판정·기준 등록·수집에는 평활화하지 않은 원래 값을 쓴다. 화면 표시의 추가 지연과 측정 시간은 구분한다.
코드: `components/PoseGuide.tsx` `smoothPoints`(`lib/poseGuide`), `features/camera/frameLoop.ts`(원래 관측값과 화면용 평활화를 끝까지 따로 둔다).

## 3. 스켈레톤과 표시 효과

기존 Pose의 33개 후보 점 중 화면 안이고 가시성 0.65 이상인 점을 표시한다.
눈·입·손·다리 연결을 확장한다. [공식 랜드마크 목록](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/PoseLandmark)에 턱 점은 없으므로 턱을 추정해 실제 추적점으로 표현하지 않는다.
별도 얼굴 모델의 추가 비용과 연구 특징 변경은 후속 결정이다.

매트릭스 모드는 관절 사이와 몸통을 장식용 파티클로 채운다. 최대 445개로 제한하며
1200ms에 모이고 잔잔한 이동/스캔을 표시한다. 단일 2D 캔버스 효과이며 3D 체형 복원이 아니다.
효과 끄기, 다시 모으기, 애니메이션 줄이기를 제공하고 초기 OS 동작 줄이기 설정을 따른다(`lib/poseVisual.ts`, `components/VisualControls.tsx`).
