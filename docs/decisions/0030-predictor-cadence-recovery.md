# ADR 0030: 예측 입력 지연과 자세 관측 연속성 분리

- 날짜: 2026-10-14
- 상태: `/dev` 개발 설정으로 채택. 실제 정확도는 미검증.
- 관련: [예측 계약](../../contracts/forecast-experiment.v1.md), [ADR 0029](0029-automatic-normal-labels-and-forecast-display.md)

## 배경

실제 웹캠에서 영상 점 13개와 유효한 규칙 판정이 나오지만 LSTM은 반복해서 준비 상태로 돌아갔다.
종료 진단의 관측 간격은 중앙값 약 81ms, 95백분위 약 269ms였고 250ms보다 긴 지연이 반복됐다.
기존 코드의 250ms 연속성 경계는 규칙과 30개 예측 입력을 동시에 초기화했다.
합성 입력에서도 2초마다 300ms 지연을 넣으면 예측 준비를 마칠 수 없었다.

## 결정

1. 규칙·알림·자동 라벨은 기존 250ms 연속성 조건을 유지한다. 이를 넘는 관측 구간은 미측정이며 이탈/정상 시간에 더하지 않는다.
2. 예측용 100ms 격자만 유효한 두 실제 관측 사이 최대 500ms 지연까지 인과적 선형 보간을 허용한다.
   아직 도착하지 않은 좌표를 앞값으로 채우지 않는다. 품질 불가·백그라운드·시각 역전·500ms 초과는 예측 이력을 버린다.
3. 감시 타이머의 입력 지연 통지는 새 원시 관측이 아니다. 원시 시각을 앞으로 옮기지 않고 표시·규칙 누적을 끊으며,
   500ms 안에서는 다음 실제 좌표를 기다린다. 기다리는 동안 예측을 새로 만들지 않는다.
4. 250ms보다 긴 지연을 메운 격자는 예측 입력일 뿐 잔차 평가 정답이 아니다. 이전 예측 큐/잔차를 비우고,
   정상 자료·기준 등록의 실제 표본 수·자동 라벨에 보간 자료를 넣지 않는다.
5. 카메라 시각과 세션 시작은 같은 `performance.now()` 축이다. 첫 결과 수신 지연을 전체 관측 시각에 더하지 않는다.
   예측 목표 시각이 현재를 지났다면 화면에서 숨긴다.
6. 화면에 실제 준비 개수/30, 마지막 초기화 이유, 최근 관측 간격과 카메라 처리 속도를 표시한다.
   입력 부족, 입력 준비 완료 후 새 출력 대기, 관측 실패를 구분한다.
7. 진단 출력에 선택 필드 `predictionInputMaxGapMs`, 내보내기 설정에 `predictor_max_gap_ms`를 남긴다.
   해당 필드가 없는 과거 자료를 새 지연 정책으로 재해석하지 않는다. 표시용 진행 상태에는 좌표를 넣지 않는다.

## 해석과 한계

500ms는 사용자 화면의 처리 지연 문제를 위한 제한적인 개발 설정이다. 학습/검증으로 최적화한 상수가 아니며
빠른 동작의 보간 오차가 생길 수 있다. 모델의 정확도나 일시 동작 판별 능력이 개선됐다고 주장하지 않는다.
실제 품질 실패·긴 누락을 정상으로 바꾸지 않는다. MediaPipe 설정과 일반 서비스 경로는 유지한다.
실제 장치별 간격/FPS·오알림·예측 오차와 보간 빈도는 별도 평가해야 한다.
