# ADR 0051: 로그인은 여러 기기에서 되고, 측정은 계정당 한 기기만 한다

- 상태: accepted
- 날짜: 2026-11-18
- 작성: klaod-tech(FE)
- 근거: 우진(lellon0403) PR #127(11/18 develop 병합), [계획 0096](../plans/completed/0096-single-device-measurement.md), FE 제안서 옛 요구 11(한 기기, 11/17 닫음)
- 관련: [ADR 0024](0024-session-ends-on-lost-connection.md)(연결이 끊기면 세션을 끝낸다), [ADR 0031](0031-jwt-access-refresh-login.md)(토큰 로그인), [ADR 0029](0029-midnight-cut-and-server-time.md)(자정 넘김), [계정 계약](../../contracts/accounts.md) 「측정과 기록」

## 배경

- 같은 계정으로 두 PC에서 동시에 측정하면 두 세션의 기록이 같은 날에 겹친다. 오늘 기록·측정 시간이 두 배로 쌓이고, 알림도 두 곳에서 따로 온다.
- 로그인 자체를 한 기기로 막으면 웹과 데스크톱 앱을 번갈아 쓰거나 다른 PC에서 기록만 보는 일도 막힌다.

## 결정

1. **로그인·refresh는 막지 않는다.** 여러 기기·탭에서 동시에 로그인해 기록·설정을 볼 수 있다.
2. **측정만 계정당 한 기기로 제한한다.** 같은 계정의 다른 세션이 측정 중이면 S1(`PUT /sessions/{id}`)이 `409 MEASUREMENT_IN_PROGRESS`다. 측정 중이란 끝나지 않은 세션이면서 실시간 연결이 붙어 있거나, S1 뒤 연결 전 30초(`posegood.realtime.measurement-claim-grace`) 안인 것이다.
3. **앱은 막기만 하고 원격으로 끝내지 않는다.** 「다른 기기에서 측정 중이에요. 그 기기에서 측정을 끝낸 뒤 다시 시작해 주세요.」를 측정 실패 화면에 보인다(`LiveSession.ts` `MEASURING_ELSEWHERE`).
4. **따로 풀어 주는 절차는 없다.** 그 기기가 `end`를 보내거나 연결이 끊기면 세션이 끝나므로(ADR 0024) 바로 다른 기기에서 시작할 수 있다.

## 이유

- 막아야 하는 것은 기록이 겹치는 것이지 로그인이 아니다.
- 다른 기기 측정을 원격으로 끝내는 기능은 그 기기 사용자의 측정을 몰래 끊을 수 있고, 연결이 끊기면 어차피 끝나므로 필요가 적다.
- 30초 유예는 S1만 하고 연결하지 못한 기기가 다른 기기를 오래 막지 않게 한다.

## 결과

- 판단은 API 한 대의 메모리로 한다. API를 여러 대로 늘리면 공유 잠금이 필요하다. API가 다시 켜지면 측정 중 표시도 사라진다(그 세션은 `SESSION_LOST`).
- 드문 경합: 두 기기가 거의 동시에 S1을 통과하면, 늦게 연결한 쪽의 `hello`가 `closed(session_lost)`로 거절된다. 이때 앱은 아직 측정 전이라 「다른 기기에서 측정 중」이 아니라 서버 연결 실패(500 화면)로 보인다(`LiveSession.ts` `closed` 처리). 드물어서 지금은 두고, 생기면 FE에서 문구를 나눈다.
- 실제 두 PC로 확인한 적은 없다(계획 0096). kafka 모드 통신 시험 때 함께 확인하면 좋다.
- kafka 모드에서는 측정을 끝내도 서버 엔진이 끝나지 않아 「측정 중」으로 남았고, 같은 계정의 새 측정이 409 `MEASUREMENT_IN_PROGRESS`로 막혔다(최대 6시간). BE가 D-98로 고쳤다(PR #136, [계획 0098](../plans/active/0098-kafka-measurement-release.md), 서버 kafka 모드 통신 시험 전). local 모드(운영)는 처음부터 문제없었다. 앱은 바꿀 것이 없다.
- 자정 넘김으로 생긴 새 세션은 같은 연결이라 측정 중으로 이어진다.
