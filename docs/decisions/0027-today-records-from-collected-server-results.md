## 배경

일별 통계(T1)는 Spark J2가 매일 00:10(KST)에 전날부터 7일 전까지를 계산한다(계획 0085, D-81). 그래서 T1만 보면 오늘 측정은 다음 날에야 합산에 들어간다.
10/14에는 「오늘 합산은 그리지 않는다」로 정했지만, 10/22 팀장이 오늘 화면도 채우기로 정했다. 10/25에는 앱이 결과를 기기에 모아 오늘 값을 만들기로 했다. 그런데 측정은 끝날 때 서버에 저장되고 R1이 오늘 세션까지 돌려주므로, 10/29부터 코드는 R1로 표시한다. 기기에 복사본을 두면 기기마다 값이 달라지고, 다른 기기와 휴대폰 앱에서는 기록이 보이지 않는다.

## 결정

1. **기록·달력·요약은 R1로 받은 기록을 앱이 KST 날짜로 나눠 집계한다.** 오늘 세션도 R1에서 온다. R1 값은 메모리에만 두고 앱을 열 때마다 다시 받는다.
2. **localStorage에는 서버 확인 전 결과만 둔다.** 키는 계정별(`posegood.account.v3.{user_id}.pending-results`)이고, R1에서 같은 세션의 저장이 확인되면 지운다. 확인 전 결과는 기록에 섞지 않고 「서버 저장 확인을 기다리는 기록 N개」로 알린다.
3. T1을 붙이면 어제까지의 기간 통계는 T1을 쓰고 오늘 값은 R1로 집계한다. 같은 날짜를 겹쳐 더하지 않는다.
4. 앱이 자세를 다시 판정하지 않는다(ADR 0021).

## 이유

- 측정은 끝날 때 서버에 저장되므로 오늘 기록도 R1 하나로 볼 수 있다. 출처가 하나면 기기마다 값이 달라지지 않는다.
- 연결이 끊겨 응답을 못 받은 결과는 서버 저장을 확인할 때까지 잃으면 안 되므로, 그것만 기기에 남긴다.
- 키를 계정별로 나눠 한 PC에서 다른 계정의 결과가 섞이지 않는다.

## 결과

- 서버 저장 확인이 끝나지 않은 결과가 있으면 새 측정을 시작하지 않는다(`useSessionPersistence.ts` `start`).
- 기록을 보려면 서버 연결이 필요하다. 연결이 안 되면 오류 안내를 보인다.
- 옛 키 `posegood.v2.records`에 쓰는 코드는 없다. 앱만의 탈퇴(`useProfileForm` `withdraw`)는 옛 키를 지운다.
- T1을 붙이면 00:00~00:10(J2 전)에는 T1이 어제를 0으로 준다. 그 10분의 어제 표시는 T1 연결 때 정한다([연동 명세 4.5](../design/fe/api-ws-spec.md#45-기록통계-r1r1br3t1-be-다음-주-범위)).
- 서버 탈퇴(A7)는 이 기기의 서버 확인 전 결과를 지우지 않는다. 맞추는 일은 [FE 제안서](../design/fe/fe-server-proposal.md) 요구 9.

## 4. 자정을 넘긴 측정의 KST 날짜별 보관 (옛 ADR 0033, 2026-10-26)

> **서버가 KST 자정에 측정을 끊게 되면([ADR 0029](0029-midnight-cut-and-server-time.md)) 측정 하나는 하루 안에 있어 이 절은 필요 없어진다.** 그때 이 절과 코드(`useSessionPersistence.ts` `observe`의 날짜 나누기)를 지운다([계획 0059](../plans/completed/0059-slim-realtime-results-over-api.md) 3번). 그 전까지와 끊기 전 기록에 쓰인다.

### 결정

한국 시간(Asia/Seoul, UTC+09:00) 00시를 날짜 경계로 사용한다. 자정에 카메라·판정 엔진·세션 ID·알림 누적을 초기화하지 않는다. 원 세션은 연속으로 유지하고 로컬 중간 기록과 종료 기록의 선택 필드 `days`에 각 날짜의 측정분을 따로 저장한다.

각 항목은 날짜·원 세션 기준 시작/끝 offset·전체/유효/정상 시간·그날 새로 확정된 사건 ID·그날의 사건별 알림 횟수를 보관한다. V3는 로컬 엔진이 없어 측정 중 받은 서버 누적 요약(`progress`의 `summary`)을 `ready.started_at`부터 나눈다(`useSessionPersistence.ts` `observe`). 원 서버 snapshot은 수정하지 않는다. API/DB의 세션을 새로 만들거나 서버 일별 배치의 규칙을 바꾼 것이 아니다.

기록·달력·기간 통계·오늘 요약은 같은 날짜별 투영을 사용한다. 사건이 자정을 넘으면 두 날짜의 상세에서 이어진 상태를 볼 수 있으나 사건 발생 수는 확정된 날짜에 한 번만 센다. 재알림은 실제 관측된 날짜에 센다. 전날부터 이어진 사건으로 그날의 발생 간격을 임의로 짧게 만들지 않는다.

자정 이후의 checkpoint에도 전날 측정분을 보관하고, 측정 도중 지난 날짜를 열면 완료된 날짜 부분을 볼 수 있다. 저장 실패 시 기존 저장 오류/재시도를 유지한다. 날짜별 합계와 원 세션 합계가 다르거나 날짜/구간이 손상된 자료는 읽기·쓰기를 거부한다. 저장용 원본을 표시용 투영으로 덮어쓰지 않는다.

### 호환성과 한계

`days`가 없는 과거 종료 기록은 원본을 유지한다. 과거에 합계만 저장된 기록은 날짜별 정상/측정 불가 시간을 복원할 수 없으므로 비율로 나누지 않는다. `days`가 없는 이전 중간 기록도 날짜별 값을 추정하지 않는다. 기존 키와 원 세션·서버 snapshot 형식은 유지한다.

실제 DB의 날짜별 영구 행/배치 처리는 앱의 로컬 보관과 별개다. 이 보관은 서버의 원 세션을 임의로 분할해 API에 제출하지 않는다.

### 검증

합성 자료로 자정·UTC offset·소수 tick·재시도/복구·정상/측정 불가·사건/재알림·전체 합계 보존을 검증한다. 실제 React와 Chrome의 합성 카메라로 자정 전 시작 → 자정 후 계속 → 종료 저장 → 두 날짜 조회 경로를 검증하며 실제 영상을 사용하지 않는다.
