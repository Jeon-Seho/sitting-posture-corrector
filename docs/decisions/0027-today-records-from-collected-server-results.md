# ADR 0027: 오늘 기록은 앱이 모은 서버 결과로 보이고, 이 기기에 키 하나로 둔다

- 상태: accepted (앱은 V3에서 이미 종료 결과를 이 기기에 남긴다 — `features/session/useSessionPersistence.ts` `finish`. 기록·달력의 T1 연결은 남음)
- 날짜: 2026-10-25 (근거 결정 2026-10-22)
- 근거: 2026-10-22 팀장(Jeon-Seho) 결정(develop `db220d8`, [연동 명세 4.5](../design/api-ws-spec.md#45-기록통계-r1r1br3t1-be-다음-주-범위)), 2026-10-25 사용자(FE) 결정 — 「왠만해선 1PC에 1명의 사람이 사용하니」 키를 나누지 않고 팀원용 주의사항으로 남긴다
- 대체: [ADR 0025](0025-app-always-measures-on-server.md) 7번의 「R1로 바꾸면 이 복사를 지운다」, 10/14 결정 「합산·그래프 같은 통계는 어제까지만 그린다」(DevOps 검토 C5)
- 관련: [ADR 0021](0021-app-sends-information-server-judges.md)(앱은 판정하지 않음), [FE 제안서](../design/fe-server-proposal.md) 2장 4·7.2, [계획 0023](../plans/active/0023-frontend-server-only.md)

## 배경

일별 통계(T1)는 Spark J2가 매일 00:00(KST)에 전날치를 만든다. 그래서 서버만 보면 오늘 측정은 다음 날에야 기록·달력의 합산에 들어간다.
10/14에는 「오늘 합산은 그리지 않는다」로 정했지만, 10/22 팀장이 오늘 화면도 채우기로 정했다.

## 결정

1. **오늘 목록·요약·달력의 오늘 칸·기간 그래프의 오늘 값은 앱이 이 기기에 모은 서버 결과로 계산한다.** 어제까지는 T1(통계)·R1·R1b(목록·상세)를 쓴다. 같은 날짜를 서버와 로컬에서 겹쳐 더하지 않는다. 오늘·어제는 KST로 나눈다.
2. 모으는 것은 측정 종료 때 서버가 확인한 요약·사건(R1과 같은 형식, `server.view` = SessionView)이다. 같은 세션 UUID는 덮어쓴다. 앱이 자세를 다시 판정하지 않는다(ADR 0021).
3. **이 복사는 기록 화면이 R1·T1을 읽게 된 뒤에도 남긴다.**
4. **로컬 기록은 계정과 상관없이 localStorage 키 하나(`posegood.v2.records`)에 둔다.** 계정별로 나누지 않는다.
5. 한 PC·한 브라우저에서 다른 계정으로 로그인하면 앞 계정의 오늘 기록이 함께 보이는 것은 **알려진 한계**로 팀 문서([연동 명세 4.5](../design/api-ws-spec.md#45-기록통계-r1r1br3t1-be-다음-주-범위) 「팀 참고」)에만 적는다. 사용자 안내 문구는 두지 않는다.

## 이유

- 오늘 측정이 다음 날에야 합산에 보이면 「오늘 얼마나 했는지」를 볼 곳이 없다. 서버에 오늘 통계를 따로 만들지 않고, 앱이 이미 받은 결과를 모으면 서버 변경 없이 채울 수 있다.
- 보통 PC 한 대를 한 사람이 쓴다. 키를 계정 ID별로 나누면 기록을 읽고 쓰는 곳(처음 불러오기, 측정 종료 저장, 탈퇴 때 지우기, 시험 데이터 준비, 저장값 검사)마다 로그인 응답의 계정 ID를 넘겨야 하고, 이미 저장된 기록을 어느 계정 것으로 볼지도 정해야 한다. 드문 경우를 위해 복잡해지는 것은 맞지 않다(10/25 FE).

## 결과

- 서버 DB·T1에는 영향이 없다. 섞여 보이는 것은 그 PC의 오늘 화면뿐이다.
- 기록·달력 화면을 서버로 바꿀 때(lellon0403, 계획 0023 3단계) 과거만 R1·T1로 바꾸고 오늘 집계 코드는 남긴다.
- 문제가 되면 키를 `posegood.v2.records.<user_id>`처럼 나누면 된다. `user_id`는 로그인(A3)·`me`(A4) 응답에 이미 있어 새로 저장할 것은 없다.
