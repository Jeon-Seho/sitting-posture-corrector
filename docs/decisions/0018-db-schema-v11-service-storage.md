# ADR 0018: 서비스 저장을 DB 스키마 V1.1로 전환

- 분야: 백엔드
- 작업: GP-0068
- 상태: accepted
- 날짜: 2026-10-06
- 근거: 사용자 결정(2026-10-05, 2026-10-06). "구조는 V0.3(현 V1.1), 빠진 부분은 기존 구현으로 채움",
  "전체 연결, V1.1에 맞게 적용", 탈퇴는 V1.1 절차.
- 개정: [ADR 0013](0013-frontend-server-feature-connection.md)의 기준 특징 비전송 원칙(영구 모드 한정),
  [ADR 0014](0014-mysql-persistence-and-accounts.md)의 Flyway 마이그레이션 적용 방식

## 결정

1. **스키마 정본은 `database/`다.** API는 테이블을 만들거나 바꾸지 않는다(Flyway 제거).
   새 DB는 `schema_V1_1.sql`과 시드를 적용하고, 운영 DB는 `database/migrations/`를 번호순으로 적용한다(DB 담당 절차).
   Compose `db`는 빈 볼륨에서만 `infra/mysql/initdb`로 같은 파일을 그대로 실행한다.
   API는 시작할 때 V1.1 테이블·컬럼·시드(`DEFAULT_TEMP`, `REFERENCE-RULE-1`, 특징 3개)를 확인하고 없으면 시작하지 않는다.
2. **데이터베이스 이름은 `posture_service`**(V1.1 파일이 정한 이름)다. 앱 계정 이름 `posegood`은 유지한다.
3. **세션 생성(영구 모드)은 `setup`을 받는다.** 장치(`capture_device`), 영상 크기, 기준 자세 요약
   (`baseline_posture`, `baseline_feature`)이 세션보다 먼저 있어야 하기 때문이다. 기준 요약은 보정 시간·표본 수·
   화면 위치(어깨 중점, 코·어깨 상자 면적)·특징 3개의 평균과 표준편차뿐이다. 영상·랜드마크·프레임별 표본은 보내지 않는다.
   이것이 ADR 0013의 "기준 특징 원값을 서버로 보내지 않는다"를 영구 모드에서 개정하는 부분이다(사용자 결정: `baseline_feature` 저장).
   CEP와 공유하는 `CreateSession`은 바꾸지 않고 API 요청에만 `setup`을 더한다. 메모리 개발 모드는 `setup`을 무시한다.
4. **기준은 세션 생성 때 고정된다.** 새 보정은 이전 활성 기준을 비활성화하고(D-27), 비활성화된 기준으로는 새 세션을 만들 수 없다(409).
5. **판정 정책은 `threshold_policy` 행이다.** 같은 값 조합을 찾거나 `USER` 행을 추가하고 행을 고치지 않는다(BR-64·65).
   정확히 저장할 수 없는 값(0.5초 단위가 아닌 확정·복귀, 1초 단위가 아닌 재알림, 소수 넷째 자리 임계값)은 반올림하지 않고 400이다.
   시간당 알림 상한은 사용자 설정이 아니므로 기본 정책 값을 따른다. 기본 정책은 이름(`DEFAULT_TEMP`, 설정값)으로 찾는다.
6. **CEP 사건은 테이블로 나눈다.** `collapse_confirmed`→`collapse_event`+첫 `correction_alert`, `reminder`→추가 알림,
   `recovery_confirmed`→회복 종료, `interrupted`→`EXCLUDED`(종료 사유가 `ended`면 `SESSION_END`).
   세션 상대 ms는 `started_at` 기준 UTC 절대시각으로 바꾼다. 사건 번호는 확인된 사건 순서로 정해 기존 행과 다르면 502로 거부한다.
   일시정지·자리 비움·판정 불가·누락 구간은 종료 때 확인된 입력으로 `excluded_interval`을 만든다.
7. **조회 요약은 `confirmed_snapshot`에 둔다.** 세션마다 최신 확인 요약 한 행만 전체 요약이고 이전 행은 작은 증명으로 바꾼다.
8. **탈퇴는 V1.1 절차**다. `deletion_request` 기록, `CLOSED`, 식별 컬럼(이메일·해시·이름·나이·직업) 비움, 로그인 철회 후
   보관 기간 0으로 소유 행을 지우고 `DONE`으로 둔다. `feature_archive`가 남은 세션은 파일 삭제 배치를 기다린다(`PROCESSING`).
9. **사용자 ID는 `user_account_id` 10진 문자열**이다. 표시 이름은 30자(`display_name`). 화면의 데모 표시 설정은 저장 칸이 없어 기기에 둔다.

## 결과와 한계

- V1.1에 종료 대기 칸이 없으므로 확인되지 않은 종료는 내구 저장하지 않는다. 응답이 유실되면 클라이언트가 같은 `end_ms`로 다시 보낸다.
  종료가 확인된 뒤 다른 `end_ms`는 409다. 복구 작업자의 순번 회전은 메모리에만 있다(재시작 시 순서만 바뀐다).
- 사건의 좌우 방향(`deviation_type`)은 붕괴 유형(T-36)이 보류라 사건 테이블에 저장하지 않는다. 기록 원문(`client_record`)에는 남는다.
- `daily_stat`은 배치 범위라 API가 채우지 않는다. 동의(`user_consent`, T-41)는 보류라 가입 동의를 저장하지 않는다.
- 이전 V1 테이블로 운영 중인 DB는 자동 전환하지 않는다. API가 시작을 거부하므로 자료 이관은 별도 작업이 필요하다.
