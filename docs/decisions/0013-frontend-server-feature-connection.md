# ADR 0013: 세 특징 계약과 선택형 서버 판정 연결

- 상태: accepted (사용자가 서버 연결부터 진행하도록 선택한 개발 범위)
- 날짜: 2026-10-01
- 관련 결정: [API·CEP 경계](0011-api-cep-boundary.md), [시간 정책](0012-session-timing-policy.md)
- 관련 계획: [서버 연결 완료](../plans/completed/0014-frontend-server-connection.md)
- 개정: [ADR 0018](0018-db-schema-v11-service-storage.md) — 영구 모드의 세션 생성은 기준 요약(평균·표준편차·보정 시간·표본 수·화면 위치)을 보낸다.
  특징 요청(입력 v2)에는 여전히 변화량만 보낸다.

## 배경

브라우저의 `referenceScore`는 머리 높이·좌우 치우침·어깨 기울기를 사용했지만 기존
FastAPI v1 입력은 두 임시 변화량만 받았다. 사용자는 DB·인증 환경이 정해지지 않은 상태에서
서버 연결부터 진행하기로 선택했다. 기존 로컬 모드·기술 스택·의존성을 유지하며 새 계약을 병행한다.

## 특징 입력과 추론 책임

[입력 v2](../../contracts/inference-request.v2.schema.json)는 `schema_version=2.0`,
`feature_version=shoulder-relative-deltas-v1`과 다음 값을 받는다.

| 값 | 의미 |
| --- | --- |
| `baseline_id` | 카메라 기준 등록의 임의 UUID. `8-4-4-4-12` 형식이며 참여자 ID가 아니다. |
| `sequence`, `start_ms`, `end_ms` | 세션 내 순서와 상대 구간 `[start_ms,end_ms)`. 구간은 1..1500ms, 시각은 최대 24시간이다. |
| `phase`, `measurement_quality` | `running/rest/away`, `good/poor`. |
| `features` | 세 변화량과 현재·기준 품질 객체 또는 명시적 `null`. |

세 변화량은 기존 모델 특징에서 **현재−기준**으로 계산한다. 이미 어깨 너비로 정규화한
머리 높이 차이는 `head_gap_delta`, 좌우 치우침 차이는 `lateral_offset_delta`,
어깨 기울기 차이는 `shoulder_tilt_delta`다. 각도나 거리의 물리 단위가 아니며
유한수만 허용한다. `[-1,1]`로 자르지 않는다. `current_quality`, `baseline_quality`는 유한한 `[0,1]` 값이다.
모델 소유의 [어댑터](../../model/prototype/serverFeatures.ts)가 변화량을 만들며
영상·랜드마크·기준 특징 원값·참여자 식별 정보를 서버 요청에 넣지 않는다.
(영구 모드 세션 생성의 기준 요약은 [ADR 0018](0018-db-schema-v11-service-storage.md)의 예외다.)

FastAPI `POST /v2/infer`는 기존 `referenceScore`와 같은 점수를 계산한다.

```text
min(1, max(abs(head_gap_delta)/0.22,
           abs(lateral_offset_delta)/0.20,
           abs(shoulder_tilt_delta)/0.03) * 0.7)
```

어깨 기울기 스케일은 2026-10-07 [ADR 0019](0019-shoulder-tilt-scale.md)로 0.13 → 0.03으로 바뀌었다.

`running`, 품질 표시 `good`, 특징 존재, 현재·기준 품질 각각 0.65 이상일 때만 유효하다.
그 외에는 `valid=false`, 점수 0, 유형 `none`이다. 유효한 점수 0도 유형 `none`이다.
정규화한 좌우 변화가 다른 두 변화보다 **엄격히 클 때** 원본 양수는 미러 화면의
`left_lean`, 음수는 `right_lean`으로 표시한다. 머리 높이·어깨 기울기가 우세하거나 동점이면
`unspecified`다. 이 특징만으로 해부학적 전방 굽힘을 단정하지 않는다.

품질 0.65, 세 스케일, 점수 계수·판정 임계값은 검증 전 규칙을 보존한 값이다.
점수 전송 이름 `collapse_probability`는 보정된 확률을 뜻하지 않는다.
출력은 기존 [관측 v2](../../contracts/posture-observation.v2.schema.json)를 유지하고
`model_version=reference-feature-rule-v1`을 사용한다. v1 입력·출력 동작도 보존한다.
[공유 합성 사례](../../contracts/examples/v2/reference-feature-cases.json)로 TS 어댑터·로컬 점수와
Python HTTP 출력을 비교하며 실제 카메라 성능이나 의료 효과를 주장하지 않는다.

## 서버 처리와 재시도

브라우저가 `POST /v1/sessions/{UUID}/features`로 입력 v2를 전송하면 API는
FastAPI v2 추론 → 관측 v2 → CEP/Esper EPL 판정 → 조회 v1 순서로 처리한다.
[특징 응답 v1](../../contracts/feature-response.v1.schema.json)은
`{schema_version:"1.0", observation, session}`을 반환한다. API·프론트에 시간 판정을 중복하지 않는다.
최초 3초·복귀 3초(2026-10-06 2초에서 개정)·같은 사건 재알림 60초 등은 ADR 0012를 따른다.

API는 세션별로 요청을 직렬화하고, 추론 성공 후 기준 UUID를 고정한다.
개발 v2 경로는 모든 출력의 모델명을 `reference-feature-rule-v1`로 검증한다.
임의 모델명을 첫 응답에서 받아들이는 방식은 구현하지 않았다.
세션당 최대 10,000개 요청의 검증된 필드 SHA-256과 추론 출력·확정 거부 상태를 보관하며
요청의 특징 값은 서버 캐시에 남기지 않는다.

- 동일 sequence·동일 내용 재시도는 처음 추론 출력을 재사용한다. CEP가 이미 수용했다면
  시간·사건·알림을 다시 누적하지 않는다. 응답의 `session`은 최신 확인 요약이므로 이후 관측이나 종료를 반영할 수 있다.
- 같은 sequence의 다른 내용, 변경한 기준, 역순·겹침은 409다. 설정도 세션 생성 시 고정한다.
- 추론 실패·계약 불일치는 502이며 마지막 성공 요약을 유지한다. 아직 추론 출력을 확보하지 못했다면 재시도 때 추론을 다시 호출한다.
  낮은 현재/기준 품질을 유효하다고 반환하는 출력도 이 개발 모델 계약의 위반으로 거부한다.
- 추론 성공 후 CEP 응답이 미확인이면 원출력을 pending으로 유지한다. 같은 요청을 먼저 재시도해야 하며
  후속 관측·종료는 409다. CEP의 확정 409/429 거부는 pending을 해제해 종료를 허용한다.
- 메모리 세션이 없으면 404다. 재시작 후 같은 UUID의 과거 세션이 복구된 것처럼 생성하지 않는다.

## 프론트 선택과 관측 구간

측정 준비에서 사용자가 개발용 서버 모드를 선택한다. 기본 로컬 모드는 유지한다.
Vite의 같은 출처 `/api` 프록시를 통해 loopback API에 연결하며 인증 연결은 아직 없다.
서버 화면은 확인된 사건·통계만 표시하고 계약에 없는 확인 진행률을 계산하지 않는다.

송신 큐는 한 요청씩 처리한다. 기본 대기 한도는 16개다. 응답 검증과 브라우저 중간 기록 저장이
완료되어야 큐 앞 요청을 제거한다. 연결 실패·시간 초과·저장 실패 때 입력을 멈추고
같은 sequence·시각·내용을 재시도한다. 409/429 특징 거부는 조회로 마지막 확인 상태를 맞춘 뒤 종료할 수 있다.
새로고침은 마지막 확인 요약·고정 기준·미확인 요청 하나를 복구하며, 아직 보내지 않은 큐 전체를 영구 보존하지 않는다.
복구 후 저장한 시작 기준과 카메라 장치·영상 크기의 일치를 확인하고, 사용자가 위치가 같다고 확인한 뒤 직접 재개한다.
재연결 때 새로 보정한 기준으로 저장된 기준을 교체하지 않는다. 장치/크기 일치가 실제 위치 이동을 감지하지는 못하며
위치 확인의 정확도는 별도 실기기 검증이 필요하다. 404 유실을 성공한 종료로 표시하지 않는다.
명시적으로 마지막 확인 요약만 보관하면 서버 종료 미확인으로 기록한다. 종료 요약에는 원래 사건·통계 snapshot을
남기며 표시용 사건에서 합쳐진 좌우 유형·제외 사유를 원자료에서 확인할 수 있다.

실험용 어댑터는 인접한 실제 프레임의 관측 시각으로 구간을 만들고 첫 프레임은 구간 시작점만 제공한다.
양 끝 특징의 품질을 확인하며, 기존 1초 프레임 유효기간을 넘는 공백에는 입력을 중단한다.
현재 끝점 특징으로 인접 구간을 대표하는 근사이며 실제 관측 창·품질 성능의 최종 확정은 아니다.
최신 저품질 프레임은 이전 정상 응답의 도착 여부와 관계없이 화면을 판정 불가로 바꾼다.
통계·사건은 확인된 서버 결과를 유지한다.
휴식 입력은 확인 가능한 구간만 기록하고 스케줄링·통신 공백을 정상이나 이탈 시간으로 채우지 않는다.
기준 특징과 미확인 변화량은 복구용으로 브라우저에 일시 보관하고 결과 저장 성공 후 정리한다.

## 남은 범위

현재 저장은 서버 프로세스 메모리와 브라우저 로컬 기록이다. DB·인증·동의·삭제·보존 기간,
실촬영 정확도·장시간 성능·알림 전달·학습 모델은 구현 또는 검증하지 않았다.
[DB·인증 설계](../design/server-persistence-and-auth.md)는 제품·제공자를 선택하지 않은 후속 설계다.
실행 방법과 오류 계약은 [서비스 안내](../../backend/README.md)를 따른다.
