# ADR 0020: 판정은 API 하나 안에서 한다 (구조·시간 정책·특징·계정)

- 상태: accepted
- 날짜: 2026-10-09 (2026-10-10 DB V2.1·V2.2, 2026-10-15 아키텍처 v5.2 반영. 2026-10-27 ADR 정리로 옛 0012 시간 정책, 옛 0013 특징·점수, 옛 0019 어깨 기준폭, 옛 0014 계정의 최종 결정을 2~5절로 옮김)
- 분야: BE
- 근거: 사용자 결정(2026-10-09) 「백엔드를 프론트와 DB에 맞게 처음부터 다시 만든다」, 판정은 API 안으로 통합. DB V2.0(CR-04)의 「CEP를 쓰지 않는다. 붕괴 확정·회복·재알림 판정은 백엔드가 맡는다」.
  2026-10-27 BE 피드백: 옛 0012·0013·0019는 최종 결정만 옮기고, 옛 0014는 맞는 문장만 살리고, 작업 내역에 가까운 옛 0011·0018·0022·0023은 지운다
- 관련: [ADR 0021](0021-app-sends-information-server-judges.md)(앱은 좌표만 보낸다), [ADR 0024](0024-session-ends-on-lost-connection.md)(끊기면 세션 종료), [ADR 0028](0028-server-time-for-baseline-registration.md)(절대 시각은 서버), [DB 안내](../../database/README.md), [백엔드 안내](../../backend/README.md)

## 1. 구조

1. **백엔드는 Spring Boot API 하나다**(Java 17·Spring Boot 4.0.8·Gradle Wrapper). Esper CEP 모듈·내부 HTTP·outbox·재전달은 없다.
2. **시간 판정은 `backend/api/.../engine/`의 순수 Java다.** 임계 비교 세 개(붕괴 확정·회복·재알림)는 `DecisionRules`에만 둔다. 정책은 2절.
3. **메모리 개발 모드는 없다.** API는 MySQL과 계정을 필수로 한다. 개발·시험은 임시 MySQL(로컬 loopback 또는 Docker)을 쓴다.
4. **DB 스키마의 정본은 `database/`다.** API는 테이블을 만들거나 바꾸지 않고, 시작할 때 필요한 테이블·컬럼·시드가 있는지만 확인한다.
5. **진행 중 판정 상태는 API 메모리에 있다**(DB에 관측·스냅샷 테이블이 없다, CR-04).
   - 사건은 처리 직후 `collapse_event`·`correction_alert`로 나눠 쓰고, 종료 때 `monitor_session`의 종료 컬럼과 `excluded_interval`을 한 트랜잭션으로 쓴다.
   - 일별 통계(`daily_stat`)는 Spark J2가 매일 00:00에 전날(KST)을 집계해 쓰고, API는 읽기만 한다(아키텍처 v5.2).
   - API를 재시작하면 진행 중 세션의 상태는 복구하지 않는다. 그래서 API는 한 인스턴스로 실행한다. 종료된 세션 상태는 30분 보관한다.
6. **시각은 KST로 저장한다**(CR-04, JDBC 세션 시간대 `Asia/Seoul`). API 응답의 시각은 UTC ISO-8601이다. 절대 시각을 누가 정하는지는 [ADR 0028](0028-server-time-for-baseline-registration.md).
7. **실시간 채널은 API의 `/v2/realtime` WebSocket이다**([실시간 계약](../../contracts/realtime/README.md)). 연결 하나가 측정 한 번 또는 등록 한 번이다.
8. 추론 서비스 연결(`InferenceClient`)은 시험용 임시 연결이라 이 ADR의 판단 근거가 아니다.

## 2. 시간 정책 (옛 0012, 2026-10-01 확정, 2026-10-06 개정)

| 항목 | 정책 |
| --- | --- |
| 최초 알림 | 유효한 이탈 관측이 연속 3초 지속되면 사건을 확정하고 첫 알림을 결정한다. |
| 정상 복귀 | 열린 사건에서 유효한 정상 관측이 연속 **3초** 지속되면 복귀를 확정한다(2026-10-06 2초 → 3초, 동욱 결정). 그 전에 다시 이탈하면 복귀 누적을 초기화한다. |
| 재알림 | 같은 사건의 마지막 알림부터 60초 후, 이탈 관측이 계속되면 다시 알린다. 재알림은 새 사건이 아니다. 새 사건의 첫 알림에는 이전 사건의 60초 간격을 적용하지 않는다. |
| 휴식 후 재개 | 열린 사건은 복귀와 구분하여 중단하고 연속 이탈·복귀 누적을 초기화한다. 재개 후 이탈이 지속되면 새 사건을 만든다. |
| 자리 비움·측정 불가·누락 | 연속 판정을 끊고 열린 사건을 중단한다. 제외 시간을 정상이나 이탈 관측으로 보충하지 않는다. |
| 통계 | 휴식·자리 비움·측정 불가·누락은 유효 시간, 정상/이탈 누적, 유지율 분모 및 사건 간격의 유효 시간에서 제외한다. 전체 경과 시간과 제외 시간은 별도 표시할 수 있다. |
| 설정 적용 | 3초·3초·60초는 기본값이다. 세션 시작 시 설정을 고정하고, 이후 변경은 다음에 새로 시작하는 세션부터 적용한다. 휴식 재개는 새 세션이 아니다. |

- 중단을 정상 복귀로 기록하거나 휴식 전후의 이탈 시간을 합쳐 최초 알림 조건을 채우지 않는다.
- 정책 식별자 `legacy-interrupt-v1`을 유지한다(호환성용 이름).
- 이 정책은 제품 요구이며 실기기 탐지 성능·최적 임계값·의료 효과를 증명하지 않는다.

## 3. 특징과 점수 (옛 0013, 옛 0019)

- **계산 위치(2026-10-30, [계획 0064](../plans/active/0064-server-3s-frame-batch-inference.md)):** 실시간 판정의 특징·점수는 추론 서버가 **프레임마다** 계산한다(API가 서버 시계로 약 3초 모은 프레임을 `POST /v3/infer`에 그대로 넘김, 평균하지 않음). 그 전에는 API(`FrameFeatures.java`)가 구간마다 평균을 내 `POST /v2/infer`에 넘겼다(A안). 아래 규칙은 그대로이고 `FrameFeatures.java`는 hello의 기준 자세 확인과 같은 규칙의 Java 기준값으로 남는다. 시간 판정·임계값 비교는 계속 API 엔진(`DecisionRules`)이다.
- **판정 가능 검사:** 코·양 어깨 visibility 0.65 이상, 화면 가장자리 2% 안쪽, 어깨 폭이 화면 너비 10% 이상, 양 귀 좌표 있음(`FrameFeatures.java`). 검증 전 값이다.
- **특징 3개:** 기준 자세 대비 **현재 − 기준**이고 모두 **어깨 너비로 정규화**한다. 물리 단위가 아니며 `[-1,1]`로 자르지 않는다.
  - `head_gap_delta`: 머리 높이 차이
  - `lateral_offset_delta`: 좌우 치우침 차이. **양 귀 가운데**(머리 중심)에서 잰다(귀가 없으면 코)
  - `shoulder_tilt_delta`: 어깨 기울기 차이
- **점수(규칙, 검증 전):** `min(1, max(|head_gap|/0.22, |lateral_offset|/0.20, |shoulder_tilt|/0.03) × 0.7)`.
  어깨 기울기 기준폭은 2026-10-07 0.13 → **0.03**으로 낮췄다(동욱 결정, 실측 확인 전 — 실제 사용자는 살짝 틀어진 상태가 많고 점점 틀어지므로). 정자세 흔들림(최대 약 0.03)과 거의 같아 오경고가 날 수 있어 실사용 확인 후 조정한다.
  점수 이름 `collapse_probability`는 보정된 확률이 아니다.
- **유효 조건:** 품질이 낮은 구간은 유효로 표시하지 않는다(`valid=false`, 점수 0, 유형 `none`).
- **유형:** 정규화한 좌우 변화가 다른 두 변화보다 엄격히 클 때 원본 양수는 사용자 본인 기준 `left_lean`, 음수는 `right_lean`이다(카메라 원본 영상은 반전되지 않아 큰 x가 사용자 왼쪽). 그 밖에는 `unspecified`다.
- **고개 돌림:** 귀 가운데 대비 코 위치가 기준보다 어깨 너비의 0.15 넘게 바뀌면 판정하지 않는다.

## 4. 계정 (옛 0014의 지금도 맞는 결정, 아키텍처 v5.2)

- 계정은 이메일·비밀번호다. 비밀번호는 적응형 단방향 password encoder로 저장한다.
- 모든 측정·기록·프로필·설정은 검증한 인증 주체의 내부 사용자 ID에 속한다. 요청 본문의 사용자 값을 인증이나 소유권의 근거로 쓰지 않는다.
- 원본 영상·비밀번호 원문은 영구 자료에 넣지 않는다.
- 로그인 끊기(비밀번호 변경·탈퇴)는 그 사용자의 로그인과 열린 실시간 연결을 끝낸다.
- 탈퇴는 **철회할 수 없다.** API는 탈퇴 접수(`deletion_request` `REQUESTED`, 계정 `CLOSED`)만 하고, 30일 유예 뒤 최종 삭제와 안내 메일은 Spark J3가 매일 04:00에 한다. CLOSED 계정은 로그인 `403 ACCOUNT_CLOSED`, 같은 이메일 재가입은 최종 삭제 전까지 `409`다.

## 5. 결과와 한계

- 재시작하면 진행 중 측정이 끊긴다([ADR 0024](0024-session-ends-on-lost-connection.md)).
- `deviation_type`(좌우·전방 방향)은 붕괴 유형(T-36) 보류로 사건 테이블에 없다.
- 시간당 알림 상한(`notify_max_per_hour`)은 아직 적용하지 않는다.
- Spark J2·J3가 켜지기 전까지는 `daily_stat`이 채워지지 않고, 유예가 끝난 탈퇴 계정도 지워지지 않는다.
