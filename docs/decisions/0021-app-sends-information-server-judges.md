# ADR 0021: 앱은 정보만 보내고 판정은 서버가 한다

- 상태: accepted (구현 전. [계획 0023](../plans/active/0023-frontend-server-only.md))
- 날짜: 2026-10-11
- 근거: v4 회의 결정(FE 회신 10/08, 지금은 [FE 제안서](../design/fe-server-proposal.md)), 2026-10-11 FE 결정(앱 판정·라벨 전부 제거)
- 대체: [ADR 0013](0013-frontend-server-feature-connection.md)의 "앱이 특징 변화량을 만들어 보낸다", "기본 로컬 모드 유지",
  [ADR 0012](0012-session-timing-policy.md)의 로컬 모드 시간 정책
- 바꾸는 문서: [데이터 플랫폼 경계](../design/data-platform-boundary.md)의 "원본 좌표 미전송",
  [실시간 계약 v1](../../contracts/realtime/README.md)의 "좌표를 넣지 않는다"

## 결정

1. **앱은 판정하지 않는다.** 점수, 상태(좋음/무너짐/측정 불가), 유형(머리·좌우 기울임), 판정 가능 검사, 고개 돌림 제외,
   복귀 대기, 시간 판정(확정·복귀·재알림)을 모두 서버가 한다.
2. **앱은 관절 좌표 같은 정보만 보낸다.** 계약 이름은 `posture.frames.v1`. 형식은 [FE 제안서](../design/fe-server-proposal.md) 4장
   (0.5초 1건, 관절 9개 `[x, y, visibility]`, 프레임 그대로)를 따른다. 일시정지(`rest`)·카메라 끊김(`away`)은 판단이 아니라 사실이라 앱이 알린다.
3. **서버 없이 쓰는 로컬 모드를 없앤다.** 앱은 로그인한 서버 모드만 있다. 서버가 없으면 측정을 시작하지 않는다.
4. **화면은 서버 결과로만 바뀐다**(`observation`·`progress`·`decision`·`alert`). 연결이 끊기면 "연결 끊김"을 화면을 막지 않게 띄우고
   카메라 화면·관절 표시는 그대로 둔다. 정보는 쌓아 두었다가 다시 연결되면 같은 순번으로 다시 보낸다. 앱 판정이 없으므로 로컬 미리보기 판정은 없다.
5. **ML용 내보내기에 앱 판정 라벨을 붙이지 않는다**(`state`·`type`·`score` 열 제거). 자세 데이터 수집 화면은 BE·ML 요구를 다시 받아 만든다.
6. 앱 설정 중 소리 켜기는 저장하지 않는다. 「자세 알림」 켜기·끄기만 서버(`user_account.alert_enabled`)에 저장한다.

## 이유

- 앱에서 라벨을 붙이면 나중에 규칙·모델을 고칠 때 과거 데이터를 다시 계산할 수 없다. 좌표가 남아 있으면 새 규칙을 다시 적용할 수 있다.
- 화면과 서버 판정이 다른 규칙을 쓰면 어긋난다. 서버 모델이 LSTM으로 바뀌면 브라우저 규칙으로는 같은 결과를 낼 수 없다.
- 서버 개발이 마무리 단계라 앱의 로컬 판정이 더는 개발·시연에 필요하지 않다.

## 결과

- 서버 부담이 늘어난다(처리 단계 추가, 세션 상태 보관, 장애 시 화면 판정 정지). 목록은 [FE 제안서](../design/fe-server-proposal.md) 9장.
- 서버가 앱과 같은 결과를 내도록 FE가 [FE 제안서](../design/fe-server-proposal.md)와
  [합성 시험 데이터](../../contracts/examples/frames/reference-rule-cases.json)를 넘긴다. 앱 판정 코드는 이 자료를 만든 뒤 지운다.
- 개인정보 경계가 바뀐다. 좌표를 보내므로 가입 때 좌표 수집 동의를 받는다(동의문은 FE, 저장 위치는 DB 요청 중).
  로컬 모드가 없으므로 **좌표 전송 동의는 서비스 이용의 필수 조건이다.** 동의하지 않으면 가입할 수 없고, 철회하면 측정할 수 없다(학술용 프로젝트라 필수 동의로 정함).
- 개발·시연에도 서버가 있어야 한다.

## 아직 정하지 않은 것

[FE 제안서](../design/fe-server-proposal.md) Q1~Q10·8장.
특히 서버가 좌표를 받는 시점, 팀 API의 세션 시작·종료 Kafka 연결, 기준 자세 계산 방식.
판정은 DevOps Kafka 경로(추론 → v1 판정기)가 한다. 앱이 붙는 곳은 2026-10-11 아키텍처 v5에서 BE가 만드는 입출구 서버(`auth`·`api`·`ws`)로 정해졌다(처음에는 FE의 독립 게이트웨이였다, [FE 제안서](../design/fe-server-proposal.md) 0장).
