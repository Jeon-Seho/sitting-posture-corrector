# ADR 0032: 판정 불가 프레임은 좌표 없이 신호만 보낸다

- 상태: accepted (2026-10-27 FE 결정, V3 반영. BE·ML·팀장에게 알릴 것 — [FE 제안서](../design/fe-server-proposal.md) BE-9)
- 날짜: 2026-10-27
- 근거: klaod-tech(FE) 10/27 결정
- 대체: [ADR 0021](0021-app-sends-information-server-judges.md) 예외(2026-10-12 회의)의 「좌표는 함께 보내고」

## 결정

앱이 사용자 위치를 판별하지 못한 프레임(어깨가 화면 밖, 추적기가 관절을 주지 않음)은 좌표를 넣지 않고 판정 불가 신호만 보낸다.

```json
{ "t_ms": 1230, "p": null, "valid": false }
```

- 사람이 아예 없는 프레임은 지금처럼 `{ "t_ms": …, "p": null }`(`valid` 없음)이다.
- 서버는 두 경우 모두 판정 불가 시간(`unknown_ms`, DB `UNMEASURABLE`)으로 센다. 서버 코드는 바꾸지 않아도 된다(BE `FrameInterval.Frame`은 `p: null`과 `valid: false`를 함께 받는다).
- 화면은 서버를 기다리지 않고 바로 「자세를 확인할 수 없어요」를 띄운다(`LiveState.placeable`, 10/27).
- 판정 가능한 프레임과 그 판정(점수·유형·사건·시간 규칙)은 ADR 0021 그대로 서버가 한다.

## 이유

- 관절 하나가 빠진 프레임은 서버가 판정하기에도 좋지 않고, LSTM 학습 데이터로도 맞지 않다.
- 빠진 관절을 `[0, 0, 0]`으로 채워 보내면 HDFS에 가짜 좌표가 남는데, 나중에 진짜와 가려낼 방법이 없다.
- ADR 0021의 이유 「좌표가 남아 있으면 새 규칙을 다시 적용할 수 있다」는 판정 가능한 프레임에는 그대로 맞다. 관절이 빠진 프레임은 새 규칙으로도 판정할 수 없어 남길 이유가 없다.

## 결과

- 판정 불가 프레임은 HDFS·학습 데이터에 좌표 없이 시각과 「판정 불가」만 남는다. ML(지성)·BE(김유진)·DevOps에 알린다.
- 앱의 판정 불가 범위는 지금 「어깨가 안 보임 또는 관절이 빠짐」이다. 정확도 부족·화면 가장자리·거리는 서버가 판정 불가로 정한다(좌표는 보냄). 이 범위를 넓힐지는 따로 정한다([계획 0059](../plans/active/0059-slim-realtime-results-over-api.md)).
- 계약 `posture.frames.v1`의 형식은 그대로다(`p`는 이미 null 가능). 뜻만 바뀌므로 설명을 고친다.
