# ADR 0025: 앱은 항상 서버로 측정한다 (로컬 모드 없음)

- 상태: accepted (앱 구현 `feature/frontend-features-and-integrationV3` `f88ffe3`)
- 날짜: 2026-10-21
- 근거: 2026-10-21 사용자(FE) 결정 — 「이젠 무조건 서버 모드로 개발해야지」, 「develop에 다 있으니까 판정 계산이나 더미 데이터는 다 지워버리자」
- 대체: [ADR 0003](0003-retro-integration.md)의 「`frontend/src/lib/engine.ts`가 웹캠과 시연의 공통 시간 정책을 담당한다」(로컬 모드 예외),
  [ADR 0021](0021-app-sends-information-server-judges.md)을 앱 코드에서 끝까지 적용한 것이다
- 관련: [ADR 0024](0024-session-ends-on-lost-connection.md)(끊기면 세션 종료), [ADR 0026](0026-baseline-average-by-app-b1.md)(자세 등록), [FE 제안서](../design/fe-server-proposal.md) 7.0·7.2, [계획 0023](../plans/active/0023-frontend-server-only.md)

## 결정

1. **「측정 시작」은 항상 서버 측정이다.** 로컬 모드와 개발자 옵션의 「서버 판정 사용」 스위치, `VITE_REALTIME_URL`·`VITE_REALTIME_FRAMES`를 없앤다.
   서버에 닿지 못하거나 로그인이 없으면 측정을 시작하지 않고 이유를 보여 준다.
2. 측정은 BE 명세 7장·11장 그대로다: S1 `PUT /v2/sessions/{id}` → `/v2/realtime` `hello`(`purpose:"measure"`) → `ready`(5초) →
   0.5초마다 좌표 구간 1개(`ready` 전에 만든 구간은 뒤에 순서대로) → `end` → `closed(ended)`. 10초 안에 안 오면 S4로 결과를 읽는다.
3. **앱은 판정하지 않는다.** 화면의 점수(100 × (1 − `collapse_probability`))·상태·알림·통계는 서버가 보낸 것만 쓴다.
   서버 결과를 앱이 다시 검사하지 않고 형식만 확인한다(FE 제안서 7.0, 10/21).
4. 앱이 보내는 구간: 잠시 쉬기는 `rest`, 카메라 영상이 1초 넘게 멈추면 `away`(카메라가 돌아와야 「측정 재개」),
   쓰던 카메라가 빠지거나 측정 중 영상 크기가 바뀌면 `end`로 종료·저장(7.0, 10/21). 어깨가 유예 뒤에도 안 보이는 프레임은 `valid:false`.
5. 이어하기(앱이 중간 저장을 두었다가 다시 여는 것)는 없다. 앱이 닫히거나 연결이 끊기면 서버가 마지막 구간까지 저장한다(ADR 0024).
6. 로컬 판정 코드(판정 엔진 `machine`·`scenario`·`snapshot`, 복귀 대기, 카메라 샘플, 로컬 측정 화면, v1 서버 측정 코드, 특징·좌표 내보내기)는
   지운다. develop에는 남아 있어 필요하면 그 브랜치에서 본다.
7. 기록·달력 화면이 서버 기록(R1·T1)을 읽기 전까지, 측정 결과를 이 기기에도 R1과 같은 형식(`server.view` = SessionView)으로 남긴다.
   R1로 바꾸면 이 복사를 지운다.

## 이유

- 판정은 서버 한 곳에서 한다(ADR 0021). 앱에 판정이 남아 있으면 서버 결과와 다른 숫자가 화면에 나오고, 두 구현을 함께 고쳐야 한다.
- 서버가 판정할 준비가 됐다(BE `/v2/realtime` 10/17 구현, DevOps 8088 시험 환경 10/21). 로컬 모드를 남겨 둘 이유가 없다.
- 스위치로 두 방식을 함께 두면 시험할 경우의 수가 두 배가 되고, 어떤 방식으로 측정됐는지 기록마다 따져야 한다.

## 결과

- 서버 없이는 측정·자세 등록을 할 수 없다. 그래서 V3를 develop에 합치는 것은 공개 서버(`api.posegood.site` 터널)가 붙은 뒤에 한다.
  Vercel 배포본(포크 develop)은 그때까지 예전 로컬 판정 앱이다.
- 로그인(`/v2/auth`)·W1 연결은 BE가 한다(10/21 DevOps 답). 그 전까지 앱의 서버 요청은 「로그인이 필요해요」로 멈춘다.
  S1 `policy`는 계정의 판정 기준(W1 `rules`)과 같아야 하므로 W1 전에는 앱 기본값을 보낸다(FE 제안서 1장 B-3).
- 브라우저 통합 시험(`check-browser`)의 로컬 측정·이어하기 시나리오는 서버 전용으로 다시 써야 한다([계획 0030](../plans/active/0030-make-check-failures.md) G6).
- 학습 데이터 수집 화면은 그대로 둔다. 그 화면이 쓰는 기준 특징은 서버 기준 좌표에서 계산해 넘긴다(임시, F5 나머지).
