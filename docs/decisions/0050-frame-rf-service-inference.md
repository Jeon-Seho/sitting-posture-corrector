# ADR 0050: 서비스 추론에 프레임별 2단계 RF를 연결한다

- 상태: accepted
- 날짜: 2026-11-19
- 관련: [계획 0098](../plans/active/0098-frame-rf-service-inference.md), [ADR 0020](0020-single-api-decision-engine.md), [ADR 0047](0047-posture-from-deviation-probability.md), [100배 증강 RF 후보](../../model/pretrained/frame-rf-100x/README.md)

## 배경

local 실시간 경로의 API는 현재 develop에서 기준 자세와 프레임 사이의 특징 변화량을 계산해 `POST /infer`에서 규칙 점수를 받는다. 2단계 RF는 관절 9점에서 계산한 6개 특징으로 개인 기준 대비 이탈을 평가한다. 이 결정은 RF를 제공하는 추론 서버 경계를 정한다. 버전 없는 이름은 [ADR 0049](0049-no-version-in-names.md)를 따른다. 기존 Java 요청은 키포인트 계약에 맞지 않아 422를 받으므로 이름 정리 브랜치를 먼저 병합하고, RF 변경과 BE의 키포인트 전환을 함께 병합·배포한다.

## 결정

1. **추론 서버에서 특징을 계산한다.** API는 `POST /infer`에 프레임과 기준 자세의 9점 좌표를 보내고, Python은 학습 코드와 같은 식으로 6개 특징을 계산한다.
2. **RF 점수를 기존 임계값에 맞춰 변환한다.** 유효 프레임의 평균 이탈 클래스 점수 `p`에 `s = 1.4·p (p ≤ 0.5)`, `s = 0.4 + 0.6·p (p > 0.5)`를 적용한다. RF 점수 0.5가 기본 정책의 0.7에 대응한다. 앱 민감도 0.6·0.7·0.8과 DB 정책을 유지한다. 양쪽 끝의 민감도는 각각 `p ≈ 0.43`, `p ≈ 0.67`에 대응한다.
3. **9점 품질을 검사한다.** 9점 중 하나라도 visibility가 0.65 미만이거나 좌표가 0~1 밖이면 RF에서 해당 프레임을 제외한다. 쓸 수 있는 프레임이 없는 구간은 측정 불가로 반환하고 규칙 점수로 대체하지 않는다.
4. **모델 초기화에 실패하면 503을 반환한다.** RF 가중치를 불러오지 못하면 `/health`와 `/infer` 모두 503이다. 규칙 모델로 되돌리려면 `POSEGOOD_INFERENCE_MODEL=rule`을 명시한다.

## 근거

- 학습과 서비스 추론에서 같은 특징 계산식과 프레임 품질 조건을 쓰면 입력의 의미를 맞출 수 있다.
- 점수 변환은 기존 민감도 선택과 DB 정책을 유지하면서 RF의 비교 기준을 연결한다. 3초 확정·3초 복귀·60초 재알림은 API 판정 엔진이 담당한다.
- 초기화 실패를 503으로 드러내면 서비스 상태와 배포한 모델을 확인할 수 있다. 명시적으로 규칙을 선택한 경우에는 규칙 모델 버전을 응답에 담는다.

## 대안

- API에서 6개 특징을 직접 계산하면 Java에도 학습 코드의 식과 품질 검사를 유지해야 한다.
- RF 원점수를 그대로 쓰고 정책 임계값을 다시 정하려면 앱 민감도와 기존 DB 정책을 함께 조정해야 한다.
- 저품질 프레임이나 초기화 실패에 규칙 점수를 자동 적용하면 구간마다 점수의 기준이 달라지거나 배포 오류가 가려질 수 있다.

## 결과와 한계

- [추론 계약](../../contracts/README.md#키포인트-입력과-관측-응답)은 관측(`schema_version: "2.0"`)에 `invalid_reason`을 추가해 BE가 측정 불가 사유를 받을 수 있게 한다. Kafka 소비자는 [features 본문](../../contracts/feature-deltas.schema.json)으로 자체 규칙 점수를 계산한다.
- DB의 기준 자세는 평균 좌표 9점만 저장한다. 앱은 등록 시 코와 양어깨의 품질을 검사하므로 학습 때 전제한 기준 9점 visibility 조건을 서비스에서 확인할 수 없다.
- 전체 자료로 학습한 이 후보의 독립 시험과 0.5 운영 기준 검증은 남아 있다. 점수 변환은 임계값 연결에 쓰이며 확률 보정의 근거는 없다.
- 9점 검사로 측정 불가 구간이 늘 수 있다. 현재 판정 엔진은 측정 불가 구간에서 열린 사건을 중단하고 연속 시간을 초기화한다. 같은 이탈이 이어져도 이후 3초간 다시 확인되면 새 최초 알림이 발생할 수 있어, 같은 사건에 적용되는 60초 재알림 간격이 반복 알림을 막지 못한다. 중단 정책 보완은 후속 과제다.
