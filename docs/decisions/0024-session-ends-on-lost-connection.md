# ADR 0024: 서버 연결이 끊기면 세션을 끝낸다

- 상태: accepted (앱 구현 `feature/frontend-camera-select-disconnect`, 2026-10-21 V3 `/v2/realtime` 측정에 다시 구현 — [ADR 0021](0021-app-sends-information-server-judges.md). 아래 "결과"의 `realtime/client.ts`·HTTP 큐는 그때 지웠다)
- 날짜: 2026-10-13 (번호: 예전 0022. BE 브랜치의 옛 ADR 0022(DB V2.3 연동)와 겹쳐 10/15에 0024로 옮겼다)
- 근거: 2026-10-13 사용자(FE) 결정
- 대체: [ADR 0021](0021-app-sends-information-server-judges.md) 4번의 "연결이 끊기면 화면을 막지 않게 띄우고,
  정보를 쌓아 두었다가 다시 연결되면 같은 순번으로 다시 보낸다"

## 결정

1. **세션**은 사용자가 「시작」을 누른 때부터 「종료」를 누르기 전까지의 측정 한 단위다.
   세션 번호는 날짜(기기의 현지 날짜)마다 시작 순서로 매긴다. 2026-10-13의 첫 세션은 1, 두 번째는 2이고,
   2026-10-14가 되면 다시 1부터 센다. 화면에는 `2026-10-13 · 세션 2`처럼 보인다(기록 목록, 끊김 화면).
2. **측정 중 서버 연결이 끊기면 그 세션은 끝난 것으로 본다.** 다시 연결하거나 쌓아 둔 정보를 다시 보내지 않는다.
   - 끊김: 서버가 세션을 받아들인 뒤(첫 응답 이후) 서버가 답하지 않는 경우(연결 실패, 응답 시간 초과),
     중계 서버가 뒤의 서버에 닿지 못했다고 답한 경우(502·503·504. 개발용 Vite 중계는 API가 꺼져 있으면 502를 준다),
     실시간 WebSocket이 닫힌 경우.
   - 서버가 답했지만 거절한 경우(그 밖의 4xx·5xx)는 끊김이 아니며 기존 처리(멈춤·다시 시도)를 따른다.
   - 세션을 받아들이기 전(시작 요청 실패)은 측정이 시작되지 않은 것이라 기존처럼 이유를 보여 주고 다시 시도하게 한다.
   - 앱은 카메라를 끄고, 서버가 이미 확인한 요약만 "서버 종료 미확인" 기록으로 남긴다. 확인되지 않은 구간은 넣지 않는다.
3. **화면을 막는 팝업을 띄운다.** 앱 전체를 어둡게 하고 가운데에 「서버와의 연결이 불안정합니다 / 재접속 후 다시
   시도해 주세요」와 「종료하기」 버튼만 둔다. 닫기·Esc로 닫히지 않는다. 「종료하기」는 데스크톱 앱을 종료한다
   (브라우저에서는 탭을 닫으며, 닫을 수 없으면 직접 닫도록 안내한다).
4. 설정 › 개발자 옵션의 「끊김 화면 확인」은 실제 끊김과 같은 경로를 탄다. 측정 중이면 그 세션이 끝나고,
   「종료하기」로 앱 종료까지 확인할 수 있다.

## 이유

- 끊긴 동안의 좌표를 나중에 다시 보내면 서버 판정 시점과 실제 시점이 어긋나고, 재전송·중복 처리를 앱과 서버가 모두 떠안는다.
- 세션 단위로 끊어 두면 기록이 "시작~종료"로 단순해지고, 끊김은 다시 시작하면 새 세션이 된다.

## 결과

- 짧은 네트워크 흔들림에도 세션이 끝난다. 사용자는 앱을 다시 열어 새 세션을 시작한다.
- 구형 브라우저 통합 시험(`tools/browser/scenarios.mjs`)의 "쉬는 중 API 재시작 → 새로고침 뒤 서버 세션 유실(404)" 시나리오는
  이 결정의 연결 끊김 처리와 맞지 않았다. 해당 시나리오는 2026-10-29 도구 정리에서 제거했으며 복원은 남은 과제가 아니다.
  현재 연결 끊김 관련 시험과 실제 서버 점검은 [품질 기준](../quality.md)을 따른다.
- 앱의 재연결·재전송 코드(`realtime/client.ts`의 재연결, HTTP 큐의 다시 시도)는 끊김에 대해서는 쓰이지 않는다.
  서버 거절에 대한 다시 시도는 남는다.
- 서버·게이트웨이 쪽 재연결 처리(실시간 계약의 `hello`·놓친 `decision` 재전송)는 앱이 쓰지 않는다. 계약 정리는 BE와 정한다.
- 세션 번호는 앱이 기록의 시작 시각으로 계산한다. 서버 DB에 번호 칸을 둘지는 DB와 정한다.
