# ADR 0029: 측정은 KST 자정에 서버가 끊고, 화면의 날짜·시각은 서버 시각을 따른다

## 배경

- 일별 통계(T1)는 Spark J2가 매일 00:00에 전날(KST) 세션을 **세션 시작 날짜**로 집계한다(DB `daily_stat.stat_date`).
- 자정을 넘긴 측정(예: 22:50~02:00)은 J2가 돌 때 아직 진행 중이라 어제 통계에 들어가지 못한다. 시작일 기준이면 앱의 오늘 화면에도 들어가지 않아 어디에도 보이지 않는다. 끝난 날 기준으로 바꾸면 서버 집계와 어긋나 섞인다.
- 10/26 기준 앱은 날짜·시각을 PC 시계로 정한다: 기록의 시작·종료 시각(`useSessionPersistence.ts` `new Date()`), 오늘 날짜(`dayKey(new Date())`), 날짜 나누기(`localDay`·`dayKey`는 브라우저 시간대). 같은 앱 안에서도 `lib/comparison.ts`는 종료 시각, 나머지는 시작 시각으로 날짜를 정한다.

## 결정

1. **측정은 KST 00:00에 끊는다. 끊는 것은 서버가 자기 시계로 한다.** 그때까지 저장하고 측정을 끝낸다(쉬기 10분 자동 종료와 같은 방식). 그래서 하나의 측정은 항상 하루 안에 있고, 시작 날짜 = 끝난 날짜다. DB의 「세션 시작 날짜로 집계」는 그대로 둔다.
2. 자정에 끊긴 뒤 측정은 이어진다. FE 기본안(BE와 정함): 서버가 새 사유(안: `closed(day_changed)`)로 닫고, 앱은 카메라를 켠 채 새 측정(새 `session_id`, S1 + WS)을 바로 시작하며 「자정이 지나 새 측정으로 이어졌어요」를 보인다.
3. **화면에 보이는 날짜·시각은 서버 시각을 따른다. 앱은 시간을 세지 않는다.**
   - 기록의 시작·종료 시각: WS `ready.started_at`, `closed.ended_at`(서버가 받은 시각, DB 값과 같음).
   - 오늘 날짜: **가장 최근에 받은 서버 날짜(KST).** A4 `today`(앱 시작, 창·탭으로 돌아올 때, 기록·달력 화면을 열 때 — 1분에 한 번까지), R1·T1 `today`, `ready`·`closed` 시각의 KST 날짜에서 받는다(10/26 수정: A4 `server_time` 대신 `today` — 앱은 날짜만 쓴다). 실시간으로 받지 않는다. 측정하지 않고 앱을 띄워 둔 채 자정이 지나도 기록·달력을 열면 그 자리에서 날짜가 바뀐다.
   - 날짜 계산과 시각 표시는 KST(`Asia/Seoul`)로 고정한다.
4. **예외 — 앱 시계를 쓰는 것:**
   - 측정 안의 시간축(좌표 구간 `t_ms`·`start_ms`·`end_ms`, 단조 시계). 측정 화면의 측정 시계(`ready`부터 지난 전체 시간, 계획 0059)도 날짜·시각이 아니라 경과 시간이라 앱 시계로 잰다. 프레임을 찍은 순간은 앱만 알고, 서버가 받은 시각을 쓰면 네트워크 지연이 판정(3초 확정 등)에 섞인다. 화면에 보이는 값이 아니라 서버에 보내는 입력이다.
   - 자세 등록의 3초 촬영(평균은 앱이 낸다, ADR 0026). 등록 시각은 서버가 정한다(DB V2.5, BE 서버 시각 ADR — 앱은 재시도 구분용 `registration_id`만 보내고, 응답의 `registered_at`은 서버 시각).
   - 자세 데이터 수집 CSV(연구용 파일)의 시각.
5. 서버에 연결할 수 없으면 날짜를 PC 시계로 대신하지 않는다. 앱은 서버 없이 측정하지 않으므로(ADR 0025) 「서버에 연결할 수 없어요」로 둔다. 다만 BE가 필드를 넣기 전(이행 기간)에는 PC 시계를 KST로 고정해 쓴다.

## 이유

- 자정에서 끊으면 측정이 두 날에 걸치지 않아 시작일·끝난 날·자정 분할을 고를 필요가 없고, J2 집계·앱의 오늘 화면·과거 T1이 겹치거나 빠지지 않는다.
- 자정과 「지금」은 벽시계 판단이라 서버 하나로 모은다. PC 시계가 틀리거나 시간대가 달라도 서버 DB·통계와 화면이 같은 날짜를 쓴다.
- 날짜는 하루에 한 번 바뀌므로 서버와 주고받을 때마다 갈아 끼우면 충분하다. 앱이 시계를 이어 세는 계산은 두지 않는다.

## 결과

- **BE (했음, 10/27 PR #65로 develop에):** `ready.started_at`(필수, = `monitor_session.started_at`), `closed.ended_at`(필수, null 가능 — 끝나기 전에 닫혔으면 null) — `b903751`. B1 `registration_id`·서버 등록 시각(DB V2.5) — `cab11c1`.
- **BE (남음, BE-6):** KST 자정 끊기, A4 `today`, R1·T1 `today`, J2 실행 시점(`Cache-Control: no-store`는 Spring Security 기본값으로 이미 붙어 요청 철회 — 10/26 BE 확인)(자정에 끊긴 세션의 저장과 겹치지 않게). Kafka 모드(`ws`, 계획 0031)도 같은 규칙.
- **계약(FE가 쓴 문서, 10/13 `d1575aa`):** 10/26 `realtime-ws.v2.schema.json`의 `ready.started_at`(필수)·`closed.ended_at`(필수, null 가능)을 BE `b903751`과 같은 정의로 맞추고 예시·시험(`tests/test_realtime_ws_v2.py`)을 고쳤다. 두 브랜치가 같은 줄을 고쳐 합칠 때 충돌이 나면 내용은 같으니 어느 쪽을 골라도 된다. 자정에 끊길 때의 메시지(A안 `closed` 새 사유 또는 B안 새 메시지)는 방식을 정한 뒤 넣는다.
- **FE (10/26 함):** 서버 시각 저장소(`features/platform/serverClock.ts`, 가장 최근 서버 시각 → 오늘), 기록 시작·종료에 서버 시각(`useSessionPersistence.ts` `recordTimes`. `ended_at`이 null이거나 `closed`가 없으면 서버 시작 + 서버가 잰 전체 시간으로 두고 기록은 「종료 미확인」(`server.confirmed: false`), R1을 읽게 되면 R1 값으로 덮어씀), B1 `registration_id`(`hooks/useCamera.ts`·`features/baseline/client.ts`, 응답의 서버 `registered_at`도 「오늘」에 반영), 창·탭으로 돌아올 때와 기록·달력을 열 때 A4(`accountClient.refreshServerTime`, 1분에 한 번까지), 날짜 함수 KST 고정(`lib/kst.ts`, `history`·`comparison`·`sessionNumber`·`recordsSource`)과 시작 시각 기준 통일, 시각 표시 KST(기록 목록·상세·하루 띠·설정의 등록 시각). **남은 것:** 자정에 끊긴 뒤 측정을 잇는 처리(방식을 정한 뒤).
- **순서 주의:** 10/27부터 앱은 측정 중(`ready` 뒤) 모르는 `closed` 사유를 「저장됨」으로 기록한다(`LiveSession.ts` `CLOSED_WHILE_MEASURING`). 그래서 `day_changed`를 서버가 먼저 켜도 기록은 남지만, 새 측정으로 이어 붙이지는 않는다 — 이어 붙이기는 FE가 사유 이름이 정해지면 넣는다.
- **10/27 FE 확인(develop `2e1fd2b` 코드):** 서버에 자정 끊기(`day_changed`)와 J2는 아직 없다. J2는 세션 시작 날짜로 집계한다(`database/README.md`). 이어 붙이기가 실패할 수 있는 곳은 자정 직후 새 S1이다 — 로그인 30분 고정이라 401. 그래서 **리프레시 토큰이 자정 끊기보다 먼저**여야 하고(연동 명세 1장 「리프레시 토큰」), 실패하면 자정까지는 저장됐으므로 「자정이 지나 측정을 이어가지 못했어요」로 끝낸다. BE에 부탁: J2를 00:00 정각보다 몇 분 뒤에(자정에 닫히는 세션 저장과 겹치지 않게), 재배포를 자정과 겹치지 않게(BE-11). develop PR #64에서 가져온 앱 날짜 나누기(ADR 0033)는 자정 끊기가 생기면 지운다.
- 남는 빈틈: 자정을 넘긴 뒤 같은 화면에 머문 채 아무 것도 하지 않으면 「오늘」 칸 이름이 다음 요청(화면 이동, 창으로 돌아오기, 측정) 때까지 어제로 남는다. 그동안 새 기록은 생기지 않는다.
