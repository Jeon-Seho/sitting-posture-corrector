# 기준·이탈 판정 먼저, 스트레칭 판정은 보류

- 상태: accepted
- 날짜: 2026-10-31
- 근거: 사용자가 첫 판정 목표에서 스트레칭을 빼고 기준·이탈만 먼저 시도하기로 함. 수집은 그대로 둠
- 이전: [ADR 0043](0043-base-deviation-stretch-collection.md) 1·3번, [ADR 0044](0044-optional-stretch-cycles.md)

## 결정

1. **첫 판정 목표는 기준·이탈 2클래스다.** 서비스 점수는 계속 `collapse_probability = p(이탈)`이고 n초 지속은 판정 서버의 시간 규칙이 맡는다.
   ADR 0043 1번의 3클래스 softmax와 3번의 스트레칭 클래스는 이 단계의 목표에서 뺀다.
2. **같은 자료로 규칙(B0)과 2클래스 분류(B1)를 먼저 비교한다.** 차이가 없으면 단순한 쪽을 고른다는 기존 원칙을 유지한다.
3. **기준·이탈이 충분히 된다고 판단하면 스트레칭을 다시 넣는다.** "충분히 된다"의 수치 기준은 아직 정하지 않았다. 다시 넣을 때 별도 ADR로 기준과 함께 기록한다.
4. **수집은 바꾸지 않는다.** `/dev`의 사이클·선택형 스트레칭·메모·33점 리플레이와 [관측 내보내기 계약](../../contracts/observation-export.v1.md)은 ADR 0044 그대로다.
   스트레칭 구간 자료도 계속 모으며, 나중에 스트레칭 판정을 다시 넣을 때 쓴다.

## 이 단계에서 스트레칭 구간을 다루는 방법

- 기준·이탈 학습과 평가에는 기준·이탈 라벨 구간만 쓴다. 스트레칭 구간을 기준이나 이탈로 바꿔 붙이지 않는다.
- 스트레칭은 이 단계의 모델이 구별하지 못한다. 실제 사용에서 기지개·팔 뻗기가 이탈로 알림될 수 있다는 한계를 그대로 기록한다.
- 스트레칭 중 시간 규칙, 팔 좌표의 서비스 계약 변경은 스트레칭 판정을 다시 넣을 때 정한다.

## 한계

- 이 결정은 목표 범위의 변경이다. 기준·이탈 판정이 된다는 측정 결과는 아직 없다.
- 실제 자료 수집·학습·평가는 이 결정으로 실행하지 않았다.
