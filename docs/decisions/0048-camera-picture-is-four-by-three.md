# ADR 0048: 카메라 영상은 항상 4:3으로 받고, 4:3을 못 주면 쓰지 않는다

- 상태: accepted
- 날짜: 2026-11-12
- 작성: klaod-tech(FE)
- 근거: 팀 결정 「좌표 수집 조건(MediaPipe 모델·`CAPTURE_RESOLUTION` 640×480·관절 목록)은 고정하고, 바꾸면 전원 다시 촬영한다」(DB 스키마 V2.2~V2.6 머리 주석), 사용자(FE) 11/12 「학습 데이터도 4:3이고, 다른 비율로 바꾸려다 4:3으로 고정하기로 했으니 막는다」
- 대체: [계획 0053](../plans/active/0053-multiple-cameras.md) 4번의 10/19 결정 「640×480을 못 주는 카메라도 시작은 막지 않는다」와 측정 화면 크기 표시(FE 제안서 F13, 11/12 취소)
- 관련: [ADR 0021](0021-app-sends-information-server-judges.md)(앱은 좌표만 보내고 서버가 판정), [연동 명세](../design/fe/api-ws-spec.md) 0장 「영상 크기」, [DB 안내](../../database/README.md) `CAPTURE_RESOLUTION`

## 배경

- 앱은 MediaPipe 정규화 좌표(0~1)를 서버로 보낸다. x는 화면 너비로, y는 화면 높이로 나눈 값이라 **화면 비율이 바뀌면 같은 자세도 좌표가 달라진다.** 16:9 화면은 4:3보다 가로가 넓어, 어깨 사이 같은 가로 거리가 작게 나온다.
- 기준 자세(B1)와 측정은 이 좌표를 그대로 비교한다. 서버는 해상도를 받지 않아 비율이 다른지 알 수 없다.
- 지금까지 앱은 640×480을 **희망값(`ideal`)**으로만 요청했다. 대부분의 노트북 카메라는 그대로 열리지만, 4:3을 못 주는 카메라는 16:9(예: 1280×720)로 열리고 측정도 그대로 시작됐다(10/19 결정). 앱은 측정 중에 크기가 바뀔 때만 끝냈고, 기준 자세를 찍은 비율과는 비교하지 않았다.

## 결정

1. **4:3을 필수로 요청한다.** 카메라 요청에 `aspectRatio: { exact: 4/3 }`와 `resizeMode: 'crop-and-scale'`을 넣는다(`features/camera/devices.ts` `requestCamera`). 크기는 지금처럼 640×480을 희망값으로 둔다.
2. **잘라서라도 4:3으로 받는다.** 16:9 카메라는 브라우저가 양옆을 잘라 4:3으로 준다(Chrome·Edge·데스크톱 앱). 사람은 보통 화면 가운데 있어 어깨·머리 판정에는 영향이 거의 없다.
3. **그래도 4:3이 아니면 쓰지 않는다.** 브라우저가 요청을 거절하거나(`OverconstrainedError`, `constraint: 'aspectRatio'`), 무시하고 다른 비율로 열면(트랙 설정·영상 크기로 확인) 카메라를 놓고 「이 카메라는 4:3 화면으로 쓸 수 없어요…」를 띄운다(`CAMERA_ERRORS.aspectUnsupported`, `hooks/useCamera.ts` `connect`). 기준 자세 등록과 측정 모두 카메라가 켜져야 하므로 둘 다 막힌다.
4. 4:3이면 크기는 묻지 않는다(640×480이 아닌 1280×960도 받는다). 좌표는 정규화돼 같은 비율이면 같은 값이다.
5. 측정 화면에 카메라 크기를 보이지 않는다(F13 취소).
6. 웹과 데스크톱 앱이 같게 동작한다. 서버·DB는 바뀌지 않는다.

## 이유

- 판정 기준(학습 데이터·기준 자세)과 다른 비율의 좌표로 판정하면, 사용자는 잘못 판정된 결과를 받고 그 사실을 알 방법이 없다. 시작을 막는 편이 틀린 결과를 저장하는 것보다 낫다.
- 잘라 받기를 먼저 쓰면 16:9 카메라 사용자 대부분이 막히지 않는다. 막히는 것은 잘라 받기를 지원하지 않는 브라우저뿐이고, 안내 문구가 다른 카메라나 Chrome·Edge·PoseGood 앱을 권한다.
- 크기 표시(F13)는 비율 불일치를 막지 못해 필요 없어졌다.

## 결과

- 4:3을 못 주는 카메라·브라우저에서는 카메라가 켜지지 않는다. 개발자 도구 › 카메라 오류 화면에 「4:3 화면 불가」로 미리 볼 수 있다.
- 저장한 주 카메라가 4:3을 못 주면 「카메라가 빠짐」으로 보지 않고(`mainCamera.ts` `missingDevice`) 위 안내를 그대로 보인다.
- 자동 시험용 가짜 카메라는 640×480이라 영향이 없다.
- 시험: `hooks/useCamera.test.tsx`(4:3 요청, 16:9 거절, 요청 거절 문구), `hooks/useCamera.devices.test.tsx`(1280×960 받음, 1280×720 거절).
- 실제 16:9 카메라에서 잘라 받기가 되는지는 아직 확인하지 않았다(Chrome·Edge·데스크톱 앱에서 확인할 것).
