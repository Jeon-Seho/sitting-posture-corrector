# ADR 0010: 실제 기록의 처음·최근 비교 기준


- 상태: 채택 (값은 임시)
- 날짜: 2026-09-28

## 근거

예시 대시보드의 전후 비교는 오늘 기준 최근 14일을 7일씩 나눈 합성 데이터라, 사용자가 처음 사용했을 때와 비교하지 않는다. 실제 기록에는 비교 화면이 없었다. 사용자가 "처음 대비 얼마나 달라졌나"를 보도록 첫 측정일 기준 비교를 선택했다.

## 결정

- 초기 구간은 첫 측정일부터 N일, 최근 구간은 오늘까지의 N일이다. 기록은 끝난 날짜(현지 시간)에 속한다.
- 두 구간이 겹치면 비교하지 않고, 첫 측정일부터 2N일이 지날 때까지 남은 일수를 안내한다. 두 구간 사이의 기록은 비교에 쓰지 않는다.
- 한쪽 구간의 유효 측정 시간이 최소값 미만이면 표는 보여 주되 "참고용"으로 표시한다. 유효 시간이 0이면 유지율·시간당 붕괴는 `계산 불가`다.
- 지표는 예시와 같다. 유지율, 시간당 붕괴, 평균 발생 간격(같은 세션 안의 연속 사건 사이), 평균 회복 시간, 알림 횟수.
- 임시값: N = 7일, 최소 유효 측정 시간 = 구간당 30분. 팀 합의 전 값이며 `frontend/src/lib/comparison.ts`의 `COMPARE_RULES` 한 곳에서 바꾼다.
- 계정 구분이 없는 미리보기라 이 브라우저의 모든 기록(이전 합성 시연 기록 포함)을 대상으로 한다.

## 결과와 한계

합성 기록으로 단위 테스트와 브라우저 표시를 확인했다. 실제 사용자 기록으로 개선 효과를 확인한 것은 아니며, 이 비교는 진단·치료 효과를 의미하지 않는다. 기록에는 판정 규칙 버전이 저장되지 않아 구간별 판정 방식은 표시하지 않는다. 판정 방식이 바뀌면 전후 비교가 섞이므로 버전 저장이 필요하다.

## 이후 변경 (2026-10-07 코드 확인)

- 서버 기록은 세션의 적용 정책(지속·복귀·재알림 시간, 임계값)과 모델·기준 정보를 보관한다. 비교 표는 두 구간 기록의 판정 출처·설정·모델 차이를 함께 보여 준다(`frontend/src/lib/comparison.ts`, [팀 요구 14절](../team-requirements.md)).
- 로컬 기록은 여전히 판정 규칙 버전을 저장하지 않는다. 위 한계는 로컬 기록에만 남는다.
- N = 7일, 구간당 30분 임시값은 그대로다.
