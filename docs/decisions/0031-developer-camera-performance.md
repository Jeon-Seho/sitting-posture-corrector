# ADR 0031: 실측에 근거한 개발 카메라 모델과 대기 정책

- 날짜: 2026-10-14
- 상태: `/dev` 개발 기본값으로 채택. 서비스 승격·정확도 검증은 별도.
- 근거: [실제 성능 측정](../ml/camera-performance.md), [관측 시간 정책](0030-predictor-cadence-recovery.md)

## 배경

M1의 실제 GPU 경로에서도 기존 Heavy와 추론 시간의 두 배 대기로 20초 평균 12.7 FPS였다.
같은 24프레임의 2회차 비교에서 Full GPU 추론은 p50 약 12ms, Heavy는 33–34ms였다.
LSTM·룰 계산보다 좌표 추출과 대기의 비용이 컸다. 유효 관측률은 이 짧은 클립에서 같았지만
실제 자세 정확도·깊이 오차·가림 성능은 검증하지 않았다.

## 결정

1. 개발 화면의 기본은 **Full / GPU 우선 / responsive**로 한다. 일반 서비스의 기본은
   Heavy / GPU 우선 / legacy로 유지한다. 공유 어댑터에는 선택 인자만 추가한다.
2. `responsive`는 처리에 쓴 시간을 목표 간격에서 빼고, 후처리 뒤 최소 8ms를 양보한다.
   GPU 최대 30 FPS, CPU 최대 20 FPS와 단일 추론·새 영상 프레임 조건은 유지한다.
   8ms는 개발 스케줄 값이며 모든 장치에 최적인 상수라고 주장하지 않는다.
3. 초기화에 실제 사용한 GPU/CPU 경로와 동일 canvas의 renderer를 표시한다.
   `auto`만 CPU fallback을 허용한다. 명시적 GPU 비교 실패를 CPU 성능으로 바꿔 보고하지 않는다.
4. 영상·좌표는 모델 비교 중 메모리에만 두고 해제한다. 내보내기는 집계 시간·유효율·장치 경로만 포함한다.
   모델 가중치는 공식 SHA-256 검증 후 Git 제외 경로에 둔다. 새 npm 패키지는 추가하지 않는다.
5. 실제 추출기의 `poseModelId`를 원본 프레임과 자동·수동 수집·정상 프로파일에 보존한다.
   수집 중 모델 변경 시 자동 구간을 분리하고 수동 수집은 중단한다. 개인 프로파일의 모델 ID가
   선택 모델과 다르거나 없으면 보존하되 적용하지 않는다. 과거 파일의 추출기를 추측하지 않는다.
6. 저품질·관측 단절·알림 경계는 바꾸지 않는다. FPS 향상을 위해 불량 관측을 정상으로 인정하지 않는다.

## 결과와 남은 한계

실제 앱의 첫 Full 측정은 27.2 FPS, 이후 재측정은 23.5 FPS였다. 기존 12.7 FPS보다 빨랐으나
다른 시각·화면 상태의 짧은 실험이며 장시간·여러 장치의 속도를 보장하지 않는다.
동기 추론은 여전히 메인 스레드에서 실행된다. Worker 이동·React 갱신 빈도 분리는 후속 후보다.
GPU 경로 확인은 GPU 사용률 측정이 아니다. MediaPipe의 속도 개선은 Panoptic LSTM의
학습/실사용 좌표 차이나 정상 등록 검증의 공백을 해결하지 않는다.
