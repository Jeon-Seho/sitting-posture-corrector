# ADR 0019: 어깨 기울기 판정 기준폭 0.13 → 0.03

- 상태: accepted (동욱 결정, 실측 확인 전)
- 날짜: 2026-10-07
- 관련 결정: [프론트·서버 특징 연결](0013-frontend-server-feature-connection.md), [세션 시간 정책](0012-session-timing-policy.md)

## 배경

변화 점수는 `min(1, max(|head|/0.22, |lateral|/0.20, |shoulder|/0.13) * 0.7)`이고 0.7 이상이 3초 지속되면 알린다.
어깨 기울기만으로 알림이 나려면 기울기 변화가 0.13 이상이어야 했다.

동욱이 앱에서 찍은 원본 좌표(2026-10-07, 한 사람·한쪽씩 1회)에서 확인한 값은 아래와 같다.
변화량은 어깨 너비로 정규화한 값이며 각도가 아니다.

| 상황 | 어깨 기울기 변화 | 기존 점수 |
| --- | --- | --- |
| 정자세 프레임 흔들림 | 표준편차 0.006, 구간 내 0.00~0.03 | 0.2 이하 |
| 정자세 세션 중 점진 이동 | 약 0.03 (30초 동안) | — |
| 고개 돌림(우) | +0.02 | — |
| 왼쪽 어깨 올리기 | −0.05~−0.08 | 0.3~0.4 |
| 오른쪽 어깨 올리기 | +0.04~+0.08 | 0.3~0.5 |
| 구부정 | +0.05~+0.07 (머리 높이 −0.35로 이미 알림) | 1.0 |

어깨를 크게 올려도 알림이 나지 않았다.

## 결정

어깨 기울기 기준폭을 **0.03**으로 낮춘다. 기울기 변화 0.03 이상이 3초 지속되면 알린다.
머리 높이 0.22, 좌우 0.20, 점수 계수 0.7, 알림 임계값 0.7, 시간 정책은 바꾸지 않는다.

동욱 근거: 측정 때는 어깨를 크게 올렸지만 실제 사용자는 살짝 틀어진 상태가 많다.
자세는 한 번에 바뀌기보다 점점 틀어지는 경우가 많으므로, 점진적인 기울기 변화도 잡아야 한다.

## 적용 범위

- 앱 로컬 점수 [pose.ts](../../model/prototype/pose.ts) `referenceScore`, `classify`
- FastAPI 추론 [service.py](../../model/inference/service.py) `SHOULDER_TILT_SCALE`
- [공유 합성 사례](../../contracts/examples/v2/reference-feature-cases.json)와 [계약 안내](../../contracts/README.md)
- 출력 형식과 모델명 `reference-feature-rule-v1`은 유지한다. 점수 식의 스케일만 바뀐다.

## 위험과 확인할 것

- 정자세 흔들림·점진 이동(최대 약 0.03)이 기준과 거의 같아 오경고가 날 수 있다. 실사용 확인 후 조정한다.
- 기울기가 우세하면 유형은 `unspecified`다. 구부정과 한쪽 어깨를 구분해 안내하는 것은 이번 범위가 아니다.
- 한 사람·1회 촬영 기준이다. 다른 팀원 자료로 다시 확인한다. 의료 효과나 최적 임계값을 주장하지 않는다.
