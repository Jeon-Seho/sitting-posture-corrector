# ADR 0007: 추적 모델과 수집 (실시간 Lite, 수집 Heavy)

- 상태: 채택 (파일럿)
- 날짜: 2026-09-22 (2026-10-27 ADR 정리로 옛 0006 「Heavy와 안내형 좌표 수집」, 옛 0004의 추적 속도, 옛 0016의 수집 바로가기, 옛 0002의 기기 안 추론 원칙을 합침. 처음 제목은 「실시간 추적기를 Lite로 전환」)
- 분야: ML (추적 모델, 학습 자료 수집)
- 관련: [안내형 수집 v2](../research/guided-collection-v2.md), [파일럿 CSV](../research/pilot-csv.md), [ADR 0021](0021-app-sends-information-server-judges.md)(앱은 좌표만 보냄)

## 2026-10-30 공통 카메라 변경

사용자 요청으로 서비스와 `/dev`는 공통 Pose Landmarker Heavy 모델과 GPU 우선·CPU 복구를 사용한다. 기존 서버 기준에는 모델 ID가 없어 Lite 기준과 Heavy 관측이 섞일 가능성이 있다. 반영 전 기준 재등록 또는 모델별 기준 관리가 필요하다. 실제 장치 성능 차이는 미검증이다.

## 1. 공통: 기기 안 추론과 모델 자산 (옛 0002·0006·0007)

- MediaPipe Pose Landmarker는 기기(브라우저·데스크톱 앱) 안에서 돌린다. 영상은 서버로 보내지 않는다.
- 공식 float16 v1 모델을 로컬에서 쓰고 tasks-vision 1.0.1을 유지한다.
- 모델 URL과 SHA-256은 `frontend/model-asset.json`에 고정하고, 가중치는 Git에 넣지 않는다. 모델과 WASM은 최초 준비 때 내려받는다.

## 2. 실시간 추적: Lite (2026-09-22)

### 근거

Heavy 추적기는 M1 Air에서 약 10 FPS로 체감될 수 있었다. 사용자가 수집·체험 화면의 부드러움을 우선 확인하기 위해 Lite 전환을 요청했다.

### 결정

- 실시간 추적은 공식 Pose Landmarker Lite float16 v1을 쓴다.
- **추적 속도(옛 0004, 2026-09-19):** GPU 초기화를 먼저 시도하고 실패하면 CPU로 돌린다. 카메라 최대 30 FPS, GPU 최대 초당 30회, CPU 최대 초당 20회이며, 직전 추론 시간의 2배보다 짧은 간격으로는 돌리지 않는다. 실제 추론 횟수/초와 호출 시간을 화면에 표시한다. 수치는 브라우저·장치·포즈에 따라 달라진다.
- 추론은 메인 스레드의 동기 호출이다([MediaPipe 공식 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)). 프레임 반복 타이머만 Worker로 돌린다([ADR 0017](0017-desktop-app-shell-and-redesign.md) 작은 카메라 창 2번).
- 수집 CSV의 `pose_model`에 모델 ID를 기록해 Heavy 자료와 Lite 자료를 모델별로 구분한다.

### 결과와 한계

Lite는 계산량을 줄이기 위한 선택이지만 이 프로젝트와 M1 Air에서 실제 FPS가 개선됐다는 결과는 아직 없다. 같은 장면에서 Heavy와 Lite의 속도·검출 안정성·좌표 분포를 비교하기 전에는 정확도 차이도 주장하지 않는다. FPS 향상을 보증하지 않는다.

## 3. 학습 자료 수집 (옛 0006, 2026-09-21. 옛 0016 수집 바로가기, 2026-10-02)

### 근거

사용자가 MediaPipe Heavy 전환과 라벨 수집 모드 구현을 요청했고, 영상 저장 여부 질문에 **좌표와 라벨만 수집**을 선택했다.
특징 3개만 저장하는 방식은 새 특징을 다시 계산하기 어렵다. 안내 과제와 실제 자세의 구분도 필요하다.

### 결정

- 수집에는 공식 Pose Landmarker Heavy float16 v1을 쓴다(처음 결정. 지금도 수집에 Heavy를 쓰는지는 ML이 확인).
- 정면이 수집 UI 기본 시점이다. 20초 촬영·5초 준비와 수정 가능한 촬영 조건은 탐색용 초기값이며 연구 프로토콜 확정을 뜻하지 않는다.
- 전용 수집 화면에서 과제를 선택하고 촬영 후 자기 보고로 라벨을 확인한다. 준비/중단/제외 구간은 정상 학습 자료로 자동 인정하지 않는다.
- 작업 상황·재석 상태·몸통 자세·추적 품질을 분리한다. 포즈 미검출로 부재를 추론하지 않는다.
- 원본 영상·음성은 저장하지 않는다. 좌표 형식은 연구 문서를 따른다(지금은 좌표 v3, 2026-10-12. 앱이 계산한 특징·판정 열은 없다).
- **수집 바로가기(옛 0016):** 로컬 미리보기에 `/#collection` 바로가기를 둔다. 시작 화면의 「프로필 없이 자세 데이터 수집」에서도 같은 화면을 연다. 프로필·계정을 만들거나 기록을 업로드하지 않고 CSV 수집 controller만 쓴다. 자세와 촬영 길이는 카메라 연결 여부와 관계없이 페이지 위쪽에서 고른다.
- 수집은 화면·탭 이동이나 카메라 끊김 때 중단한다. 저품질·누락을 정상으로 채우지 않는다.

### 결과와 한계

Heavy의 속도 개선이나 정확도 향상을 검증 없이 주장하지 않는다. 좌표는 후속 특징 계산에 쓸 수 있지만 단안 추정 좌표의 한계와 촬영 후 영상 검수 불가는 남는다.
자세·활동 분류기, 이미지/영상 모델 학습, 세밀한 프레임별 재라벨링은 이 결정의 범위 밖이다.
