# ADR 0017: 데스크톱 앱 기준 화면 재구성과 시작 프로그램 연결

- 분야: 프론트
- 작업: GP-0101
- 상태: accepted
- 날짜: 2026-10-02
- 근거: 사용자 요청 — 발표용 화면을 사용자 친화적으로 다시 디자인하고, 웹 페이지가 아니라 데스크톱 앱을 기준으로 개발.
  큰 카메라 화면, 건강을 연상시키는 따뜻한 색, 컴퓨터를 켤 때 자동으로 열려 카메라로 측정할 수 있는 연결을 열어 둘 것.
  백엔드·DB·API는 아직 준비 전이므로 임의로 연결하지 말고 연결 지점과 문서를 남길 것.

## 결정

1. **실행 형태**: `lee_app1`의 Electron 셸(`frontend/electron/`)을 `codex/posture-api-cep-hardening` 위로 가져와
   데스크톱 앱을 기준 화면으로 삼는다. 화면은 같은 React 앱이며 일반 브라우저에서도 동작한다.
2. **화면 구조**: 사이드바를 `측정하기 · 기록 · 설정` 3개로 줄인다. 기존 라우트 이름(`home`, `setup`, `session`, `dashboard`,
   `settings`, `profile`, `collection`)은 유지하고 `navigation.ts`의 `tabOf`/`resolvePage`로 탭에 묶는다. `home`은 측정하기로 해석한다.
3. **시각 체계**: 레트로 피치덱 톤을 따뜻한 건강 톤으로 교체한다([DESIGN.md](../../DESIGN.md)). 판정·시간 정책·저장 로직은 바꾸지 않는다.
4. **화면 상태 모델**: 측정 화면은 `features/session/liveView.ts`의 `LiveView`를 그린다. 상태는 플랫폼 v4 상태머신
   (NORMAL → SUSPECT → BAD → RECOVERING)과 측정 불가·쉬는 중·분석 일시 중단을 그대로 표현한다. 현재는 로컬 엔진이 채운다.
5. **시작 프로그램**: preload 브리지(`window.posegoodDesktop`)로 두 가지 선택을 제공한다. 둘 다 기본 꺼짐이다.
   - `자동으로 PoseGood 열기`: OS 시작 프로그램 등록. **패키징된 앱에서만** 켤 수 있다. 개발 실행은 개발 서버가 필요하므로 막는다.
   - `열릴 때 카메라 바로 켜기`: 시작 프로그램으로 열린 경우에만, 로그인 후 측정하기 화면에서 카메라를 한 번 연결한다.
     개인 기준은 아직 저장되지 않으므로 사용자가 기준을 확인한 뒤 측정한다.
6. **카메라 작은 창**: 측정 준비·측정·수집 화면처럼 카메라가 이미 크게 보이는 화면에서는 앱 안의 떠 있는 미리보기를 숨긴다.
   PiP 상태를 담은 컴포넌트는 계속 마운트해 둔다.
7. **백엔드 연결**: 새 네트워크 호출을 추가하지 않는다. 기존 개발 서버 판정·계정 모드는 그대로 두고(개발자 옵션),
   플랫폼 v4용 연결 지점은 `features/platform/ports.ts`(타입만)와 [연결 지점 문서](../design/frontend-platform-seams.md)로 남긴다.

## ADR 0016 대비 변경

ADR 0016은 "카메라 자동 연결은 추가하지 않는다"고 정했다. 이번 결정은 사용자의 명시적 요청에 따라
**데스크톱 앱 + 시작 프로그램 실행 + 사용자가 직접 켠 선택**이 모두 맞을 때만 자동 연결을 허용한다.
일반 브라우저, 수동 실행, 기본 설정에서는 여전히 카메라를 자동으로 켜지 않는다. 영상 저장·전송은 추가하지 않는다.
"앱 전체에서 작은 창 유지"는 위 6번처럼 카메라가 크게 보이는 화면에서만 숨기는 것으로 바꾼다.

## 남은 결정

- 설치 파일 형태(electron-builder 등), 앱 서명, 자동 업데이트. 이 결정 전에는 시작 프로그램 등록을 실제로 켤 수 없다.
- 시작 프로그램 실행 시 창을 숨기고 트레이로 둘지, 측정 중 작은 항상-위 창(시안의 `측정 중 작은 창`)을 둘지.
- 개인 기준을 서버(`POST /api/baselines`)나 기기에 저장해, 자동 실행 후 클릭 없이 측정을 시작할지. 기준 저장은 개인정보·연구 경계와 함께 정한다.
- 플랫폼 v4는 키포인트를 서버로 보내는 안이고, ADR 0013은 기준 대비 변화량만 보낸다. 어느 쪽을 따를지는 팀 합의가 필요하다.
