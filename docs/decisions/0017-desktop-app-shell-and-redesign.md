# ADR 0017: 데스크톱 앱 기준 화면 재구성과 시작 프로그램 연결

- 상태: accepted
- 날짜: 2026-10-02 (2026-10-27 ADR 정리로 옛 0016의 작은 카메라 창 부분과 옛 0028 「웹에는 작은 카메라 창을 두지 않는다」를 「작은 카메라 창」 절로 합침)
- 분야: FE (데스크톱 셸, 화면)
- 근거: 사용자 요청 — 발표용 화면을 사용자 친화적으로 다시 디자인하고, 웹 페이지가 아니라 데스크톱 앱을 기준으로 개발.
  큰 카메라 화면, 건강을 연상시키는 따뜻한 색, 컴퓨터를 켤 때 자동으로 열려 카메라로 측정할 수 있는 연결을 열어 둘 것.
  작은 창 절은 2026-10-02 수집 화면 요청(옛 0016), 2026-10-26 Chrome 시험과 사용자(FE) 결정(옛 0028), 2026-10-26 Electron 자식 창 전환(lellon0403)
- 관련: [ADR 0008](0008-single-app-entry.md)(단일 앱), [ADR 0021](0021-app-sends-information-server-judges.md)(항상 서버로 측정), [ADR 0007](0007-lite-pose-tracker.md) 수집 절(옛 0016의 수집 바로가기), [계획 0055](../plans/active/0055-desktop-camera-window.md), [FE 제안서](../design/fe-server-proposal.md) 8.4

## 결정

1. **실행 형태**: Electron 셸(`frontend/electron/`)의 데스크톱 앱을 기준 화면으로 삼는다. 화면은 같은 React 앱이며 일반 브라우저에서도 동작한다.
2. **화면 구조**: 사이드바를 `측정하기 · 기록 · 설정` 3개로 줄인다. 기존 라우트 이름(`home`, `setup`, `session`, `dashboard`,
   `settings`, `profile`, `collection`)은 유지하고 `navigation.ts`의 `tabOf`/`resolvePage`로 탭에 묶는다. `home`은 측정하기로 해석한다.
3. **시각 체계**: 레트로 피치덱 톤을 따뜻한 건강 톤으로 교체한다([DESIGN.md](../../DESIGN.md)). 판정·시간 정책·저장 로직은 바꾸지 않는다.
4. **측정 화면 상태**: 측정 화면(`features/session/live/`)은 서버 메시지가 채운다([ADR 0021](0021-app-sends-information-server-judges.md)). 처음의 로컬 상태 모델(`liveView.ts`, NORMAL → SUSPECT → BAD → RECOVERING)은 2026-10-21 지웠다.
5. **시작 프로그램**: preload 브리지(`window.posegoodDesktop`)로 두 가지 선택을 제공한다. 둘 다 기본 꺼짐이다.
   - `자동으로 PoseGood 열기`: OS 시작 프로그램 등록. **패키징된 앱에서만** 켤 수 있다. 개발 실행은 개발 서버가 필요하므로 막는다.
   - `열릴 때 카메라 바로 켜기`: 시작 프로그램으로 열린 경우에만, 로그인 후 측정하기 화면에서 카메라를 한 번 연결한다.
   - 이 경우(**데스크톱 앱 + 시작 프로그램 실행 + 사용자가 직접 켠 선택**)에만 카메라 자동 연결을 허용한다. 일반 브라우저, 수동 실행, 기본 설정에서는 카메라를 자동으로 켜지 않는다. 영상 저장·전송은 하지 않는다.
6. **작은 카메라 창**: 아래 「작은 카메라 창」 절.
7. **백엔드 연결**: 앱은 항상 서버로 측정한다([ADR 0021](0021-app-sends-information-server-judges.md)). 처음의 「새 네트워크 호출을 넣지 않는다, 개발 서버 판정·계정 모드는 개발자 옵션」은 2026-10-21 지웠다.

## 작은 카메라 창

### 결정

1. **웹(일반 브라우저)에는 작은 카메라 창을 두지 않는다.** 앱 안의 떠 있는 창, 외부 탭 Document PiP, video PiP, 자동 PiP 처리기를 모두 지웠다(V3 `409de69`). 웹 영상에는 `disablePictureInPicture`를 지정한다.
2. **웹에서도 다른 탭·다른 프로그램에 있는 동안 측정은 이어진다.** 프레임 반복 타이머를 Worker로 돌린다(`features/camera/frameTimer.ts`, V3 `86b7a46`).
3. **앱 밖 작은 창은 데스크톱 앱(Electron)에서만 띄운다.** 메인 창이 앞에 있으면 숨기고, 포커스를 잃거나 최소화되면 보인다. 자동 표시는 `showInactive`로 포커스를 가져오지 않는다. X는 측정 중이면 종료·저장이다(10/20 결정 유지).
4. **창 방식**: 화면이 `window.open('about:blank', 'posegood-camera', …)`로 열고 main(`frontend/electron/camera-window.cjs`, `setWindowOpenHandler`)이 카메라가 켜진 메인 renderer의 이 요청 하나만 `frame:false`, `alwaysOnTop:true` 자식 창으로 허락한다. 같은 출처의 자식 창이라 React portal로 같은 스트림과 상태·조작을 그린다(새 `getUserMedia` 없음). 자식 창은 새 탐색·팝업을 막고, 메인 renderer만 창 표시·접기·복귀 IPC를 쓴다. 메인 renderer는 최소화 중에도 카메라 처리가 이어지도록 `backgroundThrottling`을 끈다.
5. 측정 상태와 종료를 작은 창에 잇는 `features/session/sessionControl.ts`는 데스크톱 작은 창이 쓰므로 남긴다.
6. 카메라 종료·스트림 교체·메인 페이지 새로고침·앱 종료 때 창과 구독을 정리한다. 작은 창 닫기는 카메라 종료와 다르다.
7. 사용자에게는 「작은 카메라 창은 데스크톱 앱에서 쓸 수 있다」고 알린다. 웹의 측정하기 준비 화면 「이렇게 앉으면 좋아요」 카드에 한 줄: 「다른 탭에 가도 측정은 이어져요. 작은 카메라 창은 데스크톱 앱에서 쓸 수 있어요」(데스크톱 앱에서는 숨김).

### 이유 (2026-10-26 같은 PC, Windows 11, Chrome 156 시험)

| 시험 | 마이크 | 자동 열림 | 직접 열기(클릭) |
|---|---|---|---|
| 우리 앱(`http://127.0.0.1`, 처리기 등록·`setCameraActive`) | 없음 | 안 됨 — Chrome이 처리기를 부르지 않음 | (버튼 없음) |
| 최소 시험 페이지(처리기와 문서 PiP만) | 없음 | 안 됨 | 됨 |
| Chrome 공식 화상회의 예제 | 있음 | 됨 | — |

- 사이트 설정 「자동 PIP」는 허용, 보안 주소·카메라 트랙·사용자 조작 모두 있었다. Chrome 문서는 「카메라 또는 마이크」라고 하지만 카메라만으로는 열리지 않았다. 마이크는 쓰지 않는다(사용자 결정).
- 클릭으로 연 창은 앱 탭으로 돌아와도 닫히지 않아 측정 화면 위에서 시선을 끈다. 「앱에서는 안 보이고 밖에서만 보이는」 동작은 웹에서 만들 수 없고, 반쯤 되는 창은 오히려 측정 화면을 방해한다(사용자: 「오히려 지저분하다」).
- 숨은 탭에서 프레임 반복(`setTimeout`)이 초당 1번으로 늦춰져 측정이 「영상 멈춤」이 됐다. Worker 타이머는 456초 숨김에서도 초당 30.3장(최대 공백 218ms)이었다.
- 데스크톱 앱은 창을 직접 만들고 보이기·숨기기를 정할 수 있어 원하는 동작을 그대로 만들 수 있다. Chrome 창의 위쪽 검정 띠도 없다.

### 결과

- 웹 사용자는 다른 탭에서 자세를 화면으로 볼 수 없다. 자세 알림은 웹에서 소리·앱 안 토스트이고, 숨은 탭에서 알림이 어떻게 전달되는지는 따로 확인한다(계획 0054 기록).
- 데스크톱 작은 창은 Electron 쪽(`frontend/electron/`) 변경이라 실행 파일을 다시 만들어 보내야 한다.
- 실제 카메라·장시간 백그라운드 처리·다중 모니터·macOS/Linux 동작은 별도 장치 검증이다.

## 남은 결정

- 설치 파일 형태(electron-builder 등), 앱 서명, 자동 업데이트. 이 결정 전에는 시작 프로그램 등록을 실제로 켤 수 없다.
- 시작 프로그램 실행 시 창을 숨기고 트레이로 둘지.

## 이력

- 2026-10-02: 결정. 옛 0016(같은 날)은 「카메라 자동 연결은 하지 않는다」, 「앱 전체에서 작은 창 유지」였고, 이 ADR이 시작 프로그램 자동 연결과 「큰 카메라 화면에서는 작은 창 숨김」으로 바꿨다.
- 2026-10-21: 4번 측정 화면 상태를 서버 메시지로, 7번 개발자 옵션의 서버 판정·계정 모드를 지움(옛 0025, 지금 [ADR 0021](0021-app-sends-information-server-judges.md) 4절). 「남은 결정」의 개인 기준 저장은 서버 B1·B2로, 「키포인트를 보낼지 변화량을 보낼지」는 좌표를 보내는 것으로 정해졌다(ADR 0021).
- 2026-10-26: 웹 작은 창을 지우고 데스크톱에서만 띄움(옛 0028). 같은 날 데스크톱 작은 창을 Electron 자식 창으로 구현(lellon0403, develop PR #64).
- 2026-10-27: ADR 정리로 옛 0016의 작은 창 부분과 옛 0028을 이 문서에 합쳤다. 옛 0016의 수집 바로가기는 [ADR 0007](0007-lite-pose-tracker.md)로 옮겼다([지운 문서 기록](../removed-docs.md) 7절).
