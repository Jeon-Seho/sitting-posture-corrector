# ADR 0025: 연속 측정의 KST 날짜별 보관

- 상태: accepted
- 날짜: 2026-10-26
- 근거: 사용자가 자정을 넘긴 측정을 해당 날짜에 나눠 표시·저장하도록 요청했다.

## 결정

한국 시간(Asia/Seoul, UTC+09:00) 00시를 날짜 경계로 사용한다. 자정에 카메라·판정 엔진·세션 ID·알림 누적을 초기화하지 않는다. 원 세션은 연속으로 유지하고 로컬 중간 기록과 종료 기록의 선택 필드 `days`에 각 날짜의 측정분을 따로 저장한다.

각 항목은 날짜·원 세션 기준 시작/끝 offset·전체/유효/정상 시간·그날 새로 확정된 사건 ID·그날의 사건별 알림 횟수를 보관한다. 로컬 엔진의 관측 tick별 누적 변화량을 KST 경계에서 나눈다. 서버 개발 모드에서는 확인된 checkpoint의 변화량만 사용하고 원 서버 snapshot은 수정하지 않는다. API/DB의 세션을 새로 만들거나 서버 일별 배치의 규칙을 바꾼 것이 아니다.

기록·달력·기간 통계·오늘 요약은 같은 날짜별 투영을 사용한다. 사건이 자정을 넘으면 두 날짜의 상세에서 이어진 상태를 볼 수 있으나 사건 발생 수는 확정된 날짜에 한 번만 센다. 재알림은 실제 관측된 날짜에 센다. 전날부터 이어진 사건으로 그날의 발생 간격을 임의로 짧게 만들지 않는다.

자정 이후의 checkpoint에도 전날 측정분을 보관하고, 로컬 측정 도중 지난 날짜를 열면 완료된 날짜 부분을 볼 수 있다. 저장 실패 시 기존 저장 오류/재시도를 유지한다. 날짜별 합계와 원 세션 합계가 다르거나 날짜/구간이 손상된 자료는 읽기·쓰기를 거부한다. 저장용 원본을 표시용 투영으로 덮어쓰지 않는다.

## 호환성과 한계

`days`가 없는 과거 종료 기록은 원본을 유지한다. 과거에 합계만 저장된 기록은 날짜별 정상/측정 불가 시간을 복원할 수 없으므로 비율로 나누지 않는다. `days`가 없는 이전 중간 기록도 날짜별 값을 추정하지 않는다. 기존 키와 원 세션·서버 snapshot 형식은 유지한다.

실제 DB의 날짜별 영구 행/배치 처리는 현재 앱의 로컬 보관과 별개다. 서버 계정 연결과 배치를 통합할 때 같은 KST 경계를 계약으로 맞춰야 한다. 이번 변경은 서버의 원 세션을 임의로 분할해 API에 제출하지 않는다.

## 검증

합성 자료로 자정·UTC offset·소수 tick·재시도/복구·정상/측정 불가·사건/재알림·전체 합계 보존을 검증한다. 실제 React와 Chrome의 합성 카메라로 자정 전 시작 → 자정 후 계속 → 종료 저장 → 두 날짜 조회 경로를 검증하며 실제 영상을 사용하지 않는다.
