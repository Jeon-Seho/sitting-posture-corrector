# ADR 0028: 웹에는 작은 카메라 창을 두지 않고, 데스크톱 앱에서만 앱 밖 작은 창을 띄운다

- 상태: accepted (웹 삭제는 V3 `409de69`, 숨은 탭 측정은 `86b7a46`. 데스크톱 작은 창은 [계획 0055](../plans/active/0055-desktop-camera-window.md))
- 날짜: 2026-10-26
- 근거: 2026-10-26 같은 PC(Windows 11, Chrome 156) 시험과 사용자(FE, klaod-tech) 결정 — 「웹에서는 pip모드가 안된다고 알리고 앱에서는 가능하다고 하면 되겠네」, 「웹에서는 그냥 pip 관련되서 전부 안한다」
- 대체: [ADR 0016](0016-collection-entry-and-camera-preview-window.md)의 앱 안 떠 있는 창·외부 탭 Document PiP·video PiP·`enterpictureinpicture` 자동 PiP, [ADR 0017](0017-desktop-app-shell-and-redesign.md) 6번(작은 창 숨김 규칙), 10/20 결정 「다른 탭으로 가면 저절로 열고 수동 버튼은 두지 않는다」([FE 제안서](../design/fe-server-proposal.md) 2장·8.3)
- 관련: [계획 0054](../plans/active/0054-pip-fix-and-server-only-login.md) 1단계(시험 기록), [ADR 0025](0025-app-always-measures-on-server.md)(항상 서버로 측정), [FE 제안서](../design/fe-server-proposal.md) 8.4(데스크톱 구조)

## 배경

10/20부터 측정 중 다른 탭으로 가면 Chrome 문서 PiP가 저절로 열리게 했지만 한 번도 열리지 않았다. 10/26 시험 결과:

| 시험 | 마이크 | 자동 열림 | 직접 열기(클릭) |
|---|---|---|---|
| 우리 앱(`http://127.0.0.1`, 처리기 등록·`setCameraActive`) | 없음 | 안 됨 — Chrome이 처리기를 부르지 않음 | (버튼 없음) |
| 최소 시험 페이지(처리기와 문서 PiP만) | 없음 | 안 됨 | 됨 |
| Chrome 공식 화상회의 예제 | 있음 | 됨 | — |

- 사이트 설정 「자동 PIP」는 허용, 보안 주소(`isSecureContext`)·카메라 트랙·사용자 조작 모두 있었다. Chrome 문서는 「카메라 또는 마이크」라고 하지만 카메라만으로는 열리지 않았다.
- 마이크는 쓰지 않는다(사용자 결정). 그러면 웹에서 창을 여는 방법은 앱 안의 클릭뿐이다.
- 클릭으로 연 창은 앱 탭으로 돌아와도 닫히지 않아 측정 화면 위에서 시선을 끈다. 숨기거나 줄이는 것도 클릭이 필요하고, 닫으면 다시 열 때 또 클릭이 필요하다. 「앱에서는 안 보이고 밖에서만 보이는」 동작은 웹에서 만들 수 없다.
- 숨은 탭에서 프레임 반복(`setTimeout`)이 초당 1번으로 늦춰져 측정이 「영상 멈춤」이 됐다. Worker 타이머는 456초 숨김에서도 초당 30.3장(최대 공백 218ms)이었다.

## 결정

1. **웹(일반 브라우저)에는 작은 카메라 창을 두지 않는다.** 앱 안의 떠 있는 창, 외부 탭 Document PiP, video PiP, 자동 PiP 처리기를 모두 지운다.
2. **웹에서도 다른 탭·다른 프로그램에 있는 동안 측정은 이어진다.** 프레임 반복 타이머를 Worker로 돌린다(`features/camera/frameTimer.ts`).
3. **앱 밖 작은 창은 데스크톱 앱(Electron)에서만 띄운다.** 메인 창이 앞에 있으면 숨기고, 포커스를 잃거나 최소화되면 보인다. 클릭이나 묻는 안내 없이 Electron이 정한다. 모양과 버튼(최소화·확대·X)은 10/20 시안을 따른다. X는 측정 중이면 종료·저장이다(10/20 결정 유지).
4. 측정 상태와 종료를 작은 창에 잇는 `features/session/sessionControl.ts`는 데스크톱 작은 창이 쓰므로 남긴다.
5. 사용자에게는 「작은 카메라 창은 데스크톱 앱에서 쓸 수 있다」고 알린다. 문구와 위치는 계획 0055에서 정한다.

## 이유

- 브라우저가 정하는 조건(카메라만으로는 자동 PiP 안 됨, 창 제어에 클릭 필요) 때문에 웹에서 원하는 동작을 만들 수 없고, 반쯤 되는 창은 오히려 측정 화면을 방해한다(사용자: 「오히려 지저분하다」).
- 데스크톱 앱은 창을 직접 만들고 보이기·숨기기를 정할 수 있어 원하는 동작을 그대로 만들 수 있다. Chrome 창의 위쪽 검정 띠도 없다.

## 결과

- 웹 사용자는 다른 탭에서 자세를 화면으로 볼 수 없다. 자세 알림은 웹에서 소리·앱 안 토스트이고, 숨은 탭에서 알림이 어떻게 전달되는지는 따로 확인한다(계획 0054 기록).
- 데스크톱 작은 창은 Electron 쪽(`frontend/electron/`) 변경이라 실행 파일을 다시 만들어 보내야 한다.
- 10/20 「수동 버튼 없음」 결정은 웹에서는 창 자체가 없어져 의미가 없고, 데스크톱에서는 자동으로 보이므로 그대로 성립한다.
