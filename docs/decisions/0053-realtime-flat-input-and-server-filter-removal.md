# 실시간 단일 프레임 입력과 서버 목업 필터 제거

- 상태: accepted
- 날짜: 2026-11-19
- 관련: [계획 0099](../plans/active/0099-realtime-message-simplification.md)

## 배경

앱은 보통 구간당 한 프레임을 보내며 ack를 사용하지 않는다. 배열과 특징 평균,
품질·위치·고개 돌림 제외 규칙은 목업 단계에서 남은 처리다. 기존 앱 호환성을 유지하면서 단순화한다.

## 결정

1. 새 hello에는 schema_version이 없다. 기존 hello의 2.0도 호환 기간에 받는다.
   features에 items가 있으면 구형 배열, 없으면 평탄화 입력으로 검증한다. 혼합 형식은 거절한다.
2. 새 phase는 running·unmeasurable·rest·away다. 측정 불가의 p는 null이고 관측이 있을 때만 t_ms가 있다.
   신형 촬영 시각은 구간 안이어야 한다. 구형 t_ms 허용 범위는 유지한다.
3. 품질 판단은 FE가 담당한다. FE는 양 어깨 가시성을 확인하며 얼굴 점은 낮은 visibility도 보낸다.
   전송할 9점 좌표가 빠지면 측정 불가로 전달한다. 서버는 형식·범위와 계산 가능 여부를 확인한다.
4. 특징 평균을 제거한다. 구형 배열의 여러 장은 마지막 한 장만 사용하고, 마지막이 측정 불가면 앞의 좌표를 재사용하지 않는다.
   현재 앱의 일반적인 한 장 입력과 같은 시각 중복의 마지막 채택에 맞춘 구현 선택이다.
5. 서버 품질·위치·고개 돌림 필터와 규칙 추론의 visibility 0.65 하한을 제거한다. 고개를 돌린 프레임도 채점한다.
   FE 측정 불가와 계산 불가 구간을 정상 또는 유효 이탈로 대체하지 않는다.
6. WS ack를 제거한다. Kafka 브로커 저장 확인과 내부 접수 시각·지연 감지는 유지한다.
7. 2026-11-22 develop 통합 합의: 좌표 적재는 버전 없는 posture.keypoints 하나와 평탄화 본문을 사용한다.
   J1은 기존 체크포인트와 keypoints.jsonl에 원문을 적재하며 형식별 식별·분기·파일을 추가하지 않는다.
   이미 저장된 파일을 변환하거나 덮어쓰지 않는다. 내부 특징·추론·판정 토픽의 구조는 유지한다.
8. 장기적으로 계약의 버전 필드를 제거한다. 이번에는 새 WS 입력에 적용하고 REST·관측 응답 삭제는 후속으로 둔다.

## 전환과 검증

서버의 신구형 지원을 먼저 배포한 뒤 FE 담당자가 신형을 연동·배포한다. 구형 삭제는 배포 확인 후 별도로 진행한다.
계약 파일·토픽 이름은 ADR 0049에 따라 버전 없이 유지하며 새 WS 메시지에도 버전 번호를 넣지 않는다.
기존 단일 프레임 특징 수치, 신구형 입력 동등성, 측정 불가 제외·연속 판정·저장 완료와 적재 왕복을 검증한다.
연구 모델과 그 전처리는 실제 모델 연결 단계에서 검증한다.
