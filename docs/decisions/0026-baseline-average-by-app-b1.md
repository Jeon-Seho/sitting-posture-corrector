# ADR 0026: 자세 등록은 앱이 3초 평균을 내서 B1로 보낸다

- 상태: accepted (앱 구현 `feature/frontend-features-and-integrationV3` `0449abb`)
- 날짜: 2026-10-20 (기록 2026-10-21)
- 근거: 2026-10-20 전체 회의 — 3초 동안의 자세 평균은 FE가 담당한다
- 대체: 연동 명세 6.2(10/22 정리 뒤 5.4)와 FE 제안서 3.3의 예전 안 「앱은 WS `purpose:"calibration"`으로 프레임만 보내고 서버가 `calibration_result`로 등록한다. 앱은 평균을 계산하지 않는다」
- 관련: BE 명세 6장 B1·B2, [ADR 0025](0025-app-always-measures-on-server.md), [계획 0053](../plans/active/0053-multiple-cameras.md) 결정 5(기준 자세는 카메라와 상관없이 하나)

## 결정

1. 앱이 3·2·1 카운트다운 뒤 촬영하면서 **관절 9개(코·양 눈·양 귀·입 양쪽·양 어깨)의 x·y를 쓴 프레임 수로 나눈 단순 평균**을 낸다(소수 5자리).
   시간 가중은 하지 않는다. visibility·z는 보내지 않는다.
2. 쓰는 프레임은 판정 가능 프레임만이다(코·양 어깨 visibility 0.65 이상, 화면 가장자리 2% 안쪽, 어깨 폭이 화면 너비 10% 이상, 양 귀 좌표 있음,
   어깨 유예 프레임 제외 — BE 명세 11.3과 같은 조건). 쓸 수 없는 프레임이나 1초 넘는 빈틈이 있으면 처음부터 다시 센다.
3. 3초가 지나고 **20장 이상**(B1 `sample_count` 최소)이면 끝난다. 추적 속도가 낮으면 20장이 찰 때까지 이어 찍고, 15초가 지나면 실패로 안내한다.
   평균이 화면 밖(0~1 밖)이면 보내지 않고 「화면 안으로」 안내한다.
4. 결과를 **B1 `POST /v2/baselines`** `{registered_at, calibration_ms, sample_count, landmarks}`로 보낸다(CSRF·계정 헤더).
   `registered_at`은 촬영이 끝난 UTC 시각이고, 502·503은 같은 본문으로 1·2·4초 뒤 최대 3번 다시 보낸다(B1은 같은 본문에 같은 행을 돌려준다).
5. 응답의 `baseline_id`가 현재 기준이고 S1에 쓴다. 앱을 켜거나 로그인하면 **B2 `GET /v2/baselines/current`**로 받는다.
   B2를 받기 전에는 등록을 시작하지 않는다(서버에 이미 기준이 있을 수 있음). 404면 등록부터.
6. 이 PC에는 기준 자세를 저장하지 않는다(예전 `savedBaseline.ts` 삭제). WS 등록(`purpose:"calibration"`)은 쓰지 않는다.

## 이유

- 2026-10-20 전체 회의에서 평균 계산을 FE 몫으로 정했다. B1은 BE에 이미 있다.
- 단순 평균은 서버 WS 등록(BE 명세 11.4)이 하던 계산과 같아, 어느 쪽으로 등록해도 기준의 뜻이 같다.

## 결과

- 등록 화면에 「저장 중」 단계와 실패 사유(로그인 필요·서버 오류·화면 밖)가 생겼다.
- 학습 데이터 수집 화면처럼 아직 앱의 기준 특징이 필요한 곳은 서버 기준 좌표로 계산해 넘긴다(ADR 0025 결과).
- BE의 WS 등록 구현(`RealtimeHandlerV2` calibration)은 앱이 쓰지 않는다. 남길지는 BE가 정한다.
