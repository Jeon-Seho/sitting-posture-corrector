# 서비스 저장과 빅데이터 플랫폼의 경계

사용자는 MySQL 계정/영구 저장·Compose·배포 자동화를 요청하면서 빅데이터 플랫폼 쪽의 작업 범위를 물었다.
이 문서는 서비스의 현재 생산자 책임과 별도 분석 플랫폼의 후속 작업을 구분한다.
Kafka·Spark·HDFS·Redis를 과거 계획서에 이름이 있다는 이유로 필수 구현으로 취급하지 않는다.

## 이 저장소의 책임

서비스는 카메라에서 원본 영상/좌표를 보내지 않고 현재−개인 기준 특징 변화량과 품질을 추론에 전달한다.
시간 판정은 CEP가 수행한다. MySQL은 계정·설정·세션·처리 상태·원 추론 관측·사건·확인 요약·서비스 기록을 내구 저장한다.
비밀번호 원문·영상·랜드마크·특징 변화량 원문을 DB의 기본 자료에 넣지 않는다.

관측/사건/요약의 생산자 계약은 [기존 버전 계약](../../contracts/README.md)을 사용한다.
`(session_id, sequence)`와 `(session_id, event_id)`로 중복과 순서를 비교하고 세션의 정책·모델·기준 ID를 고정한다.
낮은 품질·휴식·자리 비움·누락을 유효 시간으로 바꾸지 않는다. DB/CEP 복구에서도 같은 의미를 유지한다.
계정 저장 동의는 연구/학습 활용 동의가 아니다. 서비스 자료를 자동으로 연구 데이터셋에 합치지 않는다.

CEP 전달용 outbox는 서비스 복구용이다. 이를 곧바로 공개 Kafka 토픽이나 연구 데이터 export로 사용하지 않는다.
별도 분석 producer가 필요하면 전달 대상·스키마·재시도·삭제·동의 검사까지 포함한 계약과 outbox를 추가한다.
MySQL 사용자/인증 세션 테이블 전체를 CDC로 흘려보내는 구성은 이 설계의 분석 경계가 아니다.

## 별도 플랫폼에서 할 작업

| 작업 | 이 저장소와 합의할 경계 | 플랫폼이 담당할 구현 |
| --- | --- | --- |
| 수집/전달 | 관측·사건 종류, 불변 ID, 스키마 버전, 세션별 순서, 동의 범위 | 필요한 경우 Kafka/CDC 연결, 소비 확인·재시도·오류 보관 |
| 비식별 연구 추출 | 승인된 자료 범위, 연구 참여자 코드와 서비스 계정의 분리, 철회/삭제 식별 | 접근 통제, 승인된 추출, 보호된 식별자 연결, 산출물/백업 보존 |
| 배치/실시간 집계 | 유효·제외 시간, 사건 중단/회복, 정책·모델 버전 차이 | SQL 집계 또는 처리량에 맞는 Spark 배치/Structured Streaming |
| 연구 저장 | 입력 특징/좌표 수집에 대한 별도 승인, 라벨·품질·수집 메타데이터 | 승인된 파일/객체 저장, Parquet/데이터셋 manifest, 필요 시 HDFS |
| 학습/평가 | 참여자 분할, 기준 등록 분리, 시각·라벨·누락 경계 | [자료 준비 도구](../research/dataset-preparation.md) 연계, 실험 재현과 모델 평가 |
| 운영 | 실패/지연/중복/분할 누수/삭제 전파의 검증 기준 | backlog·lag·오류 모니터링, 재처리, 저장 비용·보존·삭제 운영 |

Redis는 특정 캐시/처리 상태/속도 제한 요구를 정한 뒤 추가한다. 영구 저장이나 CEP 재생 기록을 Redis만으로 대체하지 않는다.
Kafka·Spark·HDFS의 실제 설치와 클러스터 운영, 연구 수집·학습은 이번 MySQL/Compose 구현과 별도다.
현재 입력은 개발 규칙 점수이며 학습 모델의 정답 라벨·보정 확률이 아니다. 서비스 사건만으로 자세 정답 데이터셋을 만들지 않는다.

## 구현 순서와 검증

1. 이 저장소에서 인증된 사용자 자료의 영구 저장·중복·재시작·삭제를 먼저 검증한다.
2. 팀이 분석 목적·필요 자료·연구 활용 동의·보존/삭제·처리량을 확정한다.
3. 필요한 최소 producer 계약과 별도 export/outbox를 정의한다. 개인 식별 정보와 인증 자료를 포함하지 않는다.
4. 합성 자료로 전달 중복·역순·오류·재처리·삭제 전파와 동일 집계를 검증한다.
5. 처리량과 운영 요구에 맞춰 플랫폼을 연결한다. 실제 자료 수집/효과/성능은 별도 측정한다.

outbox와 후속 소비자의 불일치를 줄이는 패턴은 [Debezium 공식 설명](https://debezium.io/documentation/reference/stable/transformations/outbox-event-router.html)을 참고한다.
이 문서는 Debezium을 설치하거나 연구 자료 전달을 승인하지 않는다.
분산 전달의 계약은 [Kafka 공식 설계](https://kafka.apache.org/41/design/design/), 분석 흐름은
[Spark 공식 Structured Streaming 안내](https://spark.apache.org/docs/latest/streaming/index.html)를 참고한다.
이들 기술을 쓰더라도 소비자 중복·시간 창·동의·삭제의 서비스 의미는 따로 구현하고 검증해야 한다.
