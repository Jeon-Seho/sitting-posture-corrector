# 서버 영구 저장과 인증 연결 설계

- 상태: 설계 초안. DB·인증 연결은 구현하지 않았다.
- 날짜: 2026-10-01
- 배경: 사용자는 환경이 정해지지 않은 상태에서 서버 연결부터 진행하도록 선택했다.
- 관련 결정: [특징 서버 연결](../decisions/0013-frontend-server-feature-connection.md),
  [API·CEP 경계](../decisions/0011-api-cep-boundary.md), [시간 정책](../decisions/0012-session-timing-policy.md)

## 현재 구현과 다음 경계

API와 CEP는 프로세스 메모리에 세션을 저장한다. 서버 재시작으로 세션이 사라지면 404이며,
브라우저 중간 기록이 서버 상태를 복원하지 않는다. 브라우저의 로컬 로그인·프로필·writer lock은
서버 사용자 인증이나 접근 권한을 증명하지 않는다. 현재 서버 요청은 인증 자격증명을 보내지 않는다.
DB 제품, 인증 제공자, 배포 방식은 이 문서에서 선택하지 않는다.

후속 구현은 검증한 인증 주체에서 서버 내부 `user_id`를 얻고, 모든 생성·조회·입력·종료·삭제 요청을
그 소유자 범위로 제한한다. 요청 body나 브라우저 저장소의 `user_id`, 이름, 이메일을 소유권의 근거로 받지 않는다.
인증 주체를 내부 사용자에 연결하는 키와 세션/토큰 검증·만료 방식은 실제 인증 선택 후 계약으로 정한다.
같은 UUID를 다른 사용자에게 보여주지 않도록 저장소 조회와 변경도 소유자 조건을 포함해야 한다.
미인증 401과 권한 없는 세션의 응답 정책은 인증 구현 전에 명시하고 시험한다.

## 제안하는 데이터 책임

아래는 논리적 데이터 모델이며 실제 테이블·DB 제품을 확정한 것이 아니다.

| 자료 | 소유권·고정 정보·제약 |
| --- | --- |
| 사용자 연결 | 서버 내부 `user_id`와 검증한 인증 주체의 연결. 표시용 프로필과 접근 권한을 분리한다. |
| 측정 세션 | UUID, 소유 `user_id`, 시작/종료 상태, 고정 시간·점수 정책, `timer_policy`, 계약/특징 버전, 기준 등록 UUID, 허용 모델 버전. |
| 입력 처리 기록 | `(session_id, sequence)` 유일 키, 정규화한 요청 hash, 원 추론 관측, 처리 상태·거부 상태. 동일 내용 재시도는 원출력, 다른 내용은 충돌. |
| CEP 전달 기록 | 처리 기록에 연결한 outbox 항목과 전달/확인 상태. 세션 순서와 동일 관측 재전달을 보장한다. |
| 사건 | `(session_id, event_id)` 유일 키, 유형, 시각, 발생점의 유효 시간, 중단 이유. 같은 사건을 중복 저장하거나 재알리지 않는다. |
| 확인 요약 | 마지막 확인 sequence·시간·사건 범위와 유효/제외 시간 통계. 마지막 확인 값의 후퇴·사건 변경을 거부한다. |
| 동의·삭제 처리 | 확정한 동의 버전·범위·일시와 삭제 요청의 처리 상태. 구체적 수집 항목과 기간은 미결정이다. |

시간 정책은 세션 생성 시 고정하고 기준 등록 UUID와 모델 버전은 추론 연결의 고정 조건으로 보관한다.
기준 UUID는 참여자 식별자가 아니다. 실제 기준 특징은 현재처럼 브라우저에서 보관하고,
서버 영구 저장은 원본 영상·랜드마크·기준 특징 원값·원 요청 변화량을 기본 자료에 포함하지 않는다.
규칙 버전과 모델 파일의 불변 식별자·배포 변경 정책은 재현 가능한 추론을 위해 별도로 합의한다.

## 중복·트랜잭션·재전달

현재 세션 잠금과 메모리 cache를 DB로 옮기는 것만으로 영구 복구가 완성되지 않는다.
후속 구현은 다음 순서를 만족하는 처리 상태와 트랜잭션을 설계해야 한다.

1. 인증 소유자·세션 상태·고정 기준·순서를 확인한다. `(session_id, sequence)`의 유일 제약과
   요청 hash로 동시 재시도를 비교한다. 구간이나 sequence가 누락되면 CEP의 연속 판정을 끊는 기존 의미를 유지한다.
2. 추론 호출과 DB 갱신의 경계를 나눈다. 외부 HTTP 완료를 기다리는 동안 긴 DB 트랜잭션을 유지하지 않는다.
   검증한 최초 추론 출력과 기준·모델 고정 조건을 CEP 전달 전에 내구 저장한다.
   출력 저장과 outbox 생성은 같은 트랜잭션에 넣어 저장만 성공하고 전달 작업이 사라지는 상황을 막는다.
3. 세션 순서를 지키는 작업자가 outbox를 CEP에 전달한다. 시간 초과는 수용 여부가 미확인이므로
   원 관측을 다시 보낸다. 새 점수·시각·sequence를 생성하지 않는다. CEP의 중복 수용은 집계·사건을 늘리지 않아야 한다.
4. CEP가 확인한 사건·요약·입력 완료·outbox 완료를 일관되게 기록한다. 확정 409/429와
   미확인 502를 구분하여 종료 가능한 상태와 재시도 필요한 상태를 보존한다.
5. 알림 전달은 사건 저장과 분리한다. 사건 식별자로 화면/전달 중복을 제어하되
   사건 확정 횟수를 실제 화면 표시·소리 성공 횟수로 바꾸지 않는다.

추론 완료와 원출력 내구 저장 사이의 장애는 별도 결정이 필요하다. 아직 저장한 출력이 없으면
재호출할 수 있지만, 모델 배포가 바뀐 뒤 같은 결과가 나온다고 자동 보장할 수 없다.
불변 모델 식별자와 처리 상태 복구 계약을 정하고 이 경계를 장애 시험에 포함한다.
메모리 개발 cache의 10,000건 한도와 영구 저장의 보존·재시도 만료 기간은 서로 다른 결정이다.
hash도 요청 재시도 비교용 자료이므로 보존·삭제 범위에서 빠뜨리지 않는다.

## CEP 재시작과 재생

현재 CEP 엔진의 누적 시간·열린 사건·마지막 알림 시각·중복 관측은 메모리 상태다.
DB에 최종 요약만 저장하면 연속 판정과 정확한 재알림을 재구성할 수 없다.
영구 복구는 확인된 관측을 같은 정책·규칙 버전으로 세션 순서대로 재생하거나,
검증 가능한 엔진 snapshot과 이후 관측을 함께 복원하는 방식을 정해야 한다.
원출력·제외 구간·sequence 공백·종료 시각을 모두 보존하고 다음을 검증한다.

- 기존 사건 ID·발생점·유효 시간·통계가 재생 전과 같고 기존 알림을 다시 전달하지 않는다.
- DB에는 수용됐지만 CEP에 미확인인 입력과 CEP가 수용했지만 DB 확인 전에 실패한 입력을 구분하여 재전달한다.
- 복구한 마지막 확인 범위 이후의 처리와 세션 종료가 같은 순서를 따른다.
- 복구할 자료가 없으면 세션 유실을 표시한다. 같은 UUID의 빈 세션을 과거 세션 복구로 취급하지 않는다.

현재 관측/조회 계약은 기준 등록 UUID와 모든 복구 메타데이터를 출력하지 않는다.
인증·영구 복구에 필요한 서버 메타데이터 API와 호환성 버전도 실제 연결 전에 정해야 한다.

## 아직 정하지 않은 항목과 검증

동의 목적·범위·철회, 사용자별 접근, 서버/브라우저/백업/로그의 보존 기간,
삭제 및 탈퇴 때 사건·추론 출력·hash·outbox를 정리하는 순서, 처리 중 삭제 경쟁,
연구 자료와 서비스 자료의 분리, 비밀값 주입·회전·배포 설정은 미결정이다.
기간이나 법적 충족 여부를 임의로 확정하지 않는다. 실제 영상·참여자 자료를 시험 fixture에 넣지 않는다.

연결 승인 후 두 사용자 간 접근 차단, 동시 중복/충돌, 추론·DB·CEP 경계별 장애,
outbox 재전달·CEP 재생·종료 재시도·정책/기준/모델 고정·삭제 경쟁을 합성 자료로 시험하고
실제 컴포넌트 검증을 `make check`와 CI에 연결한다. DB·인증 구현은 이 설계 작업의 완료 조건이 아니다.
