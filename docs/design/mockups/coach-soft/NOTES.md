# coach-soft 시안 노트

[playful-coach](../playful-coach/index.html)를 복사해 **색만** 바꾼 시안이다. 레이아웃·문구·상호작용·코치 「바로」의 모양·표정·애니메이션은 그대로다.
"보라색에 푸른빛 도는 흰 바탕이라 오래 보면 눈이 아프다"는 의견을 반영했다.

- 시안: [`index.html`](index.html). 화면 위 전환 바의 **배색** 버튼(세이지·웜 크림·허니)으로 바로 바꿔 볼 수 있다.
  선택은 `localStorage`에 남고, 주소에 `?pal=warm`처럼 붙여 열어도 된다(예: `index.html?pal=honey#/s5`).
- 구현: `<html data-palette>` + CSS 변수 세트 3개. 코치 SVG·실루엣·그래프·꽃가루까지 모두 변수를 쓰므로, 배색을 바꿔도 다시 그리지 않고 바로 바뀐다.

## 기본 배색: sage(세이지)

1. **강조색 채도가 셋 중 가장 낮다.** 주색 `#416b56`의 채도(CIE Lab C)가 21로, warm 테라코타(45)·honey 머스터드(59)의 절반 이하다. 원래 보라 `#6246ea`는 96이었다.
2. **바탕이 가장 덜 물들어 있다.** `--bg #f4f2ea`의 채도는 4로, 아이보리 쪽으로 아주 살짝만 기운 오프화이트다. warm 크림은 6이고 원래 `#f6f4ff`는 6이었지만 보라 쪽(색상각 298°)이었다.
3. **밝기 차이가 크지 않다.** 사이드바(`#416b56`)와 흰 글자의 대비는 5.6:1로 읽기에는 충분하다. honey의 차콜 사이드바(11.6:1)처럼 화면을 크게 가르는 명암 경계가 없다.
4. **기존 브랜드 초록 `#416b56`(DESIGN.md·`frontend/src/styles/appearance.css`)을 그대로 이어 받는다.** 그래서 `frontend/`에 적용할 때 바뀌는 범위가 가장 작다.

나머지 둘의 성격도 적어 둔다. warm은 가장 포근하지만 주색(테라코타)이 흐트러짐 알림 빨강과 같은 따뜻한 쪽에 있다. 그래서 알림과의 색 거리(ΔE76 26)가 셋 중 가장 가깝다. honey는 명랑하지만 넓은 차콜 면이 화면을 무겁게 하고, 주 버튼이 노랑 바탕에 어두운 글자라 버튼 느낌이 다른 둘과 달라진다.

### 상태색 구분(배색마다 확인)

| 상태 | 표시 | 비고 |
| --- | --- | --- |
| 정상 | 연초록 배너 + 초록 테두리 | |
| 흐트러지는 중 | 옅은 황토(honey는 살구) 배너 + 황토/주황 테두리 | honey는 주색이 머스터드라 주황으로 옮겼다 |
| 흐트러짐 알림 | **진한 진홍으로 꽉 찬 배너**(흰 글자) + 깜빡이는 테두리 | 다른 상태는 모두 옅은 배너라 채움 여부만으로도 구분된다. warm 테라코타와는 색상각·채도·채움 방식이 모두 다르다. 알림일 때만 코치 뒤에 옅은 원을 깔아 붉은 배너 위에서 코치가 묻히지 않게 했다 |
| 측정 불가 | **중립 회색** 배너 + 회색 점선 테두리 + 회색 코치 | 채도 6~7. 정상·흐트러짐 어느 쪽으로도 읽히지 않는다 |
| 연결 중 | 차분한 청회색 배너 + 청회색 점선 테두리 | 원래는 측정 불가와 같은 회색이었다. 작은 면에만 쓰는 상태색이라 바탕의 "푸른 기 제거" 원칙과 부딪히지 않는다 |
| 연결 끊김 | **어두운 차콜 배너** + 회색 점선 테두리 | 원래는 회색. 시스템 문제를 측정 불가와 다르게 보이게 했다 |
| 카메라 거부 | 카드색 배너 + 회색 **점선 외곽선** | 원래는 회색 |
| 기준 미등록 | 할 일 색 배너(sage 클레이, warm 테라코타 옅음, honey 허니 옅음) | sage에서는 주색이 초록이라 정상과 헷갈리지 않게 클레이를 썼다 |

상태 전환 버튼의 점 색도 위 색에 맞췄다. 연결 중은 청회색, 연결 끊김은 차콜, 카메라 거부는 속이 빈 회색 고리다.
상태별 배너 24개(배색 3 × 상태 8)를 한 장에 놓고 서로 구분되는지 눈으로 확인했다.

### 렌더 검사(헤드리스 Chrome)

- 방법: 헤드리스 Chrome을 띄워 배색 3 × 화면 6과 측정 상태 8을 차례로 열었다. 보이는 글자 요소마다 실제 계산된 글자색과 조상 배경을 알파 합성한 색으로 대비를 쟀다. 기준은 4.5:1이고, 24px 이상이거나 18.66px 이상 굵은 글자는 3:1이다. 비활성 버튼과 「준비 중」 소셜 버튼은 WCAG 예외로 뺐다.
- 결과: 글자 2,382개를 확인했다. 처음 검사에서 실제 미달 세 곳이 나왔고 고쳤다.
  - 사이드바 「오늘의 목표」 상자: 흰 반투명 덮개가 대비를 떨어뜨렸다. 어둡게 덮도록 바꾸고, 투명도 대신 보조 글자색을 쓰게 했다.
  - 잠긴 배지 숫자: `faint`에서 `muted`로 바꿨다.
  - 알림 배너의 「알림」 꼬리표: 흰 덮개에서 어두운 덮개로 바꿨다.
- 수정 후 남은 27건은 모두 카메라 위 「관절 표시」 라벨이다. 검사기가 카메라 무대의 그라데이션 배경을 읽지 못하고 앱 바탕으로 잘못 계산한 결과다. 실제 값은 위 표대로 14.8:1 이상이다.
- 콘솔 오류: 18개 화면을 열어 확인했고 없었다.
- 배색 전환: 버튼을 누르면 `data-palette`·`aria-pressed`·코치 몸 색(계산된 fill)이 바뀌었다. 새로 고친 뒤에도 선택이 남는 것을 확인했다.
- 좁은 창(390px): 시작·측정·기록·로그인 화면에서 배색 선택이 줄바꿈되며 깨지지 않았다.

## 확인하지 못한 것

- 실제 부스 모니터·프로젝터에서의 색 재현과 2~3m 거리 가독성은 보지 못했다(sRGB 계산과 헤드리스 캡처만 확인).
- 색각 이상 시뮬레이션은 하지 않았다. 정상(초록)과 흐트러짐 알림(진홍)은 적록 색각 이상에서 가까워질 수 있다. 알림은 꽉 찬 배너·깜빡이는 테두리·문구·코치 표정으로 함께 구분되지만 따로 확인이 필요하다.
- "눈이 덜 피로하다"는 채도·명암 수치에 근거한 판단이고, 사용자 체감 평가는 하지 않았다.
- 원본 playful-coach의 ①~⑤ 항목(UX 개선점, `제안` 목록, `frontend/` 적용 파일)은 바뀌지 않았으므로 [playful-coach/NOTES.md](../playful-coach/NOTES.md)를 그대로 따른다.
