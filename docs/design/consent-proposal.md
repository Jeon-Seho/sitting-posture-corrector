# 개인정보 수집 동의 제안서 초안

> 작성자: klaod-tech(FE) · 작성: 2026-10-13 · 최신화: 2026-10-25(3장: 가입·로그인이 계정 서버로 바뀐 것, 4장 동의 목록 형식 끝남) · 2026-10-16(탈퇴는 되돌릴 수 없음) · FE · 상태: **초안** · 대상: DB(동의 저장), BE(가입 API), PM(문구 확정)
> 근거: [FE 제안서](fe-server-proposal.md) F12, [ADR 0021](../decisions/0021-app-sends-information-server-judges.md)(좌표 수집 동의는 가입 필수), 아키텍처 v5.2(탈퇴 30일 뒤 삭제 J3, 매일 04:00)
> 한국 개인정보보호법 기준으로 FE가 정리한 안이다. 법률 검토가 아니다.

실제 서비스에서는 ML 학습용 데이터를 받지 않고 논문에도 쓰지 않는다. 학습 데이터는 서비스 전 구현 단계에서 따로 모은다.
그래서 가입 동의에는 학습용 동의를 두지 않는다.

## 1. 가입 화면 동의 목록

C1~C6은 동의 항목 번호다(코드 `ConsentId`). 연동 명세의 API C1(`PUT /v2/consents/optional-profile`)과는 다른 번호다.

| # | 동의 | 필수/선택 | 거부하면 |
|---|---|---|---|
| C1 | 서비스 이용약관 | 필수 | 가입할 수 없다 |
| C2 | 회원가입 정보 수집·이용 | 필수 | 가입할 수 없다 |
| C3 | 선택 정보(나이·직업) 수집·이용 | 선택 | 불이익 없음. 입력란을 비운다 |
| C4 | 카메라 관절 좌표 수집·이용 | 필수 | 측정을 할 수 없어 가입할 수 없다(로컬 모드 없음, ADR 0021) |
| C5 | 측정 기록 저장 | 필수 | 결과·기록·통계를 보여 줄 수 없어 가입할 수 없다 |
| C6 | 만 14세 이상 확인 | 필수 | 가입할 수 없다 |
| — | 개인정보 처리방침 | 동의 아님 | 가입 화면과 설정에 링크로 둔다 |

- 필수와 선택을 한 체크박스로 묶지 않는다. 「전체 동의」는 두되 항목마다 따로 끌 수 있게 한다.
- C4는 다른 항목과 섞지 않고 따로 받는다. 자세 좌표가 건강 관련 정보로 볼 여지가 있어서다.

## 2. 항목별 고지 내용

보유 기간은 모두 **탈퇴 후 30일**이다(아키텍처 v5.2 J3가 매일 04:00에 돌아, 30일이 지난 뒤 처음 오는 04:00에 지운다). 탈퇴는 되돌릴 수 없다(10/15 BE, 철회 경로 없음). 그 사이 로그인하면 연락처를 안내한다([연동 명세](api-ws-spec.md) 2장).

| # | 수집 항목 | 목적 |
|---|---|---|
| C2 | 이메일, 비밀번호(단방향 해시), 이름 | 로그인, 계정 관리 |
| C3 | 나이, 직업 | 사용자 환경별 통계 |
| C4 | 관절 9곳(코·눈·귀·입 양끝·어깨)의 화면 좌표와 시각. **영상·사진은 기기 밖으로 보내지 않는다** | 자세 판정과 교정 알림 |
| C5 | 측정 세션, 이탈 사건, 알림 기록, 일별 통계, 기준 자세 | 결과·기록·통계 화면 |

동의 문구에는 항목마다 수집 항목, 목적, 보유 기간, 거부할 권리와 그 불이익(1장 표)을 적는다.

## 3. 화면 (2026-10-13 구현, 10/22 계정 서버 연결)

- 첫 화면은 로그인(이메일·비밀번호)이고 아래 「회원가입」으로 간다. 이름 인사는 로그인한 뒤에만 보인다.
- 1/3 약관 동의: 「전체 동의」와 6줄. 순서는 만 14세(C6) → C1 → C2 → C4 → C5 → 선택 정보(C3, 맨 아래). 줄마다 (필수)/(선택) 표시와 |동의|비동의|. 처음에는 아무것도 골라져 있지 않다. 「전체 동의」를 누르면 화면이 「다음」 버튼까지 부드럽게 내려가고 그 버튼에 초점이 간다(움직임 줄이기 설정이면 바로 이동). 자동으로 다음 단계로 넘기지는 않는다.
  「자세히」는 팝업으로 2장의 고지 내용을 보인다(목록은 움직이지 않음). 팝업 아래 |동의|비동의|는 고르고 닫고, 오른쪽 위 X(또는 Esc)는 닫기만 한다.
  필수에 비동의를 고르면 "필수 항목이라 동의해야 가입할 수 있어요"를 보이고, 필수가 모두 동의이고 선택도 골라졌을 때만 「다음」이 눌린다.
- 2/3 계정 정보: 이메일, 비밀번호(12자 이상·72바이트 이하, 10/22 계정 서버 연결 때 켬 — `validServerPassword`), 이름. C3에 동의했을 때만 나이·직업을 받는다. 「다음」에서 가입 결과를 저장한다.
- 3/3 자세 등록(선택): 측정하기의 「다시 등록」 모드(`SetupPage registerAgain`)를 그대로 넣었다. 개발자 옵션은 숨기고 시작 버튼은 「앱 시작」이다.
  「앱 시작」은 측정하기로, 「건너뛰기」(카메라가 연결되지 않았으면 눈에 띄는 「카메라 없이 넘어가기」)는 첫 화면으로 간다. 오른쪽 아래에 「이전」과 함께 있다.
  가입을 마칠 때 카메라가 켜져 있으면 앱 화면의 영상 요소로 다시 연결한다(그대로 두면 스켈레톤 인식이 멈춘다). 건너뛴 사용자는 측정하기에서 3초 등록을 한다.
- 10/22부터 가입은 A2 `POST /v2/auth/register`(동의 목록은 `consents.ts` `consentPayload()`), 로그인은 A3로 서버가 확인한다(스위치 없음). 화면용으로 프로필·이메일·동의 선택의 사본을 이 기기에도 두고, 비밀번호는 저장하지 않는다.
- 코드: `frontend/src/features/auth/`(`consents.ts` 항목·고지·DB 유형, `ConsentList.tsx`, `ConsentDialog.tsx`, `SignupPostureStep.tsx`), `app/LocalServiceApp.tsx`.

## 4. 저장 (DB V2.3 `user_consent`)

- 가입 때 계정 행과 필수 동의 5행(`TERMS`·`ACCOUNT_INFO`·`POSE_COORDINATES`·`MEASUREMENT_RECORD`·`AGE_14_OVER`)을 한 트랜잭션으로 넣는다. 선택 정보(`OPTIONAL_PROFILE`)는 동의했을 때만 넣고, 거부는 저장하지 않는다.
- 행마다 문구 버전(`document_version`, 앱은 `service-v2`, BE 명세 10/13)을 남긴다. 약관이 바뀌면 새 버전으로 다시 받는다.
- 선택 정보 동의 철회는 `withdrawn_at`을 채우고 나이·직업을 비운다. 필수 동의 철회는 탈퇴로 처리한다.
- 가입 요청에 동의 목록을 담는 형식은 BE `contracts/accounts.v2.md`대로 끝났다(10/22, A2). 남은 것: 선택 동의 철회 C1(F12 남은 일).

## 5. API에 미치는 것

- `POST /v2/auth/register`(A2)에 동의한 항목만 `consents: [{type, document_version:"service-v2"}]`로 보낸다. `type`은 DB 유형(`AGE_14_OVER` 등), 비동의한 선택 항목은 빼고 보낸다([연동 명세](api-ws-spec.md) 4장 A2).
- 지금 계정 계약 v1의 `consent_version: "service-v1"` 하나는 이것으로 바뀐다.
