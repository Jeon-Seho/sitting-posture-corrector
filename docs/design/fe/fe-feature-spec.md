# FE 기능 명세

> 작성자: klaod-tech(FE) · 작성: 2026-11-09 · 상태: 초안(우선순위는 팀 확인 전)
> **이 문서의 역할:** 앱에 어떤 기능이 있고 지금 어디까지 구현됐는지 한곳에서 본다. API별 요청·응답과 앱이 언제 무엇을 보내고 받는지는 [연동 명세](api-ws-spec.md), 필드 규칙의 기준은 [BE API 명세](../api-spec.md), 남은 일과 요청은 [FE 제안서](fe-server-proposal.md) 1장이 기준이다.
> **범위:** 웹과 데스크톱(Electron) 앱. 휴대폰 앱은 이 명세를 끝낸 뒤 구현하므로 여기 넣지 않는다. `/dev`는 학습 데이터 수집용 개발 도구라 서비스 기능에서 뺀다([개발자 화면 안내](../../../frontend/src/features/developer/README.md)).

## 1. 읽는 법

- **시작·종료 상태:** 기능을 시작할 수 있는 상태와 끝난 뒤의 상태다.

| 상태 | 뜻 |
|---|---|
| `UNAUTHENTICATED` | 로그인하지 않음 |
| `AUTHENTICATED` | 로그인함, 측정 중이 아님 |
| `MEASURING` | 측정 중(좌표를 서버로 보내고 있음) |
| `PAUSED` | 측정 중 쉬기 또는 자리 비움 |

- **구현 상태:** `구현됨`, `일부`(앱이나 서버 한쪽 또는 일부만 있음), `구현 전`
- **API:** 번호는 [연동 명세](api-ws-spec.md) 3장 표와 같고, 상세는 7장이다. `WS`는 `/v2/realtime`이다.
- **우선순위:** 작성자 제안 값이며, 팀 확인 전이다.

## 3. 기능 상세

### 회원가입

**선행조건**

- 로그인하지 않은 상태다.
- 가입에 필요한 정보가 유효해야 한다.
  - 이메일: 형식에 맞고 254자 이하
  - 비밀번호: 12자 이상, UTF-8 72바이트 이하
  - 이름: 1~30자
  - 나이(선택): 14~120. 선택 정보에 동의한 경우만
  - 직업(선택): 1~80자. 선택 정보에 동의한 경우만

**트리거**

- 로그인 화면에서 회원가입을 시작하고, 계정 정보 단계에서 「다음」을 누른다.

**동작**

1. 약관에 동의한다. 필수 5개(서비스 이용약관, 회원가입 정보, 카메라 관절 좌표, 측정 기록, 만 14세 이상)와 선택 1개(나이·직업)다.
2. 계정 정보를 입력하면 앱이 형식을 검사하고 서버에 가입을 요청한다(A2).
3. 서버는 계정과 동의를 함께 저장하고 기본 판정 기준(3초, 3초, 60초, 0.7)을 연결한다.
4. 가입이 성공하면 바로 로그인 상태가 된다.
5. 자세 등록 단계로 간다. 등록하면 측정하기로, 건너뛰면 홈으로 간다.

**예외 / 제한사항**

| 상황 | 서버 응답 | 앱 안내 |
|---|---|---|
| 이메일·비밀번호·이름 형식이 틀림 | 요청하지 않음 | 항목별 안내 문구 |
| 이미 쓰는 이메일, 또는 탈퇴 후 30일이 지나지 않은 이메일 | 409 `ACCOUNT_EXISTS` | 「가입할 수 없는 이메일이에요. 이미 가입했거나 탈퇴 후 30일이 지나지 않았어요.」 |
| 필수 동의 누락 | 400 `CONSENT_REQUIRED` | 「필수 약관 동의를 다시 확인해 주세요.」 |
| 그 밖의 입력 오류 | 400 | 「입력 값을 확인해 주세요. 비밀번호는 12자 이상, 이름은 30자 이하, 나이는 14~120이에요.」 |
| 서버가 바쁨 | 503 | 「계정 서버가 바빠요. 잠시 뒤 다시 시도해 주세요.」 |

**비고**

- 아이디와 닉네임이 없다. 이메일로 로그인하고, 이름은 중복을 검사하지 않는다.
- 동의 항목 번호(C1~C6)와 서버 유형은 아래와 같다. 고지 문구는 `consents.ts`에 있다. 화면 순서는 C6 → C1 → C2 → C4 → C5 → C3이고, 「자세히」 팝업으로 수집 항목·목적·보유 기간(탈퇴 후 30일)을 보인다.

| 번호 | 항목 | 서버 유형 | 필수 |
|---|---|---|---|
| C1 | 서비스 이용약관 | `TERMS` | 필수 |
| C2 | 회원가입 정보 수집·이용(이메일, 비밀번호 해시, 이름) | `ACCOUNT_INFO` | 필수 |
| C3 | 선택 정보(나이·직업) 수집·이용 | `OPTIONAL_PROFILE` | 선택 |
| C4 | 카메라 관절 좌표 수집·이용(영상·사진은 보내지 않음) | `POSE_COORDINATES` | 필수 |
| C5 | 측정 기록 저장 | `MEASUREMENT_RECORD` | 필수 |
| C6 | 만 14세 이상 | `AGE_14_OVER` | 필수 |

- 자세 등록을 건너뛰어도 가입은 끝난 상태다. 측정하기에서 등록한 자세가 없으면 그때 등록한다.
- 코드: [LocalServiceApp.tsx](../../../frontend/src/app/LocalServiceApp.tsx) `register`, [SignupPostureStep.tsx](../../../frontend/src/features/auth/SignupPostureStep.tsx), [consents.ts](../../../frontend/src/features/auth/consents.ts). 서버 규칙은 [API 명세 A2](../api-spec.md#a2).

### 로그인

**선행조건**

- 로그인하지 않은 상태다.
- 가입한 이메일과 비밀번호가 있다.

**트리거**

- 로그인 화면에서 「로그인」을 누른다.

**동작**

1. 앱이 이메일 형식과 비밀번호 입력 여부를 확인한다.
2. 서버에 로그인을 요청한다(A3).
3. 성공하면 access 토큰을 메모리에 두고 홈으로 간다.
4. 판정 기준(W1), 기준 자세(B2), 기록(R1)을 받는다.

**예외 / 제한사항**

| 상황 | 서버 응답 | 앱 안내 |
|---|---|---|
| 이메일 형식이 틀리거나 비밀번호가 비어 있음 | 요청하지 않음 | 「이메일과 비밀번호를 입력해 주세요.」 |
| 이메일·비밀번호 불일치 | 401 `INVALID_CREDENTIALS` | 「이메일 또는 비밀번호가 맞지 않아요.」 |
| 탈퇴 접수한 계정 | 403 `ACCOUNT_CLOSED` | 「탈퇴한 계정입니다. 되돌릴 수 없고 탈퇴 30일 뒤 삭제됩니다.」 |
| 서버가 바쁨 | 503 | 「계정 서버가 바빠요. 잠시 뒤 다시 시도해 주세요.」 |
| 서버에 연결 안 됨 | 응답 없음 | 「계정 서버에 연결하지 못했어요. 잠시 뒤 다시 시도해 주세요.」 |

**비고**

- ID 칸에 `admin`을 넣으면 서버에 보내지 않고 개발자 계정으로 들어간다(비밀번호 `1234`). 서버 측정과 저장은 쓸 수 없는 화면 확인용이다.
- 코드: [LocalServiceApp.tsx](../../../frontend/src/app/LocalServiceApp.tsx) `login`, [accountClient.ts](../../../frontend/src/features/auth/accountClient.ts) `accountErrorMessage`.

### 로그인 유지

**선행조건**

- 로그인한 적이 있고 refresh 쿠키(14일)가 남아 있다.

**트리거**

- 앱을 연다. access 토큰 만료가 1분 30초 남는다. 요청이 401을 받는다.

**동작**

1. 앱을 열면 메모리에 토큰이 없으므로 A8로 새 토큰을 받고 A4로 계정을 확인한다. 성공하면 로그인 화면을 건너뛴다.
2. access 토큰(30분)이 끝나기 1분 30초 전에 A8로 미리 갱신한다.
3. 요청이 401이면 A8을 한 번 하고 원래 요청을 다시 보낸다.
4. 갱신은 한 번에 하나만 하고, 다른 탭에는 새 토큰을 나눠 준다(`BroadcastChannel`).
5. 창·탭으로 돌아오거나 기록·달력을 열 때 A4로 서버 날짜를 받아 「오늘」을 고친다(1분에 한 번까지).

**예외 / 제한사항**

- A8이 401이면 로그인 화면으로 간다. 네트워크 오류나 5xx면 로그아웃하지 않고 30초 뒤 다시 시도한다.
- 설치용 데스크톱 앱은 지금 배포본이 `app://posegood`에서 열려 refresh 쿠키가 실리지 않아 로그인 유지가 안 된다. 웹 주소 화면을 열게 고친 코드(F14)를 배포하면 웹처럼 유지된다. 이때 서버에 못 붙으면 앱에 든 「서버에 연결할 수 없어요」 화면을 보이고 10초마다 다시 시도한다(FE 제안서 1.0).

**비고**

- 코드: [accountClient.ts](../../../frontend/src/features/auth/accountClient.ts). 규칙은 [연동 명세](api-ws-spec.md) 1장 「로그인 유지」.

### 로그아웃

**선행조건**

- 로그인한 상태이고 측정 중이 아니다.
- 서버 확인을 기다리는 측정 결과가 없다.

**트리거**

- 계정 메뉴에서 「로그아웃」을 누른다.

**동작**

1. 서버에 로그아웃을 요청한다(A5). 이 기기의 refresh 토큰을 철회한다.
2. 카메라를 끄고 기록과 판정 기준을 화면에서 비운다.
3. 로그인 화면으로 간다.

**예외 / 제한사항**

- 측정 중이면 「측정을 종료하고 결과 저장을 확인한 뒤 로그아웃해 주세요.」
- 서버 확인을 기다리는 결과가 있으면 「결과 저장을 완료한 뒤 나가 주세요.」
- 서버 요청이 실패해도 이 기기에서는 로그아웃한다. 「서버 로그아웃을 확인하지 못했어요. 연결 후 다시 시도해 주세요.」

### 비밀번호 찾기

**선행조건**

- 로그인하지 않은 상태다.

**트리거**

- 로그인 화면에서 「비밀번호 재설정」을 누른다.

**동작**

1. 메일 화면으로 간다. 메일로 받은 코드와 새 비밀번호를 입력하는 화면이다.
2. 새 비밀번호는 12자 이상, UTF-8 72바이트 이하이고 두 번 같게 입력해야 한다.

**예외 / 제한사항**

- 서버 API와 메일 발송이 없어 요청이 나가지 않는다. 「메일 인증 서버 연결을 준비 중이에요.」를 보인다. 설정 `VITE_ACCOUNT_MAIL_API_ENABLED`가 켜지면 `/api/v2/auth/…`로 보낸다.

**비고**

- 구현 전. 설계안은 [이메일 계정 인계](../email-account-handoff.md). 코드: [MailAccessPage.tsx](../../../frontend/src/features/auth/MailAccessPage.tsx), [mailApi.ts](../../../frontend/src/features/auth/mailApi.ts).

### 프로필 수정

**선행조건**

- 로그인한 상태이고 측정 중이 아니다. 서버 확인을 기다리는 결과가 없다.

**트리거**

- 프로필 화면에서 「프로필 서버 저장」을 누른다.

**동작**

1. 화면을 열 때 W1으로 프로필을 받는다.
2. 이름(1~30자)과, 선택 정보에 동의했으면 나이(14~120)·직업(80자 이하)을 고친다.
3. 저장할 때 W1을 다시 받아 다른 화면에서 바뀌지 않았는지 확인한다.
4. 프로필만 바꿔 W2로 저장하고 「서버에 저장했어요.」를 보인다.

**예외 / 제한사항**

- 입력이 규칙에 맞지 않으면 「이름·나이·직업을 확인해 주세요.」
- 다른 화면에서 바뀌었으면 「다른 화면에서 설정이 바뀌었어요. 이 화면을 다시 열고 확인해 주세요.」
- 측정 중이거나 저장 대기 결과가 있으면 「측정을 종료하고 결과 저장을 확인한 뒤 계정을 변경해 주세요.」

**비고**

- 코드: [ServerAccountPage.tsx](../../../frontend/src/features/profile/ServerAccountPage.tsx).

### 비밀번호 변경

**선행조건**

- 로그인한 상태이고 측정 중이 아니다.

**트리거**

- 프로필 화면에서 현재 비밀번호와 새 비밀번호를 넣고 「비밀번호 변경」을 누른다.

**동작**

1. 새 비밀번호가 12자 이상, UTF-8 72바이트 이하일 때만 버튼이 켜진다.
2. 서버에 변경을 요청한다(A6). 서버는 모든 기기의 로그인을 끊는다.
3. 로그인 화면으로 가서 「비밀번호를 변경했어요. 새 비밀번호로 로그인해 주세요.」를 보인다.

**예외 / 제한사항**

- 현재 비밀번호가 틀리면 400 `INVALID_PASSWORD`. 앱은 「변경하지 못했어요. 입력과 서버 연결을 확인해 주세요.」를 보인다.

### 선택 정보 동의 철회

**선행조건**

- 로그인한 상태다.

**트리거**

- 없음. 앱에 부르는 화면이 없다.

**동작**

- 서버 API(C1)는 있다. 철회하면 서버가 나이·직업을 비우고, 다시 동의하면 동의 행을 새로 만든다.

**비고**

- 구현 전. 앱에서는 가입 때만 선택 정보 동의를 고른다.

### 회원탈퇴

**선행조건**

- 로그인한 상태이고 측정 중이 아니다.

**트리거**

- 프로필 화면에서 현재 비밀번호를 넣고 「탈퇴와 기록 삭제에 동의합니다」를 체크한 뒤 「서버 계정 탈퇴」를 누른다.

**동작**

1. 화면에 「탈퇴는 되돌릴 수 없으며 서버 정책에 따라 30일 뒤 계정과 기록이 삭제됩니다.」를 보인다.
2. 서버에 탈퇴를 접수한다(A7). 서버는 계정을 CLOSED로 바꾸고 모든 로그인을 끊는다.
3. 로그인 화면으로 가서 「서버에 탈퇴를 접수했어요.」를 보인다.
4. 30일 동안 서버 자료는 그대로 있고, 그 뒤 Spark J3(매일 04:00)가 HDFS 폴더와 DB 행을 지운다.

**예외 / 제한사항**

- 되돌릴 수 없다. 30일 안에는 같은 이메일로 다시 가입할 수 없다(409 `ACCOUNT_EXISTS`).
- 탈퇴한 계정으로 로그인하면 비밀번호가 맞을 때만 「탈퇴한 계정입니다.…」를 보인다.
- 이 기기의 서버 확인 전 결과는 지우지 않는다(FE 제안서 1.0).

### 판정 기준 설정

**선행조건**

- 로그인한 상태다.

**트리거**

- 설정 화면에서 「얼마나 민감하게」, 「알리기까지 기다리는 시간」, 「다시 알리는 간격」이나 「세밀하게 조정」의 값을 바꾼다.

**동작**

1. 화면을 열 때 W1으로 서버의 판정 기준을 받는다.
2. 값을 바꾸면 화면에 바로 보이고, W1으로 최신 프로필·알림 설정을 받아 판정 기준만 바꿔 W2로 저장한다.
3. 저장되면 「저장했어요. 다음 측정부터 적용돼요.」를 보인다.
4. 측정을 시작하면 이 값을 S1 `policy`로 보낸다. 진행 중인 측정은 시작할 때의 값을 그대로 쓴다.

| 항목 | 고르는 값 | 서버 허용 범위 |
|---|---|---|
| 얼마나 민감하게 | 느긋하게 20점·보통 30점·꼼꼼하게 40점, 세밀 조정 5~50점 | 임계값 0 초과 1 이하(점수 → 1 − 점수/100) |
| 알리기까지 기다리는 시간 | 3·5·10초, 세밀 조정 1~10초(0.5초 단위) | 0 초과 10초 이하, 0.5초 단위 |
| 다시 알리는 간격 | 1·2·3분, 세밀 조정 15~180초(5초 단위) | 1~180초 |
| 정상 복귀 유지 시간 | 세밀 조정 1~10초(0.5초 단위) | 0 초과 10초 이하, 0.5초 단위 |

**예외 / 제한사항**

- 저장에 실패하면 안내를 보이고 W1으로 서버 값을 다시 받아 되돌린다.
- 연달아 바꾸면 마지막 요청의 결과만 쓴다.
- 판정 기준은 기기에 남기지 않는다. 다른 기기에서 바꾼 직후라면 측정하기 화면을 다시 열 때 W1으로 맞춰진다. 맞춰지기 전에 시작하면 서버가 409로 거절한다.
- 개발자 계정은 화면 안에서만 바뀐다.

**비고**

- 코드: [LocalServiceApp.tsx](../../../frontend/src/app/LocalServiceApp.tsx) `saveRules`, [serverWorkspace.ts](../../../frontend/src/features/storage/serverWorkspace.ts), [SettingsPage.tsx](../../../frontend/src/pages/SettingsPage.tsx).

### 알림 설정

**선행조건**

- 로그인한 상태다.

**트리거**

- 측정 화면의 소리 버튼, 설정 화면의 「다른 창을 볼 때 팝업」을 바꾼다.

**동작**

1. 소리는 측정 화면에서 켜고 끈다. 브라우저 정책 때문에 사용자가 직접 켜야 소리가 난다.
2. 데스크톱 앱은 설정에서 앱 밖 알림창(우측 하단)을 켜고 끈다. 웹에서는 이 항목이 꺼져 있다.

**예외 / 제한사항**

- 설정 화면의 「자세 알림」은 켜짐 표시만 있고 끌 수 없다. 누르면 「화면 알림은 그대로 둬요. 소리만 측정 화면에서 끌 수 있어요.」를 보인다.
- 서버에는 자세 알림 켜기(`alerts_on`)가 있고 세션을 만들 때 복사된다. 앱은 이 값을 바꾸지 않는다.

### 카메라 준비

**선행조건**

- 로그인한 상태다. 웹은 localhost 또는 HTTPS 주소여야 카메라를 쓸 수 있다.

**트리거**

- 측정하기 화면에서 카메라를 켜거나, 설정에서 메인 카메라를 고른다.

**동작**

1. 카메라 권한을 요청하고 640×480 영상을 연다. 4:3이 아니게 열리면(16:9 카메라) 4:3 필수로 다시 열어 잘라서 받고, 4:3을 못 주면 「이 카메라는 4:3 화면으로 쓸 수 없어요…」를 띄운다([ADR 0048](../../decisions/0048-camera-picture-is-four-by-three.md)).
2. MediaPipe 자세 추적 모델을 불러온다(GPU 우선, 안 되면 CPU).
3. 고른 카메라는 이 기기에 기억한다.

**예외 / 제한사항**

| 상황 | 앱 안내 |
|---|---|
| 권한 거부 | 「카메라 권한이 꺼져 있어요. 사이트 권한에서 카메라를 허용해 주세요.」 |
| 카메라 없음 | 「연결된 카메라가 없어요. 카메라를 연결해 주세요. 기록은 카메라 없이도 볼 수 있어요.」 |
| 다른 앱이 사용 중 | 「다른 앱이 카메라를 쓰고 있을 수 있어요. 그 앱을 닫고 다시 시도해 주세요.」 |
| 지원하지 않는 환경 | 「이 브라우저에서는 카메라를 쓸 수 없어요. localhost 또는 HTTPS 주소를 Chrome으로 열어 주세요.」 |
| 모델을 못 불러옴 | 「카메라나 자세 추적 모델을 불러오지 못했어요. 연결을 확인하고 다시 시도해 주세요.」 |

**비고**

- 그래픽 가속이 꺼진 브라우저에서는 안내 팝업을 띄운다([frontend README](../../../frontend/README.md)). 코드: [errors.ts](../../../frontend/src/features/camera/errors.ts).

### 기준 자세 등록

**선행조건**

- 카메라가 켜져 있고 얼굴과 양 어깨가 보인다.

**트리거**

- 등록한 자세가 없을 때 측정하기를 연다. 설정의 「다시 등록」, 회원가입 3단계를 누른다.

**동작**

1. 얼굴과 어깨가 보이면 3·2·1을 센 뒤 촬영한다.
2. 판정 가능한 프레임만 3초 동안 모은다. 쓸 수 없는 프레임이나 1초 넘는 빈틈이 있으면 처음부터 다시 센다.
3. 3초가 지나고 20장 이상이면 관절 9개의 평균을 서버에 등록한다(B1). 재시도에는 같은 `registration_id`를 쓴다.
4. 등록하면 측정하기에서는 바로 측정을 시작하고, 설정·회원가입에서는 시작하지 않는다.
5. 앱을 열거나 로그인하면 B2로 현재 기준 자세를 받는다.

**예외 / 제한사항**

- 15초 안에 끝나지 않으면 실패를 안내한다.
- 평균 좌표가 화면 밖이면 보내지 않고 화면 안으로 오라고 안내한다.
- B2가 연결·서버 오류로 실패하면 자동으로 등록하지 않고 「다시 불러오기」, 「새로 등록」을 고르게 한다.

**비고**

- 3초 평균은 앱이 낸다(10/20 전체 회의, [ADR 0021](../../decisions/0021-app-sends-information-server-judges.md)). 절차는 [연동 명세 5.4](api-ws-spec.md). 코드: [landmarkCapture.ts](../../../frontend/src/features/baseline/landmarkCapture.ts), [usePostureRegistration.ts](../../../frontend/src/features/camera/usePostureRegistration.ts).

### 측정 시작

**선행조건**

- 카메라가 켜져 있고 추적 품질이 충분하다. 기준 자세가 등록돼 있다.
- 서버 확인을 기다리는 이전 결과가 없다.

**트리거**

- 측정하기 화면에서 「측정 시작」을 누른다. 기준 자세를 막 등록했으면 저절로 시작한다.

**동작**

1. 새 세션 UUID와 판정 기준·기준 자세로 세션을 만든다(S1). 응답을 받은 순간이 측정 시간 0이다.
2. WebSocket에 연결해 `hello`를 보내고 5초 안에 `ready`를 받는다.
3. `ready.started_at`(서버 시각)을 기록의 시작 시각으로 쓴다.
4. 측정 화면으로 간다.

**예외 / 제한사항**

| 상황 | 앱 안내 |
|---|---|
| 카메라·기준 자세가 준비 안 됨 | 「카메라 연결과 기준 등록을 완료한 뒤 시작해 주세요.」 |
| 기준 자세 없음 | 「기준 자세가 없어요. 자세를 먼저 등록해 주세요.」 |
| 이전 결과를 서버에서 확인 중 | 「이전 결과를 서버에서 확인하고 있어요. 확인 후 새 측정을 시작해 주세요.」 |
| 설정·기준 자세가 서버와 다름(409) | 「설정이나 기준 자세가 바뀌었어요. 다시 확인한 뒤 측정해 주세요.」 |
| `ready`가 5초 안에 안 옴 | 측정을 시작하지 못했다고 안내한다. 다시 할 때는 새 세션으로 S1부터 |

**비고**

- 응답이 없으면 S1을 같은 UUID·같은 본문으로 다시 보낸다. 코드: [useSessionPersistence.ts](../../../frontend/src/features/session/useSessionPersistence.ts) `start`, [LiveSession.ts](../../../frontend/src/features/session/live/LiveSession.ts) `start`.

### 쉬기·재개

**선행조건**

- 측정 중이다.

**트리거**

- 측정 화면에서 「잠시 쉬기」 또는 「측정 재개」를 누른다.

**동작**

1. 쉬는 동안 좌표 대신 `phase: "rest"` 빈 구간을 보낸다. 화면에는 「쉬는 중」이 보인다.
2. 쉰 시간은 서버가 유효 측정 시간에서 뺀다(`PAUSE`). 쉬면 진행 중이던 붕괴 사건은 중단으로 끝난다.
3. 「측정 재개」를 누르면 다시 좌표를 보낸다. 카메라 영상이 들어오고 있어야 버튼이 켜진다.

**예외 / 제한사항**

- 쉬는 중 카메라 영상이 멈추면 자리 비움(`away`)으로 바꾼다.
- 쉬기 10분 자동 종료는 없다(「쉬기 자동 종료」).

### 측정 종료

**선행조건**

- 측정 중이다.

**트리거**

- 「측정 종료」를 누른다. 데스크톱 작은 카메라 창의 X를 누른다. 쓰던 카메라가 빠지거나 영상 크기가 바뀐다.

**동작**

1. `end`를 보내고 「측정을 마무리하고 있어요」를 보인다.
2. 10초 안에 `closed(ended)`가 오면 서버가 확정한 결과로 종료 화면을 보인다.
3. 10초가 지나도 안 오면 S4로 결과를 받는다. 그것도 실패하면 마지막 `progress`로 보인다.
4. 결과를 서버 확인 전 결과로 보관하고 R1로 저장을 확인한다(「측정 결과 보관」).

**예외 / 제한사항**

- 카메라가 빠지면 「쓰던 카메라가 빠져 측정을 마쳤어요. 그때까지의 기록은 저장했어요.」
- 영상 크기가 바뀌면 「카메라 영상 크기가 바뀌어 측정을 마쳤어요. 그때까지의 기록은 저장했어요.」
- 측정 중 창을 닫으려 하면 브라우저가 확인을 묻는다.

### 실시간 판정 수신

**선행조건**

- 측정 중이다(`ready`를 받음).

**트리거**

- 카메라 프레임이 들어올 때마다.

**동작**

1. 프레임마다 관절 9개 좌표를 구간 하나로 보낸다(`features`).
2. 서버는 구간마다 `observation`을 보내고, 사건이 있으면 `decision`과 `alert`, 이어서 `ack`와 `progress`를 보낸다.
3. 앱은 `sequence`가 화면에 있는 결과보다 작거나 같으면 늦은 결과로 보고 버린다.

**예외 / 제한사항**

- 서버의 추론·DB가 잠시 멈추면 `stalled`가 와서 「분석이 잠시 멈췄어요. 측정은 계속돼요.」를 보인다. 연결은 유지된다.
- 재연결과 재전송은 없다(「연결 끊김 처리」).

**비고**

- 서버 안쪽을 Kafka로 바꿔도([계획 0031](../../plans/active/0031-realtime-kafka-transition.md)) 앱의 연결과 메시지 형식은 그대로다. 메시지 형식은 [연동 명세](api-ws-spec.md) 5장·7장.

### 측정 중 상태 표시

**선행조건**

- 측정 중이다.

**트리거**

- `observation`·`decision`을 받을 때, 앱이 판정 불가 프레임을 볼 때.

**동작**

| 화면 상태 | 문구 | 조건 |
|---|---|---|
| 첫 판정 전 | 자세를 똑바로 해주세요 | 사람이 잡혔고 아직 결과가 없음 |
| 바른 자세 | 바른 자세예요 | `posture: good`, 열린 사건 없음 |
| 주의 | 자세가 흐트러지고 있어요 + 붕괴 게이지 | `posture: bad`, 확정 전. 게이지 = `hold_ms` ÷ 정책 hold 시간 |
| 확정 경고 | 자세가 흐트러졌어요 | `decision(collapse_confirmed·reminder)` 뒤 해제 전 |
| 회복 중 | 자세가 흐트러졌어요 + 회복 게이지 | 확정 경고 중 `posture: good`. 게이지 = `recovery_ms` ÷ 정책 회복 시간 |
| 판정 불가 | 자세를 확인할 수 없어요 | 판정 불가 처리 참고 |

- 점수는 `100 × (1 − collapse_probability)`이고 판정 가능할 때만 그린다. 앱은 시간을 세지 않고 서버 값만 그린다.

**비고**

- 코드: [LiveSessionPage.tsx](../../../frontend/src/features/session/live/LiveSessionPage.tsx). 결정은 [ADR 0021](../../decisions/0021-app-sends-information-server-judges.md) 4절 8번.

### 자세 경고 알림

**선행조건**

- 측정 중이고 세션의 자세 알림이 켜져 있다(서버가 `alert`를 보낼 때만).

**트리거**

- 서버의 `alert`(`collapse_confirmed` 첫 알림, `reminder` 재알림)를 받는다.

**동작**

1. 토스트를 3초 보인다. 첫 알림은 「흐트러진 자세가 이어지고 있어요.」, 재알림은 「흐트러진 자세가 이어져 다시 알려드려요.」
2. 소리를 켰으면 알림음을 낸다.
3. 데스크톱 앱이면 우측 하단 알림창을 띄운다.
4. 카메라 테두리를 강조한다.

**예외 / 제한사항**

- 재알림 간격은 서버가 판정 기준(기본 60초)으로 센다. 앱은 거르지 않는다.
- 소리가 재생되지 않으면 「소리를 재생하지 못했습니다. 소리 켜기를 다시 눌러 주세요.」

### 판정 불가 처리

**선행조건**

- 측정 중이다.

**트리거**

- 어깨가 하나라도 안 보이거나, 관절 값이 없거나, 사람이 없다. 또는 서버가 `valid: false`를 보낸다.

**동작**

1. 앱이 판정할 수 없는 프레임은 좌표 없이 `{t_ms, p: null, valid: false}`만 보내고, 서버를 기다리지 않고 「자세를 확인할 수 없어요」를 보인다.
2. 서버만 아는 판정 불가(고개 돌림, 코·어깨 정확도 0.65 미만, 화면 가장자리, 어깨 폭 10% 미만)는 `observation.valid: false`로 온다. 고개 돌림이면 「고개를 돌린 동안은 판정하지 않아요」, 그 밖은 「얼굴과 어깨가 보이지 않아요」.
3. 판정 불가 시간은 유효 측정 시간에서 빠진다.

**예외 / 제한사항**

- 판정 불가와 자리 비움이 30분 이어지면 서버가 저장하고 끝낸다. 「자세를 확인할 수 없는 상태가 30분 이어져 측정을 마쳤어요. 그때까지 저장됐어요.」

### 자리 비움 처리

**선행조건**

- 측정 중이다.

**트리거**

- 카메라 영상이 1초 넘게 들어오지 않는다(예: 다른 USB를 꽂음).

**동작**

1. 측정을 멈추고 `phase: "away"` 빈 구간을 보낸다.
2. 「인식 중입니다. 3초 후에 측정 재개 버튼을 눌러주세요.」를 보인다.
3. 영상이 돌아오면 「측정 재개」 버튼이 켜진다.

**예외 / 제한사항**

- 자리 비움 시간은 유효 측정 시간에서 빠진다(`ABSENCE`). 판정 불가와 합쳐 30분 이어지면 서버가 끝낸다.

### 연결 끊김 처리

**선행조건**

- 측정 중이다.

**트리거**

- WebSocket이 끊긴다. 앱을 닫거나 새로 고친다. 서버가 끝난다.

**동작**

1. 다시 연결하지 않고 그 측정을 끝낸다.
2. 서버는 마지막으로 받은 구간 끝에서 세션을 끝내고 저장한다.
3. 화면을 막는 안내로 「서버 연결이 끊겨 측정을 마쳤어요. 끊기기 전까지 저장됐어요.」를 보이고, 마지막 `progress`로 종료 화면을 보인다.

**비고**

- 결정은 [ADR 0024](../../decisions/0024-session-ends-on-lost-connection.md).

### 자정 넘김 처리

**선행조건**

- 측정 중에 KST 자정이 지난다. 서버의 자정 넘김 설정이 켜져 있다.

**트리거**

- 서버가 `decision(session_ended)`에 이어 `session_rollover`를 보낸다.

**동작**

1. 이전 세션을 기록으로 닫고, 서버가 만든 새 세션 ID와 시작 시각(자정)으로 측정을 이어 간다.
2. S1과 `hello`는 다시 하지 않는다. 시간과 순번은 연결 기준으로 계속 보낸다.
3. 「자정이 지나 새 측정으로 이어졌어요.」를 보인다.

**예외 / 제한사항**

- 서버가 새 세션을 만들지 못하면 `closed(day_changed)`. 「자정이 지나 측정을 마쳤어요. 자정 전까지 저장됐어요. 새 측정을 시작해 주세요.」
- 운영 서버의 자정 넘김 설정은 아직 꺼져 있어, 지금은 자정을 넘긴 측정이 나뉘지 않는다(FE 제안서 1.0).

**비고**

- 결정은 [ADR 0029](../../decisions/0029-midnight-cut-and-server-time.md).

### 쉬기 자동 종료

**선행조건**

- 쉬는 중이다.

**트리거**

- 쉬기가 오래 이어진다(10/20 계획은 10분, 30분을 제안 중).

**동작**

- 없음. 서버와 앱 모두 구현이 없다.

**비고**

- 구현 전. FE 의견은 판정 불가·자리 비움 30분(`unmeasurable_timeout`)과 같은 방식으로 서버가 쉬기 시간을 세어 30분이면 끝내고 새 사유를 보내는 것이다. BE와 정한다(FE 제안서 BE-13).

### 측정 결과 보관

**선행조건**

- 서버 계정으로 측정 중이거나 측정이 끝났다.

**트리거**

- 측정 중 `progress`를 받을 때(1초에 한 번까지), 측정이 끝날 때.

**동작**

1. 결과를 서버 확인 전 결과로 이 기기의 계정별 키(`posegood.account.v3.{user_id}.pending-results`)에 보관한다.
2. 측정이 끝나면 R1으로 저장을 확인한다. 확인되면 보관한 결과를 지운다.
3. 측정 중이 아닐 때는 15초마다 R1으로 다시 확인한다.
4. 확인 전 결과는 기록에 섞지 않고 「서버 저장 확인을 기다리는 기록 N개」와 「저장 확인 다시 시도」 버튼으로 알린다.

**예외 / 제한사항**

- 확인 전 결과가 있으면 새 측정을 시작하지 않는다.
- 보관에 실패하면 「결과를 이 기기에 보관하지 못했어요. 창을 닫지 말고 저장 공간을 확인해 주세요.」

**비고**

- 결정은 [ADR 0027](../../decisions/0027-today-records-from-collected-server-results.md). 코드: [serverRecords.ts](../../../frontend/src/features/storage/serverRecords.ts).

### 기록 조회

**선행조건**

- 로그인한 상태다.

**트리거**

- 로그인하거나 계정이 바뀔 때, 측정이 끝났을 때, 15초마다(측정 중 아닐 때). 「오늘」·「기록」 화면을 연다.

**동작**

1. R1으로 기록 전체를 받아 메모리에 둔다. 오늘 세션도 R1에서 온다.
2. 「오늘」 화면은 오늘 세션 목록과 요약을, 「기록」 화면은 달력과 날짜별 상세를 보인다.
3. 날짜는 서버 시각의 KST로 나눈다.

**예외 / 제한사항**

- 서버의 기록 하나 조회(R1b)는 없어 상세도 R1 목록에서 찾는다.
- 기록은 기기에 저장하지 않으므로 서버에 연결해야 볼 수 있다.

### 기간 통계

**선행조건**

- 로그인한 상태다.

**트리거**

- 「기록」 화면을 연다.

**동작**

1. R1 기록을 날짜별로 집계해 최근 7일·30일의 유지율과 측정 시간, 1년 잔디를 보인다.
2. 유지율 = 바른 자세 시간 합 ÷ 유효 측정 시간 합.

**예외 / 제한사항**

- 서버 일별 통계(T1)는 없다. 생기면 어제까지는 T1, 오늘은 R1로 하고 같은 날짜를 겹쳐 더하지 않는다.

**비고**

- 코드: [recordsSource.ts](../../../frontend/src/features/history/recordsSource.ts), [RecordCalendar.tsx](../../../frontend/src/features/history/RecordCalendar.tsx).

### 기록 삭제

**선행조건**

- 로그인한 상태다.

**트리거**

- 없음. 앱에 지우는 화면이 없다.

**동작**

- 서버 API(R3)는 있다. 세션과 사건·알림·제외 구간을 지운다.

**예외 / 제한사항**

- HDFS에 적재된 기록은 지울 수 없다(409 `CONFLICT`). 화면을 만들면 「지금은 지울 수 없어요」로 안내한다.

**비고**

- 구현 전.

### 화면 구성과 이동

**선행조건**

- 로그인한 상태다.

**트리거**

- 왼쪽 메뉴를 누른다.

**동작**

| 메뉴 | 화면 |
|---|---|
| 측정하기 | 카메라, 기준 자세 등록, 측정 |
| 오늘 | 오늘 세션 목록과 요약 |
| 기록 | 달력, 날짜별 상세, 최근 흐름 |
| 설정 | 화면 테마, 알림, 판정 기준, 기준 자세, 컴퓨터를 켤 때, 계정 |

- 측정 중 다른 화면으로 가도 측정과 카메라는 이어진다.
- 홈은 로그인 직후 첫 화면이고, 프로필은 설정의 계정 메뉴에서 연다.

**예외 / 제한사항**

- 계정 변경을 처리하는 동안에는 이동하지 않는다. 「계정 변경을 확인한 뒤 이동해 주세요.」

### 테마

**선행조건**

- 없음.

**트리거**

- 설정의 화면 테마에서 고른다.

**동작**

1. 7가지 테마(초록, 살구, 오션, 틸, 차콜, 블랙, 블러플) 중 하나를 고른다.
2. 이 기기에 저장하고 바로 적용한다. 데스크톱 앱은 아이콘과 알림창에도 적용한다.

**예외 / 제한사항**

- 서버에 저장하지 않는다. 기기마다 따로 정한다.

**비고**

- 코드: [theme.ts](../../../frontend/src/features/appearance/theme.ts).

### 작은 카메라 창

**선행조건**

- 데스크톱 앱이고 카메라가 켜져 있다.

**트리거**

- 측정하기 화면에서 작은 창을 연다.

**동작**

1. 항상 위에 뜨는 테두리 없는 작은 창에 카메라를 보여 준다.
2. 다른 화면으로 가도 창은 유지된다. 자세 경고 중에는 창에도 상태가 보인다.
3. 측정 중 창의 X를 누르면 측정을 끝낸다.

**예외 / 제한사항**

- 웹에는 없다(10/26 결정, [ADR 0017](../../decisions/0017-desktop-app-shell-and-redesign.md)).

**비고**

- 코드: [useCameraWindow.ts](../../../frontend/src/features/camera/useCameraWindow.ts), [camera-window.cjs](../../../frontend/electron/camera-window.cjs).

### 컴퓨터 시작 시 실행

**선행조건**

- 데스크톱 앱이고 운영체제가 시작 프로그램 등록을 지원한다.

**트리거**
