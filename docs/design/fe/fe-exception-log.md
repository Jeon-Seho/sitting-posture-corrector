# FE 예외 처리 모음

> 작성자: klaod-tech(FE) · 작성: 2026-11-13
> **이 문서의 역할:** 앱이 오류·예외 상황에서 띄우는 화면과 문구를 한곳에 모은다. **사용자 입장에서 할 수 있는 것**으로 크게 나누고(A~D), 그 안을 **그림 있는 오류 화면**과 **그림 없는 안내**로 다시 나눈다. 모든 표는 같은 칸이다: **언제**(사용자가 무엇을 하다가), **무슨 일**, **어떻게 보이나**(표시 방식과 자리), **제목 / 설명**(화면에 나오는 문구), **버튼**(사용자가 다음에 누를 것). C는 **사용자에게 생기는 일**을 더 적는다. 문구는 코드에서 그대로 옮겼으므로 코드를 바꾸면 여기도 고친다. 아직 정하지 않은 문제는 [FE 예외 처리 방안](fe-exception-handling-plan.md), 오류 코드별 규칙은 [연동 명세](api-ws-spec.md) 2장이다.

## 분류

| 분류 | 뜻 |
|---|---|
| **A. 사용자가 해결할 수 있음** | 문구대로 하면 풀린다(다시 로그인, 카메라 권한, 자세 고치기 등) |
| **B. 기다리거나 다시 하면 됨** | 사용자 잘못이 아니고 일시적이다(서버·인터넷이 잠깐 안 됨) |
| **C. 사용자가 알 수도 고칠 수도 없음** | 앱이나 서버가 고쳐야 한다. 다시 해도 같을 수 있고, 일부는 사용자를 막아 버린다 |
| **D. 정해진 규칙에 따른 안내** | 오류가 아니다. 규칙대로 끝났거나 이어졌음을 알린다 |

## 표시 방식

| 방식 | 생김새 | 코드 |
|---|---|---|
| **전체 오류 화면** | 앱 전체를 그림 오류 화면이 차지한다(그림·제목·설명·버튼, 오류 코드는 버튼 아래 작은 글씨) | `pages/ErrorPage.tsx`, 데스크톱은 `public/offline.html` |
| **본문 오류 화면** | 왼쪽 메뉴는 그대로 두고 본문 자리를 그림 오류 화면이 차지한다. 다른 메뉴로는 갈 수 있다 | `ErrorPage` `inline` |
| **측정 자리 오류 화면** | 측정 화면 자리를 그림 오류 화면이 차지한다 | `ErrorPage` `inline` |
| **측정 실패 화면** | 측정 화면 자리에 그림 없이 작은 제목 「측정」, 큰 제목 「측정을 시작하지 못했어요」, 사유 한 줄, 「다시 준비하기」 버튼 | `LiveSessionPage` `phase === 'failed'` |
| **위쪽 알림 카드** | 화면 위 가운데에 떠서 다른 화면 위에 겹치는 작은 카드. 제목 없이 문구 한 줄, 경고(!)·확인 아이콘과 닫기(X) 버튼 | `ServiceScreens` `service-notice` |
| **카메라 칸 겹침** | 측정 화면의 카메라 칸 안에만 겹쳐 뜬다. 화면 배치는 그대로고 메뉴·오른쪽 칸도 그대로 보인다 | `LiveSessionPage` `stage-notice`·`EndingNotice` |
| **대화상자** | 브라우저나 운영체제의 기본 확인 창 | `beforeunload`, `electron/main.cjs` |
| **카메라 상자 글자** | 큰 카메라 상자 안에 제목 「카메라가 꺼져 있어요」, 그 아래 문구, 「다시 연결」 버튼 | `components/CameraStage.tsx`, `pages/SetupPage.tsx` |
| **화면 안 글자** | 그 화면의 정해진 자리에 글자로만 바뀐다(측정 화면 상태 제목·안내, 연결 상태 칸, 결과 아래 한 줄, 입력칸 아래 등). 겹치지 않는다 | 화면마다 |
| **화면 안 띠** | 그 화면 위쪽에 들어가는 색 있는 안내 띠. 겹치지 않는다 | `notice` |
| **자세 등록 화면 제목·설명** | 측정하기 준비 화면(회원가입 3단계, 설정의 「다시 등록」도 같은 화면) 맨 위의 제목과 그 아래 설명이 바뀐다. 다음 버튼은 카메라 상자 아래나 제목 오른쪽에 나온다 | `pages/SetupPage.tsx` `headline` |

그림은 lellon0403이 그린 오류 그림(`public/illustrations/themes/*-error-*.webp`)이다. 원칙: 사용자 탓을 하지 않는다, 다음에 할 일은 하나, 기록이 저장됐는지 같은 사실은 정확하게.

## A. 사용자가 해결할 수 있음

### A-1. 그림 있는 오류 화면

| 언제 | 무슨 일 | 어떻게 보이나 | 제목 / 설명 | 버튼 |
|---|---|---|---|---|
| 주소를 잘못 입력하거나 없어진 링크를 열 때 | 그런 화면이 없음 | 전체 오류 화면, 404 돋보기 | 페이지를 찾을 수 없어요 / 주소를 확인하거나 홈으로 돌아가 주세요. | 없음 |
| 「오늘」·「기록」 또는 「측정하기」·「설정」을 열 때 | 기기의 인터넷이 끊겨 그 화면의 자료(기록 R1·설정 W1)를 못 받음 | 본문 오류 화면, 502 뽑힌 케이블 | 인터넷 연결을 확인해 주세요 / 연결되면 자동으로 다시 불러올게요. | 다시 시도(인터넷이 돌아오면 자동) |

## B. 기다리거나 다시 하면 됨

### B-1. 그림 있는 오류 화면

| 언제 | 무슨 일 | 어떻게 보이나 | 제목 / 설명 | 버튼 |

「지금은 측정을 시작할 수 없어요」가 뜨는 경우. 모두 측정이 ④ `ready`까지 가지 못해 좌표를 한 장도 보내지 못했다. 그래서 결과 화면·기록이 생기지 않는다(저장할 측정이 처음부터 없음).

```
「측정 시작」 → ① S1(측정 세션 만들기) → ② WS 연결 → ③ hello → ④ ready → 좌표를 보내며 측정
```

| 무슨 일 | 코드 |
|---|---|
| ① S1이 5xx | `LiveSession.start` |
| ① S1에 응답이 없음(네트워크) | `LiveSession.start` |
| 측정 토큰을 받다 네트워크 실패(로그인은 된 상태) | `LiveSession.start` |
| ② WS를 열지 못함 | `LiveSession.start` |
| ④ 전에 연결이 끊김 | `LiveSession.closedBySocket` |
| ④ `ready`가 5초 안에 안 옴 | `LiveSession.start` 타이머 |
| ④ 대신 `closed(session_lost)`가 옴(kafka 모드: 서버가 Kafka에 시작을 못 씀) | `LiveSession.handle` |

① S1이 성공했다면 서버에 데이터 없는 빈 측정 세션이 남는다. 앱은 그 세션을 다시 쓰지 않고, 서버가 그 약속을 근거로 시간이 지나면 닫는다([FE 제안서](fe-server-proposal.md) 요구 8).
