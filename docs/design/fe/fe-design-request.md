# 오류·연결 화면 디자인 요청

> 작성자: klaod-tech(FE) · 작성: 2026-11-10 · 받는 사람: lellon0403(화면)
> **이 문서의 역할:** 서버 오류, 연결 실패, 연결 중 같은 화면을 새로 그려 달라는 요청이다. 무엇을 띄우는지와 문구·버튼은 FE가 정했고, 그림·배치·색은 디자인에서 정한다. 동작 규칙은 [FE 기능 명세](fe-feature-spec.md), 오류 코드별 앱 동작은 [연동 명세](api-ws-spec.md) 2장이다.

## 1. 원칙

1. **사용자 탓을 하지 않는다.** 서버 오류를 보고 「내가 뭘 잘못 눌렀나?」 하고 당황하지 않게 한다. 「사용자 잘못이 아니에요」를 분명히 쓴다.
2. **다음에 할 일은 하나만.** 버튼은 많아야 두 개이고, 가장 할 만한 것을 주 버튼으로 둔다.
3. **오류 코드는 작게.** 「500」 같은 숫자를 제목으로 크게 쓰지 않는다. 문의할 때 쓸 수 있게 아래에 작은 글씨로만 둔다.
4. **분위기는 가볍게, 그러나 사실대로.** 친근한 그림과 말투는 좋지만, 기록이 저장됐는지처럼 사실을 말하는 문장은 정확해야 한다(3장 「기록 안전 문구」).
5. **메뉴는 남긴다.** 로그인한 뒤에는 왼쪽 메뉴를 그대로 두고 본문 자리에만 띄워, 다른 화면으로 갈 수 있게 한다. 로그인 전·앱 시작 때만 전체 화면이다.
6. **측정 중에는 띄우지 않는다.** 측정 중 오류는 이미 처리가 있다(「분석이 잠시 멈췄어요」 안내, 연결 끊김 안내창). 이 화면들은 측정 밖에서만 쓴다.

## 2. 그릴 화면

| # | 화면 | 띄우는 때 | 범위 | 지금 상태 |
|---|---|---|---|---|
| A | 연결하는 중 | 데스크톱 앱을 켜고 서버 화면을 불러오는 동안(보통 1초 안, 최대 10초) | 데스크톱 앱, 전체 화면 | 임시 화면 있음(`frontend/public/offline.html`) |
| B | 서버에 연결할 수 없어요 | 데스크톱 앱이 10초 안에 서버 화면을 못 열 때. 10초마다 자동으로 다시 시도 | 데스크톱 앱, 전체 화면 | 임시 화면 있음(같은 파일) |
| C | 서버 문제(5xx) | 서버가 500번대로 답하고, 앱이 1·2·4초 간격으로 3번 다시 보내도 안 될 때 | 웹·데스크톱, 본문 자리 | 없음. 지금은 화면마다 한 줄 문구 |
| D | 인터넷 끊김 | 기기가 오프라인일 때(서버 문제와 구분) | 웹·데스크톱, 본문 자리 | 없음 |
| E | 예상 못 한 요청 오류(4xx) | 아래 「그리지 않는 것」에 없는 400번대 | 웹·데스크톱, 본문 자리 | 없음 |
| F | 앱 오류 | 앱 코드 오류로 화면을 그리지 못할 때 | 웹·데스크톱, 전체 화면 | 없음. 지금은 흰 화면 |

**그리지 않는 것(이미 화면 안에서 안내함):** 비밀번호 틀림(401), 이미 쓰는 이메일(409), 탈퇴한 계정(403), 기준 자세 없음(404 → 자세 등록으로), 설정이 서버와 다름(409), 로그인 만료(401 → 로그인 화면). 이들은 정상 흐름이라 입력칸 아래 문구로 둔다.

## 3. 화면별 내용

문구는 FE 초안이다. 말투는 바꿔도 되지만 뜻은 유지해 주세요.

### A. 연결하는 중

| 요소 | 내용 |
|---|---|
| 그림 | 로딩 표시(지금은 원형 스피너). 앱 시작 화면이라 브랜드 느낌이 나면 좋다 |
| 제목 | 연결하는 중이에요 |
| 설명 | 잠시만 기다려 주세요. |
| 버튼 | 없음 |

### B. 서버에 연결할 수 없어요

| 요소 | 내용 |
|---|---|
| 그림 | 서버나 연결이 끊긴 모습(참고: 고장 난 서버, 우주에서 길 잃은 우주인 같은 가벼운 그림) |
| 제목 | 서버에 연결할 수 없어요 |
| 설명 | 사용자 잘못이 아니에요. 인터넷 연결을 확인하거나 잠시 뒤 다시 시도해 주세요. / 연결되면 자동으로 다시 열어요. |
| 버튼 | 지금 다시 시도 |

### C. 서버 문제(5xx)

| 요소 | 내용 |
|---|---|
| 그림 | B와 같은 계열 |
| 제목 | 잠시 서버에 문제가 생겼어요 |
| 설명 | 사용자 잘못이 아니에요. 잠시 뒤 다시 시도해 주세요. |
| 기록 안전 문구 | 측정·기록 화면에서 난 오류일 때만 「측정한 기록은 저장돼 있어요」. 설정 저장 같은 다른 작업이 실패했을 때는 넣지 않는다 |
| 버튼 | 다시 시도(주), 홈으로 |
| 작은 글씨 | 오류 코드와 시각(예: 「오류 503 · 11/10 14:32」) |

### D. 인터넷 끊김

| 요소 | 내용 |
|---|---|
| 그림 | 와이파이·신호가 끊긴 모습 |
| 제목 | 인터넷 연결을 확인해 주세요 |
| 설명 | 연결되면 자동으로 다시 불러올게요. |
| 버튼 | 다시 시도 |

서버 문제(C)와 문구가 다른 이유: 인터넷이 끊긴 건 사용자 쪽 상황이라 「서버 문제」라고 하면 틀린 안내가 된다. 휴대폰에서는 이쪽이 더 흔하다.

### E. 예상 못 한 요청 오류(4xx)

| 요소 | 내용 |
|---|---|
| 그림 | C보다 가벼운 그림 또는 아이콘만 |
| 제목 | 요청을 처리하지 못했어요 |
| 설명 | 화면을 새로 고친 뒤 다시 해 주세요. |
| 버튼 | 새로 고침(주), 홈으로 |
| 작은 글씨 | 오류 코드 |

「입력을 확인해 주세요」처럼 사용자 탓으로 읽히는 문구는 피한다. 400번대에는 앱이 잘못된 요청을 보낸 경우(앱 버그)도 들어온다.

### F. 앱 오류

| 요소 | 내용 |
|---|---|
| 제목 | 화면을 불러오지 못했어요 |
| 설명 | 새로 고치면 대부분 해결돼요. 계속되면 알려 주세요. |
| 버튼 | 새로 고침 |

## 4. 디자인 조건

- **테마:** 앱 테마 7가지(초록, 살구, 오션, 틸, 차콜, 블랙, 블러플)에서 어울려야 한다. 지금 그림은 4가지 색 묶음(`green`·`peach`·`black`·`discord`)으로 `frontend/public/illustrations/themes/{색}-{종류}.webp`에 있고 `ThemeIllustration`이 테마에 맞춰 고른다. 새 그림도 같은 방식으로 종류를 더해 주면 된다(예: `server`, `offline`).
- **A·B는 테마를 모를 수 있다.** 데스크톱 앱 안에 든 단독 HTML이라 사용자가 고른 테마를 읽기 전에 뜬다. 기본(밝은) 한 가지로 그리거나, 밝음·어두움 두 가지면 충분하다.
- **크기:** 데스크톱 창 최소 1180×760에서 한 화면에 들어가야 한다. 휴대폰 앱(Kotlin, [휴대폰 계획](fe-mobile-records-plan.md))도 같은 문구와 그림을 쓸 예정이라 폭 360~430에서도 무너지지 않는 배치면 좋다.
- **그림 저작권:** 참고 그림(고장 난 서버, 우주인 등)은 분위기만 참고하고 새로 그린다. 남의 그림을 그대로 쓰지 않는다.
- **글꼴·색:** 앱과 같은 Pretendard와 테마 색을 쓴다.

## 5. 정할 것

1. **문의처:** C·F의 「계속되면 알려 주세요」에 둘 연락처(팀 이메일 등). 정하기 전에는 넣지 않는다.
2. **오류 코드 노출:** 작은 글씨로 둘지, 아예 뺄지.
3. **D를 C와 합칠지:** 그림을 하나로 쓰고 문구만 바꿔도 된다.

## 6. 받은 것과 연결 (11/10)

lellon0403이 PR #108로 그림 7종(코드별 403·404·500·502·503·504·505)과 미리보기 페이지를 보냈다. 화면은 코드별로 나누지 않고 **다섯 가지**로 묶는다(klaod-tech 결정, 11/10). 비밀번호 틀림 같은 예상한 오류는 대응이 다 있으므로 400번대·500번대는 각각 화면 하나로 묶는다. 그림은 새로 그리지 않고 뜻이 맞는 것을 골라 쓴다.

| 화면 | 그림 | 띄우는 곳 |
|---|---|---|
| 연결하는 중 (A) | 504 모래시계 | `public/offline.html` 로딩 |
| 서버에 연결할 수 없어요 (B) | 502 뽑힌 케이블 | `public/offline.html?state=offline` |
| 500번대 (C) | 503 쉬는 서버 | 본문 자리 |
| 인터넷 끊김 (D) | 502 뽑힌 케이블 | 본문 자리 |
| 400번대 (E) | 404 돋보기 | 본문 자리 |
| 앱 오류 (F) | 500 수리 | 전체 화면(오류 경계) |
| 없는 주소 | 404 돋보기 | 전체 화면(`404.html`, 앱 안 알 수 없는 경로) |

403·505 그림은 쓰지 않는다(지울지는 lellon0403과 정한다).

**언제 띄우나** (`src/features/connection/pageError.ts`): 화면이 **자기 자료를 불러오지 못했을 때만** 띄운다.

- 기록 R1 실패 → 「오늘」·「기록」 화면, 설정 W1 실패 → 「측정하기」·「설정」 화면. 다른 화면에서는 지금처럼 위쪽 안내 한 줄만 뜬다(15초마다 도는 기록 확인이 설정 화면을 가리지 않게).
- 401은 로그인 흐름이 처리하므로 띄우지 않는다. 그 밖의 400번대는 E, 500번대와 응답 없음은 C, 기기가 오프라인이면 D.
- 로그인·가입·비밀번호·설정 저장·삭제처럼 **사용자가 누른 동작**의 실패는 지금처럼 입력칸 아래나 안내 한 줄로 둔다. 오류 페이지로 바꾸지 않는다.
- 측정 중과 측정 화면에서는 띄우지 않는다(원칙 6). 개발자 계정·로컬 모드에서도 띄우지 않는다.
- 같은 자료를 다시 불러오는 데 성공하면 사라진다. 인터넷이 돌아오면 실패한 것을 자동으로 다시 불러온다. 로그아웃하면 지운다.
- 인터넷 끊김 그림은 끊긴 뒤에는 받을 수 없으므로 로그인한 뒤 미리 받아 둔다(브라우저 메모리, 탭을 닫으면 사라짐). 그래도 못 받으면 깨진 틀 없이 그림 자리를 숨긴다.

**요청서와 다르게 한 것:** 본문 자리에서는 「홈으로」 버튼을 빼고 다시 시도 하나만 둔다(왼쪽 메뉴가 그대로 있어 다른 화면으로 갈 수 있다, 원칙 2·5). 오류 코드와 시각은 버튼 아래 작은 글씨다(5장 2 — 우선 두기로 함). 문의처는 아직 넣지 않았다(5장 1).

미리보기: 개발자 도구 → 알림·연결 → 웹 오류 페이지, 또는 `/error/request|server|offline|app`.

## 7. 남은 것

- 데스크톱 `offline.html`은 `app://` 주소라 웹에 저장한 테마를 읽지 못해 늘 초록 그림이다(4장에서 기본 한 가지면 충분하다고 함).
- 휴대폰 앱(Kotlin)도 같은 다섯 화면과 그림을 쓴다([휴대폰 계획](fe-mobile-records-plan.md)).
- **11/10 손 확인(klaod-tech, 가짜 API 서버 + 개발 서버, 기본 테마 넓은 창):** 로그인 401은 입력칸 안내만, W1 500 → 500번대(메뉴 유지)·다시 시도로 복구, R1 500 → 기록 안전 문구, R1 400·404 → 400번대, 응답 없음 → 5초 뒤 500번대, W2 500 → 설정 화면 유지·안내 한 줄, 오프라인 → 인터넷 끊김(처음엔 그림이 안 나와 미리 받기로 고침), 앱 오류 재현, `offline.html` 연결 중·연결 실패.
- 아직 안 본 것: 테마 7가지, 1180×760, 폭 360~430, 실제 서버.
- 「오늘」·「기록」은 들어갈 때 기록을 다시 받지 않고 15초 주기로 받는다. 그래서 오류가 바뀌어도 최대 15초 늦게 보인다(기록 화면 담당 lellon0403과 정할 일).
