# 최신 develop 프론트 통합·부서 인계

기준: 2026-10-29, `origin/develop a793405` 위의 `codex/frontend-jwt-integration`.
이전 작업은 `codex/frontend-api-v2-integration`의 `6a2f765`에 보존했다. 이전 앱 전체를 덮어쓰지 않고
최신 JWT·서버 측정·카메라 구현에 보호 기능을 옮겼다. PR 병합과 서버 배포는 별도 단계다.

## 현재 동작

- `admin / 1234`: 이메일 형식 검사를 우회하는 화면 확인용 가계정. 로그인 요청·DB 계정 생성·서버 권한이 없다.
  예시 기록과 화면을 확인하며 실제 서버 측정은 일반 계정으로 한다. 처음 앱을 열 때 기존 일반 계정 복원 요청은 별도로 발생할 수 있다.
  가계정 진입 뒤 늦은 로그인 복원·갱신 응답은 권한을 되살리지 않는다.
- 일반 계정: 최신 access JWT와 refresh 쿠키를 사용한다. 계정 변경 중이던 요청은 다른 계정으로 재시도하지 않는다.
- 측정: 서버 요약을 계정별 localStorage에 약 1초 간격 및 종료 시 임시 보관한다. 좌표·영상·비밀번호·토큰은 보관하지 않는다.
  R1에서 같은 세션·기준 자세·서버 시작 시각, 종료 상태, 이전보다 감소하지 않은 측정 누적값을 확인한 뒤 임시 사본을 지운다.
  통신 실패·손상 자료·오래된 서버 응답이면 보존하고 재시도한다. 재전송으로 측정을 새로 만들지 않는다.
- 기록 화면은 서버 R1을 정본으로 읽고 공용 로컬 기록으로 덮어쓰지 않는다. 과거 공용 기록은 소유자를 알 수 없어 자동 업로드하지 않는다.
- 진행 중 측정·미확인 결과가 있으면 로그아웃과 계정 변경을 막는다. 미확인 결과 안내에서 저장 확인을 다시 요청할 수 있다.
- 서버 프로필 저장·비밀번호 변경·탈퇴 API를 사용한다. 프로필 저장 직전 서버 설정을 재조회해 화면을 연 뒤 변경된 값이면 덮어쓰지 않는다.
  서버가 수정 버전/ETag를 제공하지 않아 GET과 PUT 사이 동시 수정까지 원자적으로 막지는 못한다.
  비밀번호 변경·탈퇴 성공 후 로컬 로그인 상태를 정리한다. 탈퇴는 서버의 30일 보관 정책을 따른다.

## 접속과 재현

SSH 비밀번호는 문서·저장소에 넣지 않는다. 아래 터널은 재부팅하면 다시 열어야 한다.

```powershell
ssh -N -L 127.0.0.1:8088:127.0.0.1:8088 bdp@192.168.0.104
$env:POSEGOOD_API_URL = 'http://127.0.0.1:8088'
$env:POSEGOOD_API_PREFIX = '/api'
npm --prefix frontend run dev -- --port 5175
```

`http://127.0.0.1:5175`는 이 브랜치의 프론트, `http://127.0.0.1:8088`은 서버에 이미 배포된 프론트다.
8088 화면이 가계정을 거부한다면 이 PR의 프론트가 서버에 아직 배포되지 않은 것일 수 있다.
`/api/health`는 HTTP 200, MySQL 정상이다. 공개 도메인은 앞선 검사에서 Cloudflare 530/1033으로 실패했다.

```powershell
python tools/platform/io_api_smoke.py --base http://127.0.0.1:8088/api
python tools/platform/ws_realtime_smoke.py --base http://127.0.0.1:8088/api
node tools/browser/jwt-integration.mjs http://127.0.0.1:5175 'C:\Program Files\Google\Chrome\Application\chrome.exe'
```

위 검사는 명시적인 합성 계정과 좌표만 사용한다. 계정 탈퇴 접수 후 실제 행 삭제는 서버 보관 정책에 따른다.

과거 T1 통계와 서버 기록 삭제 UI까지 완료했다고 해석하지 않는다. 임시 결과는 서버로 보내지 못한 좌표를 복원하는 백업이 아니다.
사용자가 브라우저 저장소를 지우거나 디스크 기록 자체가 실패하면 로컬 복구는 보장할 수 없다.
