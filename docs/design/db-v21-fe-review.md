## 1. FE 질문 회신

| # | 질문 | 회신 |
|---|---|---|
| FE-1 | 제외 구간 시작·끝을 `posture.episodes.v1`로 받을까 | **동의.** decision 사건 `excluded_started`·`excluded_ended`를 추가한다. 판정 불가 판단을 서버가 하므로 경계도 서버가 낸다. 조건 ① 사유 값은 DB 허용값 4개와 같은 이름(2장 ①). ② 화면에는 표시하지 않는다. 앱은 받기만 하고 요약 횟수 검사에서 뺀다. ③ 고개 돌림·복귀 대기 구간도 판정에서 빠지므로 `UNMEASURABLE`로 기록한다. 그래야 `valid_sec`와 맞는다 |
| FE-2 | 알림 표시·억제는 누가 정하나 | **BE 제안 동의.** 저장 서비스가 `alert_enabled`·`notify_max_per_hour`로 판단하고, 앱은 게이트웨이 `alert` 메시지가 올 때만 띄운다. 앱은 따로 거르지 않는다. 정할 것 ① 시간당 상한을 **세션 기준**으로 셀지 **사용자 기준 최근 60분**으로 셀지 ② `delivered`는 "앱에 보냈다"는 뜻으로 둔다. 소리(`sound_alert_enabled`)는 앱이 정하며 저장하지 않는다 |
| FE-3 | 기준 자세 평균 18개는 누가 계산하나 | **FE가 계산해 입구 API로 보낸다.** 평균은 판정이 아니라 정보 요약이라 "앱은 판정하지 않는다" 원칙과 충돌하지 않는다. | FE-4 | 사건 지속 시간 두 가지를 화면에 쓰나 | **화면은 실제 경과 시간만 쓴다**(`SessionEvents.tsx`의 `durationSec` = 종료 − 시작). FE에는 `deviation_sec`가 필요 없다. 분석용으로 둘지는 ML이 정한다 |

DB·팀 BE 항목 중 FE 의견:

- **DB-5 기본 threshold → 0.7 동의.** 앱 기본값이 0.7(화면 30점)이고, 사용자 범위 0.5~0.95(50~5점)에서 0.5는 가장 느슨한 끝이다. 단 지금 규칙 점수 기준이라 LSTM 확률을 쓰면 다시 정해야 한다(ML 확인).
- DB-1~3·DB-6·BE-1~4는 FE와 관계없고 스키마와 맞는다. DB-2(`MISSING` → `EXCLUDED`)는 2장 ① 표와 같다.

## 2. BE 문서·스키마에서 발견한 문제

### ① 제외 사유 4개와 계약 값의 대응이 없다 (중요)

BE 문서는 "판정 불가·`rest`·`away`·누락"만 적었고, DB `excluded_interval.exclusion_reason` 4개와 잇지 않았다. 제안:

| DB 사유 | 무엇 | 누가 판단 | 계약 값 |
|---|---|---|---|
| `PAUSE` | 사용자가 일시정지 | 앱 | `phase: "rest"` |
| `MISSING` | 카메라 입력 끊김(1.5초 이상), 순번 누락 | 앱 / 서버 | `phase: "away"`, 순번 빈칸 |
| `ABSENCE` | 사람이 아예 안 잡힘(`p: null` 연속) | 서버 | 서버 판단 |
| `UNMEASURABLE` | 가림·visibility 부족·고개 돌림·복귀 대기 | 서버 | 서버 판단 |

### ② 화면 크기 컬럼이 없어졌다

V2.1에서 `monitor_session.frame_width/height`가 지워졌다(640×480 고정 전제, `CAPTURE_RESOLUTION`).
앱은 640×480을 **권장(`ideal`)으로만** 요청한다(`frontend/src/features/camera/devices.ts`). 16:9 웹캠은 다른 크기를 줄 수 있고, 특징값 계산에 가로세로 비율이 들어간다.
제안: 화면 크기를 계약 `session_started`와 HDFS 파일 메타 정보에 남긴다(DB는 그대로). 다른 방법은 앱이 640×480이 아니면 측정을 거부하는 것이다.

### ③ 좌표 수집 동의를 저장할 곳이 없다

V2.1은 `T-41 user_consent`를 보류해 뺐다. 좌표 전송은 가입 때 동의를 받는다는 전제였으므로 동의 여부·시각을 저장할 곳이 필요하다. DB 담당에게 보류 해제를 요청한다.

### ④ `feature_archive`가 "특징값" 기준이다

결정에 따라 HDFS에는 **좌표 프레임**이 쌓이고 특징값은 다시 계산할 수 있다.
컬럼 설명과 D-33 설계를 "좌표 원본 + 계산 버전"으로 고쳐야 한다.

### ⑤ 기준 시각 정의 (BE 검토의견 3장 #3)

앱의 `t_ms`는 앱이 세션을 시작한 순간이 0인 경과 시간이고 일시정지 시간도 포함한다.
`monitor_session.started_at`을 입구 API가 시작 요청을 받은 시각으로 두면 오차는 네트워크 지연(수십 ms) 정도다. 이 정의를 BE 문서에 적는다.

### ⑥ 시드 threshold 0.5와 서버·앱 0.7 불일치

1장 DB-5 참고. **해결(10/10 DB 회신):** DB는 `DEFAULT` 행을 추가하지 않고 시드 `DEFAULT_TEMP`를 0.500 → 0.700으로 직접 고쳤다(V2.2). 이 행을 가리키는 세션이 아직 없고, 나머지 4개 값이 임시값이라 `DEFAULT` 이름을 쓰지 않는다는 이유다. FE 기본값과 같으므로 FE는 할 일이 없다.

## 5. DB 회신(10/10)·V2.2 — FE에 오는 영향

DB는 이 문서보다 먼저(10/10) 회신했으므로 2장 내용을 보지 않았다. 아래는 DB 회신을 FE 쪽에서 읽은 결과다.

### ① FE-1(제외 구간 경계)이 DB 결정의 전제가 됐다

DB는 `valid_sec`(DB-3)과 "붕괴로 본 시간"(DB-4)을 **컬럼으로 두지 않고** 제외 구간에서 계산한다(DB-03 D-21, 제약 C-4·요청 R-5). FE-1이 무산되면 DB가 다음 버전(migration 012)에서 컬럼을 추가한다. FE-1은 이미 동의했으므로 유지하고, 아래 DB 조건을 FE 쪽에서 지킨다.

| DB 조건 | FE에 미치는 것 |
|---|---|
| 사유는 하나만, 우선순위 일시정지 → 누락 → 자리 비움 → 판정 불가(BR-52) | 2장 ① 대응표 순서(`PAUSE`·`MISSING`·`ABSENCE`·`UNMEASURABLE`)와 같다. 앱이 `rest`·`away`를 겹쳐 보내지 않는다. 일시정지 중 카메라가 끊겨도 `rest`만 보낸다 |
| 구간 시작·끝은 0.5초 판정 구간 경계(BR-51) | 서버가 맞춘다. 앱은 `rest`·`away` 전환 시각을 `t_ms` 그대로 보낸다 |
| 누락이 `EVENT_BREAK_SEC` 이상일 때만 이벤트 종료(BR-53). 값 미정(모델 + PM) | 짧은 끊김에는 사건 카드가 이어진다. 앱이 끊김마다 사건을 끊어 보이지 않게 한다 |
| 세션 종료 때 열린 제외 구간은 종료 시각으로 닫음(BR-12) | 앱은 종료 전에 `excluded_ended`를 기다리지 않는다 |

### ② 알림 설정이 둘로 나뉘었다 (V2.2) — FE 계약 수정 필요

| 컬럼 | 뜻 | 지금 FE |
|---|---|---|
| `user_account.alert_enabled` (새로 추가) | 「자세 알림」(화면 알림 + 소리 전체), 기본 켜짐. 측정 시작 때 세션으로 복사 | 설정의 「자세 알림」 토글 = `preferences.alerts_on` |
| `user_account.sound_alert_enabled` (뜻 바뀜) | 소리만, 기본 꺼짐 | 측정 화면 스피커 버튼. 세션마다 꺼진 상태로 시작하고 저장하지 않는다 |

V2.2가 "자세 알림 값이 `sound_alert_enabled`에 들어가고 있었다"고 한 원인은 FE 계약이다. [계정 계약](../../contracts/accounts.v1.md)이 `alerts_on`을 `sound_alert_enabled`로 적었고 팀 BE(`UserStore`, `JdbcWorkspaceStore`)가 그대로 따랐다.

할 일:

1. ~~계정 계약: `preferences.alerts_on` → `user_account.alert_enabled`로 고친다.~~ **DB 담당이 `feature/repo-backend-db-v2`(`fcc8ef7`)에서 계약·API를 함께 고쳤다.** FE는 따로 고치지 않고 그 브랜치가 `develop`에 들어오면 받는다. 키 이름(`alerts_on`)은 그대로다.
2. 소리: **저장하지 않는 쪽을 제안한다.** 브라우저는 사용자 동작 없이 소리를 켤 수 없어, 저장된 "켜짐"을 다음 측정에서 그대로 쓸 수 없다. V2.2 설명("측정 시작 버튼을 누를 때 켬")은 이 제약 때문에 측정 시작 클릭을 동작으로 쓰는 방식이다. 저장하려면 계약에 `sound_on`을 추가하고, 켜짐이면 측정 시작 클릭 때 `enableSound()`를 부른다. 어느 쪽인지 DB·팀 BE와 정한다. 1장 FE-2의 "저장하지 않는다"는 이 결정 전까지 FE 제안으로 둔다.
3. ~~팀 BE와 함께 배포한다.~~ 1과 같이 `fcc8ef7`에 들어 있다. 그 브랜치는 `sound_alert_enabled`를 "앱 설정이 없어 바꾸지 않음"으로 두어 2의 FE 결정(저장 안 함)과 맞는다.

### ③ 민감도 3단계(「정할 것」 #3) 회신안

FE는 3단계를 **threshold 값 하나로만** 저장한다. 따로 단계 컬럼이 필요 없다.

| 화면 | 점수 | threshold |
|---|---|---|
| 느긋하게 | 20점 | 0.80 |
| 보통 (기본) | 30점 | 0.70 |
| 꼼꼼하게 | 40점 | 0.60 |

「세밀하게 조정」 슬라이더는 5~50점(0.95~0.50)을 1점 단위로 받는다. 3단계에 없는 값이면 화면에 "사용자 지정"으로 보인다(`SettingsPage.tsx`). DB 허용 범위 0.5~0.95 안이므로 스키마 변경은 없다. LSTM 확률로 바뀌면 세 값을 다시 정한다(ML).

### ④ 그대로 남은 것

- **화면 크기(2장 ②):** DB는 V2.1에서 지운 그대로다. 팀 카메라 전제로 FE도 따로 제안하지 않는다(4장).
- **좌표 동의(2장 ③):** DB 회신에 언급이 없다. 저장할 곳을 다시 요청한다. 지금 가입 동의(`service-v1`)는 "연구·학습용 자료 사용에는 동의하지 않는다"이고 저장도 하지 않는다(`AuthController`가 값만 확인). 좌표 전송을 넣은 새 동의문과 버전이 필요하다.
- **`feature_archive`(2장 ④):** DB 공지가 여전히 "특징값 HDFS 적재"다. 좌표 프레임 기준으로 고쳐 달라고 다시 요청한다.
- **`calibration_uuid`(C-2·R-1):** 세션 행에는 DB의 기준 자세 값이 들어가고 앱의 `baseline_id`는 쓰이지 않는다. FE는 재촬영 직후 기준 저장 응답을 받은 뒤에 측정을 시작하게 한다. 그래야 세션과 기준이 어긋나지 않는다.
- **`.107` 재생성(DB-1):** 팀 BE의 영구 모드가 잠시 멈춘다. 그동안 FE 영구 모드 시험은 하지 않는다.
