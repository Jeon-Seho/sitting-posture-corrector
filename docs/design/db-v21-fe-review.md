## 1. FE 질문 회신

| # | 질문 | 회신 |
|---|---|---|
| FE-1 | 제외 구간 시작·끝을 `posture.episodes.v1`로 받을까 | **동의.** decision 사건 `excluded_started`·`excluded_ended`를 추가한다. 판정 불가 판단을 서버가 하므로 경계도 서버가 낸다. 조건 ① 사유 값은 DB 허용값 4개와 같은 이름(2장 ①). ② 화면에는 표시하지 않는다. 앱은 받기만 하고 요약 횟수 검사에서 뺀다. ③ 고개 돌림·복귀 대기 구간도 판정에서 빠지므로 `UNMEASURABLE`로 기록한다. 그래야 `valid_sec`와 맞는다 |
| FE-2 | 알림 표시·억제는 누가 정하나 | **BE 제안 동의.** 저장 서비스가 `alert_enabled`·`notify_max_per_hour`로 판단하고, 앱은 게이트웨이 `alert` 메시지가 올 때만 띄운다. 앱은 따로 거르지 않는다. 정할 것 ① 시간당 상한을 **세션 기준**으로 셀지 **사용자 기준 최근 60분**으로 셀지 ② `delivered`는 "앱에 보냈다"는 뜻으로 둔다. 소리(`sound_alert_enabled`)는 앱이 정하며 저장하지 않는다 |
| FE-3 | 기준 자세 평균 18개는 누가 계산하나 | **FE가 계산해 입구 API로 보낸다.** 평균은 판정이 아니라 정보 요약이라 "앱은 판정하지 않는다" 원칙과 충돌하지 않는다. D-35(Kafka 보정 처리)는 필요 없다. 함께 보내는 값: `calibration_uuid`(촬영마다 새로), `calibration_sec`(3.0, `CALIBRATION_MS`), `sample_count`. 0~1 밖 좌표가 있으면 앱이 보정 실패로 처리한다. 보정 프레임 원본은 재처리용으로 `phase: "calibration"`으로 Kafka→HDFS에 보내며 판정에는 쓰지 않는다 |
| FE-4 | 사건 지속 시간 두 가지를 화면에 쓰나 | **화면은 실제 경과 시간만 쓴다**(`SessionEvents.tsx`의 `durationSec` = 종료 − 시작). FE에는 `deviation_sec`가 필요 없다. 분석용으로 둘지는 ML이 정한다 |
| FE-5 | 세션 시작 `policy`에 알림 값 추가 | **계약을 바꾸지 않는 데 동의.** 저장 서비스가 세션 행의 정책을 쓴다. 화면 설정은 다음 측정부터 적용되므로 측정 중 바뀌지 않는다 |

DB·팀 BE 항목 중 FE 의견:

- **DB-5 기본 threshold → 0.7 동의.** 앱 기본값이 0.7(화면 30점)이고, 사용자 범위 0.5~0.95(50~5점)에서 0.5는 가장 느슨한 끝이다. 단 지금 규칙 점수 기준이라 LSTM 확률을 쓰면 다시 정해야 한다(ML 확인).
- DB-1~3·DB-6·BE-1~4는 FE와 관계없고 스키마와 맞는다. DB-2(`MISSING` → `EXCLUDED`)는 2장 ① 표와 같다.

## 2. BE 문서·스키마에서 발견한 문제

### ① 제외 사유 4개와 계약 값의 대응이 없다 (중요)

BE 문서는 "판정 불가·`rest`·`away`·누락"만 적었고, DB `excluded_interval.exclusion_reason` 4개와 잇지 않았다. 제안:

| DB 사유 | 무엇 | 누가 판단 | 계약 값 |
|---|---|---|---|
| `PAUSE` | 사용자가 일시정지 | 앱 | `phase: "rest"` |
| `MISSING` | 카메라 입력 끊김(1.5초 이상), 순번 누락 | 앱 / 서버 | `phase: "away"`, 순번 빈칸 |
| `ABSENCE` | 사람이 아예 안 잡힘(`p: null` 연속) | 서버 | 서버 판단 |
| `UNMEASURABLE` | 가림·visibility 부족·고개 돌림·복귀 대기 | 서버 | 서버 판단 |

### ② 화면 크기 컬럼이 없어졌다

V2.1에서 `monitor_session.frame_width/height`가 지워졌다(640×480 고정 전제, `CAPTURE_RESOLUTION`).
앱은 640×480을 **권장(`ideal`)으로만** 요청한다(`frontend/src/features/camera/devices.ts`). 16:9 웹캠은 다른 크기를 줄 수 있고, 특징값 계산에 가로세로 비율이 들어간다.
제안: 화면 크기를 계약 `session_started`와 HDFS 파일 메타 정보에 남긴다(DB는 그대로). 다른 방법은 앱이 640×480이 아니면 측정을 거부하는 것이다.

### ③ 좌표 수집 동의를 저장할 곳이 없다

V2.1은 `T-41 user_consent`를 보류해 뺐다. 좌표 전송은 가입 때 동의를 받는다는 전제였으므로 동의 여부·시각을 저장할 곳이 필요하다. DB 담당에게 보류 해제를 요청한다.

### ④ `feature_archive`가 "특징값" 기준이다

결정에 따라 HDFS에는 **좌표 프레임**이 쌓이고 특징값은 다시 계산할 수 있다.
컬럼 설명과 D-33 설계를 "좌표 원본 + 계산 버전"으로 고쳐야 한다.

### ⑤ 기준 시각 정의 (BE 검토의견 3장 #3)

앱의 `t_ms`는 앱이 세션을 시작한 순간이 0인 경과 시간이고 일시정지 시간도 포함한다.
`monitor_session.started_at`을 입구 API가 시작 요청을 받은 시각으로 두면 오차는 네트워크 지연(수십 ms) 정도다. 이 정의를 BE 문서에 적는다.

### ⑥ 시드 threshold 0.5와 서버·앱 0.7 불일치

1장 DB-5 참고. 시드 행은 고치지 않고 확정 `DEFAULT` 행을 추가하는 BE 제안이 BR-65와 맞다.

## 3. 우리 FE 회신(10/08)에서 고친 곳

[FE 회신: v4 회의](v4-meeting-fe-reply.md)에 반영했다.
