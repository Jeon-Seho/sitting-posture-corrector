# v8 자세 리플레이 오프라인 파일럿

`model.analysis.replay_pilot`은 `/dev`의 `observation-keypoint-replay-v8`을 이용해
개인 기준 대비 **기준/이탈**을 탐색적으로 비교한다. 안내 과제는 검증된 정답이 아니다.
이 경로는 서비스 추론을 변경하지 않고, 모델 점수를 검증된 확률이나 의학적 판단으로 해석하지 않는다.

## 준비와 실행

Python 3.12 환경에 `model/analysis/requirements-training.txt`를 설치한다. 아래 명령은 저장소 루트에서 실행한다.
`<private>`는 저장소 밖의 접근 제한 폴더다. Windows에서는 폴더의 상속 ACL을 직접 확인해야 한다.
카탈로그는 이름과 원본 경로를 포함하고, 보고서와 모델 파일도 민감할 수 있으므로 모두 외부에 둔다.
원본 JSON, 이름 매핑, 모델, 좌표는 Git에 추가하지 않는다. 입력 폴더와 기존 파일은 변경하지 않는다.

```powershell
python -m model.analysis.replay_pilot catalog --input "<v8 JSON 폴더>" --output "<private>/catalog.json"
```

카탈로그의 `name_to_id`는 입력 이름을 NFKC·소문자 기준으로 묶은 **임시 제안**이다.
연구자가 같은 사람의 다른 표기와 서로 다른 사람의 같은 표기를 원본 밖의 기록으로 확인하고,
필요하면 각 이름의 `P001` 형태 ID를 수정한다. 한 이름을 여러 사람에게 썼다면 이 카탈로그만으로
분리할 수 없으므로 원본 소유 관계를 먼저 해결한다. 확인을 마쳤을 때만 `identity_reviewed`를
`true`로 바꾼다. 이름/ID 매핑과 파일 해시가 원본에 맞지 않으면 실행을 거부한다.

```powershell
python -m model.analysis.replay_pilot evaluate --catalog "<private>/catalog.json" --output "<private>/run-01"
```

출력 폴더는 아직 존재하지 않아야 한다. 신원 검토 전 파이프라인을 확인할 때만
`--allow-unverified-identities`를 추가한다. 이 경우 보고서에 `identity_reviewed: false`가 남으며
참여자 누수 여부를 확정할 수 없다. `--revision <40자리 Git 커밋>`으로 기준 커밋을 지정할 수 있다.
보고서는 코드 파일 해시도 기록한다. `report.json`은 집계·익명 참여자별 결과이고,
`fold-models.json`은 각 시험 참여자를 제외하고 학습한 비교 모델이다. 최종 배포 모델이 아니다.

## 처리와 비교

- v8·640×480·동일 Pose 추출기 조건과 원본 해시, 촬영 ID, 시간 순서, 측정 구간과 안내 일정,
  좌표·기준 등록·중단 표식을 검사한다. 실제 좌표는 출력하지 않는다.
- 각 촬영의 등록 프레임만으로 앱의 3초 이상·20표본 이상 9점 평균을 재현한다. 유효하지 않은
  프레임이나 등록 간 공백·중단은 등록을 끊는다. 수집 당시 앱 상태를 완전히 복원한 것은 아니다.
- 코·귀·어깨 품질과 고개 돌림은 서버 `FrameFeatures`와 같은 규칙을 쓴다. 공정한 비교를 위해
  모든 모델에서 9개 입력점의 유한한 2D 좌표를 요구하므로, B0의 관측 가능 범위는 실제 서버보다
  좁을 수 있다. 낮은 품질이나 누락은 정상·이탈로 바꾸지 않고 창을 끊는다.
- 촬영·과제·재시도·구간·500ms 초과 공백·중단·측정 불가 경계를 넘어 창을 만들지 않는다.
  최근 1초, 최소 5표본·800ms 범위의 중앙값을 최소 500ms 간격으로 낸다. 등록 프레임은 평가 창에 넣지 않는다.
- B0는 현재 규칙의 기본 임계값 0.7과 내부 검증으로 선택한 임계값을 각각 표시한다. B1은
  세 특징 및 추가 2D 특징(얼굴 길이·어깨 높이·어깨폭)의 두 로지스틱 회귀다.
  세 특징은 서버의 머리 간격·좌우 치우침·어깨 기울기 변화량이다.
- 바깥쪽은 참여자 하나를 뺀 평가다. 나머지 사람들의 내부 참여자 분할에서만 표준화·정규화 강도
  (`C=0.01, 0.1, 1, 10`)와 임계값(0.10~0.90, 0.05 간격)을 선택한다. 참여자·클래스·시도별
  가중치로 긴 시도의 영향을 줄인다. 동점은 더 단순한 정규화와 기본 임계값에 가까운 값을 우선한다.
- 혼동 행렬과 클래스별 재현율은 창 단위와 시도별 점수 중앙값 단위로 보고한다. 3초 연속 이탈
  재생은 측정 구간을 독립적으로 시작하는 탐색적 근사다. 원래 전환 구간이 없으므로 전체 서비스
  타임라인을 복원하거나 실제 오알림률·실제 발생 시점부터의 지연을 계산할 수 없다.

## 현재 자료의 탐색 결과

2026-11-08, 입력 이름 기준 임시 6명·20개 파일의 신원 확인 전 결과다. 안내 라벨을 그대로 쓰고,
사람별 balanced accuracy의 평균은 B0 기본 0.852, B0 내부 검증 0.846, B1 세 특징 0.851,
B1 확장 특징 0.842였다. 비교에 사용된 창은 1,968개이며, 서버의 고개 돌림 조건으로 제외한
프레임 237개와 유효 창을 만들지 못한 시도·재시도 1개가 있었다. 각 수치는 코드·설정과
개인 기준을 확인하기 위한 파일럿이며 인구 일반화나 실제 환경 성능이 아니다.
이 실행 환경은 Python 3.14·NumPy 2.4.4·scikit-learn 1.8.0이므로 위 고정 연구 의존성과 다르다.
재현 시 `report.json`의 환경과 코드 해시를 함께 확인한다.

## 서비스 연결 전 남은 일

현재 `/v2/infer`는 세 가지 기존 특징만 받는다. 추가 특징은 입력 계약과 계산 위치의 별도 합의가
필요하며, 창을 서비스에 넣을 때는 세션별 이력·재시작·누락·지연 처리도 정해야 한다.
본 도구는 API·데이터베이스·알림 엔진을 변경하지 않는다. 독립적으로 검증한 수행 라벨과
연속적인 평소 작업·일시 동작 자료를 모으고, 실제 사용 오알림과 감지 지연을 별도로 평가한다.
