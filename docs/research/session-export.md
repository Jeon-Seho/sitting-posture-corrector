# 측정 결과 내보내기 규격 (txt·csv)

ML 담당이 측정 결과 파일을 해석하기 위한 기준 문서다. 의료적 진단 자료가 아니다.

**앱은 판정 라벨을 붙이지 않는다**(2026-10-11, [ADR 0021](../decisions/0021-app-sends-information-server-judges.md)).
csv에는 시간과 관절 좌표만 있다. 상태·유형·점수 같은 라벨은 서버·ML이 만든다.
예전 csv의 `features_ok`·`state`·`type`·`score` 열과 그 계산 규칙은 [규칙 문서](../design/server-rule-spec.md)로 옮겼다.

## 1. 파일

측정 종료 화면의 내려받기 버튼은 같은 측정에서 두 파일을 만든다.

| 파일 | 내용 |
| --- | --- |
| `posegood-kafka-features-<세션>.txt` | 서버(Kafka)로 보냈을 구간 특징값. JSON Lines, [posture.features.v1](../../contracts/realtime/README.md). 첫 줄 `session_started`에 판정 설정(`policy`)·기준 ID·화면 크기가 있다. 서버 입력이 좌표로 바뀌면([계획 0023](../plans/active/0023-frontend-server-only.md) 3단계) 이 파일도 바뀐다 |
| `posegood-pose-debug-<세션>.csv` | 프레임별 관절 좌표. **학습·분석에는 이 파일을 쓴다.** |

두 파일의 시간(ms)은 같은 시작점에서 잰다. csv의 `time_ms`와 txt의 `start_ms`/`end_ms`로 맞춰 볼 수 있다.

## 2. csv 형식

```
time_ms,width,height,nose_x,nose_y,...,right_shoulder_y
0,640,480,0.43257,0.43447,...,0.8031
56,,,0.44272,0.433,...,0.8031
```

- 한 행은 카메라가 실제로 처리한 프레임 하나다. 빠진 프레임을 채우거나 복제하지 않는다.
- **간격이 일정하지 않다.** 실측 평균은 약 60ms(초당 약 16행)이며 기기 성능에 따라 다르다. 시간축은 행 번호가 아니라 `time_ms`를 쓴다.
- 일시정지한 동안은 기록하지 않으므로 `time_ms`에 공백이 생긴다. 공백을 건너 이어 붙이지 않는다.
- 빈 칸은 값 없음이다(pandas에서 NaN). 사람이 안 잡힌 프레임은 좌표가 모두 빈 칸이다. 최대 108,000행(30fps 기준 약 1시간)까지 기록한다.

### 열

| 열 | 의미 |
| --- | --- |
| `time_ms` | 측정 시작 이후 시간(ms) |
| `width`, `height` | 카메라 원본 영상의 픽셀 크기. 세션 중 바뀌지 않으므로 **첫 행에만** 있고 이후는 빈 칸 |
| `<관절>_x`, `<관절>_y` | 관절 9개의 화면 대비 좌표 0~1, 소수 5자리. 못 찾은 점은 빈 칸 |

관절: `nose`, `left_eye`, `right_eye`, `left_ear`, `right_ear`, `mouth_left`, `mouth_right`, `left_shoulder`, `right_shoulder`
(MediaPipe Pose 번호 0, 2, 5, 7, 8, 9, 10, 11, 12). 깊이(z)·visibility·world 좌표는 기록하지 않는다.

### 좌표 주의

- 좌표는 화면 비율 값이다. 가로·세로 픽셀 수가 달라서 거리·각도를 구할 때는 x에 `width`, y에 `height`를 곱한다.
- y는 아래로 갈수록 커진다.
- 좌표는 좌우 반전 전의 원본 영상 기준이고, 관절 이름의 좌우(`left_*`, `right_*`)는 사용자 몸 기준이다. 그래서 사용자 왼어깨(`left_shoulder`)가 화면 오른쪽(큰 x)에 있다. 2026-10-08 왼어깨 올리기·고개 왼쪽 돌리기 촬영으로 확인했다(카메라 한 대).
- 앱은 표시용으로만 좌표를 부드럽게 만든다. csv는 MediaPipe 원본 좌표다.
- 귀 위치는 머리카락에 가려져도 MediaPipe가 추정한 값이다.

## 3. 한계

- **정면 카메라라 앞뒤 깊이를 재지 못한다.**
- 좌우 방향은 카메라 한 대로만 확인했다. 영상을 좌우 반전해서 보내는 카메라에서는 반대로 나올 수 있다.
- 서로 다른 측정은 기준 자세가 다를 수 있다. 기준 자세 좌표는 이 파일에 없다.

## 4. 결정 기록

- 2026-10-08: 매 행 같은 값인 `width`/`height`는 첫 행에만 쓴다.
- 2026-10-11: 앱 판정 라벨 열(`features_ok`·`state`·`type`·`score`)을 없앴다(ADR 0021). 라벨은 서버·ML이 만든다.
  그 전 형식과 라벨 규칙은 [규칙 문서](../design/server-rule-spec.md)와 git 이력에 있다.
- 미적용: 저장 간격(현재 매 프레임)·좌표 소수 자리·관절 수 축소는 필요할 때 다시 정한다.
