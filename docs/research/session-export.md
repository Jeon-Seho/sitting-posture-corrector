# 측정 결과 내보내기 (txt·csv)

측정 종료 화면의 내려받기는 두 파일을 만든다. 측정 시작 시각 기준 시간(ms)이 같아 서로 맞춰 볼 수 있다.

- `posegood-kafka-features-<세션>.txt`: 서버(Kafka)로 보냈을 구간 특징값. JSON Lines, [posture.features.v1](../../contracts/realtime/README.md).
  첫 줄 `session_started`에 판정 정책·기준 ID·화면 크기가 있다.
- `posegood-pose-debug-<세션>.csv`: 프레임별 원시 관절 좌표와 앱 규칙 판정값. 분석 전용이며 판정에 쓰이지 않는다.

## pose-debug csv 열

| 열 | 의미 |
| --- | --- |
| time_ms | 측정 시작 이후 시간 |
| width / height | 카메라 원본 영상 픽셀 크기. 세션 중 바뀌지 않아 **첫 행에만** 쓰고 이후 행은 빈 칸 |
| features_ok | 특징값 계산 가능 여부 (1/0) |
| state | 앱 규칙 판정: `g` 바른 자세 / `c` 자세 붕괴 / `u` 판정 불가 |
| type | 붕괴 유형: `h` 머리·상체 변화 / `t` 기울어짐. `c`가 아니면 빈 칸 |
| score | 0~1 규칙 점수. 소수 2자리 **버림**(0.6996 → 0.69)이라 `g`가 임계값과 같은 숫자로 보이지 않는다. `u`면 빈 칸 |
| `<관절>_x`, `<관절>_y` | 코·눈·귀·입꼬리·어깨의 화면 대비 0~1 좌표(소수 5자리) |

좌표는 화면 비율 값이므로 거리·각도를 계산할 때는 x에 width, y에 height를 곱한다.

## 라벨 열의 성격 (2026-10-08 결정)

ML 담당 요청으로 앱 규칙 판정값을 라벨 3열로 추가했다. 사람이 직접 붙이는 정답 라벨은 수집 부담 때문에 넣지 않는다.

- 화면과 같은 규칙(`referenceScore`, 세션 시작 시 고정한 `threshold`)으로 프레임마다 계산한다.
- `hold_seconds` 지속 조건을 적용하기 **전**의 프레임 판정이다. 알림 확정 여부와 다를 수 있다.
- 우리 규칙의 출력이지 검증된 정답이 아니다. 이 열만으로 학습하면 모델은 규칙을 흉내 내게 된다.
- 토큰·용량 부담 때문에 매 행 반복되는 값(화면 크기)은 첫 행에만 둔다. 저장 간격(현재 매 프레임)·소수 자리·관절 수 축소는 아직 적용하지 않았다.
