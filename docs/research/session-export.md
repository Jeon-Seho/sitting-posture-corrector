# 측정 결과 내보내기 규격 (txt·csv)

ML 담당이 측정 결과 파일을 해석하기 위한 기준 문서다. 열 이름·라벨 값·점수 계산은 이 문서를 따른다.
라벨은 앱 규칙이 낸 판정이며, 사람이 확인한 정답이 아니다. 자세 붕괴 여부를 보는 값이고 의료적 진단이 아니다.

## 1. 파일

측정 종료 화면의 내려받기 버튼은 같은 측정에서 두 파일을 만든다.

| 파일 | 내용 |
| --- | --- |
| `posegood-kafka-features-<세션>.txt` | 서버(Kafka)로 보냈을 구간 특징값. JSON Lines, [posture.features.v1](../../contracts/realtime/README.md). 첫 줄 `session_started`에 판정 설정(`policy`)·기준 ID·화면 크기가 있다. |
| `posegood-pose-debug-<세션>.csv` | 프레임별 관절 좌표와 앱 규칙 판정. **학습·분석에는 주로 이 파일을 쓴다.** |

두 파일의 시간(ms)은 같은 시작점에서 잰다. csv의 `time_ms`와 txt의 `start_ms`/`end_ms`로 맞춰 볼 수 있다.

## 2. csv 형식

```
time_ms,width,height,features_ok,state,type,score,nose_x,nose_y,...,right_shoulder_y
0,640,480,1,good,tilt_right,0.09,0.43257,0.43447,...,0.8031
56,,,1,good,head,0.10,0.44272,0.433,...,0.8031
9347,,,1,collapse,tilt_left,0.82,0.49177,0.46896,...,0.82087
```

- 한 행은 카메라가 실제로 처리한 프레임 하나다. 빠진 프레임을 채우거나 복제하지 않는다.
- **간격이 일정하지 않다.** 실측 평균은 약 60ms(초당 약 16행)이며 기기 성능에 따라 다르다. 시간축은 행 번호가 아니라 `time_ms`를 쓴다.
- 일시정지한 동안은 기록하지 않으므로 `time_ms`에 공백이 생긴다. 공백을 건너 이어 붙이지 않는다.
- 빈 칸은 값 없음이다(pandas에서 NaN). 최대 108,000행(30fps 기준 약 1시간)까지 기록한다.

### 열

| 열 | 의미 |
| --- | --- |
| `time_ms` | 측정 시작 이후 시간(ms) |
| `width`, `height` | 카메라 원본 영상의 픽셀 크기. 세션 중 바뀌지 않으므로 **첫 행에만** 있고 이후는 빈 칸 |
| `features_ok` | 판정에 필요한 특징값을 계산했으면 1, 못 했으면 0. 0이면 `state`는 `unknown`. 1인데 `unknown`이면 복귀 대기 중(3장) |
| `state` | 앱 규칙 판정 (3장) |
| `type` | 점수를 끌어올린 쪽 (3장). 고개를 돌린 프레임은 `head_turn`, 그 밖의 `unknown`은 빈 칸 |
| `score` | 기준 자세 대비 변화량 0~1 (4장) |
| `<관절>_x`, `<관절>_y` | 관절 9개의 화면 대비 좌표 0~1, 소수 5자리. 못 찾은 점은 빈 칸 |

관절: `nose`, `left_eye`, `right_eye`, `left_ear`, `right_ear`, `mouth_left`, `mouth_right`, `left_shoulder`, `right_shoulder`
(MediaPipe Pose 번호 0, 2, 5, 7, 8, 9, 10, 11, 12). **판정에는 코·양어깨 세 점만 쓴다.** 나머지는 분석용 기록이다.

좌표 주의:

- 좌표는 화면 비율 값이다. 가로·세로 픽셀 수가 달라서 거리·각도를 구할 때는 x에 `width`, y에 `height`를 곱한다.
- y는 아래로 갈수록 커진다.
- 좌표는 좌우 반전 전의 원본 영상 기준이고, 관절 이름의 좌우(`left_*`, `right_*`)는 사용자 몸 기준이다. 그래서 사용자 왼어깨(`left_shoulder`)가 화면 오른쪽(큰 x)에 있다. 2026-10-08 왼어깨 올리기·고개 왼쪽 돌리기 촬영으로 확인했다(카메라 한 대).

## 3. 라벨: state, type

### state

| 값 | 뜻 | 조건 |
| --- | --- | --- |
| `good` | 바른 자세 | `score` < 임계값 |
| `collapse` | 자세 붕괴 | `score` ≥ 임계값 |
| `unknown` | 판정 불가 | 아래 조건 중 하나 |

임계값 기본은 **0.7**이며 사용자가 설정에서 0.50~0.95로 바꿀 수 있다. 실제 값은 txt 첫 줄 `policy`에 있다.

`unknown`이 되는 경우(코·양어깨 세 점 기준):

- 세 점 중 하나라도 검출되지 않았다. 얼굴을 가려도 코가 안 보여 `unknown`이 된다.
- 세 점 중 하나라도 신뢰도(visibility)가 0.65 미만이다.
- 세 점 중 하나가 화면 가장자리 2% 안에 있다(화면 밖으로 나가는 중).
- 어깨 너비가 화면 폭의 10% 미만이다(너무 멀거나 옆으로 돌아앉음).

**복귀 대기**: 판정 불가였다가 다시 측정되기 시작하면 **3초 동안은** `state`를 `unknown`으로 둔다.
사람이 화면에 돌아와 자세를 다시 잡는 중이라 이 순간을 바른 자세나 붕괴로 판정하지 않는다.
이때는 측정이 되므로 `features_ok`는 1이고, `type`과 `score`는 분석용으로 그대로 쓴다.
측정 화면 점수, 서버 기록(`poor`), txt도 같은 규칙을 쓴다([판정 불가 처리](../design/unmeasurable-handling.md)).

**고개 돌림(`head_turn`)**: 고개를 돌린 동안은 자세를 판정하지 않는다(`unknown`, `type`은 `head_turn`, `score` 빈 칸).
양 귀 가운데에서 코가 좌우로 얼마나 벗어났는지(어깨 너비 기준)가 기준 자세보다 **0.15** 넘게 바뀌면 고개 돌림으로 본다. 살짝 돌린 고개(0.15 이하)는 그대로 판정한다.
고개를 돌리면 코만 크게 움직이고 귀 가운데는 거의 그대로이고, 몸이나 머리 전체를 기울이면 코와 귀가 같이 움직이기 때문이다.
실제 촬영(2026-10-08)에서 자세(정자세·기울임·어깨 올리기·숙이기·거북목)는 최대 0.06, 끝까지 돌린 고개는 0.15~0.4, 살짝 돌린 고개는 0.15 이하였다.
측정 화면("고개를 돌린 동안은 자세를 판정하지 않아요"), 서버 전송(`poor`), txt도 같다. 고개를 되돌린 뒤에는 **1초**만 판정을 보류한다(화면 밖·가림 뒤에는 3초).

`unknown`은 바른 자세도 붕괴도 아니다. 다른 값으로 바꾸거나 채우지 않는다.

### type: 점수를 끌어올린 쪽

`type`은 세 변화 중 **가장 크게 바뀐 쪽**이다. `good`일 때도 채운다. 그래서 `good,head,0.45`는
"아직 붕괴는 아니지만 머리 쪽으로 벗어나는 중"으로 읽는다. `collapse`일 때는 붕괴 유형이 된다.
`unknown`이면 빈 칸이다.

| 값 | 뜻 | 조건 |
| --- | --- | --- |
| `head` | 머리·목 쪽 | **머리 높이** 변화가 가장 큼(같으면 `head`) |
| `tilt_left` | 사용자 본인 **왼쪽**으로 기울어짐 | 좌우 변화가 머리 높이 변화보다 크고, 방향이 왼쪽 |
| `tilt_right` | 사용자 본인 **오른쪽**으로 기울어짐 | 좌우 변화가 머리 높이 변화보다 크고, 방향이 오른쪽 |

- `head`: 코와 어깨선 사이 높이가 기준보다 바뀌었다. 고개 숙임, 머리가 앞으로 나오며 내려감, 등이 굽어 상체가 숙여짐이 포함된다. 변화량의 절댓값을 보므로 **고개를 드는 것도 `head`**다.
- `tilt_*`: 몸·머리가 옆으로 치우쳤거나 한쪽 어깨가 처졌다. 어깨 기울기만 뜻하지 않는다.
- 좌우는 **화면이 아니라 사용자 본인 기준**이다. 좌우 치우침(머리 중심의 이동)과 어깨 기울기 중 더 크게 바뀐 쪽의 방향을 쓴다.
  - 몸이나 머리를 본인 왼쪽으로 기울이면 `tilt_left`, 오른쪽이면 `tilt_right`
  - 어깨로 보면 본인 왼어깨가 내려가고 오른어깨가 올라가면 `tilt_left`
- 한쪽 어깨만 올리면 반대쪽으로 기울어진 것과 같다. 왼어깨를 올리면 `tilt_right`, 오른어깨를 올리면 `tilt_left`다(2026-10-08 촬영으로 확인).
- 예: "오른어깨가 올라가는 습관"은 어깨 기울기 쪽에서 `tilt_left`가 반복되는 형태로 나타난다.
  다만 `tilt_left`는 몸을 왼쪽으로 기울인 경우도 포함한다. 어깨만 따로 보려면 좌표로 어깨 기울기를 직접 계산한다(4장).
- score가 0.1~0.2 정도로 낮을 때의 `type`은 4장의 흔들림에 따라 바뀌므로 큰 의미가 없다. 점수가 높을수록 의미가 커진다.

## 4. score 계산

`score`는 "좋은 정도"가 아니라 **개인 기준 자세에서 벗어난 정도**다. 0이면 기준과 같고, 클수록 많이 벗어났다.

측정 전에 사용자가 편하게 앉은 자세를 몇 초 등록한다(기준 자세). 매 프레임 코·양어깨로 세 값을 계산하고 기준과 비교한다.
모든 값은 어깨 너비(px)로 나눠서, 카메라와의 거리가 바뀌어도 크게 달라지지 않게 한다.

| 값 | 계산 (px 단위) | 허용 폭 |
| --- | --- | --- |
| 머리 높이 | (어깨 중심 y − 코 y) ÷ 어깨 너비 | 0.22 |
| 좌우 치우침 | (양 귀 가운데 x − 어깨 중심 x) ÷ 어깨 너비. 귀가 없으면 코 x | 0.20 |
| 어깨 기울기 | (왼어깨 y − 오른어깨 y) ÷ 어깨 너비 | 0.03 |

```
변화 = |현재 − 기준| ÷ 허용 폭      (세 값 각각)
score = min(1, 0.7 × 세 변화 중 최댓값)
```

- 세 값 중 하나라도 허용 폭만큼 바뀌면 score가 0.7, 곧 기본 임계값이 된다.
- csv에는 소수 2자리 **버림**으로 쓴다(0.6996 → 0.69). 그래서 `good` 행이 임계값과 같은 숫자로 보이지 않는다.
- 어깨 기울기가 가장 민감하다. 가만히 앉아 있어도 어깨 위치가 프레임마다 2~3px 흔들려 score가 0.1~0.2 정도 오르내린다.
- 허용 폭과 0.7은 실험으로 정한 값이며 의학적 기준이 아니다. 계산 코드는 `model/prototype/pose.ts`의 `features`, `referenceScore`이다.
- 앱 화면의 "자세 점수"는 보기 쉽게 뒤집은 `100 × (1 − score)`이다(csv 0.17 = 화면 83점). csv에는 뒤집기 전 값이 들어간다.

## 5. 프레임 판정과 알림의 차이

csv의 `state`는 **프레임 하나하나의 판정**이다. 앱의 실제 알림은 시간 조건을 더 거친다(기본값).

- `collapse`가 **3초** 이상 이어져야 알림이 울린다. 잠깐 움직인 것은 거른다.
- 알림 후 `good`이 **3초** 이상 이어져야 회복으로 본다.
- 붕괴가 이어지면 **60초**마다 다시 알린다.

그래서 `collapse`가 1초만 찍힌 구간은 알림 없이 지나간다. 지속 시간 기준 라벨이 필요하면 `state`를 시간축으로 묶어 직접 만든다.

## 6. 한계

- **사람이 확인한 정답이 아니다.** 규칙의 출력이므로 이 라벨만으로 학습하면 모델은 규칙을 흉내 내게 된다.
- **정면 카메라라 앞뒤 깊이를 재지 못한다.** 시선은 그대로 둔 채 머리만 앞으로 내미는 동작은 코 높이가 거의 바뀌지 않아 `good`으로 나올 수 있다.
- `head`는 고개 숙임과 위를 보는 동작을 구분하지 않는다. 붕괴 여부 판단에는 충분하지만 원인 구분용은 아니다.
- 기준 자세는 측정마다 새로 등록한다. 서로 다른 측정의 score는 각자의 기준에 대한 값이다.
- **어깨 좁히기(어깨를 안으로 마는 자세)는 거의 잡지 못한다.** 어깨 너비를 다른 값의 기준 자로 쓰기 때문에 어깨 너비 자체의 변화는 재지 않는다. 2026-10-08 촬영에서 최고 0.69, 붕괴는 순간적으로만 나왔다.
- 좌우 방향은 카메라 한 대로만 확인했다. 영상을 좌우 반전해서 보내는 카메라에서는 반대로 나올 수 있다.
- 고개 돌림 경계(0.15)는 한 사람의 촬영 세 번으로 정했다. 사람과 카메라 위치에 따라 다시 정해야 한다.
- 살짝 돌린 고개는 판정하므로, 상체가 함께 돌아 어깨 기울기가 바뀌면 점수가 오를 수 있다(촬영에서는 최대 약 0.67, 붕괴 없음).
- 귀 위치는 머리카락에 가려져도 MediaPipe가 추정한 값을 쓴다. 추정이 크게 틀리면 좌우 치우침과 고개 돌림 판단이 흔들릴 수 있다.

## 7. 결정 기록

- 2026-10-08: ML 담당 요청으로 라벨 3열(`state`, `type`, `score`)을 추가했다. 사람이 직접 붙이는 정답 라벨은 수집 부담 때문에 넣지 않는다.
- 2026-10-08: 매 행 같은 값인 `width`/`height`는 첫 행에만 쓴다. score는 소수 2자리 버림으로 쓴다.
- 2026-10-08: 파일만 받은 사람도 읽을 수 있게 약자(`g`/`c`/`u`, `h`/`t`) 대신 단어를 쓴다. 단어도 토큰 1~2개라 부담 차이가 거의 없다.
- 2026-10-08: `type`을 붕괴 때만이 아니라 `good`일 때도 채운다. 붕괴 전에 어느 쪽으로 벗어나는지 보기 위해서다.
- 2026-10-08: 사용자별 좌우 습관을 보려고 `tilt`를 `tilt_left`/`tilt_right`로 나눈다. 점수와 판정은 바뀌지 않는다.
- 2026-10-08: 기울이기 촬영 결과를 보고 좌우 규칙을 한 번 뒤집었다가, 같은 날 왼어깨 올리기·고개 돌리기 촬영(9번)을 기준으로
  원래 규칙(사용자 몸 기준)으로 되돌렸다. 앞의 기울이기 촬영은 몸 기준으로 반대쪽 동작이었다. 서버 추론도 함께 되돌려 처음과 같다
  ([ADR 0013 수정](../decisions/0013-frontend-server-feature-connection.md)).
- 2026-10-08: 고개 돌림이 붕괴로 잡혀(점수 1.00) 고쳤다. 큰 값만 쳐내는 방식은 살짝 돌린 고개가 여전히 기울임으로 잡혀 버렸다.
  대신 좌우 치우침을 코 대신 양 귀 가운데로 재고, 귀 가운데 대비 코 위치로 고개 돌림을 감지해 `head_turn`으로 판정하지 않는다.
  같은 날 자세 수집 csv의 `feature_version`을 `reference-rules-v0.2`로 올렸다(좌우 치우침 정의 변경).
- 2026-10-08: 경계 0.1에서는 살짝 돌린 고개도 걸리고 3초 대기까지 붙어 측정 시간이 크게 줄었다. 경계를 0.15로 넓히고,
