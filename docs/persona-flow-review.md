# 개인 메모 — 병철 씨 페르소나

- 분야: 프론트
- 작업: GP-0113

요구사항은 [팀 공유 문서](team-requirements.md) 한 곳에서 관리한다. 이 파일은 내 검토 흐름과 다음 할 일만 남긴다. 기존 대화식 누적 기록은 최신 결정으로 통합했으며 폐기한 선택지를 다시 적용하지 않는다.

## 페르소나와 검토한 행동

이병철, 23세, 사무직. 자세와 허리 불편이 걱정되어 서비스를 시작한다. 이는 사용 동기이며 의학적 판단이 아니다.

1. 가입 정보 입력 → 로그인 → 개인 기준/잘못된 예시 등록 → 빈 측정하기 화면.
2. 측정하기(준비 → 업무 중 측정 → 종료 결과) → 기록 탭의 당일 기록.
3. 프로필·비밀번호 변경.
4. 편하게 유지할 개인 기준으로 재등록하고 예시 추가.
5. 짧은 움직임을 걸러내도록 확정 5초, 재알림 30초, 민감도 조정.
6. 기록을 확인한 뒤 서비스가 더 필요하지 않다고 느껴 탈퇴 및 학습 사용 선택.
7. 내부 화면 이동·외부 탭 업무·카메라 단절·저장 실패·새로고침 복구까지 검토.

화면 이름은 2026-10-02 데스크톱 앱 재구성([ADR 0017](decisions/0017-desktop-app-shell-and-redesign.md)) 기준이다.
이전 이름과의 대응: 홈·측정 준비·실시간 측정 → 측정하기, 대시보드 → 기록,
자세 등록 → 설정의 자세 데이터 수집(개발자 옵션), 일시정지 → 잠시 쉬기.
흐름 자체는 바뀌지 않아 페르소나 검토를 다시 하지 않았다.

## 최신 결정 기억하기

- 중단 후 재개는 사용자 선택. 입력 복구만으로 자동 측정하지 않는다.
- 내부 화면 이동은 일시정지, 외부 탭 전환 자체로는 정지하지 않는다.
- 저장 성공 직후 통계를 갱신한다. 화면 진입마다 조회하는 선택은 폐기했다.
- 교정 알림은 우측 하단 약 3초 + 선택적 소리. 별도 알림함은 제외했다.
- 탈퇴 시 학습 사용 거절하면 스켈레톤도 삭제 대상이다.
- 기준 자세의 건강상 정확성 검증은 범위 밖이다.

## 현재 작업 상태

- 기반: `lee_app1`(2026-10-07 확인). 처음 검토는 codex/heavy-guided-collection `e35d8b1`에서 했다. 실제 자산은 Lite, 학습 LSTM은 미연결.
- 이전 feature/retro-redesign의 문제를 현재 코드에 그대로 적용하지 않는다.
- 화면 점수는 높을수록 기준과 비슷함. 알림 기준 점수를 높이면 더 민감하다.
- 팀원 구현 방향을 우선하며 과거 별도 3초 보정을 강제하지 않는다.
- 전략 정리 단계. 제품 코드 변경·서버 실행 없이 문서만 정리했다.
- 2026-10-07 `lee_app1` 기준 프론트 283개·타입 검사 통과, Python 160개 중 3개는 Windows 배포 테스트의 기존 오류. 처음 검토 때는 Python 10개·FE 26개였다. 실제 카메라/백그라운드 장시간 검증은 남았다.
