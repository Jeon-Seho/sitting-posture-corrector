# Developer Lab

`/dev`와 `/dev/`의 카메라 중심 연구 작업 공간. 일반 서비스 `/` 및 `/#forecast`와 분리한다.
단일 Vite 프로젝트의 지연 로딩 경로이며 별도 서버/권한 관리용 관리자 화면은 아니다.

카메라 위의 `DeveloperDecisionNumbers`는 선택 정책의 시간·복귀 횟수, 이탈/알림 0·1과 누적 알림을 표시한다.
룰 숫자는 `ruleDurationMs`·`ruleReturnedExcursions`를 사용하며 과거 파일의 없는 복귀 횟수는 미상으로 표시한다.
화면 좌우/상하·어깨폭 변화는 정규화로 제거되는 정보를 확인하는 진단이다. 기존 화면 수치 자체는 진단이며, 새 고정 영상 보완 경로는 별도로 계산한 몸 전체 변화 점수를 판정에 사용한다. LSTM/정상 범위의 학습 입력은 유지한다.
기본 알림 소리는 꺼져 있고 시각 알림과 집계는 계속된다. [표시 결정](../../../../docs/decisions/0033-live-decision-numbers.md).

## 큰 후방·하강 변화 보완

새 실행은 8초 등록 때의 영상 위치·어깨폭을 고정한다. 얼굴과 어깨의 공통 이동·어깨폭 축소를 상대 자세 점수와 조합한다.
작은 움직임은 등록 변동과 넉넉한 개발 하한으로 허용하고, 기존 3초 지속·복귀 조건을 유지한다. 원본 영상 기준은 내보내지 않는다.
카메라가 움직였거나 영상 비율이 바뀌면 새 등록이 필요하다. [정책·한계](../../../../docs/decisions/0034-fixed-image-posture-anchor.md).
현재 새 실행은 영상 v2 하한인 이동 18% 등록 어깨폭·축소 12%와 기존 3초 지속/복귀를 사용한다. 초기 v1 45%/20% 결과를 재해석하지 않는다.
자동 정상 선별은 거리 선택(기본 6%)에 종합 0.5배 이내·실측 룰 범위 안·실측 1초 연속을 추가한다. 이전 출처 행은 보존하며 재검토·학습 차단으로 표시한다.
[조정 근거와 출처](../../../../docs/decisions/0035-posture-and-clean-normal-selection.md).

## 실행·검증

```sh
npm --prefix frontend run dev
# http://127.0.0.1:5173/dev
make check-frontend
```

구도 확인은 약 0.5초의 유효 화면 구도를 사용한다. 기준 등록 8초에는 초기 화면 위치 고정을
요구하지 않으며 유효한 3D 얼굴·양어깨 표본을 모은다. 700ms까지의 일시 누락은 등록을
기다리고, 1000ms 이내 표본 지연은 기준 표본을 보존한다. `/dev` 등록 후 규칙·알림·자동 수집은
원시 유효 관측 간 250ms 초과에서 연속성을 끊으며 품질 손실을 정상 자세로 처리하지 않는다.
예측 입력 창의 짧은 처리 지연은 아래 별도 정책을 따른다.

UI의 합성 데모는 카메라 권한 없이 가이드와 실험 흐름을 확인한다. 실제 장치의 FPS·조명·구도·
모델 정확도 검증으로 해석하지 않는다. 로컬 `research-model/forecast.json`이 유효하면 LSTM을
기본 선택하고, 없으면 마지막 위치 유지 비교군을 사용한다. 설정에서 실제 모델 JSON을 수동으로
연결해도 LSTM을 선택한다. 명시적으로 선택한 비교군과 실행 중인 실험은 자동 변경하지 않는다.
별도 Face Landmarker 또는 영상 저장 기능은 없다.
개발 중 Fast Refresh가 실행을 해제하면 시작 대기로 초기화한다. 이전 관측을 현재 결과로 유지하지 않는다.
영상 점선은 등록 당시 화면 위치이며 3D 자세 판정 거리는 어깨 중심·폭으로 정규화한 별도 수치다.
측정이 시작되면 영상 옆에 현재 자세 요약을 배치한다. 확대·축소는 레이아웃만 바꾸고
카메라 스트림과 측정 세션을 다시 만들지 않는다. 영상 위치 수치·모델 비교·입력 상세는
기본 접힘이며 그래프의 예측 오차는 사용자가 선택할 때만 표시한다. 별도 의존성은 추가하지 않았다.

## 개발자 알림 경계

알림 기준은 기본 `rule`(개인 정상 범위 또는 거리 + 지속시간), 선택 가능한 비교군은 `predictor`(예측 + 거리·시간)이다.
실행 전에만 변경하고 실행에 고정한다. `DeveloperAlertTracker`는 선택한 코어의
`persistent_deviation_candidate`를 받아 최초 한 번과 60초 간격의 재알림만 결정한다.
`recovery_pending` 중 재이탈은 같은 사건이며 `near_reference`에서 사건을 끝낸다.
측정 불가·프레임 누락은 관측 연속성을 끊고 알림 사건도 초기화한다. 정상 복귀로 기록하지 않는다.
`observed-v2`의 `warming`은 예측 준비만 뜻하며 유효한 `ruleState` 알림을 막지 않는다.
예측을 선택한 비교 경로는 예측 준비를 기다리며 준비 완료를 새 사건으로 만들지 않는다.

코어의 조건은 거리 12% 진입/8% 복귀, 룰 3초, 예측+룰 3초 이탈과 1초 낮은 오차 또는 5초 이탈,
지속 이탈 뒤 3초 복귀다. 거리는 정규화한 3D 얼굴 9점·귀 2점·어깨 2점의 그룹 평균이다.
알림부에서 임계값이나 행동 분류를 다시 만들지 않는다. LSTM은 300ms 좌표 예측이고 스트레칭
분류기가 아니다. 높은 예측 오차만으로 일시적 동작을 확정하지 않으며 실제 복귀를 확인해야 한다.
오래 유지한 스트레칭은 알림을 유발할 수 있다. 근거는 [ADR 0025](../../../../docs/decisions/0025-local-forecast-experiment.md)다.

`DeveloperAlertAudio.arm()`은 시작·소리 켜기·테스트 같은 사용자 클릭 안에서만 호출한다.
`beep()`는 이미 준비된 컨텍스트에만 전달하고 차단 상태를 자동으로 재개하지 않는다.
음소거·종료 때 `cancel()`로 예약 소리와 미완료 준비를 취소하고, 훅 해제 때 `dispose()`로 닫는다.
해제된 인스턴스는 재사용하지 않으므로 React StrictMode의 해제 후 재설정에도 새 인스턴스를 준비한다.
음소거·차단 여부는 알림의 시각 표시와 기록을 중단하는 조건이 아니다.

메모리 기록의 선택적 `alerts`는 최근 100개 스냅샷을 오래된 순으로 보관한다.
`alertCount`는 잘린 기록과 재알림을 포함한 전체 실행 알림 수, `alertSettings`는 실행에 고정한
`basis`/`reminderMs`다. 스냅샷에 원본 좌표·기준 윤곽·영상·가중치를 넣지 않는다.
수동 JSON에는 [명시된 필드](../../../../contracts/developer-lab-export.v1.md)만 내보낸다.
음소거 상태에서 남은 알림 수는 소리가 실제로 재생된 횟수를 뜻하지 않는다.

## 서비스로 옮길 때

1. 이 디렉터리를 서비스 화면에서 직접 import하지 않는다. 필요한 순수 표시 컴포넌트나 변환기만
   공통 디렉터리로 추출하고 입력·출력·수명·스타일 범위를 명시한다.
2. 가이드 구도와 연구 시간 임계값은 서비스 정책으로 자동 승격하지 않는다. 장치·시점·대상
   조건을 적은 검증 결과와 ADR을 마련하고 서비스 계약과 맞춘다.
3. 서비스의 측정 불가·기준 등록·저장·세션 복구·권한·중단 테스트를 추가해 회귀를 확인한다.
4. 두 화면이 같은 공통 컴포넌트를 소비하도록 전환한 뒤 개발 전용 코드를 정리한다.
   연구 demo·LSTM 파일 import·진단 export는 서비스로 함께 복사하지 않는다.

## 자동 정상 후보 수집

`/dev`의 실제 카메라 측정에서 기준 등록 후 자동으로 모은다. 유효한 원본 관측의 등록 기준 거리
`deviation ≤ maximumDeviation`(기본 0.06, 선택 0.005/0.03/0.06)이면 최대 10Hz로 `정상자세(자동)` 행을 추가한다. 거리는 어깨폭으로 정규화한
얼굴 9점·귀 2점·어깨 2점의 세 그룹 평균 거리다. LSTM 오차나 정상 점수·픽셀 차이가 아니다.
기준 부근에 머무는 동안 새 관측마다 쌓이며 합성 데모·기준 밖·가림은 제외한다. 자동 수집을 멈추거나,
별도 JSON으로 내려받거나, 버퍼를 비울 수 있다. 익명 코드는 수집을 멈춘 상태에서 변경한다.

`autoNormalCollection.ts`가 원본 시각·기준·실행·참여자·세그먼트를 보존한다. 250ms 초과 누락,
품질 실패, 기준 밖, 일시정지·탭 숨김·실행 종료는 구간을 끊는다. 최대 6,000행에서 기존 자료를
지우지 않고 멈춘다. 떨어진 정상 행을 연속 예측 학습 창으로 잇지 않는다. `auto_rule`/`not_reviewed`는
초기 실험 약라벨이며 독립 평가 정답이 아니다. 자동으로 개인 모델 fitting·기준 갱신을 하지 않는다.
[자동 수집 계약](../../../../contracts/auto-normal-posture-collection.v2.md).

## 수동 정상 구간 수집과 개인 모델

`정상 자세 수집` 메뉴에서 익명 참여자/촬영 세션 코드와 자료 용도를 지정한다.
`30초 측정하기` → 준비 3초 → 유효 관측 30초 → 사용자가 구간 확인 → 개인 범위 적용/다운로드 순서다.
수동 촬영은 일반 측정과 동시에 실행하지 않는다. 화면 라벨은 `정상자세(수동)`이며 참여자 자기 보고다. 영상/음성 저장·서버 업로드·자동 영구 저장은 없다.
탭 메모리에 보관하고 원본 좌표를 포함한 JSON과 개인 범위 JSON은 수동 다운로드한다.
일반 진단 내보내기는 계속 좌표를 제외한다. [수집 계약](../../../../contracts/normal-posture-collection.v1.md).

`normalCollection.ts`/`useNormalCollection.ts`가 수집 수명·실제 시각·품질 누락·구간 확인을 관리한다.
`model/prototype/normalPosture.ts`는 9개 특징의 중앙값과 q95 절대편차×1.5(연구용 최소 폭 포함)를 맞춘다.
자료 목적은 학습 후보 또는 개인 보정으로 구분하며 실제 연구의 참여자 분할은 별도로 수행한다.
`1배`는 학습한 허용 폭 경계이고 `2/3배` 이하에서 복귀를 시작한다. 확률이나 검증된 정확도가 아니다.
학습한 정상 중심은 고정한다. 같은 추출기의 8초 등록 중앙값을 이 중심·허용 폭과 비교해 1배 이하일 때만 등록하며, 이탈 중 학습·자동 기준 갱신은 없다. 초기 안내 검사는 기존 구도 0.5초의 중앙값을 써 한 프레임 잡음으로 구도를 초기화하지 않는다.
프로필은 실행 시작에 고정하고 합성 데모에는 적용하지 않는다. 기존 Panoptic LSTM은 예측 보조 비교다.

`displaySmoothing.ts`의 One Euro 필터는 현재점 표시만 보정한다. 원본 수집/개인 기준/모델 입력에는
적용하지 않는다. 낮은 visibility·250ms 초과 누락·영상 크기 변경에는 초기화한다.
표시 설정은 min cutoff 2.5Hz, 속도 계수 5, derivative cutoff 1Hz이며 실제 판정 임계값이 아니다.
새 라이브러리는 설치하지 않았다. [최신 ML 계획](../../../../docs/ml/current-plan.md) · [HTML](../../../../docs/ml/current-plan.html).


## 실제 예측 방향 표시

LSTM은 얼굴 9점·귀 2점·어깨 2점의 xyz, 총 39차원을 예측한다. 어깨만 예측하는 모델이 아니다.
`predictionDisplay`의 실제 모델 입력 끝 좌표와 같은 입력 창에서 나온 300ms 미래 출력으로 도식을 만든다.
정면은 `(-x, y)`, 측면은 `(-z, y)`이며 현재/미래에 같은 축척을 적용한다. 정규화 world 좌표이므로
카메라 픽셀 위의 실제 미래 얼굴 위치라고 표시하지 않는다. 원본 입력·출력 좌표는 메모리 표시 전용이다.

카메라 가이드의 점선·화살표는 `기준 → 현재`, 미래 도식은 `입력 끝 → 0.3초 뒤`로 의미가 다르다.
선택된 방식이 위치 유지/등속이면 그 이름을 표시하며 LSTM으로 부르지 않는다. 예측 창 준비·품질 실패·
시간 단절·종료·영상 크기 변경·만료에는 오래된 예측을 숨긴다. `predictionTimeMs`는 잔차 대조 시각이고
미래 도식의 `targetAtMs`와 다르다. 룰 기반 알림은 예측 도식의 준비 상태와 별도로 유지한다.
[예측 표시 계약](../../../../contracts/forecast-experiment.v1.md) · [ADR 0029](../../../../docs/decisions/0029-automatic-normal-labels-and-forecast-display.md).

## 예측 입력 준비와 처리 지연

`observed-v2`의 예측 입력은 이미 도착한 유효한 두 원시 관측 사이 최대 500ms 지연만 100ms 격자로
보간한다. 아직 도착하지 않은 좌표를 복사해 채우지 않는다. 250ms 초과 구간은 규칙·알림·자동 수집에서
여전히 `unmeasurable`이며, 정상/이탈 지속시간에 더하지 않는다. 예측 창을 유지한다고 유효 관측으로 바꾸지 않는다.
실제 품질 실패·탭 숨김·시각 역전·500ms 초과 누락에서는 예측 이력도 버린다.

입력 지연 감시 타이머는 원시 관측 시각을 앞으로 옮기지 않고 표시·규칙 누적을 끊는다. 500ms 안에 다음
유효 관측이 오면 예측 입력을 연결할 수 있지만, 지연 전 예측 큐·잔차는 비워 보간 구간을 잔차 정답으로 쓰지 않는다.
보간 좌표는 기준 등록의 실제 표본 수·자동 라벨·정상 자료에도 넣지 않는다. 카메라 시각과 실행 시작은
같은 `performance.now()` 축이며 첫 프레임의 처리 지연을 전체 관측 시각에 더하지 않는다.

화면에는 `predictionStatus`의 입력 준비 개수/30, 초기화 횟수·마지막 이유, 최근 간격과 카메라 처리 FPS를
표시한다. 입력 부족, 입력 준비 완료 뒤 새 예측 대기, 관측 실패를 구분한다. 상태 카운터에는 좌표가 없고
메모리 표시 전용이다. 수치 진단에는 선택 필드 `predictionInputMaxGapMs`, 실행 설정에는 해당 필드가
있는 경우에만 `predictor_max_gap_ms`를 넣는다. 과거 파일에 새 정책을 소급하지 않는다.
500ms는 개발용 지연 대응값이며 실제 정확도·빠른 동작의 보간 오차는 미검증이다.
[ADR 0030](../../../../docs/decisions/0030-predictor-cadence-recovery.md).


## 카메라 성능 실험

`DeveloperPerformance.tsx`와 `cameraBenchmark.ts`는 개발 화면 전용 계측·비교 도구다.
공통 어댑터의 선택 인자를 통해 Lite/Full/Heavy, GPU/CPU/auto, legacy/responsive 대기를
다음 연결 전에 지정한다. 일반 서비스의 생략 인자 기본값은 변경하지 않는다.
실측 후 `/dev` 기본값은 **Full + GPU 우선 + responsive**다. 서비스 기본값은 Heavy + legacy다.
실행 중에는 모델 변경을 막고, 모델 비교 중에는 다른 카메라 작업을 차단한다.
상세 방법·통계 해석·실제 검증 상태는 [성능 기록](../../../../docs/ml/camera-performance.md)을 따른다.
공식 추가 모델은 `node frontend/scripts/prepare-benchmark-assets.mjs`로 준비한다.
영상·좌표는 비교 동안 메모리에만 있으며 결과 JSON에는 집계 시간·품질율·장치 경로만 포함한다.

자동·수동 수집 및 개인 프로파일에 실제 `poseModelId`를 보존한다. 수집 중 추출기가 바뀌면
자동 구간을 나누고 수동 수집을 중단한다. 선택한 모델과 다른 개인 프로파일 또는 모델 정보가 없는
이전 프로파일은 보존하되 적용하지 않는다. 같은 모델로 다시 수집하거나 명시적으로 선택을 맞춘다.
기본 자산 준비는 Heavy+Full, 별도 비교 자산 준비는 Lite까지 포함한다.

## MediaPipe 자료 재학습

수동 수집의 `예측 모델 평가용 · 학습 제외`는 별도 `forecast-evaluation-collection-v1`로 내보낸다.
정상 라벨·개인 프로파일을 fitting하지 않으며 기존 정상 범위를 보존한다. 학습 reader와 manifest 생성은
이 스키마를 거부한다. [평가 계약](../../../../contracts/forecast-evaluation-collection.v1.md)을 따른다.

[학습 안내](../../../../docs/ml/mediapipe-training.md)의 manifest → validate → prepare → train 경로를 사용한다.
`DeveloperTraining`은 수집 화면에서 실제 명령과 모델 연결 순서를 안내한다. PyTorch는 별도 연구 환경의 기존 의존성이다.
MediaPipe v2 모델은 같은 추출기 ID에서만 실행한다. Full/Heavy/Lite 불일치나 ID 미상은 측정을 종료하고 설정 변경을 안내한다.
개인 pilot는 독립 평가가 없고 참여자 분리 평가는 좌표 예측 성능만 뜻한다. 자동 약라벨을 자세 정답으로 사용하지 않는다.
정상 자료가 없을 때는 등록 검증을 했다고 표시하지 않는다. 13점 카운트와 별도로 3D 입력 실패를 표시하며, 진단 export에는
추출기·실제 delegate·해상도·pacing·등록 검증 결과만 추가하고 좌표는 제외한다.

현재 새 종합 판정은 사용자 지정 **0.7배 초과 진입·약0.47배 이하 복귀**다. 표시·그래프·export는 각 reading의 경계를 읽고 없는 과거 기록은 1·2/3을 유지한다. 이탈/복귀3초·자동후보0.5배/1초·무음은 유지한다. [현재 경계](../../../../docs/decisions/0036-composite-entry-point-seven.md).
