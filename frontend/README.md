# PoseGood 웹캠 프로토타입

> **결정 변경(2026-10-11, [ADR 0021](../docs/decisions/0021-app-sends-information-server-judges.md))**: 앱은 판정하지 않고 관절 좌표만 보낸다.
> 화면·기록의 유형(머리·좌우 기울임) 표시와 csv 내보내기의 판정 열은 2026-10-11 없앴다.
> **2026-10-21(V3, [ADR 0025](../docs/decisions/0025-app-always-measures-on-server.md)):** 로컬 모드·앱 판정·이어하기를 지웠다. 앱은 항상 서버로 측정하고
> 서버가 보낸 결과만 보인다. 자세 등록은 앱이 관절 9개 3초 평균을 내서 B1로 보낸다([ADR 0026](../docs/decisions/0026-baseline-average-by-app-b1.md)).
> 로그인을 서버에 잇기(BE) 전에는 등록·측정이 「로그인이 필요해요」로 멈춘다.

## 데스크톱 앱 (2026-10-02~)

화면은 데스크톱 앱 기준으로 다시 설계했다. 탭은 **측정하기 · 기록 · 달력 · 설정** 4개다(달력은 2026-10-13 추가). 받아서 실행하는 순서는 [루트 README](../README.md#데스크톱-앱-받아서-실행하기-windows)에 있다. 2026-10-12에 따로 만든 「자세 등록」 탭(계획 0024, 끝나서 지움)은 2026-10-13 측정하기로 다시 합쳤다: 등록한 자세가 없으면 등록 후 바로 측정하고, 있으면 바로 측정한다.
[ADR 0017](../docs/decisions/0017-desktop-app-shell-and-redesign.md), [화면 설계](../docs/design/fe-server-proposal.md)(8.3)·[데스크톱 창](../docs/design/fe-server-proposal.md)(8.4), [DESIGN.md](../DESIGN.md).

```sh
npm run desktop      # 개발 서버와 Electron 창을 함께 실행
npm run desktop:dev  # 이미 켠 개발 서버(5173)에 창만 연결
```

Windows에서 `npm run desktop:pack`을 실행하면 프론트를 빌드한 뒤
electron-builder가 `frontend/release/win-unpacked/`에 앱을 만들고 `frontend/PoseGood.exe`에 작은 실행기를 만든다.
`frontend/PoseGood.exe`를 더블클릭하면 개발 서버 없이 앱이 열린다. 결과물은 Git에서 제외한다.
매 실행마다 파일을 임시 폴더에 푸는 작업을 없애 시작 시간을 줄였다.
실행기와 `release/win-unpacked/`는 함께 보관해야 한다. EXE 하나만 옮기면 실행되지 않는다.
실행기 빌드에는 Windows 기본 .NET Framework 4 C# 컴파일러가 필요하다.
단일 파일 배포가 필요할 때만 `npm run desktop:portable`을 사용한다. 결과는 `release/PoseGood.exe`이며
이 버전은 매 실행 시 압축 해제로 느릴 수 있다.
Windows 압축 해제 후 폴더 rename에서 발생한 `EPERM`을 피하려고 설치된 Electron 배포본을 복사한다.
이 명령은 Windows용이며 시작 프로그램 등록에는 휴대용 원본 EXE 경로를 사용한다.
패키징된 앱은 개발 서버 대신 `app://posegood`에서 빌드 화면과 MediaPipe 정적 파일을 제공한다.

패키징 후 `node scripts/smoke-desktop.mjs`로 숨긴 창·독립 임시 프로필·합성 카메라를 사용하는 EXE 검증을 실행한다.
앱 화면·preload IPC·보안 컨텍스트·Web Locks·모델/WASM 파일·카메라 연결과 모델 초기화를 확인한다.
실제 카메라·재부팅 후 시작 프로그램 실행·다른 PC에서의 실행은 별도 수동 확인 대상이다.

2026-10-02 검증: 프론트 테스트 242개·TypeScript 검사·Vite 빌드·Electron 메인 파일 문법 검사는 통과했다.
`npm run desktop:pack`과 실제 portable EXE smoke도 통과했다. 합성 카메라 640px 영상,
MediaPipe 모델 초기화, WASM·모델 HTTP 200, packaged IPC, 보안 컨텍스트·Web Locks를 확인했다.
빠른 실행기 전환 후 같은 검증도 통과했고, 이 PC의 독립 프로필에서 화면·IPC 준비까지 1008ms가 걸렸다.

2026-10-06 검증(미리보기 `v0.1.0-preview.20261006`): 프론트 테스트 254개·`tsc -b`·Vite 빌드, `npm run desktop:pack`,
`node scripts/smoke-desktop.mjs`(합성 카메라 640px, 모델 준비, 보안 컨텍스트·Web Locks, 시작 620ms)가 통과했다.
라운드 사각형 아이콘이 앱 화면·창·작업 표시줄·두 EXE에 들어간 것을 EXE에서 직접 꺼내 확인했다.
같은 경로의 EXE 아이콘을 바꾸면 탐색기가 이전 아이콘을 보여 줄 수 있다. `ie4uinit.exe -show`나 재시작으로 아이콘 캐시를 갱신한다.
`release/PoseGood.exe`(portable)는 `desktop:portable`로 다시 만들기 전까지 이전 빌드이므로 `frontend/PoseGood.exe`를 실행한다.
이는 한 번의 로컬 측정이며 다른 PC·디스크 캐시·보안 검사에 따라 달라진다.
전체 검증(`.venv/Scripts/python.exe tools/dev.py check`)은 Python 테스트 134개 중 오류 3개·건너뜀 1개로 실패했다
(POSIX 배포 잠금과 Windows 임시 파일 잠금). 저장소 구조 검사는 통과했다.
백엔드 검증은 Maven/Java 준비 부족, Compose 검증은 Docker daemon 미실행,
웹 브라우저 통합 검증은 백엔드 JAR 부재로 완료하지 못했다. 패키징 앱 자체 검증과 구분한다.

설정의 `컴퓨터를 켤 때`에서 시작 프로그램 등록(패키징된 앱만)과 자동 카메라 연결(기본 꺼짐)을 고른다.
서버 판정·자세 데이터 수집·발표용 예시 기록은 `개발자 옵션` 안으로 옮겼다. 아래 체험 순서의 메뉴 이름은
이전 화면 기준이다: `홈`/`측정 준비`/`실시간 측정` → `측정하기`, `대시보드` → `기록`, 예전 `자세 등록`(좌표 수집) → 설정의 `자세 데이터 수집`,
`일시정지` → `잠시 쉬기`, `상세 보기` → `자세히`.

## 자세 데이터 수집 바로가기와 카메라 창

로컬 개발 앱 주소 끝에 `/#collection`을 붙이면 프로필 없이 자세 CSV 수집 화면으로 들어간다.
현재 서버 예시는 `http://127.0.0.1:61341/#collection`이며 재실행 시 포트는 달라질 수 있다.
로그인 화면의 바로가기 링크는 2026-10-13 지웠다. 주소 끝 `/#collection`으로만 들어간다.
화면 위쪽에서 **찍을 자세·촬영 길이**를 먼저 고르고 카메라 연결·자세 등록·촬영·실제 자세 확인·CSV 다운로드를 진행한다.

기록·달력·설정으로 이동해도 카메라는 유지된다. 자세 등록 중 다른 화면으로 이동하면 등록은 취소한다.

**작은 카메라 창(2026-10-26, [ADR 0028](../docs/decisions/0028-no-web-camera-window-desktop-only.md)):** 웹(일반 브라우저)에는 없다.
Chrome은 카메라만 쓰는 페이지에 탭 전환 자동 PiP를 열지 않고, 클릭으로 연 창은 앱 탭에서도 떠 있어 지웠다.
웹은 다른 탭에 가도 측정이 이어진다(프레임 타이머를 Worker로, `src/features/camera/frameTimer.ts`). 같은 탭의 다른 사이트 이동·앱 닫기는 카메라를 종료한다.
데스크톱 앱은 PoseGood 창이 포커스를 잃거나 최소화되면 오른쪽 아래에 작은 창이 저절로 보이고, 앞으로 오면 숨는다
(`src/features/desktop/DesktopCameraWindow.tsx`, `electron/main.cjs`, [계획 0055](../docs/plans/active/0055-desktop-camera-window.md)). 수집 중 다른 탭으로 이동하면 촬영은 기존대로 중단된다.
자세 데이터 수집 자료는 자동 업로드하지 않는다. [결정과 수명 경계](../docs/decisions/0016-collection-entry-and-camera-preview-window.md).

`feature/retro-redesign`의 React 18 화면·폰트·레트로 디자인에 실제 웹캠을 통합한 단일 앱이다(`src/app/ServiceApp.tsx`).
MediaPipe Pose Landmarker Lite로 상체를 추적하고, 관절 좌표를 서버로 보내 서버가 판정한 상태를 표시한다(10/22 기준 서버 규칙 `reference-feature-rule-v1`, 학습된 LSTM은 아직 연결 전).
프로필·설정은 아직 브라우저 localStorage에 두고,
자세 데이터 수집 화면에서 좌표 CSV(수집 v3, 앱 판정 열 없음)를 명시적으로 촬영·다운로드할 수 있다.

## 로그인과 회원가입

첫 화면은 로그인이고 아래 「회원가입」으로 가입한다.
회원가입은 세 단계다: ① 약관·개인정보 동의 항목 C1~C6([동의 제안서](../docs/design/consent-proposal.md))(필수/선택마다 동의·비동의를 고름) ② 이메일·비밀번호·이름, 선택 정보(C3)에 동의했을 때만 나이·직업 ③ 자세 등록(선택, 「자세 등록」 화면 재사용).

가입·로그인·로그아웃은 항상 입출구 서버 `/v2/auth`([계약](../contracts/accounts.v2.md)) A1~A5로 한다(ghdrb1246 D-66 `f27dd24`를 2026-10-22 V3로 옮김, 스위치 없음).
CSRF 토큰, 로그인 쿠키(`credentials: 'include'`), 로그아웃에 `X-PoseGood-User-Id`, 비밀번호 12자 이상, 동의는 `consentPayload()`(`service-v2`).
앱을 다시 열면 `GET /v2/auth/me`로 로그인 상태를 되살린다. 로그인되면 `setServerAuth`로 기준 자세(B1·B2)와 측정(S1)이 같은 계정·CSRF 토큰을 쓴다.
프로필은 화면이 읽도록 이 기기에도 사본을 둔다(비밀번호는 저장하지 않음).
코드는 `src/features/auth/accountClient.ts`(요청·오류 문구)와 `src/app/LocalServiceApp.tsx`(화면 흐름)다.
비밀번호 변경·탈퇴·선택 동의 철회·설정(W1·W2)은 아직 연결하지 않았다([FE 제안서](../docs/design/fe-server-proposal.md) 7.2).
예전 화면 시험(`src/app/ServiceApp.test.tsx`)만 계정 클라이언트를 「없음」으로 바꿔 이 기기 로그인으로 돈다. 이 시험 전용 경로는 [계획 0054](../docs/plans/active/0054-pip-fix-and-server-only-login.md) 2단계에서 지운다.

## 로컬 프로토타입 실행

Node.js 24 이상, npm, Python 3.9 이상을 준비한다. 저장소 루트에서:

```sh
make setup
make dev
```

`http://127.0.0.1:5173/`에서 연다. 프론트만 준비하려면 `make setup-frontend`, 검증은 `make check`.
`make`가 없는 Windows에서는 `python tools/dev.py setup` / `dev` / `check`로 같은 대상을 실행한다.
웹캠은 localhost 또는 HTTPS에서 사용한다. 내장 미리보기에서 권한을 지원하지 않으면 Chrome에서 같은 주소를 연다.
최초 설치 시 npm 패키지와 공식 Google 모델을 받는다. `model-asset.json`의 SHA-256으로 모델을 검증하며
모델·WASM은 Git에서 제외한 `public/mediapipe/`에 둔다. 이후 실행은 로컬 자산을 재사용한다.

Mac의 제한된 실행 환경에서 native FSEvents 감시가 대기해 서버 주소가 나오지 않으면 다음처럼 실행한다. 파일 감시만 polling으로 바꾸며 보안 설정은 변경하지 않는다. 변경 감지 주기는 1초다.

```sh
CHOKIDAR_USEPOLLING=1 make dev
```

## 개발 서버 판정

JDK 17과 시험용 MySQL([backend 안내](../backend/README.md))을 준비하고 `make check-backend`로 JAR를 생성한 뒤 `make dev-server`를 실행한다.
출력된 임시 포트 주소의 앱을 연다. 2026-10-21부터 앱은 항상 서버로 측정·자세 등록을 한다(선택 스위치 없음).
Ctrl+C로 프론트·API·추론을 함께 종료하고 임시 DB를 지운다.
서버 측정은 계정이 필요하다([ADR 0020](../docs/decisions/0020-single-api-decision-engine.md)). 로그인을 BE `/v2/auth`에 잇기 전까지
등록·측정은 「로그인이 필요해요」로 멈춘다(로그인 뒤 `features/platform/serverAuth.ts`의 `setServerAuth`가 계정 정보를 넘긴다).
수동 API를 연결할 때만 `POSEGOOD_API_URL=http://127.0.0.1:<포트>`를 지정한다. 실시간 채널은 같은 `/api` 중계(`/api/v2/realtime`)로 간다.

측정(`src/features/session/live/`, BE 명세 7·11장): 「측정 시작」 → S1 `PUT /v2/sessions/{id}` `{policy, baseline_id}` → WebSocket `/v2/realtime` `hello` → `ready`(5초) →
0.5초마다 관절 9개 좌표 구간 1개(`posture.frames.v1`) → 「측정 종료」 `end` → `closed(ended)`(10초 안에 안 오면 S4로 결과).
잠시 쉬기는 `rest`, 카메라 영상이 1초 넘게 멈추면 `away`(카메라가 돌아와야 「측정 재개」), 쓰던 카메라가 빠지거나 영상 크기가 바뀌거나 데스크톱 앱 작은 창의 X를 누르면 `end`.
어깨가 하나라도 안 보이는 프레임은 바로 `valid:false`로 보낸다(2026-10-22, 유예 없음). 지속·복귀·재알림 판정과 점수·통계는 모두 서버가 한다.
연결이 끊기면 그 측정은 끝나고 서버가 마지막 구간까지 저장한다(재연결·재전송 없음, [ADR 0024](../docs/decisions/0024-session-ends-on-lost-connection.md)).
진행 중 판정 상태는 API 메모리에 있어 API를 재시작하면 진행 중 세션은 `session_lost`로 끝난다.

## 체험 순서

1. 로그인하거나 회원가입한다(로그인을 서버에 잇는 것은 BE 작업). 프로필은 로그인이 서버에 붙기 전(F12)까지 이 브라우저에만 저장한다.
   처음이면 자세 등록을 하도록 `측정하기`로 이동한다.
2. `측정하기` → `카메라 켜기`. 새 측정은 실제 웹캠만 사용한다. 얼굴과 양쪽 어깨가 보이도록 정면에 앉는다. 카메라는 로그인만으로 켜지지 않는다.
3. 얼굴과 양쪽 어깨가 보이면 "3초 뒤 측정이 시작돼요" 3·2·1 뒤 3초(판정 가능 프레임 20장 이상) 동안 관절 9개 평균을 내서 서버(B1)에 저장하고, 끝나면 측정을 스스로 시작한다. 서버가 저장하지 못하면 이유를 보여 준다. 가림·유실 시 처음부터 다시 하고, 15초 안에 끝나지 않으면 멈추고 이유를 알린다. `측정 종료`로 멈출 수 있다. 이미 등록했으면 `다시 등록`을 누를 때만 다시 하며, 새 자세가 완성될 때까지 기존 자세를 유지한다. 측정 중에는 다시 등록할 수 없다. 점선 안내는 감지된 어깨 너비에 맞춰 따라간다.
4. 등록한 자세가 있으면 얼굴·어깨가 보일 때 카메라 화면의 `측정 시작`으로 바로 시작한다. 보정 없이 등록한 자세와 비교한다. 등록한 자세는 서버에 하나이고 카메라와 상관없이 쓴다(B2로 받아 옴). 서버가 자세 이탈을 확정하면(기본 3초 지속) 화면 알림을 표시한다.
5. `잠시 쉬기`로 휴식한다. 휴식·판정 불가 시간은 서버가 유효 시간에서 제외한다.
6. `측정 종료`에서 서버가 보낸 이번 세션 통계를 확인한다. 기록 화면이 서버 기록(R1)을 읽기 전까지 결과를 이 브라우저에도 남긴다.
   측정하기·자세 등록·자세 데이터 수집 사이에는 스트림을 공유한다. 로그아웃 시 해제한다.
7. 카메라 없이 홈·기존 기록을 볼 수 있다. 발표용 예시 기록·합성 시연 기록은 지울 예정이다([FE 제안서](../docs/design/fe-server-proposal.md) 7.2).
8. 사이드바 하단 계정 메뉴의 `프로필 설정`에서 이름·나이·직업 수정과 로컬 자료 삭제(탈퇴 체험)를 할 수 있다.

## 알림과 기록

기본 시간 정책과 설정 적용 범위는 [ADR 0012](../docs/decisions/0012-session-timing-policy.md)에서 확정했다. 2026-10-21부터 이 정책은 서버만 적용하고, 앱은 설정값을 측정 시작 때 S1 `policy`로 보낸다(아래는 서버 판정의 규칙이다).

확정한 기본 시간 정책은 이탈이 3초 연속 지속되면 최초 알림, 정상 자세가 3초 연속 유지되면 복귀(2026-10-06 2초 → 3초 개정),
같은 사건이 계속되면 직전 실제 알림부터 60초마다 재알림이다. 복귀·휴식·측정 불가로 기존 사건이 끝난 뒤
새 이탈이 3초 지속되면 새 사건을 만들고 최초 알림을 제공한다. 새 사건의 최초 알림에는 이전 사건의 60초 간격을 적용하지 않는다.

휴식·저품질·인식된 관측 공백은 진행 중 사건을 중단하고 이탈 확인·복귀 확인의 연속 누적을 초기화한다.
그 시간은 유효 측정·기준 유지 시간에서 제외하며, 이미 측정한 세션 전체 통계와 이전 사건 기록은 유지한다.
저품질 상태는 유효 입력이 돌아오면 새 연속 판정을 시작한다. 타이머 공백이나 카메라 입력 중단으로
자동 일시정지된 경우에는 사용자가 직접 재개해야 한다.

설정 화면에서 지속시간(기본 3초), 재알림 간격(60초), 정상 복귀 유지시간(3초), 변화 점수 임계값을 바꾼다.
기존 개발 서버 모드는 화면 알림을 유지한다. 시간 설정은 모델 재학습 없이 동작한다.
변경한 설정은 다음에 시작하는 측정에 적용되며 진행 중인 측정과 복구한 중단 기록에는 시작 당시 설정을 유지한다.
점수·측정 품질 임계값은 검증 전 값이다. 관측 공백을 인식하는 현재 구현 기준인 카메라 프레임 1초·타이머 1.5초도
이번 시간 정책 확정에 포함하지 않는다. 모든 짧은 프레임 누락을 즉시 감지하거나 그 전체 시간을 제외하는 구현은 아니다.
알림 횟수·복귀 시간은 서버 확정·재알림 결정 기준이며 소리 전달 성공 여부와 구분한다.
발생 간격은 같은 세션 안에서 계산한다. 유효 시간 기준 발생 시각이 있는 새 기록은 휴식·판정 불가·인식된 공백 시간을
뺀 유효 시간 축을 사용하므로 중단 전후의 사건도 비교할 수 있다. 유효 발생 시각이 없는 과거 기록은 제외 시간을
추측하지 않고 같은 연속 측정 구간의 사건만 연결한다. 서로 다른 세션의 사건은 연결하지 않는다.

측정 결과는 서버가 저장한다. 앱이 닫히거나 연결이 끊겨도 서버가 마지막 구간까지 저장한다(2026-10-21, 중간 저장·이어하기 없음). 쓰던 카메라가 빠져도 그때까지 저장하고 측정을 끝낸다.
기록 화면이 서버 기록(R1)을 읽기 전까지 결과를 이 브라우저에도 R1과 같은 형식으로 남긴다.
`기록` 탭은 오늘 기록, `달력` 탭은 최근 1년 잔디·월 달력(날마다 유지율 링)·고른 날의 기록·최근 7일/30일(주 단위) 흐름을 보여준다.
설정의 **`발표용 예시 기록 표시`**(새 저장소 기본 꺼짐; 기존 선택 유지)를 켜면 같은 `기록`·`달력` 화면에 고정 시드로 만든 약 4개월치 예시 기록(`src/data/exampleRecords.ts`, 저장하지 않음)을 보여주고 화면에 발표용 예시임을 표시한다(2026-10-14, 예전 예시 대시보드 대체).
로컬 기록은 기본 합산하며 `실제 웹캠 기록`/`합성 시연 기록`으로 따로 조회할 수 있다. 처음/최근 비교 칸은 2026-10-14에 없앴다. 자정 세션은 시작일 기준이다.

**서버 연동 뒤의 표시 기준(2026-10-22):** 서버 통계(T1)는 어제까지 제공·표시하고, 오늘 목록·요약·달력 링·잔디·기간 그래프의 오늘 값은 로컬에 수집한 서버 세션 요약·사건·종료 결과로 만든다. 오늘 집계 처리는 서버 연동 뒤에도 남긴다. 기간 화면에서는 서버의 과거 통계와 로컬 오늘 값을 함께 사용하되 같은 날짜·세션을 중복 합산하지 않는다. 표시별 출처와 날짜 기준은 [연동 명세 4.5](../docs/design/api-ws-spec.md#45-기록통계-r1r1br3t1-be-다음-주-범위)를 따른다. 현재 기록·달력은 전체 기간을 로컬에서 집계하며 서버 통계 조회는 아직 연결되지 않았다.

## 구현과 한계

기록의 `상세 보기`에서 적용 설정·유효/제외 시간과 사건을 확인한다. 서버 기록에는 원래 사건의 좌우 방향·중단 사유·제외 시간 구성을 표시하며
서버 종료 미확인 자료는 마지막 확인 요약과 보관 시각으로 안내한다. 없는 과거 기준·모델·제외 구성은 추정하지 않는다.
처음/최근 비교 칸은 2026-10-14에 제거됐다. 모델명·모델 버전·특징 버전은 개발·연동용 내부 정보이며 실제 서비스의 측정·기록·통계·비교 화면에는 표시하지 않는다(2026-10-22 결정, [내부 관리 기준](../contracts/README.md#모델명특징-버전의-내부-관리)). API 식별자·검증과 기존 합산/제외 기준은 유지한다. 이 문서 정리는 화면 구현·검증 완료를 뜻하지 않는다.

탈퇴·서버 종료 미확인 요약 보관 확인창은 취소 버튼에 초기 초점을 둔다. Tab/Shift+Tab으로 창 안에서 이동하고
Esc·배경 클릭·취소로 닫으면 실행 버튼에 초점을 돌린다. 실행 버튼이 사라지면 새 화면의 주영역으로 이동한다.
처리 중 중복 실행과 취소를 막고 배경 화면 조작을 차단한다. 합성 브라우저 게이트에서 두 확인창의 키보드 동작을 확인한다.

`make check-browser`는 Chrome/Chromium·서버 JAR·프로덕션 프론트 빌드가 필요하다. `make check`는 준비 순서대로 이를 실행한다.
별도 실행 전에는 `make check-frontend`와 `make check-backend`를 실행한다. 설치된 Chrome을 자동으로 찾지 못하면 실행 파일의 경로를
`POSEGOOD_CHROME`에 지정한다. 합성 입력은 명시적 개발 테스트 모드에서만 사용하며 일반 개발/preview/프로덕션에서는 활성화하지 않는다.

- 판정 가능 프레임 검사: `model/prototype/pose.ts` `measurable`·`shouldersVisible`(코·양 어깨·양 귀). 앱은 특징값·점수를 계산하지 않는다(2026-10-22 고개 돌림·머리 판정·특징값 계산 삭제).
- 서버 측정: `src/features/session/live/`(S1·`/v2/realtime`·화면). 기록 속 서버 결과 형식·검증은 `src/features/session/server/`. 로컬 시간 정책(`engine/`)은 2026-10-21 지웠고 `src/lib/engine.ts`에는 타입만 남았다.
- 자세 등록: `src/features/baseline/`(관절 평균·B1·B2). 서버 요청 공통: `src/features/platform/api.ts`.
- 앱 조립·화면 전환: `src/app/ServiceApp.tsx`. 프로필·세션 저장/복구·기록 조회·저장 검증은 `src/features/`에서 기능별로 관리한다.
- 로컬 저장: `src/features/storage/`(프로필·설정·기록 복사). 중간 저장(draft)은 2026-10-21 지웠다.
- 카메라 생명주기: `src/hooks/useCamera.ts`. 같은 스트림을 모든 화면과 데스크톱 앱 작은 창에서 공유하고 명시적 사용 종료·측정 종료·로그아웃·인증 변경 시 해제한다. 일반 화면 이동은 진행 중 자세 등록만 취소한다. 등록한 자세는 서버에 있다.
- 영상·음성은 저장하지 않고 외부 API 업로드도 없다. 자세 데이터 수집에서 촬영을 직접 시작하면 추정 랜드마크·촬영 조건·자기 보고 확인을 메모리에 모아 CSV로 다운로드한다.
- 서비스 측정은 앱 안의 기록·설정 화면으로 이동해도 계속된다(2026-10-06 사용자 결정, 카메라는 떠 있는 창으로 유지). 외부 탭 전환만으로도 정지하지 않는다. 카메라 영상이 1초 넘게 멈추면 `away`로 보내고 직접 재개해야 한다. 실제 다른 탭·최소화·절전 지원은 별도 장치 검증이 필요하다. 연구 수집은 탭 숨김 시 중단한다.
- 정면 상대 변화만 보는 체험용 규칙이다. 깊이 이동·가림·조명·체형에 오탐/미탐이 있을 수 있다.
- 가시성 0.65, 특징 임계값, 3초(최소 20표본) 등록은 검증 전 값이다. 연구용 20~30초 등록이나 정확도 검증을 대체하지 않는다.
- 카메라를 옮기거나 장치를 바꾸면 기준을 다시 등록한다. GPU 우선(불가 시 CPU)으로 추론한다. 최대 GPU 30회/초·CPU 20회/초이며 추론이 느리면 주기를 낮춘다. 스켈레톤만 화면 주기에 맞춰 평활화한다. 실제 FPS와 추론 ms는 준비·측정 화면에 표시한다. 추론은 아직 메인 스레드다.

구현 참고: [MediaPipe 웹 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js).

## 자세 데이터 수집 (안내형 좌표 수집)

화면 이름은 `자세 데이터 수집`이며 설정 › 개발자 옵션에서 연다([ADR 0017](../docs/decisions/0017-desktop-app-shell-and-redesign.md)). 사이드바의 「자세 등록」은 기준 자세 등록 탭으로 이 화면과 다르다([계획 0024](../docs/removed-docs.md)). 코드는 `CollectionPage`, `useCollection`이고 CSV는 [수집 v3](../docs/research/guided-collection-v2.md)(좌표·촬영 조건·자기 보고 확인만, 앱 판정 열 없음)다.
자세 등록 후 설정 › 개발자 옵션의 `자세 데이터 수집`을 연다. 측정이 진행 중이면 먼저 종료해야 한다.
화면 상단에서 카메라 켜기/끄기·준비 취소·자세 등록/등록 취소를 할 수 있다. 등록 목적과 3단계 안내가 있고, 카메라 방향·거리·높이·책상 배치는 접이식 `카메라·책상 환경`에 있다.
찍을 자세 선택 → `준비됐어요 · 5초 뒤 촬영 시작` → 10/20/30/60초 촬영 → 실제 자세 확인(`맞아요 · 이대로 저장`) 또는 제외 → CSV 다운로드 순서다.
자세, 공책 읽기/필기, 양쪽 모니터 보기, 고개 돌리기, 자리 비움/복귀, 얼굴 가림 등 14개 자세를 제공한다.
전용 화면에는 규칙 점수·교정 알림이 없다. 미검출도 관측으로 기록하며 부재 정답은 촬영 후 확인한다.
등록한 자세가 현재 판정에 바로 반영되지는 않는다. 개인화 학습은 미연결이며, CSV 전달은 사용자가 별도로 결정하며 앱이 연구팀에 자동 전송하지 않는다.
미확인/제외 구간을 학습 정답으로 쓰지 않는다. 화면 이동·탭 숨김·카메라 해제 시 중단하고 다시 촬영한다.
다운로드 전 데이터는 메모리에만 남는다. 실제 파일은 Git에 추가하지 않는다.
[수집 v3 지침과 pandas 예제](../docs/research/guided-collection-v2.md)를 참고한다.

## 점수와 표시 모드

자세 점수는 서버가 보낸 붕괴 확률로 100×(1−collapse_probability)를 표시한다. 100점에 가까울수록 바른 자세다. 언제 알릴지는 서버가 정하고 앱은 서버의 `alert`를 그대로 보인다(2026-10-21, ADR 0025).
설정도 같은 점수 방향으로 표시한다. 예전 수집 CSV(v1·v2)의 `rule_score`는 종전의 변화 점수이므로 `100 * (1 - rule_score)`로 환산한다. 수집 v3에는 이 열이 없다.
전체 키포인트는 Pose의 눈·입·귀·몸·팔·다리 중 보이는 점을 표시한다. 턱 추적은 포함하지 않는다.
웹캠 준비/측정의 `매트릭스 효과`는 점이 모이는 장식용 연출이다. `다시 모으기`, `애니메이션 줄이기`를 제공한다.
측정 화면의 `키포인트 표시`를 끄면 효과도 숨긴다. 추가 학습 데이터나 실제 3D 모델이 아니다.

## 저장소 오류와 여러 탭

프로필·설정·측정 요약을 검증한다. 손상/접근 오류가 있으면 원본을 유지하고 새 측정이나 변경을 차단한다. 오류 안내에서 다시 읽을 수 있지만 손상 원본을 자동 복구하거나 삭제하지 않는다. 같은 origin의 한 탭만 변경할 수 있고 두 번째 탭은 기록을 조회한다. 기존 탭을 닫은 뒤 `저장 권한 다시 확인`으로 변경 권한을 요청한다. Web Locks가 없는 환경은 읽기 전용이며 최신 Chrome의 localhost/HTTPS를 권장한다.

측정 기록의 저장은 서버가 맡는다(2026-10-21 이어하기·중간 저장 삭제). 측정 시작(S1)과 자세 저장(B1)은 응답이 없거나 502·503이면 같은 내용으로 1·2·4초 뒤 다시 보낸다(2026-10-22). 카메라 준비는 30초가 넘으면 멈추고 다시 시도하게 하며, 그 전에 취소할 수 있다. 취소 후 늦게 도착한 스트림/모델은 해제하지만 브라우저의 권한 창 자체를 앱에서 닫지는 못한다.
