# PoseGood 웹캠 프로토타입

## 데스크톱 앱 (2026-10-02~)

화면은 데스크톱 앱 기준으로 다시 설계했다. 탭은 **측정하기 · 기록 · 설정** 3개다.
[ADR 0017](../docs/decisions/0017-desktop-app-shell-and-redesign.md), [화면 설계](../docs/design/desktop-app.md), [DESIGN.md](../DESIGN.md).

```sh
npm run desktop      # 개발 서버와 Electron 창을 함께 실행
npm run desktop:dev  # 이미 켠 개발 서버(5173)에 창만 연결
```

Windows 휴대용 EXE 패키징 설정은 `npm run desktop:pack`이다. 프론트를 빌드한 뒤
electron-builder가 `frontend/release/PoseGood.exe`를 만들도록 구성했다. 결과물은 Git에서 제외한다.
패키징된 앱은 개발 서버 대신 `app://posegood`에서 빌드 화면과 MediaPipe 정적 파일을 제공한다.

2026-10-02 커밋 시점: 이전 EXE 빌드는 `ElectronFramework.unpack` 단계에서 실패했으며
원인은 확인되지 않았다. 이번 커밋 작업에서는 EXE 빌드를 재시도하지 않았다.
프론트 테스트 242개·TypeScript 검사·Vite 빌드와 Electron 메인 파일 문법 검사는 통과했다.
전체 검증(`python tools/dev.py check`)은 Python 테스트 109개 중 오류 8개·건너뜀 1개로 실패했다
(fastapi 누락 및 Windows에서 지원하지 않는 POSIX 배포 잠금). EXE 실행·카메라 권한·시작 프로그램 등록은 미검증이다.

설정의 `컴퓨터를 켤 때`에서 시작 프로그램 등록(패키징된 앱만)과 자동 카메라 연결(기본 꺼짐)을 고른다.
서버 판정·자세 데이터 수집·발표용 예시 기록은 `개발자 옵션` 안으로 옮겼다. 아래 체험 순서의 메뉴 이름은
이전 화면 기준이다: `홈`/`측정 준비`/`실시간 측정` → `측정하기`, `대시보드` → `기록`, `자세 등록` → 설정의 `자세 데이터 수집`,
`일시정지` → `잠시 쉬기`, `상세 보기` → `자세히`.

## 자세 데이터 수집 바로가기와 카메라 창

로컬 개발 앱 주소 끝에 `/#collection`을 붙이면 프로필 없이 자세 CSV 수집 화면으로 들어간다.
현재 서버 예시는 `http://127.0.0.1:61341/#collection`이며 재실행 시 포트는 달라질 수 있다.
시작 화면의 **프로필 없이 자세 데이터 수집**도 같은 진입점이다. 계정 모드는 기존 로그인 후 메뉴를 사용한다.
화면 위쪽에서 **찍을 자세·촬영 길이**를 먼저 고르고 카메라 연결·기준 등록·촬영·실제 자세 확인·CSV 다운로드를 진행한다.

카메라를 켜면 이동 가능한 미리보기 창을 제공한다. 제목 드래그나 제목에 초점을 둔 방향키로 위치를 옮기고,
오른쪽 아래 모서리로 크기를 변경한다. 접기는 미리보기만 숨기며 **카메라 사용 종료**가 스트림을 해제한다.
홈/기록으로 이동해도 카메라는 유지된다. 기준 보정 중 다른 일반 화면으로 이동하면 보정은 취소한다.

Chrome 등 지원 브라우저에서 **카메라 작은 창 열기**를 누르면 다른 사이트 위에서도 보이는 PiP 창을 연다.
지원·허용된 브라우저는 탭 전환 자동 PiP도 사용할 수 있다. 자동 실행은 브라우저 설정에 의존하며 버튼으로 직접 열 수 있다.
다른 사이트는 새 탭으로 열고 원래 앱 탭을 남겨 두어야 한다. 같은 탭의 다른 사이트 이동·앱 닫기는 카메라를 종료한다.
Codex 인앱 브라우저처럼 PiP가 없는 경우 앱 내부 창만 제공한다. 수집 중 다른 탭으로 이동하면 촬영은 기존대로 중단된다.
자세 등록 자료는 자동 업로드하지 않는다. [결정과 수명 경계](../docs/decisions/0016-collection-entry-and-camera-preview-window.md).

`feature/retro-redesign`의 React 18 화면·폰트·레트로 디자인에 실제 웹캠을 통합한 단일 앱이다(`src/app/ServiceApp.tsx`).
MediaPipe Pose Landmarker Lite로 상체를 추적하고, 5초 개인 기준과 비교하는 실험용 규칙으로 상태를 표시한다.
학습된 LSTM은 미연결이다. Compose 계정 모드는 MySQL·이메일/비밀번호 인증·서버 영구 기록을 사용한다.
기존 로컬 프로토타입은 선택형 개발 서버 판정과 브라우저 localStorage를 유지하고,
자세 등록 화면에서 좌표·자세 CSV를 명시적으로 촬영·다운로드할 수 있다.

## 실제 계정 모드

[Compose 실행](../infra/README.md): `make init-compose` 후 `docker compose up -d --build --wait`로 실행한다.
계정별 프로필·설정·기록은 서버에서 읽고 저장한다. 중간 재시도 자료는 사용자별 sessionStorage에 두며
같은 탭에서 같은 계정으로 로그인한 경우 복구한다. 계정 변경/만료는 카메라와 전송을 중단한다.
로그아웃은 화면 자료를 정리하고 완료 기록을 localStorage에 복사하지 않는다. 기존 로컬 자료를 자동 업로드하지 않는다.
비밀번호 변경 후 다시 로그인하며 탈퇴에는 현재 비밀번호와 CSRF 검증이 필요하다.
새 가입의 보관 동의는 연구 활용 동의와 구분한다. [계약](../contracts/accounts.v1.md)을 따른다.

계정 모드는 `VITE_SERVER_ACCOUNTS=true` 빌드에서 활성화된다. 앱 조립은 accounts 기능과 LocalServiceApp을
선택하고 측정/기록의 표현 화면은 공유한다. `make check-compose`가 실제 계정 UI를 합성 카메라로 검증한다.

## 로컬 프로토타입 실행

Node.js 24 이상, npm, Python 3.9 이상을 준비한다. 저장소 루트에서:

```sh
make setup
make dev
```

`http://127.0.0.1:5173/`에서 연다. 프론트만 준비하려면 `make setup-frontend`, 검증은 `make check`.
`make`가 없는 Windows에서는 `python tools/dev.py setup` / `dev` / `check`로 같은 대상을 실행한다.
웹캠은 localhost 또는 HTTPS에서 사용한다. 내장 미리보기에서 권한을 지원하지 않으면 Chrome에서 같은 주소를 연다.
최초 설치 시 npm 패키지와 공식 Google 모델을 받는다. `model-asset.json`의 SHA-256으로 모델을 검증하며
모델·WASM은 Git에서 제외한 `public/mediapipe/`에 둔다. 이후 실행은 로컬 자산을 재사용한다.

Mac의 제한된 실행 환경에서 native FSEvents 감시가 대기해 서버 주소가 나오지 않으면 다음처럼 실행한다. 파일 감시만 polling으로 바꾸며 보안 설정은 변경하지 않는다. 변경 감지 주기는 1초다.

```sh
CHOKIDAR_USEPOLLING=1 make dev
```

## 개발 서버 판정

JDK 21·Maven을 준비하고 `make check-backend`로 JAR를 생성한 뒤 `make dev-server`를 실행한다.
출력된 임시 포트 주소에서 ‘측정 준비 → 서버 판정 사용’을 선택하고 카메라·기준 등록을 완료한다.
Ctrl+C로 프론트·API·추론·CEP를 함께 종료한다. 이 선택은 기본 꺼짐이며 측정 시작 시 고정한다.
일반 `make dev`는 기본 로컬 모드다. 수동 API를 연결할 때만 `POSEGOOD_API_URL=http://127.0.0.1:<포트>`를 지정한다.

서버 모드는 개인 기준 대비 머리 높이·좌우 치우침·어깨 기울기 변화량과 품질만 전송한다.
추론은 `reference-feature-rule-v1` 규칙이고 지속·복귀·재알림은 CEP가 판단한다. 로컬 시간 엔진을 실행하지 않는다.
실제 인접 프레임 간 구간을 끝 프레임 특징으로 근사하며 1초 초과 프레임 공백은 전송하지 않는다.
서버가 제공하지 않는 진행률·카운트다운은 표시하지 않는다. 품질 0.65·특징 스케일은 검증 전 값이다.

전송은 한 번에 하나이며 미확인 요청을 그대로 재시도한다. 요청 전 고정 기준·장치·영상 크기와 미확인 본문 하나를
브라우저 중간 기록에 보관한다. 저장 실패·입력 단절·큐 포화 후에는 직접 재개한다.
새로고침 시 서버 확인 후 원래 기준으로 복구하며 장치/영상 크기와 사용자의 위치 확인을 요구한다.
서버가 세션을 잃으면 같은 ID로 새 세션을 만들지 않는다. ‘확인된 요약만 보관’은 서버 종료 미확인으로 기록한다.
종료 성공 기록에는 서버 원래 사건·통계와 모델/기준 ID를 남기고 임시 요청·기준을 정리한다.

개발 서버는 메모리 저장·세션당 최대 10,000개 관측이다. 10Hz로 전송하면 약 16분 40초, 30Hz면 약 5분 33초에
한도에 도달할 수 있다. 한도 전 종료 안내와 확정 거부 후 종료 경로를 제공하며 장시간 사용은 검증하지 않았다.
이 메모리 개발 모드는 서버 재시작·인증·DB 복구를 지원하지 않는다. Compose는 계정과 API/CEP 복구를 제공한다. [연결 결정](../docs/decisions/0013-frontend-server-feature-connection.md),
[영구 저장·인증 설계](../docs/design/server-persistence-and-auth.md)를 따른다.

## 체험 순서

1. 첫 화면에서 이름·나이·직업을 입력하고 시작한다. 실제 계정·인증은 없으며 프로필은 이 브라우저에만 저장한다.
   처음이면 `측정 준비`로, 프로필이 있으면 `홈`으로 이동한다.
2. `측정 준비` → `카메라 켜기`. 새 측정은 실제 웹캠만 사용한다. 얼굴과 양쪽 어깨가 보이도록 정면에 앉는다. 카메라는 로그인만으로 켜지지 않는다.
3. `기준 등록 시작`을 누르고 편안한 자세로 5초 유지한다. 가림·유실 시 연속 등록은 처음부터 다시 시작한다. 다시 보정할 때는 새 기준이 완성될 때까지 기존 기준을 유지하며 `보정 취소`를 제공한다.
4. `측정 시작` 후 머리·어깨를 천천히 움직인다. 기준 변화가 기본 3초 지속되면 이벤트와 화면 알림을 표시한다.
   사이드바의 `실시간 측정`은 `측정 준비` 아래 하위 탭으로, 준비·측정 중에만 보인다.
5. `일시정지`로 휴식한다. 휴식·판정 불가 시간은 유효 시간에서 제외하고 진행 중 이벤트를 복귀와 구분해 종료한다.
6. `측정 종료`에서 이번 세션 통계를 확인하고 결과가 이 브라우저에 저장된다.
   준비·측정·자세 등록 사이에는 스트림을 공유하고, 홈·대시보드·설정으로 나가면 해제한다(측정 진행 중이면 유지). 로그아웃 시에도 해제한다.
7. 카메라 없이 홈·기존 기록을 볼 수 있다. 준비 화면에는 새 시연 측정 선택이 없으며 과거 합성 시연 기록·중간 저장은 보존한다. 발표 화면 예시는 설정에서 명시적으로 켤 수 있다.
8. `설정` 아래 하위 탭 `프로필 설정`에서 이름·나이·직업 수정과 로컬 자료 삭제(탈퇴 체험)를 할 수 있다.

## 알림과 기록

기본 시간 정책과 설정 적용 범위는 [ADR 0012](../docs/decisions/0012-session-timing-policy.md)에서 확정했다.

확정한 기본 시간 정책은 이탈이 3초 연속 지속되면 최초 알림, 정상 자세가 2초 연속 유지되면 복귀,
같은 사건이 계속되면 직전 실제 알림부터 60초마다 재알림이다. 복귀·휴식·측정 불가로 기존 사건이 끝난 뒤
새 이탈이 3초 지속되면 새 사건을 만들고 최초 알림을 제공한다. 새 사건의 최초 알림에는 이전 사건의 60초 간격을 적용하지 않는다.

휴식·저품질·인식된 관측 공백은 진행 중 사건을 중단하고 이탈 확인·복귀 확인의 연속 누적을 초기화한다.
그 시간은 유효 측정·기준 유지 시간에서 제외하며, 이미 측정한 세션 전체 통계와 이전 사건 기록은 유지한다.
저품질 상태는 유효 입력이 돌아오면 새 연속 판정을 시작한다. 타이머 공백이나 카메라 입력 중단으로
자동 일시정지된 경우에는 사용자가 직접 재개해야 한다.

설정 화면에서 지속시간(기본 3초), 재알림 간격(60초), 정상 복귀 유지시간(2초), 변화 점수 임계값을 바꾼다.
기존 개발 서버 모드는 화면 알림을 유지한다. 계정 모드는 설정의 알림 선택을 서버에 보관하고 화면/소리 전달에 적용하되 CEP 사건·통계는 계속 기록한다. 시간 설정은 모델 재학습 없이 동작한다.
변경한 설정은 다음에 시작하는 측정에 적용되며 진행 중인 측정과 복구한 중단 기록에는 시작 당시 설정을 유지한다.
점수·측정 품질 임계값은 검증 전 값이다. 관측 공백을 인식하는 현재 구현 기준인 카메라 프레임 1초·타이머 1.5초도
이번 시간 정책 확정에 포함하지 않는다. 모든 짧은 프레임 누락을 즉시 감지하거나 그 전체 시간을 제외하는 구현은 아니다.
로컬 모드에서는 알림을 꺼도 이벤트는 기록하며 실제 표시한 알림을 횟수와 회복 시간의 기준으로 삼는다.
서버 모드의 횟수·복귀 시간은 CEP 확정·재알림 결정 기준이며 소리 전달 성공 여부와 구분한다.
발생 간격은 같은 세션 안에서 계산한다. 유효 시간 기준 발생 시각이 있는 새 기록은 휴식·판정 불가·인식된 공백 시간을
뺀 유효 시간 축을 사용하므로 중단 전후의 사건도 비교할 수 있다. 유효 발생 시각이 없는 과거 기록은 제외 시간을
추측하지 않고 같은 연속 측정 구간의 사건만 연결한다. 서로 다른 세션의 사건은 연결하지 않는다.

측정 결과는 종료 시 브라우저 localStorage에 저장하고, 진행 중에는 중간 저장 지점을 남겨 새로고침 후 이어하기/종료를 고를 수 있다.
저장 실패 시 결과를 유지한 채 자동·수동 재시도한다.
홈·대시보드는 설정의 **`발표용 예시 기록 표시`**(새 저장소 기본 꺼짐; 기존 선택 유지)에 따라 발표용 예시 데이터 또는 실제 저장 기록을 보여준다.
예시 데이터는 가짜이며 화면에 발표용 예시임을 표시한다. 로컬 기록은 기본 합산하며 `실제 웹캠 기록`/`합성 시연 기록`으로 따로 조회할 수 있다. 대시보드는 오늘·최근 7일·최근 30일·전체와 날짜별 가중 유지율을 제공한다. 처음/최근 비교는 선택 종류의 전체 기록에서 첫 7일과 최근 7일을 비교한다. 자정 세션은 종료일 기준이며 날짜별 분할은 아직 없다.

## 구현과 한계

기록의 `상세 보기`에서 적용 설정·유효/제외 시간과 사건을 확인한다. 서버 기록에는 원래 사건의 좌우 방향·중단 사유·제외 시간 구성을 표시하며
서버 종료 미확인 자료는 마지막 확인 요약과 보관 시각으로 안내한다. 없는 과거 기준·모델·제외 구성은 추정하지 않는다.
처음/최근 비교는 두 구간의 판정 출처·기준·모델·설정 차이를 표시하며 기존 합산/제외 기준을 유지한다.

탈퇴·서버 종료 미확인 요약 보관 확인창은 취소 버튼에 초기 초점을 둔다. Tab/Shift+Tab으로 창 안에서 이동하고
Esc·배경 클릭·취소로 닫으면 실행 버튼에 초점을 돌린다. 실행 버튼이 사라지면 새 화면의 주영역으로 이동한다.
처리 중 중복 실행과 취소를 막고 배경 화면 조작을 차단한다. 합성 브라우저 게이트에서 두 확인창의 키보드 동작을 확인한다.

`make check-browser`는 Chrome/Chromium·서버 JAR·프로덕션 프론트 빌드가 필요하다. `make check`는 준비 순서대로 이를 실행한다.
별도 실행 전에는 `make check-frontend`와 `make check-backend`를 실행한다. 설치된 Chrome을 자동으로 찾지 못하면 실행 파일의 경로를
`POSEGOOD_CHROME`에 지정한다. 합성 입력은 명시적 개발 테스트 모드에서만 사용하며 일반 개발/preview/프로덕션에서는 활성화하지 않는다.

- 특징·기준 비교: `model/prototype/pose.ts`. 기하학적 변화 점수이며 학습 확률이나 실제 관절 각도가 아니다.
- 로컬 시간 정책: `src/features/session/engine/`. 웹캠 로컬 모드와 과거 합성 시연에 적용한다. 기존 `src/lib/engine.ts` 공개 API를 유지한다.
- 서버 측정: `src/features/session/server/`. 계약 검증·순서 큐·복구·서버 결과 투영·전용 화면을 소유한다.
- 앱 조립·화면 전환: `src/app/ServiceApp.tsx`. 프로필·세션 저장/복구·기록 조회·저장 검증은 `src/features/`에서 기능별로 관리한다.
- 로컬 저장: `src/features/storage/`. 기존 `src/lib/serviceStore.ts` 공개 API와 저장 키·형식은 유지한다.
- 카메라 생명주기: `src/hooks/useCamera.ts`. 같은 스트림을 모든 화면과 작은 창에서 공유하고 명시적 사용 종료·측정 종료·로그아웃·인증 변경 시 해제한다. 일반 화면 이동은 진행 중 기준 보정만 취소한다.
- 영상·음성은 저장하지 않고 외부 API 업로드도 없다. 자세 등록에서 촬영을 직접 시작하면 추정 랜드마크·자세 정보를 메모리에 모아 CSV로 다운로드한다.
- 서비스 측정은 외부 탭 전환만으로 정지하지 않는다. 입력/스케줄링 공백이 1.5초를 넘으면 유효 관측에서 제외하고 직접 재개해야 한다. 실제 다른 탭·최소화·절전 지원은 별도 장치 검증이 필요하다. 연구 수집은 탭 숨김 시 중단한다.
- 정면 상대 변화만 보는 체험용 규칙이다. 깊이 이동·가림·조명·체형에 오탐/미탐이 있을 수 있다.
- 가시성 0.65, 특징 임계값, 5초 등록은 검증 전 값이다. 연구용 20~30초 등록이나 정확도 검증을 대체하지 않는다.
- 카메라를 옮기거나 장치를 바꾸면 기준을 다시 등록한다. GPU 우선(불가 시 CPU)으로 추론한다. 최대 GPU 30회/초·CPU 20회/초이며 추론이 느리면 주기를 낮춘다. 스켈레톤만 화면 주기에 맞춰 평활화한다. 실제 FPS와 추론 ms는 준비·측정 화면에 표시한다. 추론은 아직 메인 스레드다.

구현 참고: [MediaPipe 웹 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js).

## 자세 등록 (안내형 좌표 수집)

화면에는 연구 용어 대신 사용자용 이름 `자세 등록`을 쓴다. 내부 코드·CSV 규격은 기존 라벨 수집(`CollectionPage`, `useCollection`, 수집 v2)을 그대로 사용한다.
기준 등록 후 `자세 등록으로 이동` 또는 왼쪽 `자세 등록` 메뉴를 연다. 측정이 진행 중이면 먼저 종료해야 한다.
화면 상단에서 카메라 켜기/끄기·준비 취소·기준 등록/보정 취소를 할 수 있다. 등록 목적과 3단계 안내가 있고, 카메라 방향·거리·높이·책상 배치는 접이식 `카메라·책상 환경`에 있다.
찍을 자세 선택 → `준비됐어요 · 5초 뒤 촬영 시작` → 10/20/30/60초 촬영 → 실제 자세 확인(`맞아요 · 이대로 저장`) 또는 제외 → CSV 다운로드 순서다.
자세, 공책 읽기/필기, 양쪽 모니터 보기, 고개 돌리기, 자리 비움/복귀, 얼굴 가림 등 14개 자세를 제공한다.
전용 화면에는 규칙 점수·교정 알림이 없다. 미검출도 관측으로 기록하며 부재 정답은 촬영 후 확인한다.
등록한 자세가 현재 판정에 바로 반영되지는 않는다. 개인화 학습은 미연결이며, CSV 전달은 사용자가 별도로 결정하며 앱이 연구팀에 자동 전송하지 않는다.
미확인/제외 구간을 학습 정답으로 쓰지 않는다. 화면 이동·탭 숨김·카메라 해제 시 중단하고 다시 촬영한다.
다운로드 전 데이터는 메모리에만 남는다. 실제 파일은 Git에 추가하지 않는다.
[수집 v2 지침과 pandas 예제](../docs/research/guided-collection-v2.md)를 참고한다.

## 점수와 표시 모드

자세 점수는 100점에 가까울수록 개인 기준과 비슷하다. 기본 30점 이하가 3초 이어지면 알린다.
설정도 같은 점수 방향으로 표시한다. CSV의 `rule_score`는 종전의 변화 점수이므로 `100 * (1 - rule_score)`로 환산한다.
전체 키포인트는 Pose의 눈·입·귀·몸·팔·다리 중 보이는 점을 표시한다. 턱 추적은 포함하지 않는다.
웹캠 준비/측정의 `매트릭스 효과`는 점이 모이는 장식용 연출이다. `다시 모으기`, `애니메이션 줄이기`를 제공한다.
측정 화면의 `키포인트 표시`를 끄면 효과도 숨긴다. 추가 학습 데이터나 실제 3D 모델이 아니다.

## 저장소 오류와 여러 탭

프로필·설정·측정 요약·중간 기록을 검증한다. 손상/접근 오류가 있으면 원본을 유지하고 새 측정이나 변경을 차단한다. 오류 안내에서 다시 읽을 수 있지만 손상 원본을 자동 복구하거나 삭제하지 않는다. 같은 origin의 한 탭만 변경할 수 있고 두 번째 탭은 기록을 조회한다. 기존 탭을 닫은 뒤 `저장 권한 다시 확인`으로 변경 권한을 요청한다. Web Locks가 없는 환경은 읽기 전용이며 최신 Chrome의 localhost/HTTPS를 권장한다.

중단 기록은 마지막 저장 시각까지만 이어하거나 종료·저장한다. 최종 저장 후 draft 정리가 실패해도 결과 저장 성공과 구분하고 중복 복구하지 않는다. 저장 실패 시 같은 ID/종료시각으로 재시도하며 결과 저장 전 새 측정은 차단한다. 준비는 임시 30초 제한과 취소를 제공한다. 취소 후 늦게 도착한 스트림/모델은 해제하지만 브라우저의 권한 창 자체를 앱에서 닫지는 못한다.
